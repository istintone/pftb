### 3.45 監督の顔(2026-08-11)

**就任契約書の第三条で、自分の顔を選ぶ。** クラブチャットの監督の吹き出しに出る。

| | |
|---|---|
| 選ぶ場所 | 契約書(第三条 就任者肖像)。**顔は一度だけ選ぶ**もので、次の任期では聞かれない |
| 保存先 | `S.face`(監督名と同じ並び。キャリアより上、セーブそのものに属する) |
| 選ばなかったら | **監督名から決まる**。古いセーブと、選ばずに進んだ場合の受け皿 |
| 出る場所 | クラブチャットの監督の丸。今後の演出でも `managerArt()` を通す |

- 絵の切り出しは秘書(→docs/11 §6.27)とまったく同じ枠・同じ位置なので、
  **チャットの丸で顔が同じ高さに来る**
- 契約書の中では**丸ではなく角丸の枠**にした。書類に貼る証明写真の見立て

#### 絵を足すとき

```
src/assets/art/manager/<名前>_managers.png   ← 素材(4×2 の8人)
  → python tools/slice_manager.py
src/assets/manager/mg01a.webp …              ← 書き出し
```

**名前はシート名＋並び順**(`mg01a`, `mg01b`, …)。秘書のような通し番号にすると、
シートを1枚足しただけで番号がずれて、**選んだ監督が別人に入れ替わる**
(ステッカーで踏んだ失敗 →docs/11 §6.29)。

> **`mob` で始まるシートは既定では書き出さない。** 相手監督に使う予定の汎用の絵で、
> 出す先が無いのに埋め込むと index.html が重くなるだけ(`--all` で書き出せる)。

#### CLUB からいつでも選び直せる(2026-08-17)

顔は就任のとき(契約書 第三条)に一度きり、だった。名前と同じで**あとから変えたくなる**ので、
CLUB の監督欄から選び直せるようにした。

- 名前の左の枠が**顔そのもの**になる(それまでは頭文字の「M」だった)
- 押すと**契約書とまったく同じ部品**(`.ct-faces`)が並ぶ。片方だけ直して食い違うのを防ぐ
- 選んだ瞬間に枠が入れ替わる(決定を押すまで待たせない)
- 顔が2つ以上あるときだけ、押せる印(✎)を出す
- **絵が無い環境では頭文字に落ちる**。埋め込みを外しても画面が壊れない

### 3.46 カードの売却(2026-08-12)

**余った選手をコインに換える。** カード詳細の下に売却の欄が出る。

| | |
|---|---|
| 値段 | **段が幹、OVR が枝**。`base[段] + max(0, OVR-40) × 6` |
| | STD 60 / REG 150 / SPE 400 / WC 1200 / LEG 2600 |
| 確認 | **二段**。1回目で値段と警告、2回目で確定 |
| 消えるもの | カード本体と、そのカードの**訓練の成果と連携**(幽霊を残さない) |

#### 売れないもの(理由をそのまま画面に出す)

| | 理由 |
|---|---|
| クラブからの貸与 | 自分のものではない |
| 編成に入っている | 外してから。**勝手に外さない**(編成は監督が決めるもの) |
| 師弟の約束をした選手 | 次の任期へ連れていく約束がある |
| **実在選手** | 集めるものであって在庫ではない(→§3.13) |

> **「押せるのに何も起きない」を作らない。** `sellWhy()` は理由の文字列を返すので、
> 画面はそれをそのまま出せばよい。ボタンを消すのではなく**理由を置く**。

> **実在選手を売れなくしたのは、取り戻す手段が細いから。** 入手経路はスポンサーの
> 最上位だけで、売ると再入手に任期の半分が要る。二段の確認でも
> 「勢いで手放した」は防ぎきれない。ここは選べないほうが親切だと判断した。

#### スカウトの元は取れない値に置く

| パック | 費用 | 引いたカードの売値(期待) |
|---|---|---|
| スカウト | 600 | 242 |
| 重点スカウト | 1,600 | 437 |
| プロスカウト | 4,000 | 727 |

**引いて売るが回り出さない**ように、どの段でも1/3〜1/6に収めてある。
`TUNING.sell` を上げるときは、この表を必ず引き直すこと。

### 3.47 試合収益(2026-08-12)

**試合結果の画面に出すのは「クラブの帳簿」。** 前は `+900 コイン　+350 EXP` の一行で、
ゲームの点数に見えていた。**明細に割ると、同じ数字が収入になる**。

```
試合収益
  入場料（ホーム開催）        +120
  勝利給                     +780
  ─────────────────────────
  合計                       +900
```

| | |
|---|---|
| 入場料 | **出れば入るぶん**(=負けたときの額)。ホーム/アウェイで言い方だけ変える |
| 勝利給 / 引き分け給 | **勝敗で変わるぶん**。0 のときは行ごと出さない |
| カップ戦 | **1コインも入らない**ので「この試合の収入はありません／賞金は大会の決着で」 |

- **合計は今までとまったく同じ**。割り方を変えただけで、経済には触っていない
- **チーム熟練度(EXP)は出さない**。監督が見る数字ではないので画面から外した
- **無い収入を書かない**。カップ戦に入場料の行を作ると、入っていないお金を見せることになる

> **負の行を作らない。** はじめは入場料をホーム1.6倍/アウェイ0.6倍にして残りを成績給にした。
> 負け(120)ではホームの入場料が総額を超え、**「出場給 -72」**という行が出た。
> 「出れば入るぶん」と「勝ったぶん」に割れば、どちらも必ず0以上になる。

### 3.48 節の出来事(2026-08-14)

**10試合に1回くらい、選手のほうから何かが起きる。** 96節が「打ち手 → 試合」の
反復になっているので、たまに別の色を入れる。ブリーフィングの `event` の段に出る。

| | 誰に | 起きること |
|---|---|---|
| **控えの直訴** | 控えの1人 | 「使ってください」→ **絶好調**になる |
| **問い** | 先発の1人 | 「俺に何を求めていますか」→ **3択**。当たりで信頼 **+10** と絶好調、外れで **-3** |
| **個人練習** | 同じ国籍 or 同じクラブの2人 | 居残りで練習 → **連携 +90**(組の値) |
| **不信**(バッド) | **信頼がいちばん低い1人** | 監督を信じきれず、**調子が落ちる** |

- **同時には1つしか起きない**。`event` の段は1節に1つなので、器の側で保証される
- 順は **契約 → 師弟 → 出来事**。契約と師弟は条件が揃ったときだけなので、
  ふだんはここが出来事の席になる
- **問いの当たりは節ごとに変わる**。覚えて当て続けることはできない

#### 開き直しても同じ

起きるかどうかも、誰に起きるかも、当たりがどれかも**節から決まる**
(`mulberry32(seed ^ hash("luck:" + クラブ + ":" + 節))`)。

> **毎回引き直してはいけない。** チャットを閉じて開くだけで当たりを探せてしまう。
> 「その節に起きたこと」は世界の側の事実であって、画面を見るたびに変わるものではない。

#### バッドを1つだけにした理由

**悪いことが多いと、打ち手を選ぶ前に気分が下がる。** ここは「たまに良いことがある」
場所として置いてあり、バッドは**信頼を放っておくと起きる**という一点だけにしてある
(→§3.39 の信頼を見る理由が1つ増える)。

### 3.49 トレード(2026-08-14)

**任期の折り返し(45節)と終盤(90節)に1度ずつ、他クラブから話が来る。**
出せるのは **WORLD CLASS 以上の実名選手で、いま編成に入っていない人**だけ。
「使っていない切り札を、要る駒に替える」という判断にするため。

```
秘書: トレードのオファーが来ています。先方は ◯◯ を欲しがっています。
  ① ◯◯ を出す      → どんな選手を希望しますか（3択）→ 受信箱で受け取る
  ② トレードに出さない → この節目はもう来ない
```

#### 相手の候補は「どんな選手か」だけ分かる

3つの候補は**選ぶ前から中身が決まっている**。見せるのは手掛かりだけ。

| 手掛かり | 例 |
|---|---|
| 国籍 × ポジション | ブラジル国籍の ST |
| 所属クラブ × ポジション | マイアミ・ローズに所属している RWG |
| いちばん高い能力 | 非常に強力な ATK 能力の選手 |

- 手掛かりの種類は**候補ごとに固定**(カードのIDから決まる)。引き直しても文言が変わらない
- 段(WORLD CLASS / LEGENDS)は副題に出す。**何が来るかの見当は付くが、誰かは分からない**
- 候補は**未所持の実名選手から**。尽きたら自動生成の WORLD CLASS で埋める

#### 出す選手はその場で消え、来る選手は連絡で届く

**受け取るのは HOME の受信箱**(→§3.42)。スポンサーの報酬(→§3.40)と同じ形で、
受け取るとカード詳細がそのまま開く。

- 出した選手に紐づく**訓練の成果と連携も消す**(→§3.46 の売却と同じ始末)
- **断っても同じ節目は二度と来ない**(`career.tradeDone` に節目を記録する)
- 出せる選手が1人も居なければ話そのものが来ない

> **編成に入っている選手は出せない。** 出せてしまうと、その節の試合の直前に
> 主力が居なくなる。トレードは「余っている札の使い道」であって、
> 編成を壊す手段ではない。

### 3.50 特別采配(2026-08-14)

**指示(→§3.28 の5つ)の上に、1つだけ重ねる。** 陣形の"オーバーロード"にあたる層。

#### 使える条件は3つ

| | どこに貯まるか |
|---|---|
| **監督が覚えている** | `player.tactics` … **キャリアに残る**(移籍しても消えない) |
| **クラブが理解している** | `club.exp`(チーム熟練度) … **クラブに貯まる**(移籍したら0から) |
| **陣形が合っている** | `S.form` … 采配ごとに使える陣形が決まっている |

> **熟練度はクラブのもの、という一点がこの仕組みの背骨。**
> 監督が知っていても、選手が理解していなければ形にならない。
> **長く1つのクラブに居るほど選べる手が増え、渡り歩くと毎回積み直しになる**。
> 「腰を据える」か「上を目指して渡り歩く」かが、初めて戦術の話になる。

- 使えない采配も**理由を添えて並べる**。何を目指せば使えるのかが見えないと、
  覚える意味が伝わらない(「まだ身につけていません」「熟練度が足りません（5,000 必要）」)
- **ダイレクトプレーだけは最初から**持っている。監督なら誰でも知っている手なので

#### 中身は「チーム全体に掛かる札」

書き方はスキル(→docs/08)とまったく同じ(`at` / `grp` / `w` / `s` / `k`)。
`setTeamTactic` が**全員の `sk` に混ぜる**ので、新しい判定を1つも足していない。

**発動すればカットインのバッジに采配名が出る** — 演出が自動で付いてくるのが、
この形にした理由。

| 層 | 書くもの |
|---|---|
| 指示と同じ層 | `push`(ライン上下) / `lane` / `ordM`(能力の倍率)。**指示と足し算**になる |
| 札と同じ層 | `fx:[{at,grp,w,s}, {at,k}]` |
| 絞り込み | `role`(DF/MF/FW だけに掛ける) / `when`(条件付き) |

#### いまの15種(実測・互角の相手と2,500試合。**その采配が使える陣形で測る**)

| 采配 | 陣形 | 熟練度 | 得失点差 | 性格 |
|---|---|---|---|---|
| ダイレクトプレー | — | 0 | +0.24 | 蹴って走る。TEC を捨てて POW |
| ハイプレス | — | 1,500 | +0.26 | ライン上げ。失点↓得点↑ |
| リトリート | — | 1,500 | +0.06 | **得点も失点も下げる**(2.28/2.13) |
| ロングカウンター | 5-3-2 / 4-4-2 / 5-4-1 / 4-1-4-1 | 1,500 | +0.06 | 深く守って一発 |
| ゾーンディフェンス | 4枚系 | 5,000 | +0.10 | 面で守る。個の持ち味は薄れる |
| 5レーン | 3-5-2 / 4-2-3-1 / 3-4-3 ほか | 5,000 | -0.01 | 外から崩す。中央は薄い |
| ストーミング | 4-4-2 / 4-2-4 / 4-2-2-2 / 3-4-3 | 5,000 | +0.22 | 縦に速く。雑になる |
| ショートカウンター | 4-2-3-1 / 4-3-3 / 4-4-2 | 5,000 | -0.01 | 奪って一気に |
| ゲーゲンプレス | 4-3-3 / 4-2-3-1 | 12,000 | +0.07 | 即時奪回。失点↓ |
| カテナチオ | 5-3-2 / 5-4-1 / 4-3-2-1 | 12,000 | +0.21 | **1.99得 / 1.76失**。勝点1を持ち帰る |
| インバーテッド・フルバック | 4枚系 | 12,000 | -0.01 | **SBが中に入って起点になる** |
| フォルス9 | 4-3-3 / ゼロトップ / 4-2-3-1 | 12,000 | -0.01 | 前が下りて繋ぎ、2列目が決める |
| マンマーク | 3-5-2 / 5-3-2 / 3-4-3 / 5-4-1 | 12,000 | -0.02 | **相手に軸が居ると +0.14**(対人の采配) |
| ティキ・タカ | 4-3-3 / 4-1-4-1 / 9.5番 | 25,000 | +0.20 | 繋いで崩す。遠射はしない |
| トータルフットボール | — | 45,000 | +0.21 | **枠適性のロスが半分埋まる** |
| パーク・ザ・バス | 5-3-2 / 5-4-1 / 4-1-4-1 / 4-4-2 | 5,000 | +0.12 | **リードしているあいだだけ効く** |
| 戦術的ファウル | — | 12,000 | +0.12 | **カード2.3倍・退場3.2倍**と引き換え |
| オートマティズム | — | 25,000 | -0.03 〜 +0.12 | **連携しだい**。初対面の11人には何も起きない |

> **この表は §7.22(得点の圧縮)より前の実測。** いまの値は下の「効きの倍率」を見ること。

**帯は -0.03〜+0.26。熟練度が買うのは"強さ"ではなく"性格"。**
高い采配ほど強い、にすると「上位互換が1つある」だけの表になり、
陣形も編成も選ぶ意味が消える。測定の揺れは ±0.07 ほどあるので、
小数第2位を確定値として扱わないこと。

> **得失点差では測れない采配が3つある。** 物差しのほうを変えないと、
> 「効いていない」という誤った結論になる。
>
> | 采配 | 正しい物差し | 素 | 采配あり |
> |---|---|---|---|
> | マンマーク | **軸を持つ相手**との得失点差 | -0.02(軸なし) | **+0.14** |
> | パーク・ザ・バス | **リードした試合を勝ち切った率** | 64.3% | **70.5%** |
> | オートマティズム | **連携の積み上げ別**の得失点差 | -0.03(連携なし) | **+0.12**(十分) |
>
> マンマークは軸(→§3.44)が居て初めて効くので、軸の無い相手と測ると代償しか出ない。
> CPUは必ず軸を持つので、実戦では常に後者。
> パーク・ザ・バスは **2.23得 / 2.08失** と両方を下げる采配で、得点を捨てて
> 勝点を拾う。同じ「下がる」采配のリトリートはリード維持 65.7% どまりなので、
> **勝っている試合を終わらせる**という役割はこちらにしか無い。

#### 条件付きの采配(`when`)

固有スキルの `when`(→§3.41)をそのまま使う。いまある条件:

| 条件 | 意味 | 立つ割合 |
|---|---|---|
| `late` | 残り15分だけ | 0.256 |
| `fresh` | 脚が残っているあいだだけ | 0.337 |
| `lead` | **リードしているあいだだけ** | 0.306 |

`lead` だけは盤面の状態で決まる。スキルの条件は選手しか受け取らないので、
**点差は毎ティック `refreshStamina` が `p.lead` として選手に降ろしている**。
盤面の状態を条件にしたくなったら、同じやり方で降ろすこと。

#### 効きの倍率(2026-08-17)

**シュート側の勾配を変えると、采配の効きも一緒に潰れる。**
§7.22 で `gapPow` を 1.00 → 0.45 にしたとき、采配は能力差を作る手なので
同じ圧縮を受けた。18手を同じ物差しで測り直した結果:

| | 帯 | 平均 |
|---|---|---|
| 圧縮前 | -0.079 〜 +0.229 | +0.104 |
| 圧縮後(倍率なし) | -0.032 〜 +0.174 | **+0.068** |
| **いま(`tactic.k` 1.45)** | -0.035 〜 +0.225 | **+0.101** |

`TUNING.tactic.k` は **`s` と `k` の「1からの隔たり」を伸ばす**1つのつまみ。
18手を個別に書き直さずに帯を戻せるので、**シュート側を触るたびにここで合わせる**。

掛かる先: `s` / `k`(札の強さ) / `ordM` / `fitK` / `bondX` / `foulX`
掛からない先: **`w`(札の選ばれやすさ = 采配の性格)** / `push` / `manMark`

> **`w` だけで書いた采配は倍率が効かない。** ダイレクトプレーは `w` しか持たず、
> 圧縮で +0.161 → +0.065 に落ちたまま**倍率を上げても動かなかった**。
> `s:1.06` を足して、初めて他の采配と一緒に上げ下げできるようになった
> (+0.134 に回復)。**新しい采配には必ず `s` か `k` を持たせること。**

> **オートマティズムとマンマークはこの表では動かない。** 前者は連携が要り、
> 後者は相手に軸が要る(→上の「得失点差では測れない采配」)。倍率の効き目も
> その条件下でしか出ない。

#### 効果ごとに役割を絞れる

`fx` の1つずつに `role` を書ける。「前は下がり、2列目が出る」(フォルス9)のような
采配は、チーム全体に1つの倍率を掛けるだけでは書けない。

そのほかの専用の口:
- `fitK` … 枠適性のロスを埋める(トータルフットボール)
- `manMark` … 相手の軸への当たりを強くする(マンマーク)
- `bondX` … **連携の効きを増幅する**(オートマティズム)。`bondK` の「1からの隔たり」を
  伸ばすので、**組んだことのない11人には何も起きない**。これが代償の本体で、
  同じ11人を使い続けたクラブだけが元を取れる(→§3.31)
- `foulX` … 反則率だけを膨らませる(戦術的ファウル)。**ケガの側には掛けない**。
  狙って削るのではなく、掴んで止めている采配だから

> **`grp:"all"` に `w` を書いても何も起きない。** `w` は札の選ばれやすさで、
> 全部の札を同じだけ持ち上げれば比率は元のままになる。パーク・ザ・バスを
> `w:1.50` で書いて一度これを踏んだ。**全体に効かせたいときは `s`(判定の強さ)を使う。**

**帯は +0.0〜+0.3 に揃えてある。熟練度が買うのは"強さ"ではなく"性格"。**
高い采配ほど強い、にすると「上位互換が1つある」だけの表になり、
陣形も編成も選ぶ意味が消える。

#### 数字を触るときに知っておくこと(実測)

| いじるもの | 効き幅の目安 |
|---|---|
| `ordM` を1つの能力に ±5% | **±0.15〜0.25** |
| `stam` k=1.04(チーム全体) | **-0.10** |
| `stam` k=1.18(チーム全体) | **-1.1**(壊れる) |
| `cover` k ±0.1 | ∓0.10 |

> **`ordM` は必ず等価交換にする。** 片側だけ上げると、ただの強化になって
> 「敷かない理由」が無くなる(実際に +0.53 の采配ができた)。
>
> **関与の回数を動かすだけの采配は、必ずマイナスになる。** フォルス9の
> 「前が受けない / 2列目が受ける」は、受け手を入れ替えているだけなので
> -0.11 だった(→§3.38 で分かっていたこと)。下りた9番に**繋ぎ役としての強さ**を
> 与えて初めて釣り合った。
>
> **`grp` は、その枠が実際に持っている札の種類でなければ効かない。** フォルス9に
> `passTec` を書いたが、4-3-3 の前3枚は tec のパス札を持っておらず**一度も発動しなかった**。
> 数字を変えても結果が動かないときは、まずここを疑う。
> ダイレクトプレーは POW +6% と引き換えに TEC -6%、という形にしてある。
>
> **チーム全体の `stam` は極端に高い。** 1人に掛ける KP(→§3.44)の感覚で
> 1.45 を置いたら **-2.6** になった。11人ぶん積み上がるので、1.02〜1.06 で十分効く。

#### 采配は監督のもの、熟練度はクラブのもの(2026-08-18)

**采配は監督が恒久的に覚える。** クラブを渡り歩いても消えない。
一方**熟練度はクラブに帰属する**ので、移った先では 0 から積み直しになる。

    監督は戦い方を知っている。だが選手はまだそれを出せない。
    試合を重ねてクラブに経験が貯まると、初めて使えるようになる。

この関係を連絡の文面でそのまま伝える(`tacticNote()`)。

    監督の引き出しには入りましたが、選手がこの形を出せるようになるには
    クラブの熟練度が要ります（1,500 必要／いま 0）。試合を重ねれば届きます。

熟練度の要らない采配(メモラビリア限定など `exp:0`)は「うちでもすぐ試せます」。

#### 届くものは、必ず秘書の受信箱を通す

覚えた瞬間に増やすのではなく、**連絡が届き、受け取って初めて覚える**。
選手(→§3.52 / §3.49)と同じ道にそろえた。その場で配ると
**いつ増えたのかが記録に残らない**。

見出しは **「〈采配名〉を習得しました」**。

### 3.51 采配を盗む(2026-08-14)

**その采配で戦ってきた相手とやり合うと、確率で覚える。** 布陣を学び盗む。

```
1部・2部のクラブは采配を敷いている
  → 見立てで「戦い方は『ハイプレス』で来ます」と分かる
  → 戦う（勝つほど当たりやすい）
  → 覚えたら受信箱に連絡「『ハイプレス』を持ち帰りました」
```

#### 誰が敷いているか

| | |
|---|---|
| **3部** | 敷かない。素朴に戦う |
| **1部・2部** | 敷く。**リーグの格と部で「賢さ」が決まる**(`tier×2 + (3-部)`) |
| **カップ** | **格の高い大会・勝ち上がるほど賢い**。エリート枠はさらに一段上 |

弱いリーグの1部にゲーゲンプレスが並ぶと序盤で全部覚えられてしまうので、
**そのリーグの格に見合う采配しか敷かない**。実測ではラ・リーガやリーグアンの
上位にだけ最上位の采配が現れ、カンピオナートはダイレクトプレー中心になる。

> **上へ行くほど盗める手が増える。** 昇格と、上位リーグへの移籍そのものが
> 「新しい戦い方を知る」動機になる。

#### 覚え方

| 結果 | 1試合あたり |
|---|---|
| 勝ち | **25%** |
| 引き分け | 10% |
| 負け | 5% |
| カップ | **+10%**(上乗せ) |

- **知っている采配は引かない**。同じ相手と当たり続けても無駄にならない
- 1試合では覚えないが、**同じリーグを1季戦えばだいたい何かは持ち帰る**
  (同じ相手と2回当たるので、勝てば約44%)
- 負けても少しは覚える。**やられた戦い方ほど身に染みる**、という筋

#### これから

残りの采配(ティキ・タカ / カテナチオ / 5レーン / インバーテッド・フルバック /
フォルス9 / トータルフットボール / ゾーン / マンマーク / ロングカウンター など)は、
§3.50 の帯に収まるように測ってから流し込む。
**采配が増えるほど、上位リーグを回る意味も増える**。

### 3.52 実績の報酬(2026-08-16)

棚(→§3.36)は「獲っていない分も並べる」ことで目標の一覧にはなっていたが、
**獲っても飾りが1つ増えるだけ**だった。ここに、このゲームで一番価値のあるもの——
**WC / LE の実在選手(→§3.19)**——を結びつける。

#### 何が付くか

| 実績 | 初優勝 | 2度目から |
|---|---|---|
| プレシーズン / キングズ / スーパーキングズ / タイトルホルダー | **WC シグネチャ** | 2,500 コイン |
| ユニバーサル / コンチネンタル / チャンピオンズ / ワールドクラブ | **LE シグネチャ** | 6,000 コイン |
| リーグ DIV1 制覇(6リーグぶん) | **WC シグネチャ** | 2,500 コイン |
| リーグ DIV2 制覇 | 4,000 コイン | 2,000 コイン |
| リーグ DIV3 制覇 | 1,500 コイン | 750 コイン |

数字は `TUNING.ach`。

> **2度目からはシグネチャを配らない。** 棚に回数が増えるのが実績であって、
> 毎回配ると**同じ大会を回り続けるだけで収集が終わる**。カップは11〜16節ごとに
> 巡ってくるので、ここを塞がないと任期のあいだに同じ大会を何度も獲れてしまう。

#### 出せるのは 14 枠 / 26 人

シグネチャは WC 13人・LE 13人の 26 人。実績から出るのは
**WC 10 枠(カップ4 + DIV1 6)と LE 4 枠**の 14 枠だけで、
残りはスカウトと引換券(→§3.42)からしか出ない。**実績は最上の入手経路であって、
唯一の経路ではない**。ここを埋め尽くすと、スカウトを引く理由が消える。

**DIV1 制覇が6リーグぶんある**のが効いていて、6枚を集めるにはクラブを渡り歩く
必要がある。長居して熟練度を貯める(→§3.50)のと正面から competing する目標になり、
「どちらを取るか」が任期の選択そのものになる。

#### 配り方 — スポンサーと同じ道

スポンサーの報酬(→§3.40)とまったく同じで、**秘書のお知らせに届き、受信箱で受け取る**。
「入手した実感がわかないうちに選手が加入している」を避けるための道筋なので、
実績だけ別の配り方にはしない。

- `trophyAdd()` の中で配る。**刻む場所と配る場所を分けない**ので、
  実績を足したときに配り忘れが起きない
- 連絡の鍵に**回数まで混ぜる**(`ach:<id>:<n>`)。同じ実績を2度獲っても別の連絡になる
- 受け取り待ちの連絡は 30件の上限で消えない(→`mailTrim`)ので、
  シーズン末に実績が重なっても取りそびれない

#### 棚に報酬を出す

棚のタイルに「**WORLD CLASS シグネチャ ／ 初優勝**」と出す。獲ったあとは「受領済み」。
棚がそのまま「次にどれを獲りにいくか」の一覧になるので、報酬を隠す理由が無い。
シグネチャの行だけ金で立てて、コインの行と色で分ける。

### 3.67 移籍市場(2026-08-16)

いままでの入手経路は**全部が抽選か、向こうから来るもの**だった。

| 経路 | 選べるか |
|---|---|
| スカウト(→§3.26) | ✗ 引くまで分からない |
| 引換券(→§3.42) / 実績(→§3.52) / トレード(→§3.49) / ラッキー(→§3.48) | ✗ 段や条件までしか選べない |

**「右SBが足りない。この選手を、この値段で買う」がどこにもできなかった。**
市場はその1点のためにある。スカウトが**引く**場所なら、ここは**選ぶ**場所。

#### 並ぶもの

毎節6人。**能力も値段も全部見えている**(隠すと市場である意味が無い)。
**節が変われば総入れ替え**で、迷っているうちに居なくなる。

| 段 | 割合 | 平均OVR | 平均買値 | 値幅 |
|---|---|---|---|---|
| STANDARD | 24% | 55.6 | 919 | 400〜1,600 |
| REGULAR | 37% | 66.5 | 1,767 | 1,000〜2,600 |
| SPECIALS | 31% | 74.0 | 3,091 | 2,200〜4,000 |
| **WORLD CLASS** | 6.7% | 80.5 | **40,637** | 32,600〜49,000 |
| **WORLD CLASS(実在選手)** | 1.2% | 82.1 | **88,384** | 80,000〜98,000 |

**LEGENDS は並ばない。** 実績(→§3.52)と引換券(→§3.42)の取り分として残す。
実在の WC は **14節に1人**しか現れない。

#### 値付け — 売却カーブに乗せる

`買値 = 売値(→§3.46) × 段ごとの倍率 × (1 + 段の下限からの伸び × ovrK)`

実測でコインあたり **5.1〜5.7倍**。重点スカウトが 3.9倍なので、
**確実さと選べることに3〜4割の割増を払う**関係になり、スカウトを引く理由が残る。
買って売り直すと **80%の損**なので、往復の抜け道も無い。

> **売却カーブをそのまま買値にすると平らすぎる。** `perOvr:6` だけだと
> OVR68 と OVR80 の SPECIALS が 2,800 と 3,200 にしかならず、**能力が見えている
> 市場では「一番高いOVRを買うだけ」の作業**になる。段の下限からの伸びで
> 割増を付けて、初めて選ぶ意味が出た。

**WC は 40,000 前後 = 34節ぶんの稼ぎ**(収入は実測 1節あたり約1,191コイン)。
**実在選手は 80,000 が下限で、平均 88,000 = 74節ぶん**。任期は120節なので、
実在の1枚は「任期に一度あるかどうか」の買い物になる。
倍率だけだと OVR の低い個体が 68,700 まで落ちて「まれな一枚」に見えないので、
`sigMin` で底を打っている。

#### 逃したら消える

顔ぶれは `hash("market:" + 世界のたね + 節)` から決まる。

- **同じ節なら何度開いても同じ**(眺め直しても引き直せない)
- **節が変われば6人とも別人**。売り切れも持ち越さない
- カードの id は `mk<節>-<枠>` という**枠に紐づく仮のもの**で、
  買った瞬間に通し番号へ載せ替える。ここで `nextCardId()` を使うと、
  **画面を開くたびに番号が進んで別人になる**

### 3.68 まとめて売る(2026-08-16)

売却(→§3.46)は1枚ずつだった。整理のたびに「開く → 売る → 確認 → 閉じる」を
人数ぶん繰り返すことになり、市場(→§3.67)とスカウトで札が増えるほど苦しくなる。
**選んでから一度だけ確認する**形に変える。

#### モードとして分ける

CARDS の「まとめて売る」を押すと、**札のタップの意味が「開く」から「選ぶ」に変わる**。
意味が変わる以上、いまどちらのモードなのかは必ず画面に出す(ボタンの文言と色、
画面全体の状態クラス)。抜けると選択は破棄され、次に入るときは空から始まる。

#### 売れないものは選ばせない

`sellWhy()`(→§3.46)をそのまま使う。**一括のためのルールは1つも足していない。**
売れない札は幕を掛けて、理由を面に短く出す。

| 状態 | 面に出す言葉 |
|---|---|
| 編成に入っている | 編成中 |
| 師弟の約束をした | 師弟 |
| 実在選手 | コレクション |
| クラブからの貸与 | 貸与 |

> **カードごと薄めると理由まで読めなくなる。** 最初 `opacity:.34` を札に掛けたら、
> 上に載せた理由の札も一緒に薄まって消えた。**幕を1枚敷いて、理由はその上**に置く。

#### 何を隠してはいけないか

一括モードで札の上に足すのは**チェック**と**値段**の2つだけだが、
どちらも置き場所を間違えると判断材料を潰す。

- **チェックは左上**(クレストの位置)。右上は OVR で、**売るかどうかを決める数字**
- **値段は名前帯の上**。帯に重ねると、**誰を売るのか**が読めなくなる

どちらも一度そうなってから直した。段はカードの枠色でも分かるので、
クレストだけは隠してよい。

#### 選択はページと絞り込みをまたいで残る

1ページ12枚(→§3.46)なので、送りながら積めないと「まとめて」にならない。
「すべて選ぶ」は**いま絞り込んでいる全体**に掛かる(ページではない)。

#### 戻せないので二段

1枚売りと同じ作法。1度目で「本当に N 人を売る」に変わり、2度目で確定する。
足元の帯には**選んだ人数と合計額を常に出す**。
`sellCards()` は1枚ずつ `sellCard()` に通すので、売れないものが混ざっても
そこだけ飛ばして残りは売れる(返り値の `sold` は選んだ数と一致するとは限らない)。

### 3.53 段の数値は域内に収め、強さは★で出す(2026-08-17)

上位のカップでは **128人中128人が段の規定域を超えていた**(最大 OVR 113)。
`makeCard` が段を抽選したあとに `ovrBias` を足し、上限は `OVR_MAX`(120)しか
見ていなかったため。

**いちばんまずいのは WC102 ではなく RG99 だった。** REGULAR(規定 58〜75)が 99、
STANDARD(規定 46〜65)が 82 で出てくるので、**RG99 が WC85 より強い**。
段のバッジが何も意味しなくなっていた。

#### 直し方 — 水増しを★へ振り替える

| | 前 | いま |
|---|---|---|
| OVR | 段の抽選 **+ ovrBias**(域外へ出る) | 段の**域内**に収める |
| 強さの差 | OVR の水増し | **★**(選手あたり最大5) |
| 連携 | CPUは持たない | **育った相手は全ペア黄金線** |

★はプレイヤーの訓練(→§3.30)とまったく同じ `up`(能力ごとの上乗せ)で持つので、
`eff()` がそのまま読む。**新しい判定を1つも足していない。**

★の配り方(`TUNING.star`):
- クラブ … 部を土台に、リーグの格と順位で上下。**DIV1の強豪は★5**
- カップ … 大会の格と勝ち上がりで決まる。**上位3大会は★5**
- `goldAt` に届いた相手は**全ペアが黄金線**

> **段の中でも上下に寄せる(`bandK`)。** 水増しをそのまま域内へ押し込めると、
> **全員が上限に張り付いて段の中の個体差が消えた**(WC85 が11人並ぶ)。
> 0.35 に薄めてから寄せることで、強いクラブは域の上、弱いクラブは下に散る。

#### 強さを比べる場所は必ず `ovrOf()`

★は `c.ovr` に入らないので、**素の `c.ovr` で比べると相手を弱く見積もる**。
実際にキックオフの勢いが付かなくなった(0.10 / しきい値 0.2)。

`ovrOf(c) = c.ovr + upOf(c)` を用意して、`squadPower` / `teamStrength` /
`kickoffMom` / `bestXI` / `autoSquad` / `cpuKp` を全部これに寄せた。
**画面の実効値と下見の★も同じ**(→docs/06)。

#### 結果

段の域外は **0/2304人**。大会の手応えは素直な階段になった。

| 大会 | 相手★ | 得失点差 |
|---|---|---|
| プレシーズン | 0 | +4.47 |
| キングズ | 2 | +3.84 |
| スーパーキングズ | 3 | +1.34 |
| ユニバーサル | 5 | +1.01 |
| コンチネンタル | 4 | +0.05 |
| チャンピオンズ | 5 | +0.07 |
| **ワールドクラブ** | 5 | **-0.32** |

前は最上位が **-2.37**(一方的に負ける)だった。いまは**五分**。

> **連携は補填にならない。** 積み上げ160でも700でも **-0.06** しか動かない。
> 効いたのは黄金線(`k4=1.50`)のほうで、それでも★には遠く及ばない。
> **★だけが OVR と同じ通貨**なので、水増しの受け皿になれるのはここだけ。

#### まだ CPU に無いもの(→backlog)

**交代をしない**(~0.15)と**指示を出さない**(~0)。どちらも `orderMatch` が
UIからしか積まれないため。**敵監督の設定**として後から入れる。
固有スキルを持てない点は、プレイヤー側のご褒美として残す。

### 3.54 クラブのエンブレム(2026-08-17)

**絵を1枚も持たずに、コードで描く。**

#### なぜ画像にしなかったか

| | コードで描く | 汎用パターン画像 |
|---|---|---|
| 必要数 | **184個**(クラブ144 + カップの架空名40) | 同じ |
| index.html への追加 | **0 バイト** | 12枚で約 64KB(base64) |
| 出せる個性 | **144クラブが全部ちがう顔** | 12通りを15クラブずつ共有 |
| 拡大 | どの大きさでも輪郭が出る | 小さい絵を大きく出すと甘い |
| 仕組み | 不要 | 切り出しと埋め込みの手順が1本増える |

決め手は3行目。**汎用パターンだと15クラブが同じ絵柄を共有する**ので、
「クラブごとに個性を」という目的に対して画像は個性を**減らす**方向に働く。

クラブも名簿も陣形もIDから決まる作りなので、エンブレムも同じ流儀に乗せた。
**クラブを足せばエンブレムも生える**(採番も素材も要らない)。

#### 組み立て

`形4 × 地の柄7 × 紋章8 × 色相144` — 実測で **144クラブが144通り**。

- **かたち**(5) … 盾 / 丸 / **縦長丸** / 尖り盾 / バナー
- **地の柄**(9) … 無地 / 縦縞 / 左右割り / 四分割 / たすき / 横帯 / 山形 / **十字** / **ななめ十字**
- **紋章**(11) … 星 / 王冠 / **鷲** / **獅子** / **馬** / **騎士の兜** / ボール / 塔 / 剣 / 稲妻(と「文字」)
- **外装**(5) … なし / 王冠 / 月桂樹 / リボン / 月桂冠(→§3.54a)
- **色**(26×2) … ホーム(地)とアウェイ(柄)を選ぶ。選ばなければ `clubHue()` から決まる

縦長丸は、鳥や兜のように**縦に伸びる紋章**が収まりやすい。

#### 色は盤面にも効く

ホームカラーは `clubColor()` にも効かせる。**エンブレムだけ選んだ色で、
ピッチの影が別の色**、を作らない。色相だけを持たせてあるので、
明るさと彩度は既にある決まり(→docs/06 §6.13)がそのまま掛かる。

#### 中央は**ラテン文字のモノグラム**

クラブ名は日本語なので、そのまま盾に入れるとカタカナが窮屈に収まる。
カタカナ→ラテンの表を持ち、**「・」で区切られた語の頭を1文字ずつ**拾って2文字にする。

    マンチェスター・レッズ → MR      ライプツィヒ・ローテブレン → RR

紋章は**3クラブに1つくらい**にしてある。全部を紋章にすると、
どのクラブか名前でしか分からなくなる。

#### ★ = ワールドクラブチャンピオン

**獲った数だけ盾の上に載る。3つで打ち止め**(`TUNING.emblem.maxStar`)。
自分のクラブにだけ付く(CPUはこの大会を獲らない)。

★が付くと `viewBox` を上に広げる。**盾を縮めない**ので、
1つ目の★が付いた瞬間に紋章が小さくなる、が起きない。

#### 組み替えられる

CLUB の CREST 欄を押すと、色2つ・かたち・地の柄・紋章・外装から選べる
(`S.club.emblem`)。**見本は実物で描く**ので、押す前にどうなるかが分かる。
ただし**色だけは色そのものを並べる** — 小さい盾を12個並べても色が読めない。
`S.club` の中に持つので、**別のクラブへ移れば新しいクラブの顔に戻る**。

#### どこに出すか

**クラブを色の丸で表していた場所は、全部エンブレムに置き換える。**

| 場所 | 前 | いま |
|---|---|---|
| ヘッダー | クラブ名の頭文字 | エンブレム(★つき) |
| 試合のスコアボード | クラブカラーの丸 | エンブレム |
| リーグ戦の日程 | クラブカラーの丸 | エンブレム |
| 本節タイルの相手 | クラブカラーの丸 | エンブレム |

**同じ相手と2度当たる**ので、日程の行には節ごとに別の `tag` を渡す。
渡さないと `clipPath` の id がぶつかり、**後の行の盾が前の行の形に切り抜かれる**。

クラブカラーそのものを使い続けるのは、**クラブではなく「そのチームの選手」**を
指す場所だけ(ピッチの足元の影・カードの地・カットインの丸)。

> **`>>` ではなく `>>>` でずらす。** `hashStr` は 32bit いっぱいを返すので、
> 符号つきでずらすと負になり、配列の外(`undefined`)を引く。
> 実際に**地の柄が消えたクラブ**があった。drive.js が意匠の欠けを見張っている。

### 3.55 メモラビリア(2026-08-18)

**普段は戦えない編成**との一戦。合言葉を読ませると開き、以後いつでも挑める。

#### 何が特別か

- 相手は**常に最強**。全員★上限(5)・**全ペア黄金線**(→§3.31)
- **限定の采配**を敷いてくる。低い確率で盗める
- 勝つと**相手の選手を1人**もらえることがある
- **節も日程も消費しない**。キャリアの進行には一切触らないので、何度でも挑める

#### 手に入れ方は2つ

**① ワールドクラブチャンピオンカップを制す**(→§3.23)。
まだ持っていないものから**1つ**が秘書の受信箱に届く。
最高峰のクラブに勝てるチームだけが挑める、**その先の遊びへの入口**として置いた。

全部そろっていれば何も起きない(空の連絡を出さない)。
今後メモラビリアを足せば、**次に世界を獲ったときに自然と次のものが届く**。

**② 合言葉を読ませる**(下記)。配りたいときに配れる道を、優勝とは別に残しておく。

#### 合言葉は QR で配る

`hash` を `MEMORABILIA` にそのまま置く。**難読化しない** —
オフラインの単一HTMLなので隠しても読めてしまうし、隠すと配った側が確かめられない。

読ませ方は2つ。

- **URL に付ける** … `…/index.html#mem=ROSSONERI-2005`。
  **QRはこれを開くために配る**。カメラを使わずに済むので、単一HTMLのまま成立する。
  一度読んだら URL からは消す(再読み込みで何度も知らせが出ないように)
- **手で入れる** … CLUB の入力欄。大文字小文字と前後の空白は無視する

#### 所属で絞る采配

限定の采配には `club` を持たせられる。**その所属の選手にしか効かない**。

    イル・メラヴィリオーゾ … 4-4-2ダイヤ限定 / ミラノ・ロッソネリの選手のみ
      TEC ×1.10・POW ×0.96 ／ 消耗 ×1.05

持ち帰っても万能の手にはならない、というのがこの鍵の意味。
`setTeamTactic` は所属の違う選手を飛ばし、`setTeamOrder` は**指示のぶんだけ**を渡す。

> 実測: ミランの11人には TEC ×1.145 が乗り、**よそのクラブに敷くと 1.000**(効かない)。

#### 触り方

一覧の行は**2つに割れている**。

| 押すところ | 行き先 |
|---|---|
| 見出し(黄色の帯) | **相手の下見**。リーグ戦とまったく同じ画面を使い回す |
| `›` | その場で開戦 |

下見では**敷いてくる采配まで見せる**。盗む相手が何を使うかは、下見の値打ちそのもの。

一戦のあとは「次の予定へ」ではなく **「再戦する」**。
節を消費しないので、結果画面からそのまま挑み直せる。

#### 第1号 — 2005 CL 決勝 ACミラン

4-4-2ダイヤ / 監督 アンチェロッティ / 軸 カカ / 指示 攻撃重視。

    GK  ジーダ
    DF  マルディーニ ネスタ スタム カフー
    MF  ピルロ ガットゥーゾ セードルフ カカ
    FW  クレスポ シェフチェンコ
    控え インザーギ アンブロジーニ ルイ・コスタ カラーゼ コスタクルタ

> **手応え(実測)**: プレミア1位の編成で挑んで **勝率14%**(1.34 - 3.07)。
> 勝ったときに選手が出るのが 20.8%、采配が 31.1% なので、
> **1回の挑戦あたりで見ると選手 2.8% / 采配 4.3%**。何度でも挑めるので、
> 「いつかは獲れる」重さに収まっている。

### 3.56 相手監督(2026-08-18)

CPUは**交代をせず、指示も出さない**まま戦っていた(→§3.53 の宿題)。
同じ11人でも「誰が指揮しているか」で運びが変わるようにする。

#### できるのは指示と交代の2つだけ

**采配(→§3.50)は動かさない。** 掛け直せる手にすると編成の意味が薄れるので、
そこは監督の領分にしない。

性分は**名前と同じ key から決まる**ので、同じ相手はいつ当たっても同じ運びをする
(下見と試合で食い違わない)。下見には性分を出す。

| 性分 | 指示 | 交代 |
|---|---|---|
| **堅物** | 変えない | **しない**(ケガと退場だけ) |
| **標準** | 前後半で入れ替える | 55分から3人 |
| **気まぐれ** | 15分おきにでたらめ | 25分から3人 |
| **知能** | 負けていれば攻撃・勝っていれば守備 | 58分から3人 |
| **出し惜しみ** | **75分まで動かない** | 75分から一気に3人 |
| **知将** | **勝っていれば攻撃・負けていれば守備** | 60分から3人 |
| **キーマン** | **軸の居る側へ振る** | 62分から2人 |

> **知将だけは向きが逆**。ふつうは追う側が前に出るが、この型は
> 「勝っているうちに畳みかけ、負けたら傷を広げない」。
> 一種類だけ逆を混ぜておくと、下見で性分を見る意味が出る。

#### 顔を出す

下見の監督バーに顔が入る。**key から決まる**ので、同じ相手はいつも同じ顔。

| 相手 | 顔 |
|---|---|
| **DIV1** / カップの上位(`bias>=9`) / メモラビリア | **有名な顔**(`mg01` / `mg02`) |
| それ以外 | 汎用の顔(`mob01`) |

有名どころは**プレイヤーが契約書で選ぶのと同じ16人**から引く。
格の高い相手だけ顔で分かるようにしておくと、
**上へ行くほど相手の顔ぶれが変わる**という手応えになる。

自分の監督も同じ枠・同じ作りで DECK に出す(→§3.45)。
切り出しはチャットの丸・契約書と同じなので、枠が違っても顔がずれない。

#### 実測(相手は同じ11人・各150試合)

| 性分 | 指示替え | 交代 | 最終の指示 | 得失点差 |
|---|---|---|---|---|
| 堅物 | 0.0回 | 0.0人 | center(100%) | **+1.88** |
| 標準 | 2.0回 | 3.0人 | center(100%) | **+1.30** |
| 気まぐれ | 5.0回 | 3.0人 | left(25%) | +1.59 |
| 知能 | 1.2回 | 3.0人 | attack(72%) | +1.49 |
| 出し惜しみ | 0.9回 | 3.0人 | attack(71%) | +1.39 |
| 知将 | 1.2回 | 3.0人 | defend(69%) | +1.31 |
| キーマン | 1.3回 | 2.0人 | **right(74%)** | +1.45 |

**監督が付くと 0.5 ぶん手強くなる**(堅物 +1.88 → 標準 +1.30)。
効いているのはほぼ交代で、**堅物が一番弱いのは代えないから**。

> **`cpuOrder` という名前は使えない。** world.js が順位の並べ替えで先に使っており、
> 結合順(world → match-core)のせいで**あとから上書きしてしまう**。実際に踏んで
> シーズンの昇降格が落ちた。同じ前置きの名前を別ファイルで作るときは、
> 先に `grep` して確かめること。

### 3.49a 受信箱に届く実在選手は、**手元に入る瞬間に採番する**(2026-08-19)

WC以上のトレードで、**受け取ったのに選手が手元に居ない**ことがあった。

原因は id の作り方。実在選手の型紙は `makeSignature()` で
**`8000000 + 通し番号` の固定 id** を持つ(並び順から作るとカードを1人足しただけで
既存の手札とぶつかるため、こうしてある →§3.19)。

受信箱に添えるカードは、この**型紙をそのまま**入れていた。そして受け取りは

    if(g.card && !S.player.coll.some(x=>x.id===g.card.id)) coll.push(g.card);

だった。二重受け取りを防ぐつもりのこの条件が、**別の贈り物なのに id が同じ**
というだけで静かに握り潰す。しかも `m.got=true` は先に立っているので、
連絡は「受け取り済み」になり、UI は「加入しました」とまで出す。

同じ人が2つ届くのは、**「持っていない人からしか出さない」の判定が
`S.player.coll` しか見ていない**ため。受け取り待ちのカードはそこに居ないので、
実績の報酬とトレードが同じ人を同時に用意できてしまう。

直しは2つ。

1. **手元に入れる瞬間に `nextCardId()` へ載せ替える** — 市場が既にやっている始末
   (`marketBuy`)と同じ。二重受け取りは `m.got` が止めるので、id の一致で
   弾く必要はない
2. `pendingSigs()` を足し、**受け取り待ちの連絡に居る実在選手も「持っている」**
   として扱う。市場・`drawSig`・トレード・メモラビリアの4か所が同じ判定を使う

### 3.40a スポンサーの報酬は**引換券**で配る(2026-08-19)

選手をその場で手札に入れていたのを、**引換券**に変えた。

#### なぜ

- **引く時機を監督が選べる**。強化が要るのは節の直前とは限らない
- **今後の時限の催しに繋がる**。「期間中に配る → 好きなときに引く」が、
  券なら追加の仕組みなしで成り立つ
- **選手が直接届くのはトレードだけ**になり、トレードの手触りが際立つ(→§3.49)

#### 選手が手札に入る場所は4つだけ

| 経路 | 入り方 |
|---|---|
| SCOUT(コイン / 引換券) | 監督がその場で引く |
| 移籍市場 | 名指しで買う(→§3.67) |
| 秘書の受信箱 | トレード / 実績 / メモラビリア(→§3.49a) |
| 師弟の持ち越し | 任期をまたぐときだけ(→§3.39) |

**報酬として降ってくる選手は、すべて受信箱を通る。** スポンサーだけが
`sponPay()` から直接 `coll` へ押し込んでいたので、そこを塞いだ。

#### 枠は「受け取るとき」ではなく「引くとき」に選ぶ

ポジション確定の券は、以前は**受信箱で受け取る前に**枠を決めさせていた。
券にした以上それでは意味がない — 決めた瞬間に「持っておく」自由が消える。
SCOUT の券の行に GK/DF/MF/FW を並べ、**押した枠でその場で引く**形にした。

    scoutPos    枠を選ぶ  SPECIALS か WORLD CLASS(自動生成)
    scoutWc     枠は自由  WORLD CLASS 確定・実在選手が先
    scoutWcPos  枠を選ぶ  WORLD CLASS 確定・実在選手が先
    scoutLe     枠は自由  LEGENDS 確定・実在選手が先

`TICKETS` の id は `SPON_PRIZE` の `kind` と同じにしてある。段が増えても
券の定義を足すだけで繋がる。

### 3.54a 紋章を「本物らしく」する(2026-08-19)

最初の紋章は**かわいいが子供っぽかった**。丸みのある塊で描いていたのが原因で、
実在クラブの紋章と並べると玩具に見える。作り直して分かったのは次の3点。

| 効いたこと | なぜ |
|---|---|
| **輪郭を角ばらせ、切り込みを深く取る** | 羽・鬣・王冠の刻みは紋章の「らしさ」そのもの |
| **内側を縁色で抜く**(目・口・面の割り) | 塗り一色の塊は、輪郭が正しくても平たい影に見える |
| **盾いっぱいに大きく置く** | 小さく収めると図案ではなくアイコンになる |

#### 生き物は「一目で分かる特徴」を1つ立てる

器物(星・王冠・ボール・塔・剣・稲妻)は輪郭だけで通じるが、生き物は通じない。
実際に踏んだ失敗:

| 描いたもの | 見えたもの | 直し方 |
|---|---|---|
| 獅子(全身) | 熊 | **横顔＋一方向へなびく鬣**にした。等間隔の三角形を放射状に並べると太陽の光線になる |
| 鷲(細い羽根を並べる) | 案山子・鳩 | **翼を面で取ってから後縁を段で抉る**。胴を太くして頭を載せる |
| 馬(耳を2本立てた頭) | 犬 | **長い鼻筋と反った首**を通す |
| 騎士の兜(横向き・羽根飾り) | 壺・拳・蜂 | **天面を平らに切ったグレートヘルム(正面)**。飾りは持たせない |

兜の「平天面」が一番の決め手だった。上を丸めると、輪郭がそのまま盾に見える。

#### 外装(盾の外)

盾の**外**に載る飾りを4種足した。王冠 / 月桂樹 / リボン / 月桂冠。

- **月桂樹とリボンは盾の後ろ、王冠は前**に描く。順番を逆にすると紙が盾に刺さって見える
- 外装ごとに `embOrnPad()` で **`viewBox` を上下左右に広げる**。★と同じ流儀で、
  **盾は縮めない**
- リボンは**折り返した端を先に暗い面で敷く**。これが無いと帯が平たい紙のままになる
- 月桂樹は**中心(50,52)・半径44の円弧を素直になぞる**。
  はじめは「縦線を中央でくぼませる」式で置いたが、それは真ん中が一番内側に入る
  **砂時計**であって円ではない。冠に見えなかった原因はこれ
- 葉は**接線と外向き法線の中間**を向く。上からの角度を φ とすると
  接線 `φ-180` / 法線 `φ-90` なので **`φ-135`** で出る。
  角度を素直に増やすと下向きに流れて、月桂冠が上下逆さに見える
- 茎を1本通してから葉を**外側・内側の二列**に生やす。
  一列だけ点々と置くと草の切れ端に見える

外装も紋章と同じく**3クラブに1つくらい**。全部に王冠を載せると格が語れなくなる。

#### ★は名指しで数える

★は `class="emb-star"` を持つ。月桂樹の葉も `transform` 付きの `<path>` なので、
`path[transform]` で数えていたドライバの検査は**外装を足した瞬間に壊れた**。

### 3.54b 紋章は**描いた意匠を輪郭追跡してパスにする**(2026-08-19)

紋章を手で座標を置いて描いてきた(→§3.54a)が、生き物はどうしても可愛くなる。
獅子は熊に、鷲は案山子に、馬は犬に見え、何度描き直しても抜けなかった。
**白いシルエットのシートを描いてもらい、それを輪郭追跡してパスに起こす**方式へ変えた。

#### なぜ画像のまま貼らないか

エンブレムは 形 × 地の柄 × 紋章 × 色相 の組み合わせで作る(→§3.54)。
紋章は**クラブの2色(ink / edge)で塗り分ける**ので、ラスタのまま貼ると色が乗らない。
ベクターに起こせば

- 既にある塗りの仕組みがそのまま効く(縁取りも `paint-order` のまま)
- どの大きさでも輪郭が出る(22px の一覧から 110px の CLUB まで同じ絵)
- **index.html が太らない**(12個ぶんで +23KB。PNG で持つと桁が変わる)

#### 追跡の手順(`tools/slice_emblem.py`)

1. しきい値で白黒に落とす
2. **マーチングスクエア**で閉じた輪郭を全部拾う。画素の角で折ると階段になるので、
   **辺の中点どうしを結ぶ**。45度の斜めが自然に出る
3. Ramer-Douglas-Peucker で点を間引く(許容 0.9 画素)
4. 0..100 の枠へ正規化する

**穴は輪郭を並べて `fill-rule="evenodd"` に任せる。** 兜の面、塔の窓、車輪の輻(や)は
どれも穴で、外周と穴の向きを揃える必要がない。

#### 枠は 70 で取る

盾は上下と左右がすぼまる。枠いっぱい(92)に広げると、
**王冠の十字や獅子の前脚が盾の外へ出た**。70 に絞ると収まる。

#### 手で持つものと、追跡するもの

| | 紋章 |
|---|---|
| **追跡する** | 王冠 / 鷲 / 獅子 / 馬 / 兜 / 塔 / 竜 / 百合 / 大砲 / グリフォン / ワイバーン / 女神 |
| **手で持つ** | 星 / ボール / 剣 / 稲妻 |

星や剣は**直線と角度で決まる**ので、描いた絵を追跡するとかえって辺が揺れる。
生き物は逆で、輪郭で語る形は手で座標を置くと必ずどこか可愛くなる。

**盾の外の王冠も同じ意匠を縮めて載せる。** 別に描くと2つの王冠が食い違う(→§3.54a)。

### 3.54c 幾何の紋章を外し、文字の並べ方を3通りにする(2026-08-19)

#### 剣・稲妻・塔・ボールを外す

輪郭追跡した意匠(→§3.54b)と並べると、**絵の密度が違いすぎて浮いた**。
獅子やグリフォンが線の密な図案なのに対して、剣や稲妻は面が2〜3枚しかない。
同じ盾の中に置くと、片方だけ「後から足した記号」に見える。

**星だけは残した。** 単純すぎて逆に浮かない — 星は紋章学でも記号として
成立している形で、密度の差が「そういうもの」として読める。

紋章は 16 → 12 になった。`embDesign` の割り当ても変わるので、
**クラブの顔ぶれは一度そっくり入れ替わる**。

保存された指定が一覧から消えている場合に備え、`embDesign` で
**一覧に無い指定は既定へ戻す**ようにした。これが無いと、昔の保存が
「剣」を指したまま、紋章も文字も出ない空の盾になる。

#### 文字の並べ方を3通りに

紋章を持つクラブは3つに1つ(→§3.54)。**残り3分の2は文字だけ**なので、
文字の置き方が効く場所は広い。横一列だけだったのを3通りにした。

| | 置き方 |
|---|---|
| `row` | 横に2文字。既定 |
| `col` | 縦に積む。**字を少し小さく**しないと盾のすぼまりに肩が当たる |
| `diag` | 斜めに流す。**たすき(sash)と同じ向き**なので、地の柄と喧嘩しない |

縦と斜めは**1文字ずつ置く**。`<text>` に改行は無く、`textLength` で
潰すと字が歪む。

CLUB の CREST 欄でも選べる。**見本は紋章を「なし」にして描く** —
紋章を出したままだと、押しても何も変わらないように見えてしまう。

### 3.54d クラブの顔は**名前から決める**(2026-08-19)

クラブの色と紋章を、ハッシュではなく**クラブ名から引く**ようにした。

#### 名前が既に答えを持っていた

クラブ名は実在クラブの愛称をもとにしていて、**色と生き物の語が入っている**。

    ミラノ・ロッソネーリ    ロッソ(赤) + ネーリ(黒)
    レシフェ・レオン        レオン(獅子)
    ロンドン・ガナーズ      ガナーズ(大砲)
    ジェノヴァ・グリフォーニ グリフォーニ(グリフォン)
    フランクフルト・アドラー アドラー(鷲)

ここに乱数を当てる理由がない。`EMB_WORDS` に **[語, ホーム, アウェイ, 紋章]** を並べ、
**上から順に見て最初に当たったものを使う**。**複合語を先に置く**のが要
(`ロッソネーリ` を `ロッソ` より先に見ないと、黒が落ちる)。

**144クラブすべてが名前から引ける**(テストで検査している)。

#### 紋章は3段階

| 語 | 出るもの |
|---|---|
| 意匠を名乗る(レオン / ガナーズ) | **その紋章** |
| 別の生き物を名乗る(カナリーズ / タイガース) | **何も出さない**(`""` 印) |
| どちらでもない(セインツ / マニョス) | 3回に1回くらいハッシュで |

真ん中が要る。これが無いと**カナリーズに獅子が付く** — 名前と絵が食い違うのは、
絵が無いより悪い。結果、44/144 が紋章を持つ(約3割。設計どおり)。

#### 盤面の色も同じ出所にした

以前 `clubHue()` は**並び順**から色相を振っていた。

- 盤面は虹色で、**エンブレムの色とも別物**だった
- **クラブを1つ足すと、それ以降の色が全部ずれた**

いまは `embDesign()` のホームカラーを1か所から配る。
**マンチェスター・レッズはどこで見ても赤**になり、クラブを足しても他はずれない。

色は**サッカーで実際に使う13色**から取る(→§3.54)。インクカラーまで混ぜると
CPUのクラブが蛍光色だらけになってサッカーに見えない。
実測の散らばりは 赤34 / 青31 / 白26 で、現実のクラブの分布に近い。

### 3.55a メモラビリア 2つ目 — インヴィンシブルズ(2026-08-19)

`INVINCIBLES-2004` で開く。2003-04 の無敗優勝の11人。

| | ミラン(→§3.55) | ガナーズ |
|---|---|---|
| 陣形 | 4-4-2ダイヤ | **4-4-2** |
| 監督 | アンチェロッティ／知将型 | ヴェンゲル／**キーマン型** |
| 采配 | イル・メラヴィリオーゾ(技巧) | **インヴィンシブルズ(速さ)** |
| KP | カカ | **アンリ** |

**2つ目は1つ目と違う手触りにする。** 同じ陣形・同じ監督の性分・同じ効き方の采配を
出しても、開ける意味が薄い。ミランが「技巧で崩す・消耗が激しい」なら、
ガナーズは「速さで裏返す・背後が薄い」。監督の性分も知将型からキーマン型へ変え、
**軸(アンリ)の居る側へ振ってくる**ようにした。

采配の名前は**記念の名前をそのまま**。ここは言葉遊びより、
**その一戦を指す名前**であるほうが強い。

### 3.58 残留 — 同じクラブに居続けるなら、全部引き継ぐ(2026-08-20)

任期が明けると career は畳まれ、クラブも作り直される。同じクラブを選び直しても
**いちから育て直し**だった。これを変え、**残留したときだけ全部引き継ぐ**ようにした。

#### 何が続いて、何が切れるか

| | 残留 | 移籍 |
|---|---|---|
| コイン / チーム熟練度 / 施設 | **続く** | 初期化 |
| 所属選手(貸与) | **そのまま** | 新しいクラブの名簿 |
| 覚醒(★・裏パラ) / 連携 / 黄金線 | **全部** | 師弟のぶんだけ(→§3.39) |
| 信頼 / 師弟 | **切れる** | 切れる |
| **部と組み分け**(昇降格の結果) | **続く** | そのクラブの持ち場から |
| 組んでいた形と編成 | **そのまま** | 組み直し |
| オーナーの評価 / 期待 / スポンサー | **引き直す** | 引き直す |

**評価と契約は残留でも引き直す。** 前の任期の貯金で最初から安泰、にはしない。
スポンサーは期限のある契約なので、跨がせると期限そのものが意味を失う。

#### 信頼と師弟は、残留でも切る

覚醒や連携が「**チームに積んだもの**」なのに対して、師弟は
「**この任期で誰と組むか**」という選び直しの余地。残留でも切れるからこそ、
**いまの顔ぶれから結び直すきっかけが毎期生まれる**。

移籍のときに連れていけるのは師弟だけ(→§3.39)なので、
「そろそろ出るか」と思ったその任期に誰と組むかが、そのまま次への持ち出しになる。

#### 部を引き継ぐのが要

`startTenure` は `S.world.div` をそのクラブの**持ち場**(CLUBS の静的な値)へ戻していた。
これでは DIV3 を勝ち上がっても任期をまたいだ瞬間に DIV3 へ落ちる。
**昇降格の結果(`div` と `divs`)ごと持ち越す**ので、残留は「積み上がる」に変わる。

#### 師弟を二重にしない

`makeLegacy` は**貸与だった師弟を写しにして連れていく**(→§3.39)。
残留では所属選手がそのまま残るので、これを重ねると**同じ選手が2人**になる。
残留では持ち越しそのものを使わない(`S.player.legacy=null`)。

#### 狙いと、いまの偏り

半永続的に積み上げられる筋道を作るもの。高難度のカップやメモラビリア(→§3.55)と
対等に戦える段まで、**同じクラブで登っていける**。

引き換えは「ほかのリーグへ挑めないこと」だが、**いまはそれだけでは釣り合っていない**。
残留は毎期ユース(→§3.57)も受け取れるので、いまの実装では**残るほうが常に得**。
釣り合いは今後のミッション(「特定のクラブで DIV3 優勝」など)で取る前提で、
そこまでは残留が強い状態が続く。

### 3.57 ユース — タダで手に入る代わりに、置いていく(2026-08-20)

選手の入る経路のうち**残っていた「ユース」**を埋める(→§3.67 の経路の表)。

#### ユース組織という施設

施設に5つ目を足した。**1段でも建っていれば機能する**。

| ユース組織の段 | 上がってくる段 |
|---|---|
| 1 / 2 | REGULAR |
| 3 / 4 | SPECIALS |
| **5** | **WORLD CLASS** |

施設は「今を取る(即戦力)か、先を取るか」の判断だった(→§3.5)が、
そこに**先を取ると人が来る**という筋道が加わる。
コインでは買えない強さを、時間で買う経路になる。

#### 任期に1人。40節か80節のどちらか

上がってくる節は**任期ごとにどちらか一方**に決まる。

**選ばれた節を過ぎていれば来る。** その節までに建て終わらなくても拾えるようにした
— 間に合わなかった瞬間に権利が消えると、建てる判断が博打になる。

#### ★は上限で上がってくる

伸びしろは無い代わりに、**最初から仕上がっている**。
★5ぶんの伸びは `youthUps` が **枠に効く能力へ寄せつつ散らす**。

重みは3乗して立ててある。平らに引くと、段が上がって主能力が上限に張り付いたときに
**GK の atk のような使い道の無い能力へ伸びが流れる**(実測で WC の GK が atk+3 を引いた)。

#### 札は「クラブユース」と「スーパーサブ」

**クラブユースは数の効果を持たない札。** 連携の扱いそのものを変える。

> 積み上げに関わらず、**編成の全員と黄金線**(→§3.31 の k4)。
> 下部組織で一緒に育った、という筋書きなので、**片方がユースなら成立する**。

これが「任期中は強力に作用する」の中身。OVR で押すのではなく、
**その選手が絡むパスが全部最上段になる**。連携を積む時間が要らないので、
上がってきたその節から効く。

札の枠は**1つ広げてある**。2枚で埋まると REGULAR のユースが全員まったく同じ札になる。

#### クラブの預かりなので、置いていく

`S.club.loan` に入る。**手札(`S.player.coll`)には入らない**ので、

- 売れない(→§3.46)
- 師弟にできない(→§3.39)
- **任期が明ければクラブに残る**(`S.club` ごと作り直されるため、特別な後始末は要らない)

配るのは秘書の受信箱(→§3.40a)。降ってくる選手は全部そこを通す。

#### 検査で引っかかった2つ

- **数の効果を持たない札**は、スキル表の検査(「掛かり先がある」)を通らない。
  素通しにはせず、**数を1つも持っていないこと**を確かめる例外にした
- **生成の抽選に混ぜない札**は、ドライバの「誰も引けないスキル」に引っかかる。
  固有スキルと同じ扱いにした

### 3.59 貸与の買い取り — 師弟が鍵(2026-08-20)

選手の入る経路(→§3.67)の最後の1つ。**師弟の約束を結んだ貸与選手だけ**、
コインで自分のカードにできる。

#### なぜ師弟を鍵にするか

師弟は**任期が明ければ切れる**(→§3.58)ので、約束のままでは毎期結び直しになる。
枠も3つしかない(`TUNING.trust.max`)。

買い取ればその選手だけは恒久的に自分のものになり、**師弟の枠も空く**。
つまり「**連れて出るために買う**」という判断で、
残留が明確に強いいまの釣り合いにも効く — 残るなら貸与のままでも失わないので、
**買うのは出ていくときのため**になる。

値段は**売値の 3.5 倍**。市場(5倍〜 →§3.67)より安いのは、既に一緒に戦っているぶん。
売値より高いのは、**売って買い直せる**抜け道を作らないため。

#### IDを付け替える

貸与のIDは**クラブから決定的に決まる**(`clubRoster` が `uid` をクラブのハッシュで
置き換える)。同じクラブへ戻れば**同じIDでもう一度生える**ので、
そのまま手札へ移すと同じIDのカードが2枚になる(→§3.49a と同じ罠)。

付け替えるぶん、**積み上げも全部新しいIDへ移す**。

    訓練の記録 / 連携 / 黄金線 / 信頼 / 編成の枠 / 軸

移し忘れると、買った瞬間に★も連携も消える。買う理由がそこにあるので、
ここが切れると機能そのものが無意味になる。

**貸与に付いていた黄金線の写し(`c.gold`)は捨てる。** 相手はもう仲間とは限らないし、
本物の黄金線は career 側(`bondGold`)が持っている(→§3.31)。

#### 買った選手はクラブの名簿から抜く

クラブの名簿は決定的に生え直すので、抜かないと戻ってきたときに
**「買った本人」と「同じ顔の別人」が並ぶ**。
買い取ったカードに元のID(`from`)を控え、`myRoster()` がそれを外す。

#### フリーは作らない

契約の切れた選手を拾う経路は**置かない**と決めた。
スカウト(引く)・市場(選ぶ)・ユース(育つ)・トレード(替える)・実績(貰う)で
入口は足りていて、フリーを足しても**「安く手に入る」だけの5本目**になる。
経路は数ではなく、**入り方の違い**で分けたい。

### 3.60 連携の掛かり先を増やす(2026-08-20)

打ち手3種のうち**交流だけが効かない**歪み(→docs/05 D)を潰した。

#### 倍率ではなく、掛かる場所が足りなかった

連携は `resolveChannel` の**1か所**にしか掛かっていなかった。
1か所に掛ける倍率は、上げてもすぐ頭打ちになる。実測(900試合・互角の相手):

    段3(×1.34) +0.144  →  黄金線(×1.50) +0.146     ほとんど動かない

比べる式が `aSc > dSc × th` なので、勝てる競り合いは既に勝っていて、
**倍率を足しても勝ちが増えない**。だから掛かる場所を2つ増やした。

| 掛かり先 | 何が変わるか |
|---|---|
| 競り合い(`resolveChannel`) | 元からある。パスを通せるか |
| **誰に預けるか**(`receiverAt`) | 分かり合った相手を探しに行く |
| **決定機の質**(`chanceOf`) | 渡した側と撃つ側の呼吸 |

前2つは掛け合わさる — よく分かり合った相手を**選び**、その相手への**パスが通る**。

#### 増やした掛かり先は「積み上げ」だけが見る

**ここが要。** 黄金線は「印」なので、**強豪クラブには丸ごと無償で配られている**
(→§3.53)。増やした掛かり先をそこにも効かせると、監督の打ち手ではなく
**CPUの強豪だけが強くなる**。実測でそうなった:

    強豪同士の1試合   4.05 → 5.07 点
    格差戦の4点差以上  38.6% → 51.0%

そこで、増やした2か所は `bondBuilt` — **積み上げた値だけ**を見る。印は見ない。

- CPUの強豪(印だけ)… 増えた掛かり先を**見ない**。リーグの得点は**完全に不変**
- 監督が積んだ連携 … 全部効く
- 自分で育てた黄金線 … 積み上げも t3 を越えているので、ちゃんと最上段が乗る
- 上がりたてのユース(→§3.57)… 印だけなので競り合いには効くが、
  受け手の選び方と決定機の質は**これから積む**

#### 結果(800試合・互角の相手・得失点差)

| 打ち手 | 前 | 後 |
|---|---|---|
| 休息(コンディション+1) | +0.330 | 変わらず |
| 訓練(★2ぶん・全員) | +0.266 | 変わらず |
| **交流 段1(全組)** | +0.033 | **+0.145** |
| **交流 段3(全組)** | +0.144 | **+0.451** |
| **自前の黄金線** | +0.146 | **+0.472** |
| もらった黄金線(印だけ) | +0.177 | 変わらず |

1シーズンぶん(段1)で休息の半分、積み切れば休息を超える。
**すぐには効かないが、積むほど返る**という形になった。

`seekK` は 1.6 より上げても動かない(そこで頭打ち)。**掛かる場所を増やす**以外に
効きを伸ばす方法が無いことが、ここでも確かめられた。

### 3.61 歪みの測り直し(2026-08-20)

docs/05 D に並べていた歪みを、いまの版で測り直した。
**3つのうち2つは、他の直しの副産物で解消していた。**

#### 枠ごとのカードの価値 — 14倍 → 4.0倍

同じ上げ幅(OVR+10)を1枠だけに乗せて得失点差を見る(2500試合・4-4-2)。

    ST +0.246 ／ CF +0.170 ／ GK +0.156 ／ LMF +0.107
    CB +0.097 ／ LSB +0.083 ／ CMF +0.082 ／ RSB +0.066 ／ CMF +0.062

★を総合力に載せた(→§3.30)ことと、段の数値を域内に収めた(→§3.53)ことで、
**14倍あった開きが 4.0倍**まで縮んでいた。3〜4倍は「FWのほうが価値が高い」
として妥当な範囲なので、**ここは直さない**。

600試合では左右で差が出たが(LMF +0.152 / RMF +0.077)、2500試合では消えた。
**この物差しのノイズは ±0.02 程度**なので、それ未満の差で判断しない。

#### 相手チームは連携を持たない — 三段の梯子になっていた

強豪クラブには黄金線が丸ごと配られている(→§3.53)ので、いまは

| | 連携の状態 | 互角の11人どうしの得失点差 |
|---|---|---|
| 弱いCPU | 何も無い | 基準 |
| 強豪CPU | **印だけ** | +0.177 |
| 積み切った監督 | 印＋積み上げ | **+0.472** |

就任直後は強豪CPU相手に **-0.111(勝率34%)**、積み切ると **+0.361(勝率46%)**。
**最初は格上に届かず、積むほど追い越す**という梯子になっているので、
これも**直さない**。

#### GKは受け手にならない — 直せないと分かった

`ballTarget` の前進量は常に正なので、**エンジンに後ろ向きのパスが1つも無い**。
GKが受け手になれないのはその結果で、`receiverAt` の除外を外しても
「後ろに居るので選ばれない」だけになる。

代わりにゴールキックの繋がりやすさ(`gkFeed`)にGKの組み立てを効かせてみたが、
**測って効かないと分かったので戻した**。

    ゴールキック起点は1試合 33.2 回中 4.6 回(14%)
    ビルドアップの札の効き  feedLo=0.60 → -0.006 ／ 0.30 → +0.004 ／ 0.10 → +0.003

幅をどれだけ広げても誤差の範囲。**梃子そのものが小さい**ので、ここを触っても
GKの攻撃面は生き返らない。生き返らせるには**後ろ向きのパスを足す**という
構造の変更が要る — 連鎖の定義(→docs/07 §7.9)そのものを変えることになるので、
**やるなら独立した判断として**。

**代わりに、守る側で仕事を作った**(→§3.62)。

### 3.62 GKの飛び出し — 死に能力に仕事を与える(2026-08-20)

GKの **atk** はどこにも効いていなかった。`resolveShot` が見るのは def / pow / tec だけで、
枠の重み(→cards.js `STAT_W`)でも atk は 0.45 と最軽量。
**引いても意味の無い数字**がカードに載り続けていた。

繋ぎ役として使う道は塞がっている(→§3.61)ので、**守る側で仕事を作った**。

#### 出ていって角度を消す

    ① 出られたか … spd と距離で判定。**近いほど間に合う**
    ② 消せた角度 … atk。出られたときだけ、枠に飛ぶ率を削る

**二段に分ける**のが要。掛け算1本にすると「速いだけのGK」と「立ちはだかるGK」が
同じ絵になる。分けたことで**2つの能力が掛け合わさる**(実測: atk+8 が +0.058、
spd+8 が +0.030、両方で +0.109 — 個別の和を超える)。

**20 で割らない。** GKは枠の重みの都合で atk が素で5前後、spd が10前後しか無く、
`STAT_MAX` で正規化すると範囲の大半を捨てる(実測で効きが半減した)。
`rushRef`(=12)で割り、**GKの現実的な幅**を使い切る。

#### 減った得点は、ちゃんと枠外へ行った

同じ11人どうし1200試合、1試合あたり:

| | 枠外 | セーブ | ゴール | ブロック | 近距離の枠外率 | 遠距離の枠外率 |
|---|---|---|---|---|---|---|
| 無し | 8.63 | 7.51 | 4.20 | 12.64 | 38.9% | 56.7% |
| 有り | 9.61 | 6.82 | **3.80** | 12.70 | **44.6%** | 59.2% |

- **ブロックが動いていない** … 他の局面に漏れていない
- **近距離の効きが遠距離の2倍以上** … 「出ていく」という絵と数字が合っている

得点が 4.20 → 3.80 に下がるが、これは**GKが仕事をした結果**。
現実のサッカー(2.7前後)にも近づく。

#### どのラインも比例して下がるだけ

ライン単位で +10 を乗せて測る(4000試合):

|---|---|---|---|---|
| 無し | +0.217 | +0.211 | +0.372 | +0.125 |
| 有り | +0.184 | +0.196 | +0.344 | +0.114 |

**順序も比も変わらない。** 1枚あたりでは FW +0.172 / GK +0.114 / DF +0.046 で
およそ 3.7倍 — §3.61 で測った 4.0倍と整合する。

**枠ごとの物差しは、1枠ずつだとノイズ床(±0.02)に埋もれる。** 低い枠で
「9.1倍」のような数字が出るのは見かけで、**ラインごとにまとめて測る**ほうが確か。

### 3.63 相互カバー — 厚く構えた形は終盤に持つ(2026-08-20)

#### まず、最初の測定が間違っていた

「守備的な陣形に存在意義が無い(幅 0.802 GD)」と測ったが、**1つの名簿だけで測った**
ので、**陣形の強さと名簿との相性が混ざっていた**。

| | 1クラブ(sam-8)で測る | **5クラブで均す** |
|---|---|---|
| 幅 | 0.802 | **0.183** |
| ゼロトップ | +0.477 | **-0.016** |
| 5-3-2 | -0.304 | -0.097 |

ゼロトップが突出して見えたのは、sam-8 の名簿が**たまたまその形に嵌まった**から
(枠適性 0.977 に対して 5-3-2 は 0.932)。均せば平凡な形だった。

**陣形を測るときは名簿を変えて均すこと。** 1つの名簿で出た差は、
その名簿の相性を測っているだけかもしれない。

#### 残った本物の信号

5バック系(5-3-2 / 5-4-1)が **0.10 ほど不利**。幅そのものは打ち手1つぶんと
同程度なので大問題ではないが、この2つは**パーク・ザ・バス**(→§3.50)の前提陣形で、
ここが不利だと**采配ごと死ぬ**。

#### 消耗で効かせる

局所の被り(`coverOf`)で差を付けようとしたが、**陣形で 4〜6% しか動かない**
(ボールは大半の時間を中盤で過ごし、どの形でも局所密度が似る)。

**周りに味方が居るほど消耗が緩い**、にすると陣形の差がそのまま出る:

    ゼロトップ 0.54 ／ 4-4-2 0.60 ／ 5-3-2 0.72 ／ 5-4-1 0.74   （6倍以上の開き）

枠の位置は試合中変わらないので、**組んだ時点で1度だけ数える**。

#### 効果

| | 幅 | 5-3-2 | DIV1の得点 | 格差戦の4点差以上 |
|---|---|---|---|---|
| 無し | 0.183 | -0.097 | 4.28 | 36% |
| 有り | **0.152** | **-0.042** | **3.55** | **27%** |

守備的な形が使えるようになるだけでなく、**得点が現実のサッカー(2.7前後)に近づき、
大差も減る**。GKの飛び出し(→§3.62)と合わせて、DIV1 の 4.28 → 3.55。

打ち手の効き幅は順序が保たれている(休息 +0.273 / 訓練 +0.228 / 交流段1 +0.188)。

### 3.64 能力の価値を均す — 一歩目(2026-08-20)

**能力の価値はフラットであるべきで、尖りは監督の判断(陣形・人選・采配・指示)から
生まれるべき**、という方針で測り直した。

#### 物差しは得失点差ではなく勝点で見る

得点は伸びしろが無限だが、失点は 0 で床を打つ。得失点差で測ると
**守備の能力が構造的に低く出る**。勝点(3-1-0)で測ると景色が変わる。

| 能力 | 勝点/試合 | 勝率 | 得失点差 |
|---|---|---|---|
| pow | +0.627 | +23.4pt | +0.911 |
| tec | +0.533 | +19.6pt | +0.782 |
| atk | +0.492 | +18.8pt | +0.731 |
| def | +0.416 | +12.4pt | +0.511 |
| spd | +0.391 | +13.8pt | +0.567 |
| **sta** | **+0.052** | +1.6pt | +0.095 |

**sta を除けば 1.6倍以内**に収まっている。均すべき相手は sta ただ1つ。

#### 見つけた癒着 — 能力と kind

起点の札は定義上 pow/tec/spd が 13枚ずつで均等なのに、**発動は pow 45.2% /
tec 29.8% / spd 25.0%** と偏っていた。原因は**能力と kind の癒着**:

    pow … 13枚中 11枚が pass（carry ゼロ）
    spd … 13枚中 11枚が carry

`pickOriginCh` は carry を減点し pass を加点する(→docs/07 §7.9)。
連携も pass にしか掛からない(→§3.60)。**「パスが有利」がそのまま「pow が有利」に
化けていた**。DMF / CMF の3枚を組み替えて癒着を解いた(発動 pow 39.0% / spd 30.1%)。

> **CB は触らない。** pow の carry を持たせると、pow の高い CB が運びを選びすぎて
> 「前へ行くほど止められやすい」が崩れた。混ぜるのは中盤だけでよい。

あわせて**ブロックの守備側を `def*0.6 + pow*0.4` から `def*0.6 + pow*0.2 + spd*0.2`**
にした。身体を入れるのは力だけでなく反応でもある。pow が「守備の第2能力」を
1人で占めている理由が無かった。

#### sta は調整では届かない

疲労の係数をどれだけ振っても sta は届かない(実測):

    staReduce 0.45 → +0.041 ／ 0.75 → +0.066 ／ 0.90＋消耗増 → +0.049
    （このときリーグの得点だけが 1.99 → 1.61 に崩れる）

**梃子が構造的に小さい**(スタミナは両チームが同じように削れるので差が残らない)。
GKのゴールキック(→§3.61)と同じ結論で、**ここを触っても sta は生き返らない**。

生き返らせるなら「消耗が緩む」以外の仕事が要る。方針(尖りは采配から)に沿うなら、
**指示や采配が消耗を増やし、sta がそれを支える**形にするのが筋
(攻撃重視は削れる / 守備重視は保つ)。**独立した仕事として**。

#### 本命は「深くへ届く札(`to`)」の独占だった

kind の癒着を解いても値は動かなかった。効いていたのは
**一発でボックスまで届く札(`to` を持つ札)を pow が独占していた**ことだった。

    直す前  pow 8 ／ tec 2 ／ spd 0
    直した後 pow 4 ／ tec 2 ／ spd 4

「早いクロス」は**速さの手**なので spd が筋。SB と WG の2組を spd に移し、
空いた carry を pow が受ける。

> **3組すべてを移すと行き過ぎる。** SB・WG に加えて LMF/RMF まで移したら、
> 今度は **spd +0.668 / pow +0.477** と逆転した。2組で釣り合う。

#### 結果 — pow / tec / spd が 1.12倍以内に

4クラブ×3陣形×600試合。**陣形も名簿も均す**(4-4-2 だけで測ると LWG/RWG の札が
一度も出ず、変更が数字に現れない)。

| 能力 | 勝点/試合 | 勝率 |
|---|---|---|
| spd | +0.602 | +21.9pt |
| tec | +0.545 | +19.9pt |
| pow | +0.539 | +19.5pt |
| atk | +0.520 | +19.4pt |
| def | +0.471 | +14.4pt |
| **sta** | **+0.085** | +2.7pt |

**pow / tec / spd は 1.12倍**、sta を除く5能力でも **1.28倍**に収まった。
起点の発動も pow 39.1% / spd 31.8% / tec 29.1%。

大差も減っている(格差戦の4点差以上 27% → 18.1%)。**残るは sta ただ1つ**。

### 3.65 sta を生き返らせる(2026-08-20)

§3.55 で残した最後の1つ。**疲労の係数では届かない**ことを、今度は端まで確かめた。

    staReduce 0.45 → sta+6 は +0.060 ／ 0.70 → +0.083 ／ 0.95 → +0.081
    消耗 ×1.5 → +0.062 ／ ×2.2 → +0.058 ／ ×3.0 → +0.084

**0.95 は「最高の sta なら消耗が95%緩む」= ほぼ無限体力**だが、それでも +0.08。
天井そのものを測ると理由が出た:

| | 勝点/試合 | 得点/試合 |
|---|---|---|
| 通常 | 1.397 | 2.21 |
| **両チームとも一切疲れない** | 1.448 | 3.09 |

**疲労は得点の総量を4割動かすのに、勝敗はほとんど動かさない。**
疲労はダイヤルであって、差ではなかった。

#### 原因 — `p.stam` が全能力に一律で掛かっていた

`eff()` の中で `stam` は6能力すべてに同じ倍率で掛かる。この形は
**比で決まる判定(攻撃側 vs 守備側)で最も相殺されやすい**。
片方が10%落ちても、その10%は攻撃にも守備にも等しく効くので、
チームは「弱くなる」だけで「負けやすくなる」わけではない。

打ち手を3つ試して、2つ採った。

#### ✗ 守る側は全員が走る(`chase`) — 却下

1回の攻撃で `inv` が増えるのは競り合った1人だけで、残り9人は動いていない扱いだった。
守備側の全員に消耗を足したが:

    chase 0     → sta+6 +0.105 ／ 得点 2.12
    chase 0.012 → sta+6 +0.100 ／ 得点 1.32

**sta は動かず得点だけ崩れる**。理由は同じで、両チームが同じだけ守るので
また一様な倍率になる。しかも**弱いチームほど守る時間が長い**ので、
§3.63 で潰した大差が戻ってくる。却下。

#### ✓ 立つ位置で走る量が違う(`offBall`)

`perMin` は全員一律 0.0040 だった。90分ずっと往復するサイドハーフと、
自陣の帯から出ない CB が**同じだけ削れていた**。枠の座標から素直に出す。

```js
const mid  = clamp(1 - Math.abs(p.y0 - 52) / 35, 0, 1);   // 中盤の帯 = 往復が長い
const wide = clamp(Math.abs(p.x - 50) / 40, 0, 1);        // 外 = 上下動が長い
return F.offBase + F.offMid * mid + F.offWide * wide;     // 0.60 + 0.50m + 0.35w
```

    GK 0.60 ＜ CB 0.90 ＜ CMF 1.22 ＜ LMF 1.34   （全陣形の平均 0.974 = 総量は不変）

采配で動かす**前**の `y0` で測る。指示で変えると§3.55 で却下した
「指示消耗」に戻ってしまうため。

副産物として**陣形ごとに走行量が違う**(4-3-3 は 0.946 / 5-4-1 は 1.050)。
中盤を厚くすれば走る量も増える、が自動的に成り立つ。

> **これ単体では総量が増えない。** 平均を保つ設計なので、sta の価値を
> 配り直しただけだった(枠ごとに測ると中盤が常に上位、DF/FW はゼロ)。次が本体。

#### ✓ 疲れると足と技から落ちて、力は残る(`wear`)

一律倍率をやめ、**能力ごとに `stam^wear` の指数を変える**。

| | spd | tec | atk | def | pow |
|---|---|---|---|---|---|
| wear | 1.35 | 1.25 | 1.00 | 0.90 | 0.70 |

疲れたチームは「弱くなる」のではなく**形が変わる**。足と技が先に落ちるので
**精度の判定(枠に飛ぶ・パスが通る)に差が出て、ここは比では相殺されない**。

> **開きを大きくしすぎると pow が王に戻る。** wear を 1.70/1.45/1.00/0.85/0.45 に
> すると、力が最後まで残るぶん pow が終盤に強くなり **pow +0.610 / tec +0.464** と
> 1.31倍に開いた。1.35〜0.70 の幅なら並びを崩さない。

#### 結果

4クラブ×3陣形×500試合:

| 能力 | 勝点/試合 | 勝率 |
|---|---|---|
| pow | +0.598 | +21.7pt |
| spd | +0.577 | +20.8pt |
| tec | +0.544 | +19.6pt |
| atk | +0.534 | +19.8pt |
| def | +0.477 | +14.1pt |
| **sta** | **+0.146** | +4.9pt |

**sta は +0.060 → +0.146 と 2.4倍**。同時に pow / tec / spd は
**1.12倍 → 1.10倍**、sta を除く5能力も **1.28倍 → 1.25倍**と、
どちらも崩さずむしろ縮まった。リーグの得点は DIV1 3.48 → 3.40。

sta はまだ他の5能力の1/4だが、**これは正しい**。sta は単独では点を取らず、
**「誰をどこに置くか」と「いつ代えるか」で初めて効く**能力だからで、
方針(能力の価値はフラット、尖りは采配から)そのものになった。

### 3.9a このクラブに来てからの戦績(2026-08-21)

監督の生涯成績(→MANAGER の CAREER / TROPHIES)とは別に、
**いまの在任だけ**を抜いた戦績を CLUB に置く。

    過去の季 … このクラブでの着地(昇格・残留・優勝…)
    このクラブでの戴冠 … 在任中に獲ったトロフィー

#### 抜き方は「経歴を遡って、クラブが変わったら止める」

for(let i=h.length-1;i>=0;i--){ if(h[i].clubId!==S.club.id)break; out.unshift(h[i]); }

### 3.43b 秘書のお知らせを足す(2026-08-21)

**受信箱は「あとから辿れる場所」**(→§3.42)。その場でしか出ない知らせは、
その節にログインしていなければ**起きたこと自体を見逃す**。4つ足した。

#### ① メモラビリアが開いたら招待状(→§3.55)

開き方は**3通り**あるのに、知らせが届くのは世界の頂点を獲ったときだけだった。
**合言葉や URL で開いた人は、開いたことも、そこで戦えることも知らないまま**になる。

    褒賞   memAward → 受信箱の贈り物 → mailTake で開く
    合言葉 memUnlock
    URL    memFromUrl → memUnlock

合流点は「開いた瞬間」なので、そこに `memInvite()` を1つ置いて全経路を賄う。
文面は**強豪クラブからのエキシビジョンの招待**にして、MANAGER のメモラビリアへ送る。

> **褒賞の経路では、受け取るまで招待を出さない。** `memAward` の連絡は
> 「記録が届きました」という贈り物で、受け取って初めて開く。
> 開く前に招待を出すと、持っていないものへ誘うことになる。

#### ② 施設の完成

`facTick` の `built` は**1節だけ持つ**知らせで、CLUB NEWS がそれを読む。
数節がかりの投資なのに、**建った節を跨ぐと何が建ったのか分からなくなる**。
受信箱にも1通残す(`fac:<施設>:<段>` で段ごとに一度きり)。

#### ③④ 案内を6通から8通へ

    6/8 はじめての移籍市場 … 名指しで買える唯一の場所(→§3.67)。存在を知らないと手が1つ減る
    7/8 はじめての采配     … 試合の中にしか入口が無い(→§3.50)。案内が無いと気づけない

**閉じの1通(「それでは監督」)は最後のまま**にする。`tut:` の番号だけを 6 → 8 に
繰り下げ、**id は動かさない**。id を付け替えると、配った控え(→§3.42)が別物と見て
**既に読んだ案内をもう一度配ってしまう**。

> **「開いた画面を覚える」をタブ以外にも広げた。** それまで `seenAll()` に
> 印が立つのはタブ画面だけで、市場のような「入っていく画面」をきっかけにできなかった。

### 3.54e クラブの3文字の略号(2026-08-21)

ヘッダーに正式名称を置くと長すぎる(→docs/11 §6.48)。**3文字の英字**にする。

既にある `EMB_ROMA` は1文字＝1子音なので、「バルサローナ」が **BRS** になって読めない。
綴りとして読める略号には**音節ごとのローマ字**が要る。

```js
embRomaji("バルサローナ")  // → "barusaroona"
clubAbbr("バルサローナ・ブラウグラナ")  // → "BAR"
```

### 3.66 受けに行く動き — 元気なうちは技と速さ、疲れたら力(2026-08-21)

§3.65 で `wear` を入れた結果、**pow だけが終盤まで痩せない**ようになった。
裏を返せば「疲れたら力が強い」だけの試合になる。**スタミナがあるうちは
tec と spd が pow を上回るべき**で、そこを演出ごと作る。

> ボールを持たない近くの選手が tec や spd でボールを受けに行く動きとして
> ボール保持者への加点ができると調整しやすいのではないか (監督)

`resolveChannel` は起点も連結もすべて通る唯一の関門なので、ここに刺す。

```js
function offBallHelp(T,atk,h,x){
  let n=0,w=0;
  for(const q of T.players){
    if(q===atk||q.role==="GK")continue;
    const dh=(heightOf(q)-h)/O.h, dx=((q.x-x)/100)/O.x;
    const near=Math.exp(-(dh*dh+dx*dx));
    if(near<0.02)continue;
    const qual=(q.c.tec*O.tecW+q.c.spd*(1-O.tecW))/O.ref;
    w+=near; n+=near*(qual-1)*Math.pow(q.stam,O.wear);   // ← 差 × スタミナ
  }
  return w?n/w:0;
}
aSc *= 1+clamp(offBallHelp(T,atk,h,x),-O.max,O.max)*O.k;
```

#### 掴むまでに3回作り直した

**① 素の量をそのまま足す** — 効かなかった。加点が `1 + help×k` の形だと、
**基準そのものが底上げされて能力の差が薄まる**。k を 0 → 0.18 と振っても
pow +0.66 のまま動かなかった。

**② 密集度を外して加重平均にする** — 効いた。ただし**得点が前半に偏った**
(52:48 → **56:44**)。素の量にスタミナを掛けると、疲れるほど全チームの加点が
一様に減るため。`linePenalty` を 0.85 → 1.45 に振っても 0.540 → 0.547 しか戻らず、
`offb.wear` を下げると今度は釣り合いが崩れた(pow/tec 1.18倍)。

**③ 平均からの差にスタミナを掛ける** — これが正解。

    help = 平均( 近さ × (質 − 1) × スタミナ^1.6 )

平均的な選手は疲れても **0 のまま**なので得点の時間配分は動かず、
**技と速さの差だけが「走れるうち」に出る**。53:47 に戻った。

#### 得点の水準は締め直さない

加点のぶんリーグの得点が上がるので `th.shot` で戻そうとしたが、
**加点を受け取れない弱小クラブだけが痩せた**。

| | DIV1 | DIV2 | DIV3 |
|---|---|---|---|
| 変更前 | 2.82 | 2.22 | 1.94 |
| 加点あり・締めない | 3.01 | 2.36 | **1.95** |
| 加点あり・`th.shot` で締める | 2.85 | 2.24 | **1.84** |

tec/spd が低いクラブは「能力でも劣り、受けに行く動きでも劣る」と二重に罰せられる。
**加点自体は DIV3 を傷つけていない**(1.94 → 1.95)ので、締めないほうが正しい。
下振れだけ浅く頭打ちにする案も試したが、効果が測れなかった(1.84 → 1.85)ので入れていない。

> `th.origin` で締めるのはもっと悪い。DIV3 が 1.94 → **1.80** まで落ちて
> careertest の下限(2.0)を割った。全体の栓を締めると弱いクラブから先に痩せる。

#### 結果 — 時間で入れ替わる

6クラブ×4陣形×400試合。**名簿と陣形を広く取る**(4クラブだけで測ると
pow が +0.598 にも +0.670 にも見え、判断を誤る)。

| 能力 | 勝点/試合 | 前半のゴール増 | 後半のゴール増 |
|---|---|---|---|
| pow | +0.608 | +0.365 | **+0.332** |
| spd | +0.582 | **+0.406** | +0.284 |
| tec | +0.549 | **+0.373** | +0.298 |
| atk | +0.512 | +0.340 | +0.359 |
| def | +0.466 | +0.009 | −0.033 |
| sta | +0.091 | +0.065 | +0.018 |

**前半は spd・tec がともに pow を上回り、後半は pow が上回る。**
pow / tec / spd の開きも同一ハーネスで **1.18倍 → 1.11倍**。
前半:後半の得点は 52:48 のまま、大差は 8.0% → 6.0% とむしろ減った。

これで「能力の価値はフラット、尖りは采配から」がもう一段進んだ。
**同じ11人でも、いつ攻めるかで要る能力が変わる** — 立ち上がりに畳みかけるなら
技と速さ、終盤に殴り合うなら力。交代とスタミナ管理がその選択そのものになる。

### 3.13d 銀河系軍団 — 同じ人物の別の時代(2026-08-22)

マドリー・ブランコスの14枚を足した。

    MF  マケレレ / カンビアッソ / グティ / フィーゴ / ベッカム / ソラーリ
    FW  ラウール / ロナウド / モリエンテス

左に流れて組み立てる形もこの1枚で賄える。

#### 同じ人物でも、別の時代は別のカード

    ベッカム  マンチェスター・レッズ(le_rmf01) ／ マドリー・ブランコス(le_rwg03)
    ロナウド  C. ロナウド(le_rwg01) ／ **R. ナザーリオ**(le_cf06)

前者は**同じ人物の別の時代**、後者は**同姓の別人**。どちらも別カードとして扱う。
`id` が別なら別のカードなので、仕組みの上では何も特別なことをしていない。

> **固有スキルは `id` に紐づく。** ベッカムの「精密機械」はマンチェスターの
> カードのものなので、マドリーのベッカムには使えない
> (careertest が「他人の固有スキルを持っている」で落とす)。
> 別の時代には**別の固有スキル**を用意する — 「白い背番号23」。

#### 固有スキルは、証明済みの形から採る

新しい層と群の組み合わせを試すと、**値の妥当性と札の妥当性が同時に動いて
切り分けられない**。既存の12枚で careertest の帯に収まると分かっている形だけを使う。

それでも4回落ちた。

| 札 | 何が起きたか |
|---|---|
| 白い矢 | `w:1.85` で選ばれやすくしたうえ `s:1.14` も付けて **40.3**(帯は 16.2〜30.0) |
| 怪物 | `when:"fresh"` の成分が **2.00枚ぶん**(条件付きの帯は 1.2〜1.8) |
| 静かな加速 | `origin/spd` は**発動率が高い群**。`s:1.13` で **43.3** |
| 背中で語る | `finish` は**目標が高い層**(56.9)。`origin` と同じ `s` では **23.1** で届かない |

**`w` と `s` を同時に上げない。** 「魔法の足」が `w:1.85 / s:1.36` で成立するのは
`when:"fresh"` で発動場面を半分に絞っているからで、条件を外すなら `w` は付けない。

**層によって目標が違う**ことも忘れやすい(起点 23.1 / 迎撃 45.6 / 仕上げ 56.9)。
同じ `s:1.09` でも、起点なら妥当で仕上げなら足りない。

#### LEGENDS は全員が固有スキルを持つ

`drive.js` が **1枚目のスキルが自分の固有スキルであること**を見張っている。
最初は主要な7人にだけ固有スキルを用意したが、残り7人が落ちた。
**14枚ぶん14種**を用意して、1枚目に置き直した。

### 3.13e メモラビリア4つ目 — ロス・ガラクティコス(2026-08-22)

`GALACTICOS-2004` で開く。**2002-04 銀河系軍団**、星を並べた11人。

| | ミラン | ガナーズ | ブラウグラナ | 銀河系 |
|---|---|---|---|---|
| 陣形 | 4-4-2ダイヤ | 4-4-2 | 4-3-3 | **4-2-3-1** |
| 監督 | アンチェロッティ／知将 | ヴェンゲル／キーマン | グアルディオラ／知能 | **デル・ボスケ／堅物** |
| 采配 | 技巧 | 速さ | 技と速さ | **個の力** |
| 弱点 | 消耗 | 止める場面 | 空中戦 | **奪い返せない** |

采配は初めて **atk / def の軸**を動かす(他の3つは tec / spd / pow)。

    ロス・ガラクティコス … 4-2-3-1限定 / マドリー・ブランコスの選手のみ
      ATK ×1.10・DEF ×0.96 ／ 迎撃(press) ×0.96

#### **他より強い11人**にする(2026-08-22 改訂)

> スター軍団の銀河系なので OVR はほかより高くてもよいと思います。そのうえで
> 守備を捨てて攻撃を獲りに行って崩壊してしまうという事実もかみ合う (監督)

最初は他と同じ帯(平均85.3)に置いたが、それだと**ただ弱いだけのチーム**になった。
星を並べた11人なので、**能力は他より高くしてよい**。

| | ミラン | ガナーズ | ブラウグラナ | 銀河系 |
|---|---|---|---|---|
| 合計 | 944 | 936 | 944 | **975** |
| 平均 | 85.8 | 85.1 | 85.8 | **88.6** |
| 最低 | 82 | 82 | 82 | **86** |

**上げたのは攻撃側だけ**で、DEF は1も動かしていない。
前の4枚は 8 / 8 / 8 / 3 のまま。**守れない選手が4人いる**という編成の性格が、
数字を上げたあとも残る。

#### それでも失点は減らない — そこが持ち味

    総当たりの通算(3戦ぶんの勝点合計・400試合ずつ)
      ブラウグラナ  5.57   得点 2.82   失点 2.02
      ミラン      4.98   得点 2.79   失点 2.22
      銀河系      3.74   得点 2.51   失点 **2.94**
      ガナーズ     3.70   得点 2.09   失点 2.44

**失点だけが突出している。** 平均OVR で3ポイント上回っても、勝点では並ばない。

梃子を全部試して、どれが効くかも測った。

| 触ったもの | 勝点計 | 失点 |
|---|---|---|
| いま | 3.74 | 2.94 |
| 前4枚 sta+3 | 3.88 | 2.98 |
| 全員 sta+2 | 4.00 | 2.90 |
| 全員 atk+2 | 4.19 | 2.97 |
| **全員 def+2** | **4.46** | **2.50** |

**このチームを勝たせる梃子は守備しかない。** 攻撃をいくら積んでも失点が変わらず、
勝点は伸びきらない。**だから守備には触らない。**
「守備を捨てて攻撃を獲りに行き、そのぶん崩れる」が数字の上でもそのまま出ている。

> **弱いのではなく、そういうチーム。** 平均88.6は4つの中でいちばん高い。
> 使えば1試合2.5点取れる。ただし2.9点取られる。
> **殴り合いに持ち込めば勝てるが、守り合いになると勝てない**11人として置く。
