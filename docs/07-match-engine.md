## 7. 試合エンジン

card-eleven の考え方を土台にしつつ、**1つずつ設計しながら**移植する。
このドキュメントは移植した段の記録であり、まだ入れていない層は §7.7 に置く。

### 7.1 柱 — 見せかけのロジックを持たない

**勝敗に関わる試合ロジックが正で、見かけはその結果に追従する。**
そのために、エンジンは**90分を先に最後まで解いてから**描画に渡す。

```
 simulateMatch(home, away, seed)
        ↓
   { hg, ag, events[] }        ← 90分ぶんの起きたことが全部入っている
        ↓
   描画は events を順に再生するだけ
```

| これが効くところ | |
|---|---|
| **演出が結果を変えられない** | 構造的に不可能。描画は読むだけで書かない |
| **倍速 / スキップ / 自動消化** | 「再生速度」だけの違いになる(→§3.6) |
| **他クラブ同士の試合** | 同じエンジンをそのまま使い、描画しないので一瞬 |
| **選手の位置** | エンジンが持つ。描画は既知の座標を補間するだけでよい |
| **検証** | headless Node で何千試合でも回せる |

> **card-eleven との違い。** あちらは判定の途中に `await` で演出を挟む構造で、
> 進行と描画が絡み合っていた。**選手が唐突にピッチを飛び回る**のもここに由来する
> (描画側がその場の都合で位置を動かしていたため)。pftb は
> **位置をイベントに持たせ、描画は補間しかしない**ので、原理的に飛ばない。

#### 同じたねなら必ず同じ試合になる

`seed` から `mulberry32` を起こし、**その試合の中だけで乱数を消費する**。
節ごと・カードごとではなく **1試合1たね**(`W.seed ^ hash(home+vs+away+season+節)`)。

- 同じ節を何度解いても同じ結果 → 描画するかどうかで結果が変わらない
- `careertest` が「同じたね → 同じスコア・同じイベント列 / 違うたね → 別の試合」を検査する

### 7.2 時計 — 90分 + アディショナルタイム / 3分刻み

card-eleven を踏襲して **1ティック = 3分**。45分 = 15ティックを2回で90分。

```
 前半 15ティック(3,6,…,45分) + AT 0〜2ティック
 後半 15ティック(48,…,90分)  + AT 0〜3ティック
 → 1試合 30〜35ティック
```

- **ATはキックオフの時点で確定する。** 後から伸ばすと、先に解いた結果と再生が食い違う
- AT のティックは `min` が 45 / 90 のまま `at:true` が立つ(表示は `45+` `90+`)
- 実測のATティック数の分布: 0が8% / 1が16% / 2が23% / 3が30% / 4が17% / 5が6%

### 7.3 有効値 — すべての判定の単一集約点

```js
eff(p, k) = 素の能力値 × 枠適性
```

**能力に掛かる修正は必ずここへ足す。** そうすれば全判定に一様に効き、
新しい層を入れるたびに判定式を触らずに済む(card-eleven の `eff` と同じ設計)。

いまは枠適性(→§3.14)だけ。これから足す予定のものは §7.7。

### 7.4 判定の形

**攻撃側スコア > 守備側スコア × 閾値** で成功。全判定でこの形にそろえる。

各スコアに **`rr() = 0.6 + random×0.8`**(0.6〜1.4)が**独立して**乗る。
攻守それぞれに揺らぎが乗るので、実力差があっても番狂わせが起きる。

| 判定 | 攻撃側 | 守備側 | 閾値 |
|---|---|---|---|
| シュート vs GK | `atk×0.7 + pow×0.3` | GK の `def` | `TUNING.th.shot` |

### 7.5 1ティックの流れ(現状)

```
 ① 支配率     midPower(H) × ホーム補正  vs  midPower(A)
 ② 攻撃権     その比で抽選
 ③ 起点の選手 前の選手ほど選ばれやすい
 ④ シュートまで到達するか  TUNING.atk.toShot
 ⑤ シュート判定 → goal / save
```

**支配率**は中盤の `tec×0.45 + spd×0.30 + sta×0.25` を、MF を厚く(×1.0、他は×0.32)
重み付けして合計する(card-eleven から踏襲)。

#### 実測(同一編成どうし2000試合)

| | 実測 | 現実の水準 |
|---|---|---|
| 1試合の平均得点 | **2.90点** | 約2.7点 |
| 引き分け | **23.4%** | 約25% |
| ホーム勝率 | **38.5%** | 約45% |
| 1チームのシュート数 | **約12本** | 約12本 |
| 決定率 | **約12%** | 約10% |

`TUNING.atk.toShot`(シュートまで到達する率)と `TUNING.th.shot`(GKを越える閾値)の
2つで調整する。片方だけ動かすとシュート数か決定率のどちらかが崩れるので、
**必ず両方を見て決める**。

### 7.6 監督は任意のタイミングで手を打てる(D25 — 決定 2026-08-02)

WCCF を踏襲し、**試合中いつでも指示を出せる**。
§7.1 の「先に解く」と両立させるため、**解く単位を「試合」ではなく「1ティック(3分)」**にする。

```
 [ 解済 ][ 解済 ][ 解済 ]│ 未解決 …
                        ↑ 再生ヘッド
 監督が指示 → M.orders に積まれる
            → **次のティックの入力**として効く
```

| 不変条件 | |
|---|---|
| 描画は**解き終わったティックしか触らない** | 見せかけは結果に触れない(§7.1 は保たれる) |
| 指示は**演出ではなく、シミュレーションの引数** | `orderMatch()` で積み、`applyOrders()` がティックの頭で適用する |
| 止めても・止めなくても同じ | **指示が無ければ**1ティックずつ解いても一気に解いても同一 |

#### API

```js
const M = createMatch(home, away, seed);   // 状態を作る(まだ解かない)
stepMatch(M)      // 1ティック解いて、そのティックのイベントを返す
orderMatch(M, side, order)   // 指示を積む。いつ呼んでもよい
finishMatch(M)    // 残りを一気に解く(スキップ / 自動消化 / CPU同士)
```

#### ティックごとに独立したたね

```js
tickSeed = matchSeed ^ hashStr("t:" + tickIndex)
```

**途中で指示を出しても、以降のティックの乱数列がずれない。**
だから「同じ試合・同じ流れで、采配だけが違いを生む」というA/Bが成立し、
**采配の価値を数字で測れる**(例: ger-4 vs ger-5 を1500試合、60分に1枚交代で勝率 74.7% → 75.7%)。

> たねを1本の連番にすると、指示が乱数の消費数を変えて**以降が丸ごと別物**になる。
> それでは「その采配が効いたのか、乱数がずれただけか」が区別できない。

#### いま出せる指示

| 種類 | 内容 | 状態 |
|---|---|---|
| `sub` | 交代。控えが**出る選手の枠をそのまま引き継ぐ**(位置と適性は枠側の属性) | **実装済み**(上限 `TUNING.squad.subMax` = 3) |
| 戦術変更 | 攻撃的 / 守備的 など | 未(戦術の定義が D10-3 待ち) |
| 采配スキル | 監督が持つ切り札(→[03. §3.7](03-game-design.md)) | 未 |

`careertest` が検査するもの:
1ティックずつでも一気にでも同じ / 指示より前のイベントは1つも変わらない /
交代枠の上限(積んだ分も数える) / **止めても指示が無ければ結果は不変**

### 7.7 モメンタム(勢い)(D26 — 決定 2026-08-02)

**-1〜+1 の1本のゲージ**(`M.mom`、+ がホーム優勢)。
決めるのは**起点の高さ**——押されていれば自陣から、勢いがあれば前から攻撃が始まる。

```
 キックオフ  両チームのOVR差で傾く(強いチームが前から始められる)
      ↓
 起きたことで上下   得点 +0.54 / シュート +0.16 / 止めた側 +0.19
                    起点の成立 +0.11 / 起点で失う 相手に +0.21
      ↓
 毎ティック中立へ戻る(×0.90)   ← 流れは移ろう。掴んだままにはならない
```

- 初期値は `kickCap`(0.45)で頭打ち。**強豪でも一方的に始まらない**
- 上下の幅と減衰は「実測の平均絶対値が 0.3 前後」を狙って決めた
  (小さすぎると起点が中盤に張り付き、大きすぎると振り切れたまま戻らない)
- 連鎖(§7.10)を入れたら、**マッチアップの勝敗**が主な増減源になる

### 7.8 起点 — 高さ → 選手 → チャンネル(D26)

```
 モメンタム ──▶ 狙う高さ ──▶ 起点の選手 ──▶ サブポジのチャンネル ──▶ 成否
```

#### ① モメンタムが「狙う高さ」を決める

```js
target = 0.5 + mom × spread        // spread=0.55
```

#### ② 高さが選手を決める(確率的)

選手の高さは**陣形のy座標**から出す(`heightOf` = `(87-y)/74`、0=自陣ゴール前 / 1=敵陣ゴール前)。
狙う高さとの距離に**ガウス重み**を掛けて抽選する。

```js
weight(p) = exp(-((heightOf(p) - target) / sigma)²)     // sigma=0.18
```

- **陣形の座標をそのまま使う**ので、3-4-3 は高い起点が、5-4-1 は低い起点が出やすい
- ガウスなので**狙いから外れた位置も低確率で選ばれる**(一意には決まらない)
- 左右のレーンは**当面見ない**。監督の指示(サイドアタック/中央突破)で操作する段で、
  同じ形の2次元版に広げる

実測(同一編成どうし400試合):

| モメンタム | GK | DF | MF | FW |
|---|---|---|---|---|
| 押されている(< −0.2) | 7% | **72%** | 20% | 0% |
| 拮抗(−0.2〜0.2) | 0% | 9% | **89%** | 2% |
| 勢いがある(> 0.2) | 0% | 0% | 43% | **57%** |

#### ③ サブポジがチャンネルを決める

`ORIGINS[サブポジ]` に**3種ずつ**(13サブポジ × 3 = **39種**)。
「その選手がボールを持ったときに何をするか」で、**得意な能力のものほど選ばれやすい**。

| | |
|---|---|
| `stat` | 成否を決める能力。**選ばれやすさと成功率の両方**に効く |
| `risk` | 成功のしやすさ(**相対値**)。絶対の水準は `TUNING.atk.originK` で一括調整 |
| `gain` | 成功時に稼ぐ前進。次のシュート到達率に効く |

**`risk` と `gain` はトレードオフに置く。** 3種は必ず「安全だが小さい」「中間」「一発だが落としやすい」
の関係になっており、テストが「最も安全な選択が最大の gain を持たない」ことを検査する。

```
CB   持ち上がり(spd 安全)     縦パス(tec 中間)      ロングフィード(pow 一発)
LWG  カットイン(tec)          縦へ突破(spd)         早いクロス(pow)
CF   引いて受ける(tec 安全)   ポストプレー(pow)     裏へ抜ける(spd 一発)
```

- 3種は**それぞれ別の能力**で決まる(テストが検査)。同じ選手でも試合ごとに違う手を選ぶ
- 成否は `risk × originK × (0.55 + 能力/20 × 0.45)`。
  **能力が低い選手は同じ選択をしても失敗しやすい**

#### 実測(この段のあと)

| | 実測 | 現実の水準 |
|---|---|---|
| 1試合の平均得点 | **2.82点** | 約2.7点 |
| 引き分け | **22.5%** | 約25% |
| 1チームのシュート | **約12本** | 約12本 |
| 決定率 | **約12%** | 約10% |
| 起点の成立率 | 約79% | — |

### 7.9 いま分かっている歪み

#### GK の def が上限に張り付いている

96人中 **52人(54%)が def=20**。`statsFor` が GK の def に重み1.75を配るため、
OVR がある程度あるとすぐ上限に達する。

- 結果として**シュート判定の守備側がほぼ定数**になり、モデルが攻撃偏重になっている
- 強豪 vs 弱小の差が、GK の質ではなく**攻撃側の質だけ**で出ている

> GKのセーブ側にも `pow`(反応)や `tec`(ポジショニング)を配合するか、
> GK の能力配分そのものを見直すかを、シュート判定を作り込む段で決める。

#### 外れたシュートが全部「セーブ」になっている

枠外・ポスト・ブロックが無く、goal でなければ必ず save。
**連鎖(§7.10)を入れる段で、シュートの結果を枝分かれさせる。**

### 7.10 これから足す層(card-eleven から順に持ってくる)

| 層 | 内容 | 状態 |
|---|---|---|
| **連鎖チェーン** | 起点 → リンク×N → シュート。マッチアップの勝敗がモメンタムを動かす | 次 |
| **疲労** | 関与回数主体。活躍した選手ほど終盤に落ちる | 未 |
| **奪取(カウンター)** | `press/(press+security)` で攻守が入れ替わる | 未 |
| **状況補正** | 終盤(clutch)・ビハインド(losing) | 未 |
| **モメンタム** | **実装済み**(→§7.7)。起点の高さを決める | 済 |
| **左右のレーン** | 監督の指示(サイドアタック/中央突破)で操作する | 未 |
| **スキルの効果** | いまスキルは名前だけ。`fx` 相当が要る | 未 |
| **キーポジション** | 陣形ごとに特徴を担う枠のステを強化(→§3.16) | 未 |
| **交代** | **実装済み**(→§7.6)。CPU側が自分で交代するのは未 | 一部 |
| **セットプレー / ファウル / 負傷** | | 未 |
