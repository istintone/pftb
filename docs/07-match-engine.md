## 7. 試合エンジン

card-eleven の考え方を土台にしつつ、**1つずつ設計しながら**移植する。
このドキュメントは移植した段の記録であり、まだ入れていない層は §7.7 に置く。

### 7.1 柱 — 見せかけのロジックを持たない

**勝敗に関わる試合ロジックが正で、見かけはその結果に追従する。**
そのために、エンジンは**90分を先に最後まで解いてから**描画に渡す。

```
 simulateMatch(home, away, seed)
        ↓
   { hg, ag, events[] }        ← 90分ぶんの起きたことが全部入っている
        ↓
   描画は events を順に再生するだけ
```

| これが効くところ | |
|---|---|
| **演出が結果を変えられない** | 構造的に不可能。描画は読むだけで書かない |
| **倍速 / スキップ / 自動消化** | 「再生速度」だけの違いになる(→§3.6) |
| **他クラブ同士の試合** | 同じエンジンをそのまま使い、描画しないので一瞬 |
| **選手の位置** | エンジンが持つ。描画は既知の座標を補間するだけでよい |
| **検証** | headless Node で何千試合でも回せる |

> **card-eleven との違い。** あちらは判定の途中に `await` で演出を挟む構造で、
> 進行と描画が絡み合っていた。**選手が唐突にピッチを飛び回る**のもここに由来する
> (描画側がその場の都合で位置を動かしていたため)。pftb は
> **位置をイベントに持たせ、描画は補間しかしない**ので、原理的に飛ばない。

#### 同じたねなら必ず同じ試合になる

`seed` から `mulberry32` を起こし、**その試合の中だけで乱数を消費する**。
節ごと・カードごとではなく **1試合1たね**(`W.seed ^ hash(home+vs+away+season+節)`)。

- 同じ節を何度解いても同じ結果 → 描画するかどうかで結果が変わらない
- `careertest` が「同じたね → 同じスコア・同じイベント列 / 違うたね → 別の試合」を検査する

### 7.2 時計 — 90分 + アディショナルタイム / 3分刻み

card-eleven を踏襲して **1ティック = 3分**。45分 = 15ティックを2回で90分。

```
 前半 15ティック(3,6,…,45分) + AT 0〜2ティック
 後半 15ティック(48,…,90分)  + AT 0〜3ティック
 → 1試合 30〜35ティック
```

- **ATはキックオフの時点で確定する。** 後から伸ばすと、先に解いた結果と再生が食い違う
- AT のティックは `min` が 45 / 90 のまま `at:true` が立つ(表示は `45+` `90+`)
- 実測のATティック数の分布: 0が8% / 1が16% / 2が23% / 3が30% / 4が17% / 5が6%

### 7.3 有効値 — すべての判定の単一集約点

```js
eff(p, k) = 素の能力値 × 枠適性
```

**能力に掛かる修正は必ずここへ足す。** そうすれば全判定に一様に効き、
新しい層を入れるたびに判定式を触らずに済む(card-eleven の `eff` と同じ設計)。

いまは枠適性(→§3.14)だけ。これから足す予定のものは §7.7。

### 7.4 判定の形

**攻撃側スコア > 守備側スコア × 閾値** で成功。全判定でこの形にそろえる。

各スコアに **`rr() = 0.6 + random×0.8`**(0.6〜1.4)が**独立して**乗る。
攻守それぞれに揺らぎが乗るので、実力差があっても番狂わせが起きる。

| 判定 | 攻撃側 | 守備側 | 閾値 |
|---|---|---|---|
| シュート vs GK | `atk×0.7 + pow×0.3` | GK の `def` | `TUNING.th.shot` |

### 7.5 1ティックの流れ(現状)

```
 ① 支配率     midPower(H) × ホーム補正  vs  midPower(A)
 ② 攻撃権     その比で抽選
 ③ 起点の選手 前の選手ほど選ばれやすい
 ④ シュートまで到達するか  TUNING.atk.toShot
 ⑤ シュート判定 → goal / save
```

**支配率**は中盤の `tec×0.45 + spd×0.30 + sta×0.25` を、MF を厚く(×1.0、他は×0.32)
重み付けして合計する(card-eleven から踏襲)。

#### 実測(同一編成どうし2000試合)

| | 実測 | 現実の水準 |
|---|---|---|
| 1試合の平均得点 | **2.90点** | 約2.7点 |
| 引き分け | **23.4%** | 約25% |
| ホーム勝率 | **38.5%** | 約45% |
| 1チームのシュート数 | **約12本** | 約12本 |
| 決定率 | **約12%** | 約10% |

`TUNING.atk.toShot`(シュートまで到達する率)と `TUNING.th.shot`(GKを越える閾値)の
2つで調整する。片方だけ動かすとシュート数か決定率のどちらかが崩れるので、
**必ず両方を見て決める**。

### 7.6 監督は任意のタイミングで手を打てる(D25 — 決定 2026-08-02)

WCCF を踏襲し、**試合中いつでも指示を出せる**。
§7.1 の「先に解く」と両立させるため、**解く単位を「試合」ではなく「1ティック(3分)」**にする。

```
 [ 解済 ][ 解済 ][ 解済 ]│ 未解決 …
                        ↑ 再生ヘッド
 監督が指示 → M.orders に積まれる
            → **次のティックの入力**として効く
```

| 不変条件 | |
|---|---|
| 描画は**解き終わったティックしか触らない** | 見せかけは結果に触れない(§7.1 は保たれる) |
| 指示は**演出ではなく、シミュレーションの引数** | `orderMatch()` で積み、`applyOrders()` がティックの頭で適用する |
| 止めても・止めなくても同じ | **指示が無ければ**1ティックずつ解いても一気に解いても同一 |

#### API

```js
const M = createMatch(home, away, seed);   // 状態を作る(まだ解かない)
stepMatch(M)      // 1ティック解いて、そのティックのイベントを返す
orderMatch(M, side, order)   // 指示を積む。いつ呼んでもよい
finishMatch(M)    // 残りを一気に解く(スキップ / 自動消化 / CPU同士)
```

#### ティックごとに独立したたね

```js
tickSeed = matchSeed ^ hashStr("t:" + tickIndex)
```

**途中で指示を出しても、以降のティックの乱数列がずれない。**
だから「同じ試合・同じ流れで、采配だけが違いを生む」というA/Bが成立し、
**采配の価値を数字で測れる**(例: ger-4 vs ger-5 を1500試合、60分に1枚交代で勝率 74.7% → 75.7%)。

> たねを1本の連番にすると、指示が乱数の消費数を変えて**以降が丸ごと別物**になる。
> それでは「その采配が効いたのか、乱数がずれただけか」が区別できない。

#### いま出せる指示

| 種類 | 内容 | 状態 |
|---|---|---|
| `sub` | 交代。控えが**出る選手の枠をそのまま引き継ぐ**(位置と適性は枠側の属性) | **実装済み**(上限 `TUNING.squad.subMax` = 3) |
| 戦術変更 | 攻撃的 / 守備的 など | 未(戦術の定義が D10-3 待ち) |
| 采配スキル | 監督が持つ切り札(→[03. §3.7](03-game-design.md)) | 未 |

`careertest` が検査するもの:
1ティックずつでも一気にでも同じ / 指示より前のイベントは1つも変わらない /
交代枠の上限(積んだ分も数える) / **止めても指示が無ければ結果は不変**

### 7.7 モメンタム(勢い)(D26 — 決定 2026-08-02)

**-1〜+1 の1本のゲージ**(`M.mom`、+ がホーム優勢)。
決めるのは**起点の高さ**——押されていれば自陣から、勢いがあれば前から攻撃が始まる。

```
 キックオフ  両チームのOVR差で傾く(強いチームが前から始められる)
      ↓
 起きたことで上下   得点 +0.54 / シュート +0.16 / 止めた側 +0.19
                    起点の成立 +0.11 / 起点で失う 相手に +0.21
      ↓
 毎ティック中立へ戻る(×0.90)   ← 流れは移ろう。掴んだままにはならない
```

- 初期値は `kickCap`(0.45)で頭打ち。**強豪でも一方的に始まらない**
- 上下の幅と減衰は「実測の平均絶対値が 0.3 前後」を狙って決めた
  (小さすぎると起点が中盤に張り付き、大きすぎると振り切れたまま戻らない)
- 連鎖(§7.10)を入れたら、**マッチアップの勝敗**が主な増減源になる

### 7.8 起点 — 高さ → 選手 → チャンネル(D26)

```
 モメンタム ──▶ 狙う高さ ──▶ 起点の選手 ──▶ サブポジのチャンネル ──▶ 成否
```

#### ① モメンタムが「狙う高さ」を決める

```js
target = 0.5 + mom × spread        // spread=0.55
```

#### ② 高さが選手を決める(確率的)

選手の高さは**陣形のy座標**から出す(`heightOf` = `(87-y)/74`、0=自陣ゴール前 / 1=敵陣ゴール前)。
狙う高さとの距離に**ガウス重み**を掛けて抽選する。

```js
weight(p) = exp(-((heightOf(p) - target) / sigma)²)     // sigma=0.18
```

- **陣形の座標をそのまま使う**ので、3-4-3 は高い起点が、5-4-1 は低い起点が出やすい
- ガウスなので**狙いから外れた位置も低確率で選ばれる**(一意には決まらない)
- 左右のレーンは**当面見ない**。監督の指示(サイドアタック/中央突破)で操作する段で、
  同じ形の2次元版に広げる

実測(同一編成どうし400試合):

| モメンタム | GK | DF | MF | FW |
|---|---|---|---|---|
| 押されている(< −0.2) | 7% | **72%** | 20% | 0% |
| 拮抗(−0.2〜0.2) | 0% | 9% | **89%** | 2% |
| 勢いがある(> 0.2) | 0% | 0% | 43% | **57%** |

#### ③ サブポジがチャンネルを決める

`ORIGINS[サブポジ]` に**3種ずつ**(13サブポジ × 3 = **39種**)。
「その選手がボールを持ったときに何をするか」で、**得意な能力のものほど選ばれやすい**。

| | |
|---|---|
| `stat` | 成否を決める能力。**選ばれやすさと成功率の両方**に効く |
| `risk` | 成功のしやすさ(**相対値**)。絶対の水準は `TUNING.atk.originK` で一括調整 |
| `gain` | 成功時に稼ぐ前進。次のシュート到達率に効く |

**`risk` と `gain` はトレードオフに置く。** 3種は必ず「安全だが小さい」「中間」「一発だが落としやすい」
の関係になっており、テストが「最も安全な選択が最大の gain を持たない」ことを検査する。

```
CB   持ち上がり(spd 安全)       縦パス(tec 中間)     ロングフィード(pow 一発)
LWG  カットイン(tec)            縦の突破(spd)        早いクロス(pow)
CF   反転からの持ち上がり(tec 安全) 前線からのプレス(def) 裏抜け(spd 一発)
```

> **置くのは「自分から仕掛ける動き」だけ。**
> 「クロスに合わせる」「引いて受ける」「ポストプレー」のような**受け手のアクションは置かない**。
> それは連鎖(§7.10)の中で起きることで、攻撃の起点ではない。
> 前線の選手なら「前線からのプレスで奪う」「裏へ走り出す」「こぼれ球への詰め」が起点にあたる。
> **`def` が起点の能力として登場するのはここ**(高い位置での奪取)。

- 3種は**それぞれ別の能力**で決まる(テストが検査)。同じ選手でも試合ごとに違う手を選ぶ

#### ④ 成否は**相手とのマッチアップ**で決まる(D27)

§7.4 の形にそろえる。相手は**座標が近いほど対応しやすく、遠いほど関与しない**。

```js
// 対応する相手を選ぶ — 両チームは向かい合っているので、
// 攻撃側の高さ h に対応する守備者は自軍フレームで 1-h の高さにいる
weight(q) = exp(-((heightOf(q)-(1-h))/σh)² - (((q.x-(100-x))/100)/σx)²)

aSc = (eff(atk,"atk")×0.25 + eff(atk, ch.stat)×0.75) × ch.risk × originK × rr()
dSc = (eff(df,"def")×0.75 + eff(df, ch.stat)×0.25) × rr()
成功 = aSc > dSc × TUNING.th.origin
```

**攻守を同じ形にする。** 「総合力(`atk`/`def`) + チャンネルと同じ能力」の配合で、
`atkW` / `defW` の2つのダイヤルが鏡像になる。片側だけハイブリッドだと、
調整のときにどちらの式を触っているのか読みにくい。

- 守備側は速さで抜けようとすれば速い守備者が追いつき、技術で運べば読める守備者が止める
- **`atkW`(0.25)は `defW`(0.75)より小さい。** `atk` は役割差が大きく
  (DF 8.0 対 FW 18.5)、大きくすると起点の勾配が潰れるため
- これで **DFの `atk` が生きる**。ボールを持てるCBは起点として実際に強い
  (`atk+6` で DF起点の成功率 88% → 93% / `atk-6` で 82%)
- GKは外す(GKの仕事はシュートを止めること)

> `atk` は決定力なので、CBのビルドアップを決定力でゲートするのは概念的には少し歪む。
> 6能力に「攻撃を作る総合力」が無いための代用で、重みを 0.25 に抑えているのはそのため。

**座標のミラーだけで、攻守の噛み合わせが自然に決まる。**

| 起点 | 対応する相手 | 成功率 | 出現 |
|---|---|---|---|
| DF起点(h≒0.2) | **相手FW**(h'≒0.8) | **88%** | 15% |
| MF起点(h≒0.5) | **相手MF**(h'≒0.5) | **83%** | 52% |
| FW起点(h≒0.85) | **相手DF**(h'≒0.15) | **65%** | 12% |

**FWの `def` は低い(平均7.5 対 DFの18.8)ので、自陣からのビルドアップはほとんど止まらない。**
押し込まれて DF 起点になっても攻撃自体は始まり、**勝負は中盤から前になる**——
という構造が、係数を足さずに座標だけで出てくる。

> **これを入れるまで、フィールドプレーヤーの `def` は完全に死んでいた。**
> ±8 動かしても得点が1つも変わらず、守備の経路は GK の `def` 1本だけだった
> (しかも GK は上限20に張り付いている → §7.9)。
> いまは失点が `def+6` で 1.17 / `def-6` で 1.75 と動く。`careertest` が毎回検査する。

### 7.9 連鎖 — 起点のあと、ボールが繋がっていく(D28 — 決定 2026-08-02)

起点が成立したら、そこから攻撃が続く。
**各ステップは起点とまったく同じ仕組み**で回す——ボールを持った選手がサブポジの3枚から
チャンネルを選び、座標の近い相手と競る。勝てば次へ、負ければそこで失う。

```
 起点(成功) ─▶ 行き先を抽選(高さ × レーン) ─▶ 次に持つ選手 ─▶ 同じ判定 ─▶ …
                                                                 ↓
                                                          シュート / 失う
```

#### チャンネルの `kind` が「次に誰が持つか」を決める

| kind | 意味 | 次の持ち手 |
|---|---|---|
| `carry` | ドリブル / キープ | **自分がそのまま次の起点**になる |
| `pass` | パス | 行き先に近い**味方**へ渡る(自分は外す) |
| `shot` | その場で撃つ | 連鎖はここで終わる |

39種の内訳は `carry` 22 / `pass` 15 / `shot` 2。

#### 行き先(高さ × レーン)を抽選する

**ボールの位置は選手の枠とは別に持つ。** 持ち運びで動くのはボールであって、
枠(FORMATIONS の座標)は動かない。マッチアップも受け手選びもこの位置で引く。

```js
// 高さ: 残りの距離に対する割合で進む
h' = h + gain × (1-h) × gainK × (1 ± jitter)
// to を持つチャンネルは「最低ここまで届く」を保証する
if (ch.to) h' = max(h', ch.to × (1 ± toJitter))
// 左右: lane 規則 + ばらつき
x' = laneTarget(ch, x) ± spread
```

**`to` は「一発で前線へ送る手」だけが持つ。** 割合計算だけだと、自陣からのロングフィードが
頭打ちになって「一発」にならない。パス系にしか付けない(テストが検査)。

| チャンネル | `to` | 実測の到達 |
|---|---|---|
| GK ロングキック | 0.60 | 0.00 → **0.61** |
| SB 早いクロス | 0.88 | 0.33 → **0.88** |
| CB ロングフィード | 0.76 | 0.25 → **0.77** |
| CMF スルーパス | 0.82 | 0.53 → **0.83** |
| WG/MF クロス | 0.90 | 0.61 → **0.90** |

比較: `to` を持たない手は 持ち上がり 0.25 → 0.46 / インナーラップ 0.34 → 0.55。

| lane | 行き先 | 使う例 |
|---|---|---|
| `same` | そのレーン | 縦パス / スルーパス |
| `in` | 中央へ寄る | カットイン / 絞り込み |
| `out` | 近い方のタッチライン際 | オーバーラップ / 展開 |
| `switch` | **逆サイド** | サイドチェンジ |
| `box` | ペナルティエリア中央 | クロス系(ばらつき小) |
| `any` | 散らす(ばらつき大) | ロングフィード / 散らし |

> **前進を足し算にすると2手でゴール前に着いてしまい、連鎖が成立しない**(実際にそうなった)。
> 残り距離に対する割合にすることで、自陣では大きく進み、敵陣深くでは進みにくくなる。

- 受け手は**行き先に近い味方**をガウス重みで抽選する(起点の選び方と同じ形)
- 直前と同じチャンネルは重みを落とす(`repeatW=0.30`)。同じ選手が運び続けるとき、
  同じ札の連発になるのを避ける

#### 運ぶほど手放したくなる(D31 — 決定 2026-08-03)

`carry` は自分が次の起点になるので、放っておくと**1人が枠を離れて延々と独走する**。
陣形が崩れたままの絵になり、実況も「持ち上がり」が積み上がるだけになる。

ボールの位置と**その選手の枠**との距離 `stray` を出し、離れるほど `carry` の重みを落として
`pass` に寄せる。**判定そのものには触らない**(離れても弱くはならない)。選ぶ手が変わるだけ。

```js
stray = √( (h - 自分の高さ)² + ((x - 自分のx)/100)² )
carry の重み × max(strayFloor, 1 - stray/strayFull)   // 0.15 .. 1.0
pass  の重み × (1 + stray × strayPass)                 // 1.0 .. 
```

| | 入れる前 | 入れた後 |
|---|---|---|
| `carry` の割合 | 52% | **43%** |
| 3回以上続けて運ぶ | 5.8% | **1.8%** |
| 連鎖時の stray(90%点) | 0.44 | **0.39** |

> 「まったく続かない」ようにはしない。**独走は稀に起きるから見せ場になる。**

#### 撃つ判断

```js
urge = (shotBase + h^3 × shotDepth + step × shotStep) × (0.3 + atk/20 × 0.7)
```

**深く入るほど(高さの累乗)・繋ぐほど・撃てる選手ほど**撃ちに行く。

**判断するのは「ボールを収めた選手」。** チャンネルを解決してから受け手を決め、
そのうえで撃つかを問う。順番を逆にすると
**スルーパスを出した本人がその球を自分で撃つ**ことになる(実際にそうなっていた)。
直したことで撃ち手が前線寄りになり、ブロック率と決定率が動いたので、
`th.block` 1.55→**1.36** / `th.shot` 0.82→**0.86** で元の水準に戻した
(平均2.92点 / 引き分け25.9% / block 28% miss 39% save 21% goal 12%)。

> **高さを線形にすると、自陣寄りからの苦し紛れが半分を占めた**(実際にそうなった)。
> DFの30m弾がシュートの主役になり、決定率が崩れる。累乗にして撃てる選手の重みを
> 掛けることで、遠距離シュートは3%に収まった。`careertest` が1割未満を検査する。

#### シュートは4つに枝分かれする(D29)

**GKに全部が来るわけではない。** 守備者が身体を入れ、技術が足りなければ枠を外れ、
止められてもこぼれれば詰められる。

```
 シュート
   ├ ① ブロック    打点に近い守備者が身体を入れる。GKに届かない
   ├ ② 枠外        技術と距離で決まる。**GKは関与しない**
   └ ③ 枠内 → GK
        ├ ゴール
        └ セーブ → ④ こぼれ球(30%) → 詰め合い → 勝てばゴール前から撃ち直し(1回だけ)
```

| 判定 | 攻撃側 | 守備側 |
|---|---|---|
| **ブロック** | `tec×0.5 + atk×0.5` | `def×0.6 + pow×0.4`(打点に近い守備者) |
| **枠内/枠外** | `(accBase + tec/20×accTec) × near^accRange` | — |
| **GK** | `(atk×0.7 + pow×0.3) × near^rangePow` | `def×0.65 + pow×0.20 + tec×0.15` |
| **こぼれ球の詰め** | `spd×0.5 + atk×0.5` | `def×0.5 + spd×0.5` |

```js
near = clamp((h - deadZone)/(1 - deadZone), minRange, 1)   // h=1 がゴール前
```

- **距離はブロック以外の全部に効く。** 遠いほど枠を外し、GKにも勝てない。
  これが無いと**遠目の苦し紛れが決定機と同じ確率で入る**
- **GKは `def` だけで守らない。** `def` は上限20に張り付きやすく(96人中52人)、
  それだけだと守備側がほぼ定数になってGKの質が結果に出ない。
  反応(`pow`)とポジショニング(`tec`)を混ぜたことで、セーブ値が **12.0〜19.6** に散った
- **こぼれ球の詰め直しは回数を決め打ちしない。** 「こぼれる(30%) × 詰め合いに勝つ(約43%)」で
  1回あたり約13%なので、**幾何級数的に収束する**。実測の深さは 0回目96.5% / 1回目3.4% /
  2回目0.1% / 3回目0.0%。`reboundMax` は暴走を防ぐ安全網でしかない

実測(1試合の試投21本の内訳):

| | 実測 | 現実の水準 |
|---|---|---|
| ブロック | **26%** | 約30% |
| 枠外 | **33%** | 約30% |
| セーブ | **27%** | 約28% |
| ゴール | **13%** | 約11% |
| 枠内シュート | **8.4本** | 約9本 |
| こぼれ球 | 1.7回/試合(43%が拾える) | — |

#### マッチアップの勝敗が勢いを動かす

連鎖の1ステップごとに `duelWon` / `duelLost` でモメンタムが動く。
**これが勢いの主な動力**になり、§7.7 の「勝ち続けると押し込める」が実際に成立する。

#### 実測(この段のあと)

| | 実測 | 現実の水準 |
|---|---|---|
| 1試合の平均得点 | **2.70点** | 約2.7点 |
| 引き分け | **25.0%** | 約25% |
| 1チームのシュート試投 | **約10.5本** | 約12本 |
| 決定率(試投あたり) | **約13%** | 約11% |
| 1攻撃の平均手数 | **2.11手** | — |
| マッチアップ勝率 | 約82% | — |
| シュートに至った手数 | 1手36% / 2手34% / 3手20% / 4手7% / 5手3% | — |
| 遠距離(h<0.6)シュート | **3%** | — |

守備の効き(失点):

| | |
|---|---|
| フィールドの `def` | +6 で **0.86** / −6 で **2.39**(2.8倍) |
| GKの `def` | +4 で **1.47** / −4 で **2.58**(1.8倍) |

**連鎖で1攻撃あたり2回以上のマッチアップが起きるので、守備能力が積算で効く。**

### 7.10 スタミナ(D30 — 決定 2026-08-02)

**全員が時間とともに減り、動いた選手はさらに減る。**
減ったぶんは `eff` に掛かるので、**攻守どちらのスコアにも同じように効く。GKも例外ではない。**

```js
消耗 = (出場時間 × perMin + 関与回数 × perAct) × staMul
staMul = 1 − (sta−1)/19 × staReduce        // sta が高いほど緩やか
stamina = clamp(1 − 消耗, minStam, 1)       // 下限 30%
```

- スタミナは**ティックの頭で確定**し、そのティックの間は動かさない
- `eff(p,k) = 素の能力 × 枠適性 × スタミナ`。**修正はすべて `eff` に集約する**(→§7.3)

実測(90分終了時 / 同一編成どうし300試合):

| | |
|---|---|
| 最も消耗した選手 | **30%**(下限) |
| 中央値 | **58%** |
| 最も余力のある選手 | 74% |
| 関与12回以上の選手 | 平均 **50%** |
| 関与3回以下の選手 | 平均 **69%** |

#### 守備ラインの綻び

個々のスタミナとは別に、**DFラインの平均消耗ぶんだけ守備スコアを薄く減じる**
(card-eleven から踏襲)。不感帯(`lineFree`)を超えた消耗だけが響く。

> **これが無いと得点が前半に偏る。** 疲労は「枠に飛ぶか」(絶対値の判定)を
> 一方的に下げるだけで、競り合いは両側に等しく掛かって相殺されるため。
> 実測で前半61% 対 後半39%になった。ラインの綻びを入れて **54% 対 46%** に戻した。

#### 交代がキーアクションになる

消耗した選手を**万全の控え**と入れ替えると、実際に勝率が上がる。

| | 勝率 | 得点 | 失点 |
|---|---|---|---|
| 交代なし | 40.3% | 1.47 | 1.34 |
| **60分に3枚交代** | **47.4%** | 1.69 | 1.18 |

> **控えはポジションを揃えて選ぶ**(→[03. §3.17](03-game-design.md))。
> 素のOVR順だけで取るとGKもDFも居ない控えができ、投入した選手が枠適性0.50になって
> **交代が損になる**(実測で勝率 −0.8pt)。`benchOrder` が GK/DF/MF/FW を1枚ずつ
> 確保してから OVR 順に埋める。

### 7.11 セットプレー(D32 — 決定 2026-08-03)

**ファウルは独立に抽選しない。** 「守備側が競り合いに勝った瞬間」だけが入口で、
そこから位置に応じて重さが決まる。独立抽選にすると「何も起きていないのにPK」が出て、
それは見せかけのロジックそのものになる(→§7.1)。

```
連鎖のマッチアップで守備側が勝つ ──┬─ h≧fkH  → FK(蹴る)
   (foulDuel = 32%)                └─ h<fkH  → 反則のみ(蹴らない。カードは引く)

シュートをブロックした ────────────┬─ h≧boxH → PK
   (foulBlock = 5.5%)              ├─ h≧fkH  → FK
                                   └─ コーナー(ckOnBlock = 34%)
GKがセーブした ──────────────────── コーナー(ckOnSave = 28%)
```

> **PKになるのはシュートを止めに行った反則だけ。** 陣形の最前列は h≒1.0 に立つので、
> 連鎖のファウルまでPKにすると「FW起点で潰された = 必ずPK」になる(実際にそうなり、
> PKが1試合0.7本出た)。止めに行った身体の入れ方だけがエリア内の反則になる。

#### 蹴りかた

| | 蹴る人 | 決着 |
|---|---|---|
| PK | atk×1.2 + tec の最良 | **壁もブロックも無い**。枠内 86% → GK と勝負(威力 ×1.62) |
| FK(直接) | tec×1.2 + atk×0.8 | h≧0.62 のとき 55%。壁がブロックに入る。tec で枠内、威力 ×1.15 |
| FK(クロス) | 同上 | 空中戦へ |
| CK | pow + atk×0.6 | 空中戦へ |

**空中戦は pow が主役**(pow 0.65 + atk/def 0.35)。足元の巧い選手ではなく
高さのある選手が主役になる。勝てばヘディングシュート(枠内 50%)。

セットプレーはすべて**通常のシュートと同じ経路**(ブロック→枠外→GK→こぼれ球)に合流する。
別経路にすると funnel が二重管理になり、片方だけ壊れる。

1回の攻撃で重ねられるセットプレーは `maxSp = 2` まで。CK→ブロック→CK の無限ループを止める。

#### キッカーの指名

`S.kickers = {pk,fk,ck}` にカードIDを持つ。**指名が最優先で、居なければ能力で自動選出**。
交代や退場で盤面から消えた選手は自動選出に戻る。CPU側は常に自動。
抽選ではないので、同じ場面なら必ず同じ選手が蹴る。

#### カードと退場

ファウルのたびにカードを引く。**蹴らない位置のファウルでも引く**ので、
軽い反則の積み重ねが退場につながる。

| | 警告 | 一発レッド |
|---|---|---|
| エリア内(PK) | 62% | 3.0% |
| それ以外 | 55% | 0.8% |

2枚目の警告か一発レッドで**退場**し、そのまま人数が減ったまま試合が続く。
盤面からも消え、`midPower` も守備も薄くなるので、**残り時間の戦力が実際に落ちる**。

- **GKは退場させない**。代役を立てる仕組みが無く、盤面が壊れるため。
- 8人を下回る退場は起こさない(`minPlayers`)。

#### 実測(4リーグ総当たり 224試合)

| | |
|---|---|
| 平均得点 / 引き分け | 2.85点 / 26.2% |
| FK / PK / CK | 2.50 / 0.24 / 4.26 本(1試合) |
| 警告 / 退場 | 1.54枚 / 0.13人(1試合) |
| セットプレーからの得点 | 全得点の 16%(PK 0.13 / FK 0.18 / ヘディング 0.14 本) |

> セットプレーを入れると試投が 24 → 27 本に増える。決定率をそのままにすると
> 平均4.1点まで跳ねたので、`th.shot` 0.86→**0.96** / `th.aerial` **1.15** で戻した。
