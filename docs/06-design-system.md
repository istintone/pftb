## 6. デザインシステム

**正本は [`src/assets/design/P-footBall.html`](../src/assets/design/P-footBall.html)**(Claude Design 製のモックアップ)。
実装(`src/css`・`src/js`)はこのモックを写す形で作り、**見た目の判断に迷ったらモックを開いて確認する**。
このドキュメントはモックから抽出した「使う値と決まりごと」の要約であり、モックが更新されたら追従して書き直す。

> モックはブラウザで直接開ける(React+バンドル済みの単体HTML)。**実行時アセットではない**ため
> `build.py` は取り込まない(画像以外は走査対象外なので `index.html` は肥大化しない)。

### 6.1 コンセプト

暗色の落ち着いた盤面に、**ゴールドのアクセント**を1色だけ効かせる。
情報は細いモノスペースのラベルで整理し、数値は縦長のコンデンス体で見せる。
ピクセルの選手だけが色を持って動く、という対比を作る。

### 6.2 カラートークン

色は `oklch` で指定する(モックと同じ表色系を保つ)。

| `--line` | `oklch(0.28 0.02 255)` | 罫線・枠 |
| `--accent` | `oklch(0.78 0.14 85)` | **ゴールド**。強調・選択中・重要数値 |
| `--accent-dim` | `oklch(0.55 0.10 85)` | ゴールドの枠線・控えめな強調 |
| `--text` | `oklch(0.94 0.01 90)` | 主テキスト |
| `--text-2` | `oklch(0.85 0.01 90)` | 副テキスト |

**レアリティ色**(カード枠・ラベル):

| キー | ラベル | 識別色 | カードの地 |
|---|---|---|---|
| `STD` | STANDARD | `oklch(0.62 0.01 90)` 灰白 | **白** |
| `REG` | REGULAR | `oklch(0.80 0.01 255)` 銀 | **黒** |
| `SPE` | SPECIALS | `oklch(0.66 0.15 285)` 青紫 | **黒のホロ** |

識別色は UI 上の枠と発光に使う色で、カードの地そのものではない。

### 6.3 タイポグラフィ

| 用途 | フォント | 例 |
|---|---|---|
| 見出し・数値・ボタン | **Oswald**(コンデンス) | スコア・OVR・`TAP TO START` |
| ラベル・データ・注記 | **JetBrains Mono** | `SEASON 12 · MATCHDAY 05`・順位表の見出し |
| 本文・日本語 | **Inter** → 日本語はシステムフォント | 実況・説明文 |

- サイズは **7〜14px を主体**とした密なスケール(最頻値は 10・11・12px)。見出しのみ 16〜40px。
- 英字ラベルは **`letter-spacing: 1〜2px` + 大文字**。日本語には字間を入れない。
- **オフライン対応**: Oswald / JetBrains Mono は **latin サブセットの woff2 を base64 で埋め込む**
  (英数字ラベル専用なので数十KBで足りる)。日本語はシステムフォントに任せ、外部リクエストは発生させない
  (→[01. アーキテクチャ](01-architecture.md) の「外部フォントを読まない」を、この形で満たす)。

### 6.4 レイアウトと形

- **端末枠**: 幅 `402px` / 最小高 `874px`(スマホ縦持ち)。PC で開いたときは中央に枠として表示する。
- **角丸**: パネル `8〜12px` / タグ・バッジ `3〜4px` / ピル・端末枠 `24〜28px` / アバター `50%`。
- **区切り**: 1px の `--line`。影は基本使わず、面の明度差で階層を出す。
- **タブバー**: 下部固定・5タブ。アイコン(記号文字)＋ Oswald 9px の英字ラベル。選択中はゴールド。

### 6.6 モックが示すデータ(実装の出発点)

モックには仮データが入っており、**ゲームの語彙と粒度**がここから読み取れる。

- **選手**: `name` / `pos`(GK・DF・MF・FW) / `favPos`(CB, SB, DMF, OMF, WG, CF …の細分) /
  `rarity` / `ovr` / `age` / `nation` / `skills[]` / `combo`(コンビネーション = 所属クラブ)
- **能力値**: モックは `OVR` + ATK/DEF/SPD/TEC の4種だったが、**D17 で6種(各20上限・OVR=合計)に変更**した(→[03. §3.12](03-game-design.md))
- **架空の国**: ノルディア / イベリア / エストラ / アビシナ / ガリア → **D21 で実在6リーグ + 実在16国籍に置き換えた**(→[03. §3.8 / §3.15](03-game-design.md))
- **架空クラブ**: ノルフィエルFC / カサブランカ・ユニオン / … → **D21 で「元ネタが分かる程度に改変した実在クラブ名」に置き換えた**
  (マンチェスター・レッズ / マドリード・ブランコス など)
- **大会**: PREMIER LEAGUE(リーグ) / CHAMPIONS CUP(ノックアウト)
- **通貨**: コイン(例 12,400)と**ガチャチケット**の2種
- **契約**: 「1シーズン(更新可)」・`SEASON 12` 表記

#### 突き合わせの結果(D10 — 決定 2026-07-31)

モックの表現と D1〜D8 の機構決定が食い違っていた箇所の決着。

| # | 論点 | 決定 |
|---|---|---|
| 1 | 通貨 | **コイン1本 + チケット(報酬券)**。パックも施設もコインを奪い合う。チケットは依頼達成・タイトル・実績の報酬としてのみ手に入る(→[03. §3.5](03-game-design.md)) |
| 2 | 契約期間 | **1シーズン(更新可)** — モックの契約書通り。施設投資の緊張がむしろ鋭くなる(→[03. §3.3](03-game-design.md)) |
| 3 | EXP | **契約中のクラブのチーム熟練度**。上がるほど選べる戦術が増え、退任すると 0 に戻る。采配スキル(監督の恒久資産)とは別物(→[03. §3.7](03-game-design.md)) |
| 4 | 名声・期待順位・スポンサー依頼のUI | **意味の合う画面へ分散**する(→§6.7) |

### 6.7 モックに無い要素の配置(D12 — 決定 2026-07-31)

新規画面は増やさず、**既存画面の役割に沿って**置く。

| 要素 | 置き場所 | 理由 |
|---|---|---|
| **名声** | クラブハウス(`⛨ CLUB`)の監督プロフィール、トロフィーの隣 | 名声もトロフィーも**監督個人の恒久資産**。同じ場所にあるのが自然 |
| **目標順位 / オーナーの評価** | シーズン画面(`☰ SCHEDULE`)の任期スケジュール | 既に「リーグ2位・勝点16」など**今季の成績**を出している画面。期待と実績を並べて見せられる |
| **スポンサー依頼** | 秘書画面 + ホームの秘書連絡欄から導線 | 依頼は**外から持ち込まれる話**であり、秘書が取り次ぐ形が筋に合う。モックの連絡欄がそのまま使える |
| **チーム熟練度(EXP)** | デッキ(`◆ DECK`)の戦術選択の近く | 熟練度が決めるのは**選べる戦術の幅**。ロックされた戦術と一緒に見せると意味が伝わる |
| **采配スキル** | デッキの監督欄 + 試合画面の采配ボタン | 監督が持つ切り札。編成時に確認し、試合中に切る |
| **イベント(D11)** | ホームの CLUB NEWS 欄 / 秘書画面 | 節の合間に差し込む読み物。既存の器をそのまま使う |

> **原則**: タブは5つのまま増やさない。新しい情報は「その情報が誰のものか」で置き場所を決める
> (監督のもの → CLUB / クラブの今季 → SCHEDULE / 外からの話 → 秘書)。

### 6.8 HOME = 監督のデバイス(ゲーム体験のハブ)

HOME は単なるトップ画面ではなく、**監督自身が持っているデバイス**という設定の画面。
自分のスケジュール・クラブ関係者からの通知・キャリアにまつわる情報がここに集まり、
**ゲーム体験全体のハブ**として機能する。

```
 ┌ HOME(監督のデバイス) ────────────┐
 │  SEASON 12 · MATCHDAY 05          │
 │  次の一戦 vs SOLVIK UNITED — HOME  │
 │                                    │
 │  ┌ SEC 秘書 ──────────────┐  │
 │  │ ナラティブな誘導 / お知らせ  │  │ ← 次に何をすべきか
 │  └──────────────────────┘  │
 │                                    │
 │  ┌ CLUB NEWS ──────────────┐ │
 │  │ クラブにまつわる出来事        │ │ ← 今のクラブの状態
 │  └──────────────────────┘ │
 └────────────────────────────────┘
```

#### 2つの通知チャンネルを使い分ける

| | **CLUB NEWS** | **秘書(SEC)** |
|---|---|---|
| 扱うもの | **クラブにまつわる出来事** | **プレイヤーへの誘導・お知らせ** |
| 性格 | 今のクラブの**一時的なコンディション表示**でもある | ナラティブな案内 + ゲーム側(メタ)の通知 |
| 例 | クラブの目標 / ライバルとの対戦 / サポーターからの相談 / けが人情報 / 施設の増築・カスタムのお知らせ | 「次はこれをするとよい」という誘導 / 新しいスカウトが登場した等の**ゲーム機能の追加告知** |
| 寿命 | 状況が変われば消える(状態の写し) | 読んだら流れる(導線) |

- **CLUB NEWS は「クラブの今」を読む欄**。順位表や名簿を開かなくても、
  ここを見ればクラブの状態(誰が怪我している・サポーターが何を気にしている・施設がどうなった)が分かる。
- **秘書は「プレイヤーの手を引く欄」**。ゲームに不慣れな段階では次の一手を示し、
  慣れた後は新機能や新要素の登場を伝える窓口になる。**リアルとメタの両方を1人が担う**。
- イベント(→[03. §3.7](03-game-design.md) の `EVENTS`)はこの2つの欄に差し込まれる。
  クラブ発の出来事は CLUB NEWS、監督個人・ゲーム進行に関わるものは秘書から出す。


#### NEXT MATCH のタイル(2026-08-04)

**ボタンを置かず、タイルごとタップ**して日程へ送る。
「試合を進める」ボタンは、HOME が進行の操作盤に見えてしまう
——HOME は監督のデバイスであって、試合はスケジュールから始める。

```
 ┌──────────────────────────┐
 │ SEASON 1 · MATCHDAY 01    │ ← 節はタイルの中に入れる
 │ [開幕]                    │ ← 局面の名前
 │ ここから始まる。            │
 │ 長い航海の第一歩。          │ ← 煽り(2行まで)
 │   自クラブ  VS  相手クラブ  │ ← VSが中心。左右で釣り合う
 │ HOME ／ 第1節              │
 │            > See Schedule │ ← 行き先は右下に文字だけ
 └──────────────────────────┘
```

- **VS を中心に固定する**。`flex` で並べるとクラブ名の長さで中心がずれて落ち着かない。
  `grid-template-columns:1fr auto 1fr` にして、左は右寄せ・右は左寄せにする
  (`drive.js` が中心のズレ2px以内を検査する)
- 煽りは**状況から選ぶ**(→データは `HYPE`、判定は `hypeOf`)。
  開幕 / 最終節 / 残留争い / 首位攻防 / 格上挑戦 / 格下相手 / 実力伯仲 / 終盤戦 / 汎用。
  順位が当てになるのは4節目から。それまでは**クラブの格**で見る
- **同じ節なら毎回同じ文**にする。描画のたびに入れ替わると読み物ではなく雑音になる
- 局面の名前(`[開幕]`)を添えると、**なぜこの煽りなのか**が伝わる

#### タイルが押せるなら、中にボタンを置かない(2026-08-05)

タイル全体がリンクなのに中に塗りボタンを置くと、**押す面が二重**になって
「ボタンだけが押せる」ように見える。塗りは剥がし、**行き先を右下に文字だけ**添える。

| 画面 | 押す面 | 添える文字 |
|---|---|---|
| HOME の NEXT MATCH | タイル全体 → SEASON | `> See Schedule` |
| SEASON の現在節 | タイル全体 → クラブチャット | `第XX節を開始する` |

- 文字は**アクセント色・右寄せ**。塗らないので、タイル自体の金枠が主役のまま残る
- 同じ理由で、**節のタイルには操作を持たせない**(→docs/03 §3.29)。
  決めごとは開いた先の画面が持つ

> 煽りの候補は**1行を1要素にした配列**で持つ。文字列の中に改行を書くと、
> 生成の過程でソースが壊れることがある(実際に壊れた)。

### 6.9 タイトルの2状態

| 状態 | 見せ方 | 理由 |
|---|---|---|
| **セーブ無し** | `TAP TO START` のピル。**画面のどこを押しても開始** | 初回は迷わせない。選択肢を出す意味がない |
| **セーブ有り** | `RETURN TO CAREER`(ゴールド塗り) / `NEW CAREER`(輪郭のみ)の2択 | 続きがあるなら「再開」が第一選択。塗りと輪郭で主従を付ける |

- **セーブがある間は全画面タップを無効にする**。誤タップで新規開始に落ちるとキャリアが消えるため。
- `NEW CAREER` は上書き確認を挟む。

### 6.10 就任契約書 — ここだけ明色にする

暗色で統一されたアプリの中で、**契約画面だけクリーム地に黒文字の「紙の書類」**にする。
就任という行為を他のどの操作とも違うものとして見せるための意図的な反転
(デザインモックの構成に準拠)。

| 要素 | 仕様 |
|---|---|
| 紙 | `oklch(0.93 0.012 85)` / 角丸 3px / 影 `0 20px 50px rgba(0,0,0,.5)` |
| 上端の帯 | 高さ 5px の `oklch(0.55 0.10 85)`(金) |
| 見出し | 協会名(mono 8px・字間3px)→ `監 督 就 任 契 約 書`(Oswald 20px・字間2px)→ 契約名+シーズン。下は**二重罫** |
| 本文 | 11px / 行間 2.0 の委任文。読ませるためのものではなく「書類らしさ」の担保 |
| 記入欄 | **枠を持たず下線のみ**(`border-bottom` 1.5px)。背景も透明にして「書き込む欄」に見せる |
| 契約条件 | 2列グリッド。上下を金の細罫で挟む |
| 署名 | 記入した氏名を**その場で署名欄へ反映**する。右に朱色(`oklch(0.55 0.16 25)`)の丸い認証印 |
| ボタン | 暗色 `oklch(0.22 0.03 255)` / 角丸 4px。紙の上で唯一の暗い面にする |

> **背景も暗いまま敷く**: 紙より下の余白が本文領域の地色に戻ると2つの暗色が並んで見えるため、
> 契約画面には `min-height:100%` を与えて画面いっぱいに暗色を敷く。

### 6.11 進行の導線 — スケジュールが起点

**クラブの進行はすべて「任期スケジュール(SEASON)」から始まる**。
card-eleven のキャリア画面にあたる位置づけで、就任から任期満了までをここで一望する。

```
 HOME(監督のデバイス)
   └ 次戦の告知 →「試合を進める」
        ↓
 SEASON(任期スケジュール) ← タブ ☰ SCHEDULE の着地点
   ├ 契約(クラブ・目標順位・オーナーの評価・熟練度)
   ├ エントリー中の大会  ─┬─ LEAGUE ─┐
   │                      └─ CUP    ─┤
   └ CAREER(任期の推移)                │
                                       ↓
 FIXTURES(大会の日程表・参照用) ── リーグ戦 / カップ戦の切替
   ├ 全14節(節・クラブ色・相手・HOME/AWAY)
   │    済 → スコア ／ 次戦 → 「次戦」 ／ 先 → vs
   └ STANDINGS 要約 →「詳細を見る ›」→ 順位表
        ↓
     試合 → 結果
```

- **HOME からは試合に直接入らない**。HOME は「監督のデバイス」(→§6.8)であって進行の操作盤ではないので、
  次戦の告知はするが、実際に始めるのは SEASON の任期カレンダーに置く。
- **試合を始める場所は1つだけ**。打ち手を選んでから試合に入る流れ(→[03. §3.2.3](03-game-design.md))なので、
  打ち手の無い日程表から試合に入れてしまうと入口が二重になる。FIXTURES は**参照専用**にした。
- **リーグ戦 / カップ戦は独立画面ではなく日程画面の切替**(モックの構成に合わせた)。
- 日程の1行は `節 / クラブ色の丸 / 相手名 + HOME・AWAY / 状態` の並び。
  状態は**済=スコア・次戦=`試合開始`ボタン・未来=`vs`** の3種で、次戦の行だけ枠と背景を金で強調する。
- **クラブ色**は `CLUBS` の並び順から**黄金角(137.5°)で色相を回して**割り当てる。
  ハッシュの剰余だと色相が固まって数色しか出ない。

#### 任期カレンダーは SEASON に置く(card-eleven のキャリア日程と同じ)

**監督がどんな手を打ち、どんなキャリアをクラブと描いたか** —— それがこのゲームのドラマなので、
カレンダーは大会の日程表(FIXTURES)ではなく **SEASON(任期スケジュール)の主役**として置く。
FIXTURES は「その大会がどうなっているか」を見るための参照画面に留める。

任期96節を**1本の縦列**にし、過去・現在・未来を同じ帯の上で見せる(→[03. §3.2.3](03-game-design.md))。

| 区間 | 見せ方 |
|---|---|
| **過去** | 打ち手のアイコン + 相手 + `S1 第3節 ／ HOME` + スコアと ○△●(勝=緑 / 分=灰 / 敗=赤) |
| **現在** | 行ではなく**カード**。`① 打ち手` → `② 出場する大会` の順に選び、両方そろうと `試合開始` が押せる |
| **未来(予定確定)** | カップの連戦など、先に埋まっている節。金の枠で「予定確定」と示す |
| **未来(空枠)** | `未定`。**任期の上限まで全部並べる**(下記) |

**空枠を最大任期まで並べる理由**: カップ戦の開催日程を**事前に知らせる**ため。
リーグの日程を節に敷き詰めてしまうと、後からカップが割り込む余地が見えなくなる。
枠だけ先に並べておけば、「この節にカップが入る」と分かった時点でそこに書き込める。
空枠は高さを詰めて出す(96〜120枠あるため)。

- **クラブが変わっても帯は途切れない**。任期は節で通算するので、過去行には別クラブ時代の節も並ぶ。
  シーズンとクラブが変わる位置に `SEASON n · クラブ名` の区切り行を挟み、
  そのシーズンの着地(`5位で終了（期待に対して 続投）`)も帯の中に残す。
- 96節あるので、画面を開いたら**現在節へ自動でスクロール**する。

### 6.12 選手カード

カードは**一覧タイル**と**詳細**で同じ言語を使う。どちらもデザインモックの構成に準拠。

#### 共通の決まり

カードは**背景画像1枚の上に、枠と文字をすべて CSS で載せる**(→§6.13)。
一覧タイルも詳細も**同じ部品**を使い、大きさだけが変わる。

| 要素 | 位置 | 内容 |
|---|---|---|
| **背景** | 全面 | レアリティごとの画像。**外周の枠と縁線も背景が持つ**(CSSでは描かない) |
| **クレスト** | 左上（盾の中） | レアリティの**2文字略称**(ST / RG / SP / WC / LE)。正式名称は盾に入らない |
| **OVR** | 右上 | 6能力の合計(最大120) |
| **能力欄** | 右・下ぞろえ | 6行(ATK/DEF/POW/TEC/SPD/STA)。**20 に達した行だけ赤** |
| **名前帯** | 下 | 名前 / プライマリのサブ(+N) · 所属クラブ |
| ★ | 名前の前 | **自分のカード**の印(貸与と見分ける → [03. §3.4](03-game-design.md) D13) |

**盾の実測位置は 横 9〜25% / 縦 2〜12%**。クレストはその上半分に収める
(座標がずれると盾からはみ出す)。

#### 文字色は3系統に分ける

| 変数 | 対象 | 決め方 |
|---|---|---|
| `--ink` | クレスト・OVR・**選手名** | レアリティの色を出す“カードの顔” |
| `--stat` | 6能力のラベルと数値 | **白か黒のみ**。地の明暗で決める |
| `--mx` | **20 に到達した能力だけ** | 赤 `oklch(0.62 0.23 27)`。全段共通 |

| 段 | 地 | `--ink` | `--stat` |
|---|---|---|---|
| STANDARD | 白 | 黒 | 黒 |
| REGULAR / SPECIALS | 黒 | 白 | 白 |
| WORLD CLASS | 銀 | **`#c71585`** | 黒 |
| LEGENDS | 黒金 | **金** | 白 |

> 能力値まで色を付けると数字が読みにくくなるため、**色を持つのは“顔”だけ**にする。
> 20 の赤は白地でも黒地でも読める明度を選んである。

**サイズは `cqw`(カード幅基準)で指定**する。`container-type: inline-size` を使うことで、
一覧(幅120px)でも詳細(幅250px)でも**同じ比率で拡大**され、書き分けが要らない。

#### 一覧タイル(CARDS)

```
 ┌──────────┐
 │RARE        84│  ← 左上:レア度 / 右上:OVR
 │ ╱╱╱╱╱╱╱╱╱╱ │  ← クラブカラーの斜めストライプ(3:4)
 │ PLAYER PHOTO │
 ├──────────┤
 │ ★ アスプルンド │  ← ★=自分のカード
 │ OMF +1  FKソルベリ│  ← プライマリのサブ(+N=他のサブ数) / 所属クラブ
 └──────────┘
```

- 3列グリッド・gap 10px。フィルタは**ピル型で横スクロール**(ALL/GK/DF/MF/FW)。
- 件数は `所持カード N / M　★ 自分のカード K 枚`。

#### 詳細(モーダル)

絵柄(4:3・OVR 40px) → 名前(Oswald 19px) → `pos · クラブ · 国` →
`年齢` / `得意ポジション` の2枠 → **ABILITY**(ATK/DEF/POW/TEC/SPD/STA の6本。バーは `値 / 20`) →
**SKILLS**(ピル) → **COMBINATION** → **PROFILE**(紹介文 + 所有か貸与か)。

- バーは**トラック + フィル**の2層(`.tr > i`)。フィルだけだと残量が見えない。
- **PROFILE は本作独自**。カードの属性から紹介文を組み立て、続けて「移籍しても連れて行ける / このクラブに残る」を明示する。
- 外側をタップしても閉じる。

### 6.13 カードは3層で組む

> **カード詳細のシートにホロは掛けない**(2026-08-05)。段の色は**縁と光だけ**で示す。
> シートごとホロにしていたら、WORLD CLASS の虹が能力バーと文字の上を流れて
> **読めなくなっていた**。ホロを持つのはカードそのもの(`.cm-card`)だけ。

カードは**背景・選手・文字の3層**を重ねて作る。**レアリティで変わるのは背景だけ**。

| 層 | 中身 | レアリティで変わるか | 実装 |
|---|---|---|---|
| ① 最前面 | 名前・OVR・能力値・ポジション等**すべての文字と数値** | **変わらない** | CSS |
| ② 中間 | **選手のイラスト**(ピクセルアート) | **変わらない** | `.pc-art > .pc-img` |
| ③ 最背面 | **カードの背景レイアウト** | **これが主役** | 画像 |

#### 重なり順は 選手 > 文字 > ホロ > 段の文字 > 背景(2026-08-03 改定)

ホロは**背景の演出であって、選手に掛けるものではない**。選手の上に虹や光沢が乗ると
絵が沈んで誰なのか分からなくなる。`z-index` は次で固定する。

| z | 中身 |
|---|---|
| 5 | ✦粒子（カード面全体に散る飾り。面の演出なので選手の上に残す） |
| **4** | **選手**（`.pc-art`）… **カードの主役なので一番上** |
| 3 | 文字（クレスト・OVR・能力欄・名前帯） |
| 2 | ホロ / キラ流光（`::after` / `::before`） |
| **1** | **段のデザイン文字**（`.pc-grade`）… 地の一部として敷く |
| 0 | 背景画像（`.pcard` の `background`） |

- 選手は**カード中央に大きく**置く(`.pc-art` は左右12% / 上12% / 下20%)。
  **主役は選手**なので、能力欄と重なったら選手が勝つ。
- 改定前は 文字 > 選手 だった。入れ替えたことで、選手と重なる位置の
  **能力欄のラベルが欠ける**(「ATK」→「TK」など)。数値は右端にあるので残る。

#### ポジションは OVR の下(2026-08-03)

```
        110      ← OVR
        CMF      ← 第一サブポジション(右端を OVR と揃える)
          +      ← 他にもサブポジがあるときだけ
```

- 2文字(`ST`)と3文字(`CMF`)が混ざるので、`min-width:3.4ch` で箱の幅を決めて右寄せする。
  そうしないとカードごとに位置がずれて、一覧で目が滑る
- **数は出さない**(`+1` ではなく `+`)。何に使えるかはカード詳細で見るもので、
  カード面は「他にもある」ことだけ伝われば足りる
- これに伴い、**名前帯からポジションを外してクラブだけ**にした。
  同じ情報を2箇所に出すと、狭いカード面では両方が読みにくくなる

能力欄は下へ寄せる(`bottom:19%`)。選手は `object-position:bottom` で足元が揃うので、
右上ほど空きやすい ——**空くのは上、混むのは下**。それでも下へ寄せるのは、
OVR とポジションの塊が右上を占めるようになったため。

#### 段のデザイン文字(`.pc-grade`)

ホロを持つ段だけ、段の名前を**左側に上から下へ流す**。特別感を作るための意匠であって、
語を読ませるものではないので、**地の一部として一番下(ホロの下)**に敷く。

> 右側は能力欄が占めているので、**左に置く**。右に置くと数値の裏に隠れて意匠にならない。
> 内側へ 9.5% 寄せる。LEGENDS のように**外枠の飾りが太い段**があるので、
> 縁ぎりぎりに置くと文字が枠に食われる(5% でもまだ掛かった)。

| 段 | 文字 |
|---|---|
| SPECIALS | `SPECIALS` |
| WORLD CLASS | `WORLDCLASS`（空白は詰める） |
| LEGENDS | `LEGENDS` |

- `writing-mode:vertical-rl` で縦に流し、字間を `.28em` 空けて**縁に沿う帯**に見せる
- 色は段の文字色(`--ink`)。不透明度 .26 — 一覧サイズでは1文字10pxしかないので、
  薄すぎると消える。**地に沈めつつ在ることは分かる**濃さに置く
- 8〜10文字が縦に収まる大きさ(10.5cqw)にする。はみ出して語が切れるとただのノイズになる
  (カードは 360:525 なので、縦に使えるのはおよそ 122cqw)
- 文字が絵に乗るので、**縁取り(`--halo`)を必ず掛ける**。地の色ではなく
  **文字色の反対**で決める(黒文字なら白、白/金文字なら黒)。
- 縁取りは**小さいぼかしを3回重ねて**実質のアウトラインにする。1発のぼかしでは
  一覧サイズ(カード幅120px)で選手の色に負けて読めない。
- **上限20は数値だけを赤にする**。ラベルまで赤くすると行全体が警告に見えて、
  「その能力が振り切っている」という意味が伝わらない。
- 能力ラベルを `opacity` で弱めない。**縁取りまで薄くなる**。色側で弱める。
- **明るい地の段(STANDARD / WORLD CLASS)だけ、弱め方を変える**
  (`--lab` 能力ラベル / `--sub` クラブ名)。
  暗い地は「文字色に地の色を混ぜる / `opacity` で薄める」で問題ないが、
  **明るい地で同じことをすると白に白を混ぜることになり消える**。
  明るい地では薄めず、値より少し明るい程度の暗色を直に指定する。

  | | 能力ラベル | クラブ名 |
  |---|---|---|
  | 暗い地(REG/SPE/LEG) | 文字色×74% + 地×26% | 文字色 + `opacity:.6` |
  | STANDARD | `oklch(0.38 …)` | `oklch(0.40 …)` |
  | WORLD CLASS | `oklch(0.38 …)` | `oklch(0.34 …)` |

  > WORLD CLASS はクラブ名まで**マゼンタ**(段の色)にしていたが、
  > 虹のホロに沈んで読めなかった。名前だけ段の色にして、クラブ名は黒に寄せる。
  >
  > **暗い地の見え方には触らない。** 一度まとめて `--sub` に置き換えたところ、
  > 暗い地のクラブ名が沈んで読みにくくなった。段ごとの上書きに留める。
- 能力欄は**ラベルと数値を同じ大きさにして右端へ寄せる**(`justify-content:flex-end`)。
  `space-between` で左右に離すと**間に選手が覗いて、ラベルと数値が別々のものに見える**。
  数値は mono の桁幅(`min-width:2.2ch`)で揃えるので、1桁でも右端がずれない。

#### 背景画像は4枚(5段ぶん)

| 画像 | 使う段 | 地 |
|---|---|---|
| `card-bg-std` | STANDARD | 白 |
| `card-bg-reg` | REGULAR ／ **SPECIALS** | 黒 |
| `card-bg-wc` | WORLD CLASS | 銀(クローム) |
| `card-bg-leg` | LEGENDS | 黒金 |

**SPECIALS は REGULAR と同じ背景**を使い、差は CSS の光沢で付ける。
対応は `RARITY[段].bg` が持つ。置き場所は `src/assets/carddesign/`(WebP・4枚で計21KB)。

- 背景画像には**文字も数字も描かない**。**外周の枠と縁線は背景が持つ**(CSSでは描かない)。
- **ホロは画像に焼き込まない**。焼き込むと角度と解像度が固定されて質が落ちる。

#### ホロは CSS で3層に重ねる

card-eleven の演出に倣い、「ホロ + キラ流光 + ✦粒子」で輝かせる。

| 層 | 動き | 周期 |
|---|---|---|
| **ホロ**(`::after`) | 地の色が揺らぐ | SPE 4.5s / WC 5.5s / LEG 7s |
| **キラ流光**(`::before`) | 細く鋭い光が**速く走り抜ける** | SPE 5.5s / WC 4.2s / LEG 6.5s |
| **✦粒子** | 明滅(回転しながら弾ける) | 3.4s・遅延をずらす。SPE 2つ / WC・LEG 3つ |

`RARITY[段].holo` が `sheen`(白い光沢) / `rainbow`(虹) / `gold`(金) / `null` を持ち、
UI は `holo-<種類>` クラスを付けるだけでよい。`prefers-reduced-motion` で全て停止する。

#### ②の層(選手のイラスト)

`playerArt(c)` が `c.art` から `ASSETS.players[<art>_play]` を引き、あれば `<img class="pc-img">`、
無ければ `PLAYER` のプレースホルダを返す。**絵が無くてもカードは成立する**ので、
イラストは1人ずつ後から足していける。

- 使うのは3枚セットのうち**②プレイ絵**(①立ち絵は会話、③ゴールモーションは得点演出用)
- `image-rendering:pixelated` **必須**。付けないと拡大時に補間されてピクセルアートが濁る
- `object-fit:contain` + `object-position:bottom` で**足元を枠の下端に揃える**
  (絵ごとに背丈が変わって見えないようにするため)
- `isolation:isolate` を付けて、ホロの `mix-blend-mode` が選手に掛からないようにする

#### 参照用の画像は埋め込まない

`build.py` の `ASSET_SKIP = {"design", "fonts"}` で `src/assets/design/` を除外している。
除外しないとデザインモック(2MB)まで `index.html` に入り、**5MB まで肥大化する**(実際に起きた)。

### 6.14 カード見本(GALLERY)

WORLD CLASS と LEGENDS は実在選手の段でパックからは出ないため、
**通常のプレーでは見る手段が無い**。CLUB から開ける見本画面で全段を並べる。

- 固定シードで生成するので**毎回同じ見本**が出る(見比べに使える)
- **実在選手カードが定義済みの段は、見本ではなく本物を並べる**(WC はロナウドのカードそのもの)
- 見本は所持カードではないので、`openCard()` は**IDでもカードそのものでも開ける**
- 下にレアリティ一覧(略称バッジ・役割・排出率)を添える



### 6.15 DECK(編成)

上から **監督バー → ピッチ → BENCH → 操作 → CAPTAIN → SET PIECES**。

> **控えはピッチのすぐ下**(2026-08-05)。モックでは操作の下だったが、
> 先発11と控え5は**ひとつのチーム**なので、離すと全体を掴めない。
> 5枠は `grid-template-columns:repeat(5,1fr)` で**画面幅に収める**
> (横スクロールだと5人目が切れて、そこに誰が居るのか分からなくなる)。

```
 ┌ MGR  監督 C. モレッティ          61 │ ← 監督・陣形・総合力(Oswald 20px 金)
 │      陣形: 4-4-2                    │
 ├────────────────────────────────┤
 │ AWAY                                │
 │        ▲CF      ▲ST                │ ← 立ち絵 / 下に名前 / 上に枠のポジション
 │   ▲LMF   ▲CMF ▲CMF   ▲RMF        │
 │   ▲LSB   ▲CB   ▲CB   ▲RSB        │
 │              ▲GK                    │
 │ HOME                                │ ← 自陣は金。向きが一目で分かる
 └────────────────────────────────┘
```

#### ピッチは `aspect-ratio` で形を決める

**高さを px で固定してはいけない**。端末幅が変わると縦横比が崩れてピッチが歪む(実際に起きた)。

- `aspect-ratio:3/4` + `container-type:inline-size`
- **線の寸法はすべて `cqw`(ピッチ幅基準)**。幅が変わっても比率のまま拡縮する
- 芝は `repeating-linear-gradient(0deg, …)` の横縞(1本 10.8cqw)
- 白線は一律 `oklch(1 0 0 / .30)`、ゴールだけ `.55` の塗り
- 線の実寸(モックの 370px 幅を 100cqw として換算):
  外枠の余白 2.7 / センターサークル 29.7 / センタースポット 1.6 /
  ペナルティエリア 40.5 × 17.8 / ゴールエリア 20.0 × 7.6 / ゴール 14.0 × 1.35

線はすべて装飾なので `index.html` に静的に置き、**JSが描くのは選手だけ**(`#deckSlots`)。

#### 選手の見せ方

| 部位 | 中身 |
|---|---|
| 立ち絵(46px枠) | **プレー絵**。足元にクラブカラーの影を敷き、ピッチ上(→§6.17)と揃える |
| 絵の右肩 | **適性を掛けた実効値**(`OVR × slotFit`)を黒地に重ねる |
| 絵の足元 | 名前(黒帯の小さいピル)、その下に**覚醒の★**(→[03. §3.30](03-game-design.md)) |
| 絵の上 | **枠のポジション**(`LSB`/`CMF` など) |

> **丸ではなく立ち絵にする(2026-08-05)。** 誰がどこに居るかを顔で掴めるようにした。
> あわせて**貸与の `C` は編成では出さない**(誰の持ち物かは編成の判断材料ではない)。
> **控え・キャプテン・セットプレー担当も同じ立ち絵**に揃えてある。

#### 「1人を指名する枠」は同じタイル(2026-08-05)

キャプテンもセットプレー担当(PK/FK/CK)も、やることは**誰に任せるか**で同じ。
形が違うと別の機能に見えるので、同じ横長タイル(`.ptile`)に揃えて縦に積む。

```
 ┌────────────────────────────┐
 │ ▲[CAP]  S. シケイラ            › │ ← 立ち絵 + 役割の金ピル
 │         指名  スタミナの減りが…   │
 └────────────────────────────┘
 ┌────────────────────────────┐
 │ ▲[PK]   O. オリヴェイラ         › │
 │         自動  ペナルティキック    │
 └────────────────────────────┘
```

- 役割は**金のピル**で立ち絵の足元に置く(CAP / PK / FK / CK)
- 2行目は「指名 / 自動」+ **何をする枠か**。3枠を横に並べていたときは
  略称だけで、PK が何を指すのか読み取れなかった
- `›` を右端に置いて、タップで選び直せることを示す

> **数値も名前も行として積まない。** 陣形の座標は選手の背丈を前提に決めてあるので、
> 枠が縦に伸びると枠同士が重なる(46px枠で行を積んだら16陣形中50か所で重なった)。
> **実効値は右肩、名前と★は足元に重ねる**ことで、枠の高さを
> 「ポジション名 + 立ち絵」だけに抑えている。
>
> - 実効値を足元に置くと**名前とぶつかる**(長い名前で数字が隠れた)ので右肩へ
> - 枠のポジション名は `z-index` で絵より手前に置く(頭が枠から出るため)
> - 大きさは**控えと揃える**。同じチームなのに先発だけ小さいと、盤面とベンチが
>   別の画面のように見える

> **枠のポジションはモックに無い**が、空き枠に誰を入れるべきか分からなくなるため足した。
> ピッチの白線と同じ `oklch(1 0 0 / .55)` にして、盤面の一部として読めるようにしている。

#### 枠適性はポジション名の濃さで見せる

**数値(100% / 85% / 70%)はピッチ上に出さない**。11枠ぶんの数字が並ぶと盤面が読めなくなるため、
[03. §3.14](03-game-design.md) の3段を**ポジション名の濃さ**に写す。合っているほど前に出る。

| 段 | ポジション名 | **実効値の数字** |
|---|---|---|
| サブ一致(1.00) | `.fit-a` 白96% + 太字。**この枠だけがはっきり読める** | 素のまま(白) |
| メインのみ(0.75) | `.fit-b` 白52% | **黄** `--fit-warn` |
| 不一致(0.50) | `.fit-c` 白30%。沈んで「機能していない」と見える | **赤** `--fit-bad` |

**濃淡と色の2重で示す。** 濃淡だけだと「薄い＝どのくらい損か」が読めない。
数字に色を付けることで、**数字そのものが目減りを語る**ようになる。

- **空き枠は段を付けない**(白55%のまま)。適性の話ではなく「何を入れるか」の表示だから。
- 濃淡だけでは意味が伝わらないので、**ピッチの直下に凡例**を置く。
  凡例のチップは**ピッチと同じ地色**(`oklch(0.28 0.07 150)`)に載せ、盤面での見え方とずらさない。
- 監督バーの総合力は**配置込み**(`squadPowerAt`)。適性で目減りしている分は
  陣形の隣に `適性ロス −8` として出す。
- **丸の数字も実効値にそろえる。** 素のOVRを出すと、適性50%の選手のほうが
  数字が大きく見えて**「置き間違いのほうが強い」という逆の読み**になる(実際に起きた)。
  ピッチの丸・枠のピッカー・監督バーの総合力は**すべて同じ物差し**で並べる。
  素のOVRはピッカーの行とカード詳細で見られる。
- **ベンチだけは素のOVR**。枠に入っていないので掛ける適性が無い。

#### 枠のピッカー

枠をタップすると、その枠に入れる選手を**適性 × OVR の高い順**で並べる(=そのまま推奨順)。

| 操作 | 結果 |
|---|---|
| 行をタップ | その枠に入れる。既に他の枠にいる選手なら**その枠と入れ替える** |
| **左端の「›」** | **その選手の詳細**。入れ替えは起きない |

- 詳細は**ピッカーを閉じずに上へ重ねる**(`#cardModal` の `z-index` を 52 にしてある)。
  閉じてしまうと並びを見失い、比べながら選べない。
- 行には実効値・名前・サブポジション・**いま入っている枠**を出す。
  素のOVRと適性%は出さない(数字と色が同じことを言うので、読む要素が増えるだけ)。

#### BENCH も枠

控え5人は飾りではなく**枠**(→[03. §3.17](03-game-design.md))。先発と同じくタップで差し替えられる。

- 数字は**素のOVR**。控えは枠のポジションを持たないので適性が掛からない
- ピッカーの見出しは `控え1`〜`控え5`、並びはOVR順、**色分けもしない**
- 先発の選手を選べばその枠と入れ替わる(昇格・降格が同じ操作で済む)

#### BENCH も枠

控え5人は飾りではなく**枠**(→[03. §3.17](03-game-design.md))。先発と同じくタップで差し替えられる。

- 数字は**素のOVR**。控えは枠のポジションを持たないので適性が掛からない
- ピッカーの見出しは `控え1`〜`控え5`、並びはOVR順、**色分けもしない**
- 先発の選手を選べばその枠と入れ替わる(昇格・降格が同じ操作で済む)

#### 枠が重ならない条件

1枠の描画は「ポジション名 + 丸 + 名前帯」で **幅 最大56px / 高さ 約60px**。
ピッチ 354×472 に対して **15.8% / 12.7%** なので、
**どの2枠も `dx ≥ 15.8` または `dy ≥ 12.7` を満たす**必要がある。

> **実測だけに頼らない。** `drive.js` は実際に描いて重なりを測るが、
> 名前の長さで結果が変わるため**短い名前の回だけ通る**ことがある(実際に起きた)。
> `worldtest.js` が座標の側で条件を検査し、実測はその裏取りに使う。

#### 陣形のピッカー

16種あるので巡回ボタンでは選べない。ピッカーにして、各行に
**いまの11人をその形へ並べ直したときの総合力**を出す(→[03. §3.16](03-game-design.md))。

- 陣形は好みではなく「手持ちがどの形に噛み合うか」で選ぶもの。**選ぶ前に結果が見える**必要がある
- **数字に色は付けない。** 黄と赤は「枠適性で目減りしている」印なので、
  「一番ではない」の意味に流用すると読み違える(実際に一度やって全部黄色になった)。
  最も高い形にだけ `最適` のバッジを出す

- クラブカラーは `clubColor()` が **CLUBS の並び順から黄金角(137.5°)で回して**決める。
  ハッシュの剰余だと色相が固まって数色しか出ない。
- 配置は `FORMATIONS` が持つ `%` をそのまま使う。**GK は y=87**
  (以前の 92 は高さ330px固定のピッチ向けで、3:4 にすると名前帯がゴールラインの外へ出る)。

### 6.16 HELP — 説明は枠の右端に隠す

**画面本体に説明文を置かない。**盤面には「今どうなっているか(状態)」だけを出し、
「どう読むのか・なぜそうなるのか」は**左端のタブ**に収める(card-eleven のヘルプタブに倣う)。

```
 ┌───────────────┐
 │  ヘッダー          │
 │                    │
 │                   H│ ← 枠の右端に貼り付いたタブ(縦書き)
 │   本文             E│   触ると右からドロワーが滑り出す
 │                   L│
 │                   P│
 │  タブバー          │
 └───────────────┘
```

> **左端ではなく右端**。左端は「戻る」の操作(左からのスワイプ・ヘッダー左の戻るボタン)と
> 手が当たる。実際に触って邪魔だったので移した。

| | |
|---|---|
| 中身 | `data.js` の **`HELP`**(キー = 画面ID)。`helpFor(id)` で取り出す |
| 数字 | **必ず `TUNING` から引く**。生の値を書くと、調整したときに説明だけが古くなる |
| タブを出す条件 | **`HELP` にその画面の項目があること**。無ければタブごと消える |
| 開閉 | タブで開閉 / ✕ / **外側のどこかを触る**。画面が変わったら必ず閉じる |
| 位置 | **右端**。`#app` の内側に絶対配置し、`overflow:hidden` で**枠からはみ出さない** |

#### 右端の柱 — HELP と同じ形で「参照するもの」を隠す

**画面の主役でない参照物は、本文から出して右端のタブにする。** SEASON画面は
「任期の記録」が主役で、契約の内容とエントリー中の大会は**見たいときだけ見るもの**。
本文に積むと、記録に辿り着くまでに2画面ぶんスクロールさせることになる。

```
 ┌───────────────┐
 │  ヘッダー          │
 │  [ TENURE 12/96 ] │ ← 進行バーは上に貼り付く(sticky)
 │                   契│
 │   任期の記録       約│ ← 上から 契約 / 日程 / HELP
 │                   日│
 │                   程│
 │                   H │
 │  タブバー         ELP│
 └───────────────┘
```

| | |
|---|---|
| 柱 | `#sideTabs`。**タブを1本の柱にまとめる**ので、出ているタブが1枚でも3枚でも重心が動かない |
| 並び | 上から **契約 / 日程 / HELP**。HELP は常に足元(どの画面にもあるものなので) |
| 引き出し | 契約と日程は**同じ引き出し**(`#sideDrawer`)を使い分ける。別のタブを押すと中身が入れ替わる |
| 中身 | **画面の部品をそのまま**入れる(`#seasonBox` / `#seasonComps`)。描画側は移動を知らない |
| 出る条件 | 契約・日程は **SEASON にいる間だけ**。画面が変わったら閉じる |

> **進行バーだけは本文に残して貼り付ける**(`.stick-top`)。任期のどこにいるかは、
> 記録をどこまで送っても見えていないと意味がない。スクロール容器は `#appBody` なので、
> その中の `position:sticky` がそのまま効く。

> **説明は実装より先に腐る**(2026-08-06)。仕様を作り直すたびに `HELP` が置き去りになり、
> **「★が自分のカード」(実際は逆で借りている側に印)** や
> **「WORLD CLASSはパックから出ない」(プロスカウトから出る)** のような、
> 明確な嘘が残っていた。`season` と `gacha` に至っては**同じキーを2回定義**していて、
> 先に書いたほうが丸ごと死んでいた(カップの説明がどこにも出ていなかった)。
>
> そこで drive.js が毎回検算する:
> **①全画面ぶんの組み立てが壊れていないか**(`undefined`/`NaN`/閉じていないタグ/差し込みの残り)、
> **②廃止した言葉が残っていないか**(「会長」「期待順位」「任期が削られ」など)。
> キーの重複は「1画面1エントリ」の検算で表に出る。

#### 置かない画面

**止めてはいけない画面には出さない。** 試合と開封演出は流れを切らせない画面で、
タイトルと結果には説明するものが無い。

`title` / `match` / `result` / `career` の4つ。`HELP` に項目を作らないことがそのまま設定になる。
`integration.js` が「この4つには説明が無い / 残り全部には説明がある」を検査する。

> **初期状態は `class="off"`** にしておくこと。起動直後のタイトルは `show()` を通らないため、
> 隠しておかないとタイトルにタブが出る(実際に起きた)。

#### 何をヘルプへ寄せるか

| 盤面に残す | ヘルプへ寄せる |
|---|---|
| 数・順位・状態(「貸与 6人 ／ 枠に合っていない選手 4人」) | 読み方の凡例(枠適性の3段とその意味) |
| 未実装の告知(「カップ戦は未実装です」) | 仕組みの説明(「打ち手 → 大会 → 試合の順で決めます」) |

`HELP` の項目は**文字列でも関数でもよい**。`TUNING` の値を出したいときは関数にする
(枠適性の凡例は `TUNING.fit` から作っているので、係数を変えれば説明も追従する)。


### 6.17 MATCH(試合)

デザインモックの構成に準拠。ただし**ピッチは編成画面と同じ大きさ**にする
(モックは165px幅の小さいピッチだったが、選手とボールの動きを見せる画面なので大きく取る)。

```
 ┌ スコアボード ─────────────┐
 │ ●自分    18分      ●相手  │
 │  クラブ名  1 - 0   クラブ名 │
 ├───────────────────────────┤
 │                            │
 │   ピッチ(編成画面と同じ)     │  ← .pitch をそのまま使う(線も大きさも共通)
 │   ・22人の点 + ボール        │
 │   ・カットイン(GOAL!! 等)    │
 │                            │
 ├───────────────────────────┤
 │ 実況(新しい行が上)          │
 ├───────────────────────────┤
 │ ⏸一時停止  ×1  スキップ    │
 └───────────────────────────┘
```

#### 選手は**全身**で出す(2026-08-03)

点(丸)ではなく、カードと同じピクセルアートを並べる。**使うのはプレイ絵**。
立ち絵だと棒立ちが22人並んで、試合が止まって見える。
座標は**足元**に合わせるので、前後の重なりが自然に見える。

> プレイ絵には**ボールが描き込まれている**。そのままだと本物のボールが
> どれか分からないので、実際のボールは**金色に光らせて**区別する。

**絵そのものにはクラブカラーが無い**(キットの色は絵ごとに固定)。
そこで **足元の影をチームカラー**にして、どちらのチームかを影で見分ける
(card-eleven の見せ方を踏襲)。影だけでは弱いので、輪郭にも同じ色を薄く回す。

```css
.mp img  { filter:drop-shadow(0 0 1.5px var(--kit)) ... }   /* 輪郭にチームカラー */
.mp-sh   { background:var(--kit); opacity:.75; filter:blur(1px) }  /* 足元の影 */
```

絵を持たないカードのために、丸(`.mp-dot`)も残してある。

#### 向きは**常に自分が下**(D37 — 決定 2026-08-03)

ホームを下に固定していたので、アウェイの試合だけ自分が上から下へ攻めることになり、
毎回「どちらが自分か」を読み替えることになっていた。WCCF と同じく、
**見る側の陣地を固定して、相手だけを反転させる**。

```js
mMine()      // 自分のクラブの側("H" or "A")
mFlip(side)  // その側を上下左右ひっくり返して描くか = side !== mMine()
```

`mFlip` を通すのは**座標を扱う全部**: 選手の枠(`slotXY`) / イベント位置(`toScreen`) /
自陣ゴールの側 / シュートが飛ぶゴール / 寄せる向き。

揃えるのは盤面だけではない。

- **スコアボードも左が自分**。ピッチの下が自分なのに名前がホーム基準では読み替えになる
- **実況の中のスコアも同じ並び**(`scOrder`)。スコアボードと食い違うと混乱する
- ピッチの隅の見出しは `HOME` / `AWAY` ではなく **`自陣` / `相手`**

> `integration` がホーム・アウェイ両方で「自分側は反転しない / スコアは左が自分」を検査し、
> `drive.js` が実際の盤面で「自分のGKが下・相手のGKが上」「実況とスコアボードが同じ並び」を見る。


#### 描画は再生するだけ

**エンジンが解き終えたイベントを順に見せるだけ**(→[07. §7.1](07-match-engine.md))。
描画が結果に触れることは構造的にできない。

| | |
|---|---|
| ボール | イベントの `pos` へ移動する。CSS の transition で補間するだけ。
  **シュートは打点に置いたあと実際にゴールラインまで飛ばす**(下記) |
| 選手 | 陣形を保ったままボールへ寄る(→§6.18) |
| 強調 | 関与した2人(持ち手=白い輪 / 対応する相手=赤い輪)だけ大きくする |
| カットイン | 見せ場で**中央を横切る帯**に大きく出す(→§6.19) |

> **card-eleven で選手が唐突にピッチを飛び回ったのは、描画側がその場の都合で
> 位置を動かしていたため。** ここではボールの位置はイベントが持ち、
> 選手の動きは陣形からの差分としてのみ作る(→§6.18)。

#### 向きと、縦の詰め方

両チームの陣形は同じ座標系(y 13=前 / 87=自陣)なので、**アウェイは上下左右を反転**して描く。
イベントの `pos` も攻撃側のフレームなので、`side==="A"` なら同じく反転する。

**そのうえで縦を詰める。** 陣形の 13〜87 は**ピッチいっぱいに広げた1チーム分**の立ち位置で、
編成画面(1チームだけ)ならそのままでよい。しかし試合では2チームを同じピッチに並べるため、
広げたままだと両陣形が重なり、

```
  HOME の CF   y=13
  AWAY の最終ライン  y=100-73 = 27       ← 相手DFより深い = 常時オフサイド
```

となる。**全16陣形でそうなっていた。**
`dispY()` が 13〜87 を `lineTop`(24.9)〜`lineBottom`(93) に写して、両ブロックを噛み合わせる。

| | 詰めたあと |
|---|---|
| HOMEのGK | y **93**(自陣ゴールは98%) |
| HOMEの最前線 | y **25** |
| AWAYの最終ライン | y **20** ← 最前線より手前 ✓ |
| AWAYのGK | y **7** |

**ボールも同じ写像を通す**ので、選手とボールがずれない。
`drive.js` が毎回「自軍の最前線が相手の最終ラインより手前にいる」ことを検査する。

#### 再開の局面は自陣に収める

**キックオフ / ハーフタイム / 得点直後**は、両チームとも自陣にいる。
通常の並び(`lineTop` 24.9)のままだと、開始時点で相手陣内に選手が立っていて違和感が出る。

| | 通常 | 再開時 |
|---|---|---|
| 写像の始点 | `lineTop` **24.9** | `kickTop` **53** |
| HOMEの範囲 | y 25〜93 | y **53〜93**(自陣のみ) |
| AWAYの範囲 | y 7〜75 | y **7〜47**(自陣のみ) |

再開中はボールも中央に置き、**関与している選手をボールへ寄せる処理も止める**
(隊形を崩さない)。次に位置を持つイベントが来たら通常の並びへ戻る。
`drive.js` が「どちらのチームも中央線を越えていない」ことを検査する。

> 編成画面(§6.15)はこの写像を通さない。1チームしか描かないので、
> ピッチいっぱいに広げたほうが枠の関係が読みやすい。

#### 実況

`matchLine(e, M)` が**イベントを日本語に直すだけ**。ここで結果を作ることは一切しない。
`possession` / `build` のような内部の刻みは出さない。

| 色 | 内容 |
|---|---|
| **金** | ゴール / ハーフタイム等の節目 |
| **青** | 自チームのプレー |
| **赤** | 相手のプレー |
| 無色 | キックオフ・交代などの案内 |

**チャンネル名がそのまま実況の語になる**(「カルドーゾ（CB）の持ち上がりから仕掛ける」)。
39種のチャンネルを作った時点で、実況の語彙も同時に用意できていた。

#### 再生の速さ

`TUNING.ui.tickMs`(1ティック=3分ぶんの表示時間)を速度で割る。
`speeds:[1,2,4]` を順に切り替える。**スキップは `finishMatch` を呼ぶだけ**で、
残りを一気に解いて結果へ飛ぶ。どちらでも結果は同じ(→07. §7.1)。


### 6.18 選手の動き — **演出専用の層**

点が枠に張り付いていると盤面が死んで見える。実際のサッカーの動きを真似て、
**陣形を保ったまま**ボールへ寄せる。

> **ここは見た目だけを作る層。** エンジンの判定にも `events` にも一切影響しない
> (→[07. §7.1](07-match-engine.md))。数値は `TUNING.play` にまとめてある。

```
 表示位置 = 枠(陣形の座標)
          + ブロックがボールへ寄る(縦・横。ラインごとに強さが違う)
          + 攻めている側は前へ / 守っている側は下がる
          + 攻めている側は広がる / 守っている側は圧縮する
          + ゆっくりした揺れ(全員が少しずつ違う位相)
          【上限】枠から離れられる幅を制限する
 ただし   関与している選手は**ボールまで実際に動く**
          GKはゴールラインに残り、左右にだけ追従する
```

| 決め手 | |
|---|---|
| **ラインごとの寄り方** | MF 1.00 > DF 0.85 > FW 0.55 > GK 0.15。MFが一番ボールを追い、DFはラインを保つ |
| **枠から離れる上限** | 縦13% / 横11%。**これが無いと全員がボールに吸い寄せられて団子になる**(実際にそうなった) |
| **関与者は例外** | 持ち手はボールの上、対応する相手は自陣側から寄せる。ここが「戦略的に見える」核 |
| **揺れ** | 位相を選手ごとにずらした sin/cos。完全静止させない |

> **位置を持たないイベント(`possession` など)では、直前のボール位置を保つ。**
> 中央に戻すと、攻撃の合間に全員が中央へ吸い寄せられて不自然になる(実際にそうなった)。

`drive.js` が毎回検査する: **7割以上の選手が枠から動いていること**(固まっていない)と、
**枠から22%以上離れた選手が4人以下**であること(陣形が崩壊していない)。



#### 運動量 — 年齢と残スタミナで動きが変わる(2026-08-03)

全員が同じ量だけ動くと、**盤面が一枚の板のように平行移動して見える**。
選手ごとに `vigor`(運動量)を出し、寄せ・揺れ・枠から離れられる幅の**全部に掛ける**。

```js
vigor = 年齢の係数(18歳 1.16 … 34歳 0.84) × (0.30 + 0.70 × スタミナ)
```

- 若い選手はよく走り、**終盤に消耗した選手は足が止まる**
- スタミナは試合中に減っていく(→[07. §7.10](07-match-engine.md))ので、
  **後半になるほど盤面の動きが落ちる**。試合の疲れが絵に出る
- これは**見た目だけ**の係数。判定側の疲労は `eff()` が持っていて別物

#### ボールへ詰める / 空きを狙う

| 動き | やっていること |
|---|---|
| **ボールへ詰める** | ボールに近い選手ほど強く引かれる(ガウス重み × vigor)。ブロックごと平行移動するだけだと、**誰もボールに行っていないように見える** |
| **空きを狙う** | 攻めている側の GK/DF 以外は、**一番近い相手から離れる**。マークを外す動きに見えるうえ、密集がほどけて盤面が読みやすくなる |

空きを狙うには相手の座標が要るので、**2周する**(1周目で両チームの位置を決め、2周目で離れる)。

> 枠から離れられる幅(`maxDev`)にも vigor を掛ける。よく走る選手ほど遠くまで行けるが、
> 上限そのものは残るので**陣形は消えない**。`drive.js` が
> 「22%以上離れたのが4人以内」「ボールへ詰めているのが3人以上」を検査する。

### 6.19 カットイン — 中央を横切る帯

**見せる演出なので大胆に。** card-eleven の見せ方を踏襲し、
ピッチの中央を横切る帯にプレーを大きく出す(背後は暗幕で沈める)。

```
 ─────────────────────────────
      裏抜け
   ● 82          VS          ● 72
   デ・グラーフ            アランダ
   ST ATK 19            LSB ATK 9
              突破!
 ─────────────────────────────
```

| 型 | 局面 | 見せ方 |
|---|---|---|
| **VS** | マッチアップ | 左=自チーム、右=相手。**勝者は金に光り、敗者はグレースケールで沈む**。下に決着語(突破! / STOP!) |
| **SHOT** | シュート(得点/セーブ/ブロック/枠外) | **まず「シュート!」で撃ち手と守り手を見せ、そのあとで結果を出す**(下記) |
| **PASS** | パス成功 | 左に出し手 → 右から**受け手がスライドイン**。「つながった!」 |
| **KICK OFF** | 開始 | 両クラブを向かい合わせる。**card-eleven と同じく開始から演出する** |

- **競った能力を添える**(`ST ATK 19` 対 `LSB ATK 9`)。何で勝ったのかが読める
- 顔は**イラストがあれば使い、無ければクラブカラーの丸に OVR**。
  自動生成の選手に絵が無くても成立する(→[03. D19](03-game-design.md))
#### シュートの着地点はピッチの実寸に合わせる

CSS の実測値(ピッチ 354×472 のとき):

| | 値 |
|---|---|
| ゴールライン(`.pt-frame` の内側) | y **2.0%** / 98.0% |
| ゴールの帯(`.pt-goal`) | y 1.2〜2.2% |
| ポストの内側(`.pt-goal` の幅 14cqw) | x **43〜57** |

| シュート | 着地点 |
|---|---|
| ゴール | ネットの中(y 1.6% / 98.4%、x 45〜55) |
| セーブ | GKの手元(y 4.5% / 95.5%) |
| 枠外 | ポストの外(x 38〜42 または 58〜62) |
| ブロック | 弾かれて手前へ戻る |

> **選手の枠の座標(13〜87)で扱ってはいけない。** あれは「最前線〜自陣ゴール前」の
> 選手の立ち位置であって、ゴールラインではない。混同すると
> **ボールがピッチの中で止まって見える**(実際にそうなった)。

#### シュートは2段で見せる

```
  0.0s  SHOT      撃ち手 (ATK 18 / POW 14)  VS  GK (DEF 20)   「シュート!」
  1.0s  結果      撃ち手が光り、GKが沈む → 帯が金に染まり画面が揺れる → 「GOAL!!」
                  (止めたなら GK が光り「SAVE!」)
```

> **いきなり結果を出すと、何に対する結果なのか読めない。**
> 誰が誰に対して撃ったのかを先に見せてから決着させる。
> ボールも同じ間で飛ぶので、カットインとピッチが揃う。

#### 順に見せる — 同時に動かすと読めない

```
  0.00s  帯が開く(scaleY)
  0.18s  両者が左右から入ってくる(対等に並ぶ。能力値が読める)
  0.62s  **決着** … 勝者が金に光り、敗者が沈む
  0.62s  決着語が弾んで出る
  1.7s   閉じる
```

> **最初から勝敗を見せない。** 両者が出そろってから決着させることで、
> 「誰と誰が、何を競って、どちらが勝ったか」が順に読める。
> すべて同時に動かすと**速すぎて認知が追いつかない**(実際にそうなった)。

#### 選手は丸からはみ出して全身を見せる(2026-08-03)

丸の中に閉じ込めると、どのカットインでも同じ「顔のアップ」になって、
**誰が何をしているのか**が読めない。丸はクラブカラーの座布団として残し、
その上に全身を立たせる(`height:190%` / `bottom:-2px`)。

> 見出しと選手の間は 40px 空ける。詰めると**選手の頭が見出しを横切って**、
> 両方とも読めなくなる(実際にそうなり、ゴール時の「1 - 0 アシスト ○○」が
> 「0 アシスト ○○」に見えた)。

表示時間は `TUNING.play` の `cutMs`(1.7秒) / `goalMs`(2.6秒) / `kickMs`(2.0秒)。
演出そのものに約1秒かかるので、それに**読む間**を足した長さにしてある。

#### いつ出すか

| 局面 | |
|---|---|
| キックオフ / ゴール / セーブ / ブロック | **必ず** |
| 枠外 | 25% |
| 競り合いに負けた | 20% |
| 競り合いに勝った・パス成功 | 22% |

**倍速(×2以上)では出さない。** 飛ばしたい人の邪魔をしない。

セットプレー(→[07. §7.11](07-match-engine.md))は**必ず出す**。試合の山場であり、
「誰が蹴るのか」がそのまま読み物になる。1人だけを中央に大きく出し、
帯の縁を金にして通常のマッチアップと区別する。退場は赤い帯で、盤面から1人減ることを
はっきり伝える(この帯が出た次のフレームで、ピッチの点も実際に消える)。

> カットインの間は再生を止める(`mApply` が待ち時間を返し、次のイベントを遅らせる)。
> **止めているのは描画だけで、試合はすでに解き終わっている**(→[07. §7.1](07-match-engine.md))。


### 6.20 RESULT — 試合結果(スタッツと MOM)

試合が終わったら、**何が起きた試合だったのか**を1画面で読ませる。
上から「事実 → 主役 → 内訳 → 個人」の順に、粒度が細かくなっていく。

```
FULL TIME
  サンパウロ・チマォン  3 - 1  モンテビデオ・カルボネーロ
              勝利
        ┌──────────┐
        │  カード   │      MAN OF THE MATCH
        └──────────┘
  61%  ──── 支配率 ────  39%      ← 2色の帯。左が自チーム
  17   ─── シュート ───   8
   7   ──── 枠内 ─────   1
   3   ─── ブロック ───   1
  86%  ── パス成功率 ──  75%
PLAYER RATINGS
  ST ペレイラ ⚽2      7  −   90'  9.3
  ...
+2,000 コイン / +350 EXP
  他会場の結果
  [ホームへ] [シーズンへ]
```

- **MOM は両チームから1人**。カード面をそのまま出す(この画面だけの特別扱いはしない)。
  自軍とは限らない — 敵の10番に沈められた試合は、そう見えるべき。
- **採点表は自チームのみ**。評価の高い順。交代で退いた選手も含み、
  90分未満はトーンを落とす。行タップでカード詳細へ。
- 数字はすべて `matchStats()` / `matchRatings()` がイベント列から数え直したもので、
  **画面用に別途持っている値はない**(→[07. §7.1](07-match-engine.md))。
  パス成功率が「−」になるのは、その選手がパス系チャンネルを一度も引かなかったとき。

#### 採点の考え方(`matchRating`)

| | |
|---|---|
| 土台 | 関与回数の**対数**。4.0 + 2.05·log10(1+関与) — 出続ければ上がるが青天井にはしない |
| 加点 | ゴール +0.9 / アシスト +0.55 / 競り勝ち +0.10 / ブロック +0.16 |
| 減点 | 競り負け −0.10 / 決められなかったシュート −0.06 |
| DF | 無失点 +0.5、失点は1点あたり −0.18(上限 −0.8) |
| GK | 別式。5.5 + セーブ×0.35、無失点 +0.7 / 失点 −0.30(上限 −1.2) |

範囲は 3.0〜10.0。**採点は勝敗に一切影響しない**、起きたことを読むためだけの層。


#### 虹と金は**彩度で寄せる**(2026-08-04)

WORLD CLASS の虹は `mix-blend-mode:color-dodge` で乗る。
**不透明度を上げると白に飛ぶ**ので、濃くしたいときは彩度(chroma)を上げる。
銀(クローム)の明るい地に乗るぶん、仕上がりはパステル寄りの玉虫色になる。

#### LEGENDS だけは金の帯(2026-08-04)

ホロは3種とも「明るい所が斜めに流れる」だけだったので、LEGENDS が
**REGULAR の光沢と見分けにくかった**。LE だけ帯そのものを作り込む。

```
transparent → 暗い金(落ち影) → 濃い金 → 白に近い芯 → 濃い金 → 暗い金 → transparent
```

- **細い芯を濃い金で挟む**と、単色をぼかしただけの「明るい所」ではなく金属の帯に見える
- 両側に落ち影のような暗い縁を置くと、帯が地から**浮いて**見える
- **芯を明るくしすぎない**。`mix-blend-mode:screen` で乗るので、
  ピークで能力値が飲み込まれる(実際にそうなり、0.95→0.72 に落とした)

#### 印を付けるのは**借りている側**(2026-08-04)

以前は自分のカードに ★ を付けていたが、**最終的にはほとんどが自分のカードになる**ので、
印が付いているのが当たり前になって意味を失う。逆にして、
**クラブから借りているカードの名前の後ろに `(CLUBS)`** を添える。

| 場所 | 出し方 |
|---|---|
| カード面の名前帯 / 一覧のピッカー | 名前の後ろに `(CLUBS)`(名前より弱く) |
| 編成のピッチ・ベンチ | OVRの丸の右上に `C` のバッジ(名前を出す幅が無い) |
| カード詳細の帰属 | `(CLUBS) クラブからの貸与 — 退任するとこのクラブに残ります` |

#### CAPTAIN — 誰が腕章を巻くか(→[03. §3.20](03-game-design.md))

SET PIECES の上に1枠だけ置く。**効果まで書く**のが要点で、
「スタミナの減りが28%緩やか」と出ていないと、なぜ指名するのかが分からない。

```
CAPTAIN
 ┌──────────────────────────────────┐
 │ (CAP)  R. コエーリョ              ›│
 │        自動　スタミナの減りが28%緩やか│
 └──────────────────────────────────┘
```

腕章の丸はクラブカラー。指名していないときは名前を淡くして `自動` と添える
(SET PIECES と同じ約束)。

#### SET PIECES — 誰が蹴るか(→[07. §7.11](07-match-engine.md))

DECK のピッチの下に PK / FK / CK の3枠を置く。**指名しなくても成立する**画面なので、
自動選出のときも「実際に蹴る選手の名前」を出し、`自動` と添えて区別する。

```
SET PIECES
 ┌────────┬────────┬────────┐
 │   PK   │   FK   │   CK   │
 │ ピリス  │ドラクロワ│ ハリス  │
 │  指名   │  自動   │  自動   │
 └────────┴────────┴────────┘
```

枠をタップすると先発から選ぶ一覧が出る。左の数字は**その種類の適性**
(PK=atk×1.2+tec / FK=tec×1.2+atk×0.8 / CK=pow+atk×0.6)で、
エンジンの自動選出とまったく同じ式。指名を外せば自動に戻る。
**先発に居ないと蹴れない**ので、交代で退いた選手は自動選出に戻る。

#### 実況の言い回し

**チャンネル名がそのまま実況の語になる。** そのため `ORIGINS` の `label` は
すべて体言(名詞)で揃えてある — 「サイドを上がる」のような用言だと
「〜で持ち出す」に埋め込んだ瞬間に文が壊れる。

同じ局面でも文を変える。言い回しは**イベントの中身から決定的に引く**ので、
同じ試合を何度再生しても同じ実況になる(→[07. §7.1](07-match-engine.md))。

| 局面 | 例 |
|---|---|
| 起点 | 中盤、カルヴァーリョ（CMF）の持ち出しから仕掛ける |
| シュート | ヴィエイラの**GKとの一対一**！リッチがセーブ |
| ゴール | ⚽ クイパー **ニアへの一撃**でゴール！ |
| 連鎖(pass) | オセイがスルーパスで繋ぐ |
| 連鎖(carry) 1手目 | ハリスが縦の突破で持ち出す |
| 連鎖(carry) 2手目以降 | **なおもハリス、敵陣まで運ぶ** / ハリスはまだ離さない |
| 失敗(carry) | **ボスの体当たり**、ヴィラルバを止めた |
| 失敗(pass) | デ・グラーフの展開、**ロシャの体当たり**に引っかかる |

**止めた側が何をしたか**も必ず出す(→[07. §7.12](07-match-engine.md))。
守備が「止めた」としか言えないと、守備側の采配が読み物にならない。
カットインでも、守備側の枠には**自分が選んだ守備チャンネルとその能力**を出す
(「並走 SPD 11」)。攻撃側の能力を並べても、何で競っているのかが読めない。

高さは「自陣 / 中盤 / 敵陣 / ゴール前」の4段に丸めて文に混ぜる。
どこで起きているかが、盤面を見ていなくても読めるようにするため。

### 6.21 選手交代(2026-08-03)

**HELP と同じ形のタブ**を試合画面の右端に出す。試合中だけ表示し、終了したら消える。

```
 ┌──────────────────┐
 │                  │╲
 │   ピッチ          │ 交代 ← タブ(右端)
 │                  │╱
 └──────────────────┘
```

#### 開くと試合が止まる

走らせたまま選ばせると、決めている間に局面が進んで
**「誰を替えるつもりだったか」が変わってしまう**。開いた時点で一時停止し、
閉じたときに元の状態(再生中だったか)へ戻す。
自分で止めてから開いた場合は、閉じても止めたままにする。

#### スタミナで選ぶ画面

名前より先に**バーが目に入る**ように積む。残量で色が変わる(緑 → 黄 → 赤)ので、
一覧を眺めるだけで替えどきが決まる。

```
 ┌ SUBSTITUTION ──────────┐  ← 見出しと説明は固定
 │ 一度下がった選手は戻れません│
 ├────────────────────────┤
 │ ピッチ                  │
 │  GK  ダイクストラ  IN 100%│  ↕ ここだけスクロール
 │  CB  コスタ          97% │
 │ ベンチ                  │
 │  ST  ラモス         100% │
 │ 交代済み（戻れません）    │
 │  CB  バチスタ    OUT  31%│
 ├────────────────────────┤
 │  交代する　残り2回        │  ← ボタンも固定
 └────────────────────────┘
```

**説明とボタンは固定、選手だけスクロールする。** 替える相手を探して上下する画面なので、
決定ボタンが流れて消えると押せなくなる。

- **押した瞬間にリスト上で入れ替わる**。実際の反映は次の再開時だが、
  リストが変わらないと「もう選んだのか、まだなのか」が分からず**3枠を続けて使えない**
- 入った選手は `IN` を付けて**施錠**する(打ち消し線にすると意味が逆に読める)。
  下がった選手は `交代済み` に落ちて選べなくなる
- **一度下がった選手は戻れない**。ベンチに残るのは未出場の選手だけ
- 残り回数は**ボタンに出す**(`交代する　残り2回`)。0 になったらボタンを止める。
  閉じるのは × ボタン
- **枠を使い切っても一覧は薄くしない**。ここは最後まで
  「誰がどれだけ消耗しているか」を読む画面でもある
- 交代枠は3。**申請中のぶんも数える**(適用は次の再開時なので、
  済んだ数だけ見ていると枠を超えて積める → docs/07 §7.6)
- 反映は**次の再開時(3分ごと)**。ここは engine の `orderMatch` にそのまま乗る。
  即時に反映しないのは、試合が「解いたものを再生している」構造だから

### 6.22 監督の采配(2026-08-04)

**交代の反対側にタブを置く。** 右が「誰を出すか」、左が「どう戦うか」。
試合中に触る手が2つあるので、**画面の左右に振り分けて指が迷わないようにする**。

| | 交代 | 采配 |
|---|---|---|
| 位置 | 右端(青) | **左端(金)** |
| 開いたとき | 試合が止まる | 試合が止まる |
| 閉じ方 | × を押す | **選んだ時点で閉じる** |
| 選べる数 | 1試合3回まで | **同時に1つだけ・何度でも** |

#### 十字に並べる

```
        ▲ 攻撃重視
  ◀ 左サイド  ◆ 中央  ▶ 右サイド
        ▼ 守備重視
```

配置そのものが意味になっている(上が前、下が後ろ、左右がレーン)ので、
**ラベルを読まなくても手が動く**。CSS の `grid-area` で行と列を直接指定する
(自動配置に任せると DOM 順で流れて十字が崩れる)。

- 選ぶと**すぐ閉じて試合が再開**する。決定ボタンを置かない
  (交代と違って取り返しがつく手なので、確認を挟むほうが煩わしい)
- いま出している指示は**金で塗る**。もう一度押すと解除
- 下の説明文は選んでいる指示の内容を出す。**得るものと失うものを1行で**書く

### 6.23 クラブチャット(2026-08-04)

**節の進行をチャットにする。** モックの秘書チャットをそのまま拡張し、
選手も同じグループに入ってくる形にした。

| | |
|---|---|
| 秘書 | **紫の丸**。名前は吹き出しの上に小さく置く |
| 選手 | **灰の丸**。立ち絵をバストアップに切り抜く。誰が話しているか絵で分かる |
| 監督 | **金の丸**を右に。吹き出しも右寄せ・金 |
| 吹き出し | 角丸12px、話者側だけ 4px に落として向きを作る |

**丸は3者とも同じ形・同じ大きさ**(36px、ヘッダーは54px)にして、
**色だけで役割を分ける**。誰か1人だけ形が違うと、そこが機能ボタンに見えてしまう。

#### 秘書と監督の顔はプレースホルダー

絵がまだ無いので、丸の中にシルエットを CSS で描いている(頭 + 肩)。
**割合で描いてあるので大きさを変えても崩れない。**

```
src/assets/faces/sec.png   ← 置けば秘書の顔に差し替わる
src/assets/faces/mgr.png   ← 置けば監督の顔に差し替わる
```

`window.ASSETS.faces` を見るだけなので、**絵を足すのに JS は触らない**
(選手の絵と同じ考え方 →docs/03 §3.19)。

- 選択肢は**会話の続きとして下にせり出す**
- 選手を選ぶときだけ**2列のグリッド**にして、名前・枠・OVR を並べる
- 開いたら必ず**最新まで送る**(会話は下が最新)
- 最後は「試合へ向かう」の1つだけ。**節の出口をここに一本化する**

> **節のタイルには何も置かない。** 金枠と「クラブチャットを開く」だけにして、
> 決めごとは全部この画面に集める(→docs/03 §3.29)。

#### 口調を3者で分ける(2026-08-05)

| | 口調 | 例 |
|---|---|---|
| 秘書 | **やわらかい丁寧語**。言い切らず、判断は監督に残す | 「さて、チームには何をさせましょうか。」 |
| 監督 | **短くても文**。命令形か意思表示で終える | 「体を作る日にする。」「フレイタス をここへ。」 |
| 選手 | ふつうの敬語。手応えを素直に言う | 「悪くない感触です。続けます。」 |

**監督の発言は選択肢のラベルとは別に持つ**(`say`)。ラベルをそのまま喋らせると
「訓練」「フレイタス」「攻撃練習」と**単語だけの会話**になり、人が話している感じが消える。
どの台詞も**節ごとに3種から選ぶ**ので、同じ節では変わらず、節が変われば言い回しが変わる。

> **差し込みは `{x}` を総なめで置換する。** 以前は `{d}` `{c}` … と1つずつ
> 列挙していて、新しい差し込みを足すたびに書き忘れ、画面に
> 「{t} をやろう。」がそのまま出た(2回)。`drive.js` が
> **`{…}` が本文に残っていないか**と**監督が単語で返していないか**を見張る。

#### アイコンはバストアップに収める

素材は全身の立ち絵(420×500)。そのまま丸に入れると**腹が中心**に来て顔が潰れ、
逆に寄せすぎると**顔だけ**になって窮屈に見える。素材を実測すると、図の上から
27% までが頭、30% が首(いちばん細い)、35% で肩、40% から胸だった。
**頭上に少し余白を残し、上から約38%(頭〜胸)**が入るところで組む。

```css
.ch-sm img, .ch-av-in img{
  position:absolute; left:50%; top:0;
  width:224%; height:auto;              /* 丸の直径の2.2倍 = 図の約38%が見える */
  transform:translate(-52.4%,-3.3%);    /* 立ち絵の重心 / 頭上の余白ぶん */
}
```

`-52.4%` は立ち絵の重心が中央よりわずかに右にあるぶん、`-3.3%` は頭のてっぺんの
上に**丸の直径の5%ぶんの余白**を作る位置。証明写真と同じで、頭がぴったり上端に
付くと窮屈に見える。**割合で書いてあるので、吹き出し用(36px)と
ヘッダー用(54px)が同じ規則で揃う。**


### 6.24 ブリーフィング — 明るいのは吹き出しのほう(2026-08-07 / 反転 2026-08-09)

**暗い地に暗い吹き出しを置くと、輪郭が沈んで誰が何を言ったのか読み取れない。**
明るくする対象は2通りある。**地**を明るくするか、**吹き出し**を明るくするか。

> **吹き出しを明るくするほうを採る**(2026-08-09)。一度は地をクリームにして
> 吹き出しを紺のままにしたが、**この画面だけ地が他と違う**ぶん目が慣れず、
> かえって読みづらかった。地はアプリ共通の暗いまま、会話の塊だけを浮かせる。

色は `#scr-chat` の中で閉じた変数で持つ。

| | |
|---|---|
| 地 | **アプリ共通の暗いまま**。この画面だけ地を変えない |
| 吹き出し | `oklch(0.938 0.026 91)` クリーム。**暗い地に明るい塊**が乗る |
| 監督の吹き出し | 金。右寄せ。文字は暗いまま |
| 発言者の名前 | **本文と同じ濃さ**。落とすとクリームの吹き出しに沈んで誰の発言か読めない |
| 見出し・注記・選択肢 | **地の上に直接乗る**ので、周りの画面と同じ明るい字・濃い札 |
| 丸(秘書・監督・選手) | 暗いまま(周りの画面と同じ) |
| 覚醒の合図 | 濃い地の上の緑の光(元のまま) |

> **明るいのは吹き出しの中だけ。** 地・見出し・選択肢は他の画面と同じ暗い側に置く。
> 画面ごと地の色が変わると、行き来したときに目が慣れない。

> **アプリの外枠は暗いまま**。ヘッダー・タブ・引き出しは共通の部品なので触らない。
> 明るいのは「1節の相談をする部屋」だけ、という切り分けにしてある。

#### 見出しは相手クラブ

自クラブ名はアプリのヘッダーに常に出ている。ここで繰り返すより、
**VS + 今節の相手**を置いたほうがこの画面の役に立つ。副題は `第N節` だけ。

#### 出さないもの

- **`SEASON n ・ NODE n` の行**。節は見出しの副題に出ている
- **打ち手3つの説明文**。3つの違いは覚えるもので、毎節読むものではない
- **強化メニューの説明文**。同上(どちらも HELP には残してある)

会話が長いので、**毎節必ず読む場所に読まなくてよい字を置かない**。

#### 発言者にポジションを添える

選手の名前の右に **CF / GK** のような小さなタグを置く。
**誰を育てるかを決める画面**でもあるので、名前だけだと判断材料が足りない
(選手を選ぶ一覧のほうには前からポジションと OVR が出ている)。

#### 打ち手の呼び名

| 旧 | 新 |
|---|---|
| 訓練 | **強化トレーニング** |
| 交流 | **コミュニケーション** |
| 休息 | **休養** |

呼び名は `HANDS` の `label` が正本。**テストや drive.js で文字列を直接書かない**
(`handById("bond").label` を引く)。書き写していたせいで、名前を変えた瞬間に
drive.js が落ちた。

### 6.27 秘書はクラブごと(2026-08-09)

**クラブを移れば秘書も替わる。** 誰になるかは**クラブIDから決まる**ので、
同じクラブに居る限り同じ人が座っている(節をまたいでも、セーブを跨いでも変わらない)。

| | |
|---|---|
| 素材 | `src/assets/art/secretary/*.png`(複数人が並んだ1枚。埋め込まれない) |
| 書き出し | `src/assets/secretary/sec01.webp …`(`tools/slice_secretary.py`) |
| 出る場所 | **HOME のひとこと**・クラブチャット・受信箱の丸。話し手の丸は3者とも同じ形(→§6.23) |

- 切り出しは**アルファの切れ目で人を分ける**。並びや人数が変わっても同じ手順で通る
- **既定では上段だけ**書き出す(`--rows=N` で増やせる)。使わない絵まで書き出すと、
  そのぶん index.html に埋め込まれて重くなるだけ
- 枠は**選手の立ち絵と同じ 420×500**、頭の上端 6% / 足元 97.5% に合わせてある。
  丸の切り出し(図の上から約38%)が選手と共通なので、**枠が違うと顔の位置がずれる**

> **絵を足しても JS は触らない。** 候補は `window.ASSETS.secretary` の並びそのもの。
> 人を増やしたければ素材を足して切り出すだけで、その日から配られる先が増える。

#### HOME のひとこと

顔 + 吹き出しで1行にする。**未読の印は丸の肩に付ける**(通知の印はアイコンに付くもの)。
見出しの「秘書」の真下に丸が来るので、印が見出しに被らないぶんだけ行を下げてある。



### 6.28 クラブカラーはパステル寄りのネオン(2026-08-10)

**暗い盤面の上に暗い丸を置くと、クラブの見分けが付かない。** 明度と彩度を上げて、
どの色も地から浮くようにした。

| | 前 | 後 |
|---|---|---|
| クラブカラー | `oklch(0.58 0.14 h)` | **`oklch(0.80 0.17 h)`** |
| 色相 | CLUBS の並びから黄金角(137.5°)で散らす | 変わらず |

出る場所: 試合のスコア帯の丸 / 足元の影 / カットインの座布団 / DECKの足元 /
任期カレンダーの点 / 交代の一覧。

> **丸の上に字が乗るところは、字を暗い側に 取る。** 明るい丸に白い字だと読めない。
> `clubInk()` が同じ色相の暗い色を返すので、**丸と字が必ず同じ家族**になる。
> 掛かるのは 交代の一覧の枠名・カットインのOVR・足元の★の3つ。

チャットの丸(秘書・監督・選手)も同じ調子に合わせた。こちらは絵が上に乗るので、
色は「誰が話しているか」を形以外で示すためだけに使う。


### 6.29 タイトルはステッカーの壁(2026-08-10)

**Pの丸いマークをやめて、ステッカーを一面に貼った壁にした。** ロゴを一点置くより、
「街の壁に勝手に貼られている」ほうがこのゲームの気分に合う。

素材(`src/assets/art/sticker/*.png`)は**白地の絵**なので、そのままでは白い四角が並ぶ。
`tools/slice_sticker.py` で切り抜く。ここが一番の勘所で、**単純な「灰色を消す」は使えない**
— 元絵は鉛筆画で、灰色こそが絵の本体だからだ。

1. `keyout_white` … **縁から連結した明るい画素だけ**をフラッドフィルで抜く(選手の絵と同じ考え方)
2. `peel_shadow` … 透明になった画素から内側へBFSし、**透明と隣り合う中間の無彩色(196〜245)だけ**剥がす。
   ステッカーの落ち影はここで消える。絵の内側の灰色には手が届かないので無事
3. `drop_specks` … いちばん大きい塊の2%未満のごみを落とす
4. 余白を詰めて**幅220pxのWEBP(q78)**へ。14枚で 277KB(元は 18.3MB)

**書き出し名は素材のファイル名がそのまま**(`scout.png` → `ASSETS.sticker.scout`)。
壁は全部を混ぜて使うが、HOME は絵を名指しで使う(→§6.30)ので、通し番号にはできない。

> **素材そのものを `src/assets/` の直下に置いてはいけない。** `build.py` は直下の画像を
> ぜんぶ base64 で埋め込むので、素材のサイズがそのまま index.html に入る(実際に一度やった)。
> **素材は `art/` の下、書き出しは `sticker/` の下**。
>
> **足すのは素材を置いて `python tools/slice_sticker.py` を流すだけ。**
> 壁は袋から配るので、枚数を意識する場所は無い。
> **名前は中身が分かるものにして、一度決めたら変えない**(HOME が名指しで使う)。

壁の敷き方は `titleWall()`。4列の升目を土台に、**同じ絵が隣り合わないよう袋から順に配る**
(毎回乱数で引くと同じ絵が固まって、壁ではなく壁紙に見える)。位置・角度(±25°)・
濃さ(0.58〜0.92)を散らす。

**種は起動ごとに振るので、壁は毎回ちがう。** 貼り替えられる壁のほうが街らしい。
揃えるのは**大きさだけ**で、セルの 0.95〜1.35 倍に収めてある。ここが広すぎると、
小さい絵は模様に、大きい絵は背景画に見えて、貼り紙らしさが消える。

| 悩んだところ | 落としどころ |
|---|---|
| 白い縁取りが素材に無い | `drop-shadow(0 0 1.5px #fff)` を3枚重ねて型抜きの縁を作る |
| 文字が絵に埋もれる | `.t-plate`(暗い板・−1.4°)に載せ、`.t-name` は柔らかい光ではなく**2pxの硬い縁**を持たせる |
| 版の表記が読めない | `.t-foot` に丸い暗い座布団を敷く |
| 起動直後に壁が途中で切れる | **要素の実測をあてにしない**。ビューポートと突き合わせて大きいほうを採り、2行多めに敷く |


### 6.30 HOME にステッカーを貼る(2026-08-10)

**タイトルの壁(→§6.29)と同じ素材を、HOME の余白に1枚ずつ貼る。**
タイルは文字だけで持たせていたので右側が空いていた。そこに行き先を絵で見せる。

| 場所 | 絵 | 選び方 |
|---|---|---|
| スカウトのタイル | `scout`(手帳を持つスカウトマン) | **固定** |
| チーム編成のタイル | `board`(戦術ボード) | **固定** |
| 次戦のタイル | `stadium` / `coach` / `fans` | **試合ごとに1枚** |

> **次戦のタイルの右上にあった光(`.nx::after` の橙の円)は外した**(2026-08-10)。
> 同じ角に飾りが2つ重なると、どちらも主張しきれずに濁る。
> 席をステッカーに明け渡して、絵を 132px → **190px** に大きくしてある。

- 次戦の絵は `hashStr(クラブ+シーズン+節)` で決める。**試合が変われば変わるが、
  描き直しても変わらない**。毎描画で引き直すと、HOMEに戻るたびに絵が飛ぶ
- 素材が無ければ `stickerArt()` は空文字を返す。**絵を消しても画面は崩れない**

#### 貼り方

```css
.tile-st{ right:-16px; bottom:-14px; width:84px; transform:rotate(-7deg) }
.tile-st .stk{ opacity:.42 }      /* 次戦のタイルは .30(文字が大きいので薄く) */
```

- **枠から少しはみ出させて、傾ける。** きれいに収めると枠の中の飾りになってしまい、
  「貼ってある」感じが出ない。`overflow:hidden` で切り落とすところまで含めて絵にする
- **文字を上に置く**(`.tile-t/.tile-s/.tile-i` に `z-index:1`)。絵は下に潜らせる
- 白い縁は素材に無いので、§6.29 と同じく白の `drop-shadow` を重ねて型抜きの縁を作る

> **書き出し名で名指しするので、素材のファイル名を変えてはいけない。**
> 最初は `st01`〜`st14` の通し番号にしていたが、**素材を1枚足すと番号がずれて
> スカウトのタイルにスタジアムが出る**。素材名(`scout.png`)をそのままキーにして、
> 番号に依存しないようにした(→tools/slice_sticker.py)。


### 6.31 任期カレンダーの飾り(2026-08-10)

**96個の枠が同じ顔で並ぶ表なので、「いま」と「狙える大会」だけを立たせる。**

#### 出られない大会はトーンを落とす

カレンダーには**出られない節の開催予定も並べてある**(→docs/03 §3.23)。
先の予定が全部消えると次に何を狙うか決められないからだが、
狙える大会と同じ強さで並ぶと、**いま何ができるのかが埋もれる**。

| | 見た目 |
|---|---|
| エントリーできる | 文字はそのまま ＋ **トロフィーのステッカー** |
| 大会が進行中 / 間隔待ち / 条件を満たさない | 文字を `--text-dim`／`--text-mute` に落とし、**絵は付けない** |

> **理由の但し書きは書かない**(2026-08-10 に外した)。
> 「開催予定（条件を満たせば参加できます）」のような一文を全部の行に添えていたが、
> 出られるかどうかは**文字のトーンで分かる**し、条件そのものは日程タブが持っている。
> 96行ぜんぶに但し書きが付くと、カレンダーが注意書きの列になる。
> 残すのは「他N大会と同日・選べます」だけ — これは**その節にしか無い情報**なので。

判定は `cupCalNote()` の `open`。塞いでいるもの(進行中の大会・`TUNING.cup.rest` の間隔・
参加条件)が**ひとつでもあれば付けない**。理由ごとに書き分けた文はそのまま残す。

#### 済んだ節には飾りを置かない

**読みたいのはスコア**なので、消化した行からは絵を外してある(2026-08-10)。

- カップ戦の記録に貼っていた**トロフィーの絵は出さない**。右端のスコアと重なって読みにくい
- **打ち手の絵文字(💪🤝🛌📣)も出さない**。何をしたかは `title` に残してある

打ち手の絵文字は**ブリーフィングの選択肢からも外した**。選ぶのは3つだけで、
文字を読めば分かる。絵文字は行を賑やかにするが、意味は増やしていなかった。

#### いまの節はロッカーの絵

現在節のタイルにだけ `locker` を貼る。**並んだ枠の中で1枚だけ絵が入る**ので、
数字を読まなくても「ここが今日」だと分かる。

あわせて**見出しを行き先そのものにした**。前は見出しが「この節の準備」で、
押したら何が起きるか(「第N節を開始する」)は右下に小さく置いていた。
タイルの用は1つしかないので、行き先を見出しに上げて、右下の案内は消した。
話しかけたあとの進み具合(「準備完了 ／ 試合へ向かえます」)だけを下に添える。

> **素材の側の限界。** トロフィーの絵は**本体も飛沫も同じ黄緑**なので、
> 行の高さ(50px弱)では形まで読めない。拡大しても、窓を作って寄せても、
> `contrast` を上げても変わらなかった(全部試した)。
> いまは「貼り紙が枠からのぞいている」印として置いてある。
> 形を読ませたいなら、**絵の側に濃淡を入れる**か、行を高くするしかない。


### 6.32 スポンサーの看板(2026-08-10)

**契約中のスポンサー(→docs/03 §3.40)を、ピッチ脇の広告板として出す。**
社名の文字だけだと「設定」に留まるが、看板の絵があると**クラブに金が付いている**感じが出る。

| 場所 | 出し方 |
|---|---|
| HOME の次戦タイル | `OFFICIAL PARTNER` の見出しの右。**社名の代わりに看板が入る** |
| キックオフのカットイン | 両チームのキャプテンの下。帯の幅の72% |

- 絵は**スポンサーの id で引く**(`ASSETS.banner["dynasty"]`)。無ければ**今までどおり社名**
- 23社ぶんを一度に描けるわけがないので、**絵のある会社と無い会社が混ざる前提**で作る。
  見出し(`OFFICIAL PARTNER`)は常に出して、枠だけは揃えておく

#### 絵の作り方

依頼書は [`src/assets/design/sponsor-banner-prompt.md`](../src/assets/design/sponsor-banner-prompt.md)。

1. **1シートに4社ぶんを縦に並べて**描いてもらう(1024×640 / 1段 1024×160)
2. `python tools/slice_banner.py <シート> <id> <id> <id> <id>` で縦4等分 → 幅640のWEBP
3. `python build.py` で埋め込む

> **生成AIはキャンバスサイズを守らない**ので、サイズではなく**割り付け**(縦N等分)を
> 守ってもらい、受け取った画像を等分して切る。選手の立ち絵と同じ考え方(→§6.29)。
>
> **看板は矩形の広告そのもの**なので、ステッカーや立ち絵と違って**背景を抜かない**。
> 切り出しは等分と縮小だけで済む。

#### 依頼で外せない3つ

| | なぜ |
|---|---|
| **社名の文字は板の高さの45〜60%** | 実際に出るのは横350px。ふつうの広告の比率だと読めない |
| **ラテン文字だけ** | 日本語は崩れる。実際のピッチ脇の看板もラテン文字が多い |
| **真っ黒と山吹色を大面積で使わない** | 暗い画面に沈む／主役の金色と喧嘩する |


### 6.33 タイトルを明るくする(2026-08-10)

ステッカーの壁(→§6.29)を敷いたあと、**題字も打ち手も暗いままだった**ので、
壁だけが賑やかで中央が沈んで見えていた。**中央を明るい札に寄せる**ことで直した。

| | 前 | 後 |
|---|---|---|
| 題字の札 | 暗い板(`oklch(0.13 …)`) ＋ 金の細い枠 | **クリームの札** ＋ **白フチ7px** |
| 題字の色 | 白 ＋ 影と滲み | **濃紺の字**(明るい地なので縁は不要) |
| `Ball` | `--accent`(山吹) | **濃いオレンジ**(クリームの上で沈まない色に) |
| 打ち手 | 金の細い線 ＋ 薄い字 | **塗りつぶした札** ＋ 白フチ |
| 覆い(`.t-scrim`) | 中央 97% | **中央 74%**。札が読ませる役を持ったので薄くできる |

- **暗い札は壁に穴を開ける。** 貼り紙の壁の真ん中に暗い矩形を置くと、
  そこだけ絵が抜けたように見えて画面がしぼむ。壁と同じ**白フチの貼り紙**にすると、
  題字が「いちばん大きいステッカー」として壁の一部になる
- **打ち手の脈動で明るさを落とさない。** 前は `opacity:.55` まで落としていたが、
  これは「点滅」ではなく「暗い」と読まれる。**光の輪だけを呼吸させる**形に変えた
- 明るい地に変えたので、**金色は使えない**(クリームの上で読めない)。
  `Ball` と字の色はそれぞれ濃い側へ寄せてある


### 6.34 固有スキルの帯を派手にする(2026-08-11)

**バッジだけでは「何か出た」が試合の速さに埋もれる。** 金の札(→§6.26)は付いていたが、
カットインは他と同じ見た目だったので、固有スキルが出た瞬間が流れていってしまう。
**帯ごと様子を変える**。

| | 中身 |
|---|---|
| 地と縁 | 暖色の地 ＋ **金の縁** ＋ 内側に金のにじみ |
| 掃引の光 | 白→**金**。速さも 1.1s → **0.7s** |
| 見出し | 金にして、字間を広げ、光を回す(技名がここに出る) |
| **きらめき** | 8点が時間差で瞬く |
| **揺れ** | 帯が出た瞬間に一度だけ揺れる(`.mcut.shake` を流用) |

```
判定 → 固有スキルが出た → 帯に .sig → 金の帯・きらめき・揺れ
```

- **きらめきの位置と間は固定**。毎回散らすと帯がちらついて、肝心の技名が読めない
- **掃引は濃くしすぎない**。`.55` だと通った瞬間に選手の顔が飛ぶので `.38` に留めた
- 揺れは `cutShow` が帯に `.cut.sig` を見つけたときだけ掛ける。
  ゴールの揺れと同じ仕掛けなので、**新しい仕組みは足していない**

> **帯は3種類ある。** マッチアップ(`cutVs`)・パス(`cutPass`)・シュート(`cutShot`)。
> 最初はパスの帯を直し忘れていて、**ベッカムの「精密機械」が出ても見た目が変わらなかった**
> (クロスの札なので、通ればパスの帯になる)。3つとも同じ扱いにすること。
>
> **固有スキルが出たら、抽選で間引かない。** パスの帯は `cutPass` の確率で、
> 枠外は `cutMiss` の確率で間引いている。12人しか持っていない札が出た瞬間まで
> 間引かれると、**出たこと自体に気付けない**。`sigIn()` が立ったら必ず出す。


### 6.35 一覧のページ送りと、戻せない操作(2026-08-12)

#### CARDS のページ送り

所持カードは任期をまたいで増え続けるので、**1ページ12枚**で区切る。

- **1ページに収まるときはページ送りを出さない**。要らない操作を置かない
- **絞り込みを変えたら1ページ目へ戻す**。前のページ番号が残ると空振りする
- 売って減ってページ数が縮んだら、最後のページへ寄せる
- ページを送ったら一覧の頭までスクロールを戻す

#### 戻せない操作は二段にする

売却(→docs/03 §3.46)は**押し直しで確定**にした。

```
[売却する] → [本当に売る]（赤・「この操作は戻せません」を添える）
```

- **同じ見た目のまま二度押させない**。確認の段はボタンの色を変える
- カード詳細を閉じたら確認は解ける(開き直したら最初から)
- 売れないカードは**ボタンを消して理由を置く**。押せるのに何も起きない、を作らない


### 6.36 チャットに実在感を出す(2026-08-12)

**色ではなく「型」で本物らしくする。** 地とクリームの配色(→§6.24)は動かさず、
**普段使っているメッセージアプリと同じ振る舞い**を足した。

| | 中身 |
|---|---|
| **まとまり** | 同じ人が続けて話したら、顔と名前は**最初の1回だけ**。行間も詰める |
| **尻尾** | まとまりの**先頭の吹き出しだけ**に付ける |
| **時刻** | 各発言の足元に。**節から決まる**ので開き直しても同じ |
| **既読** | 監督の最後の発言に付く(相手が読んだ、という形) |
| **日付の区切り** | 会話の頭に「第N節　試合当日」の丸い札 |
| **壁紙** | ごく薄い斜めの綾。ベタ塗りの地は「UI」に見える |

- **いちばん効いたのは"まとまり"。** 秘書が5行続けて話すとき、顔と名前が5回並ぶと
  帳票に見える。1回にするだけで会話になる
- **尻尾を全部に付けない。** 続きの吹き出しにも付けると縁が鋸の歯になる
- **時刻は決定的に作る**(`chatClock`)。実時間で作ると、開き直すたびに
  会話の時刻が動いて嘘になる。9時過ぎから2〜3分おきに話している体
- 壁紙は**柄が読めるほど濃くしない**。読むのは文字であって背景ではない

> **時刻は「発言」ではない。** 秘書は数字を読み上げない決まり(→docs/03 §3.35)があり、
> drive.js が chatLog の文字を見て検査している。時刻を足したらそこに引っかかったので、
> **検査の対象を吹き出しの中(`.ch-b`)に絞った**。画面の飾りと発言は分けて数える。

### 6.37 軸(KP)を盤面で読ませる(2026-08-17)

軸(→[03. §3.44](03-game-design.md))は指名の引き出しの中にしか出ていなかった。
**いま誰を軸にしているのかを見るために、試合を止めて引き出しを開く**必要があり、
指名した実感も無かった。

#### ピッチで光らせる

`.mp.kp` に**クラブカラー(`--kit`)の発光と、足元で呼吸する輪**を付ける。

- **両チームぶん出す。** どちらの軸かは**色で読む**
- 関与中(`.on`)や競り合い(`.vs`)は**一瞬の印**なので足元のリングを使っている。
  軸は**続いている状態**なので、絵そのものの発光と別の輪で分けた
- 指名した瞬間・自動で外れた瞬間の両方で `mKpMark()` を呼ぶ。
  描き直しのときだけ更新すると、**指名しても次のイベントまで光らない**

#### 引き出しは「11人が一度に見えること」が要件

試合を止めて開く画面なので、**送って探すぶんだけ試合が止まる**。
11人が入らないなら、入るまで削るのが正しい。

| 削ったもの | どこへ行ったか |
|---|---|
| 軸の効果の説明(3行) | **DECK のヘルプ**へ。試合画面は止めてはいけないのでヘルプを持てない |
| 相手の軸の行 | **ピッチの光**へ |
| 「ピッチ」の見出し | 控えは並ばないので元から要らなかった |
| 名前の下の固有スキル | **名前の横**へ。縦に積むと1人ぶんの高さが倍になる |

行の詰めは `#kpDrawer` の中だけに効かせる。**`.sb-r` は交代の引き出しと共用**で、
あちらは控えも並ぶぶん行数が違う。

#### 高さはピッチの実寸から取る

引き出しは**ピッチと同じ上端・同じ高さ**にする。盤面の代わりに開く画面なので、
覆う範囲が盤面と一致していると、開いても位置の感覚が途切れない。

**割合(`height:74%`)で決め打ちにしない。** ピッチは `aspect-ratio:3/4` で
幅から高さが決まるので、端末が変われば高さも変わる。`openKp()` が
**開くたびにピッチを実測**して `top` と `height` を入れる。

行の高さはその中の割り当てで決まる。**1行 38px**(11行 + 見出しでピッチの 472px に収まる)。
最初 32px まで詰めたが押しにくく、逆に 9px の余白まで広げると **31px はみ出した**。

> **収まりと押しやすさは両方テストで見る。** 「入るはず」で置いた値は、
> フォントや端末で崩れる。drive.js が
> **①11人目の下端が引き出しからはみ出していないか ②引き出しとピッチの上端・高さが
> 一致しているか ③1行が 30px を下回っていないか**を、実際の描画から測っている。

#### 選んだら閉じる

采配(→§6.22)と同じ作法。**指名は1人だけ**なので、選んだあとに開いたままでも
続きの操作が無い。閉じれば試合がそのまま再開する。

### 6.38 采配を盤面に出し、タブを分ける(2026-08-17)

采配(→[03. §3.50](03-game-design.md))は指示の引き出しの下に間借りしていて、
**開かないと何を敷いているのか分からなかった**。相手が何で来ているのかは
どこにも出ていなかった。

#### 画面外から差し込む帯

ピッチの**対角**に、クラブカラーの半透明の帯を出す。

| 位置 | 誰の |
|---|---|
| **右上** | 相手 |
| **左下** | 自分 |

- **画面外から伸ばす**(`right:-3cqw` / `left:-3cqw`)。`.pitch` は `overflow:hidden` なので
  端で断ち落ちて、**盤面の一部ではなく外から掛かっているもの**に見える
- 対角に置くのは「自分は必ず下」(→§6.17)の延長。**位置でどちらかが読める**
- 敷いていなければ帯ごと消える。**空の枠は出さない**
- 出すのは **`_M` のチームが実際に持っている采配**であって、次の試合の設定ではない

#### TAC タブを分ける

左端は上から **KP → TAC → 指示**。**采配は指示より上位の構え**なので、
上下の並びがそのまま「どちらが土台か」を表す。

**敷けるものだけを並べる。** 試合を止めて開く画面なので、
「覚えていない手」「この陣形では使えない手」を混ぜると選ぶまでが遠くなる。
何を目指せば増えるのかは **`ほかに N 手（熟練度と陣形の条件があります）` の1行**で足りる
(条件つきの一覧を見せるのは、覚える場面 →[03. §3.51](03-game-design.md) の仕事)。

選んだら閉じる。敷いているあいだはタブが光る(軸タブと同じ作法 →§6.37)。

> **試合中に敷き替えられるようにした。** それまで `setTeamTactic` は
> `createMatch` からしか呼ばれず、試合中に選んでも**次の試合まで何も起きなかった**
> (トーストは「次の再開から」と嘘をついていた)。
> 引き出しを分けて盤面に出す以上、押して何も起きないままにはできない。
>
> **掛け直せるようにするのが要点。** 采配は札を `push` し、`k` を掛け算で混ぜるので、
> 素の状態を控えずに2度呼ぶと**前の采配が乗ったまま重なる**。
> `p.sk0` / `p.fit0` に素を控え、毎回そこまで戻してから掛け直す。
> **指示の掛け直しも忘れない**(上げ下げと能力の倍率は采配と合成している)。

### 6.39 試合中の引き出しを揃える(2026-08-17)

軸・采配・指示・交代の4つが、**別々に書かれたせいで別々の作法になっていた**。

#### 左端の3つは同じ見た目にする

`#kpTab` / `#tacTab` / `#ordTab` を**1つの規則にまとめた**。
別々に書いていたら KP だけ縁が明るく(`--accent`)、TAC と ORD が沈んで(`--accent-dim`)
いて、同じ役割のものが違う階層に見えていた。

違うのは**縦の位置と、効いているときの光り方**だけ。上から **KP → TAC → ORD**。

> **ORD だけは光らせない。** 指示は「無指示」も普通の状態なので、
> 光を「何かが効いている」の合図に使えるのは軸と采配だけ。

タブ名は **ORD**(旧「指示」)。KP / TAC と同じ3文字の略号にそろえた。

#### 説明文を全部落とす

**試合を止めて開く画面に読み物を置かない。** 読んでいるあいだ試合は止まっている。

| 落としたもの |
|---|
| 「いま出している指示: ○○（もう一度押すと解除）」 |
| 指示の効果説明(「攻撃重視。前に出るぶん…」) |
| 「ほかに N 手（熟練度と陣形の条件があります）」 |
| 「スタミナの少ない選手から替えます。一度下がった選手は戻れません。…」 |

十字に並んだ5手は**形そのものが意味**で、選ばれている手は色で分かる。
交代のスタミナは**バーの色**で分かる。落として困るものは何も無かった。

#### 同時に開けるのは1つだけ

4つとも試合を止めて開くので、重なると**どれを閉じれば再開するのか**が分からない。
開くときに他を畳む。

**止めた/戻すの管理を1つにまとめる**のが要点。引き出しごとに
「自分が止めたか」を持たせていたので、**別の引き出しへ移った瞬間に
再生と停止が二重に走っていた**。いまは `_drawerPaused` 1つで、
「何も開いていない状態から開いたとき」だけ記録する。

> drive.js が **KP → TAC → 交代 → ORD と渡り歩いて、常に1つだけが開いていること**、
> **移動中も止まったままであること**、**閉じたら再開すること**を見ている。
