### 6.21 選手交代(2026-08-03)

**HELP と同じ形のタブ**を試合画面の右端に出す。試合中だけ表示し、終了したら消える。

```
 ┌──────────────────┐
 │                  │╲
 │   ピッチ          │ 交代 ← タブ(右端)
 │                  │╱
 └──────────────────┘
```

#### 開くと試合が止まる

走らせたまま選ばせると、決めている間に局面が進んで
**「誰を替えるつもりだったか」が変わってしまう**。開いた時点で一時停止し、
閉じたときに元の状態(再生中だったか)へ戻す。
自分で止めてから開いた場合は、閉じても止めたままにする。

#### スタミナで選ぶ画面

名前より先に**バーが目に入る**ように積む。残量で色が変わる(緑 → 黄 → 赤)ので、
一覧を眺めるだけで替えどきが決まる。

```
 ┌ SUBSTITUTION ──────────┐  ← 見出しと説明は固定
 │ 一度下がった選手は戻れません│
 ├────────────────────────┤
 │ ピッチ                  │
 │  GK  ダイクストラ  IN 100%│  ↕ ここだけスクロール
 │  CB  コスタ          97% │
 │ ベンチ                  │
 │  ST  ラモス         100% │
 │ 交代済み（戻れません）    │
 │  CB  バチスタ    OUT  31%│
 ├────────────────────────┤
 │  交代する　残り2回        │  ← ボタンも固定
 └────────────────────────┘
```

**説明とボタンは固定、選手だけスクロールする。** 替える相手を探して上下する画面なので、
決定ボタンが流れて消えると押せなくなる。

- **押した瞬間にリスト上で入れ替わる**。実際の反映は次の再開時だが、
  リストが変わらないと「もう選んだのか、まだなのか」が分からず**3枠を続けて使えない**
- 入った選手は `IN` を付けて**施錠**する(打ち消し線にすると意味が逆に読める)。
  下がった選手は `交代済み` に落ちて選べなくなる
- **一度下がった選手は戻れない**。ベンチに残るのは未出場の選手だけ
- 残り回数は**ボタンに出す**(`交代する　残り2回`)。0 になったらボタンを止める。
  閉じるのは × ボタン
- **枠を使い切っても一覧は薄くしない**。ここは最後まで
  「誰がどれだけ消耗しているか」を読む画面でもある
- 交代枠は3。**申請中のぶんも数える**(適用は次の再開時なので、
  済んだ数だけ見ていると枠を超えて積める → docs/07 §7.6)
- 反映は**次の再開時(3分ごと)**。ここは engine の `orderMatch` にそのまま乗る。
  即時に反映しないのは、試合が「解いたものを再生している」構造だから

### 6.22 監督の采配(2026-08-04)

**交代の反対側にタブを置く。** 右が「誰を出すか」、左が「どう戦うか」。
試合中に触る手が2つあるので、**画面の左右に振り分けて指が迷わないようにする**。

| | 交代 | 采配 |
|---|---|---|
| 位置 | 右端(青) | **左端(金)** |
| 開いたとき | 試合が止まる | 試合が止まる |
| 閉じ方 | × を押す | **選んだ時点で閉じる** |
| 選べる数 | 1試合3回まで | **同時に1つだけ・何度でも** |

#### 十字に並べる

```
        ▲ 攻撃重視
  ◀ 左サイド  ◆ 中央  ▶ 右サイド
        ▼ 守備重視
```

配置そのものが意味になっている(上が前、下が後ろ、左右がレーン)ので、
**ラベルを読まなくても手が動く**。CSS の `grid-area` で行と列を直接指定する
(自動配置に任せると DOM 順で流れて十字が崩れる)。

- 選ぶと**すぐ閉じて試合が再開**する。決定ボタンを置かない
  (交代と違って取り返しがつく手なので、確認を挟むほうが煩わしい)
- いま出している指示は**金で塗る**。もう一度押すと解除
- 下の説明文は選んでいる指示の内容を出す。**得るものと失うものを1行で**書く

### 6.23 クラブチャット(2026-08-04)

**節の進行をチャットにする。** モックの秘書チャットをそのまま拡張し、
選手も同じグループに入ってくる形にした。

| | |
|---|---|
| 秘書 | **紫の丸**。名前は吹き出しの上に小さく置く |
| 選手 | **灰の丸**。立ち絵をバストアップに切り抜く。誰が話しているか絵で分かる |
| 監督 | **金の丸**を右に。吹き出しも右寄せ・金 |
| 吹き出し | 角丸12px、話者側だけ 4px に落として向きを作る |

**丸は3者とも同じ形・同じ大きさ**(36px、ヘッダーは54px)にして、
**色だけで役割を分ける**。誰か1人だけ形が違うと、そこが機能ボタンに見えてしまう。

#### 秘書と監督の顔はプレースホルダー

絵がまだ無いので、丸の中にシルエットを CSS で描いている(頭 + 肩)。
**割合で描いてあるので大きさを変えても崩れない。**

```
src/assets/faces/sec.png   ← 置けば秘書の顔に差し替わる
src/assets/faces/mgr.png   ← 置けば監督の顔に差し替わる
```

`window.ASSETS.faces` を見るだけなので、**絵を足すのに JS は触らない**
(選手の絵と同じ考え方 →docs/03 §3.19)。

- 選択肢は**会話の続きとして下にせり出す**
- 選手を選ぶときだけ**2列のグリッド**にして、名前・枠・OVR を並べる
- 開いたら必ず**最新まで送る**(会話は下が最新)
- 最後は「試合へ向かう」の1つだけ。**節の出口をここに一本化する**

> **節のタイルには何も置かない。** 金枠と「クラブチャットを開く」だけにして、
> 決めごとは全部この画面に集める(→docs/03 §3.29)。

#### 口調を3者で分ける(2026-08-05)

| | 口調 | 例 |
|---|---|---|
| 秘書 | **やわらかい丁寧語**。言い切らず、判断は監督に残す | 「さて、チームには何をさせましょうか。」 |
| 監督 | **短くても文**。命令形か意思表示で終える | 「体を作る日にする。」「フレイタス をここへ。」 |
| 選手 | ふつうの敬語。手応えを素直に言う | 「悪くない感触です。続けます。」 |

**監督の発言は選択肢のラベルとは別に持つ**(`say`)。ラベルをそのまま喋らせると
「訓練」「フレイタス」「攻撃練習」と**単語だけの会話**になり、人が話している感じが消える。
どの台詞も**節ごとに3種から選ぶ**ので、同じ節では変わらず、節が変われば言い回しが変わる。

> **差し込みは `{x}` を総なめで置換する。** 以前は `{d}` `{c}` … と1つずつ
> 列挙していて、新しい差し込みを足すたびに書き忘れ、画面に
> 「{t} をやろう。」がそのまま出た(2回)。`drive.js` が
> **`{…}` が本文に残っていないか**と**監督が単語で返していないか**を見張る。

#### アイコンはバストアップに収める

素材は全身の立ち絵(420×500)。そのまま丸に入れると**腹が中心**に来て顔が潰れ、
逆に寄せすぎると**顔だけ**になって窮屈に見える。素材を実測すると、図の上から
27% までが頭、30% が首(いちばん細い)、35% で肩、40% から胸だった。
**頭上に少し余白を残し、上から約38%(頭〜胸)**が入るところで組む。

```css
.ch-sm img, .ch-av-in img{
  position:absolute; left:50%; top:0;
  width:224%; height:auto;              /* 丸の直径の2.2倍 = 図の約38%が見える */
  transform:translate(-52.4%,-3.3%);    /* 立ち絵の重心 / 頭上の余白ぶん */
}
```

`-52.4%` は立ち絵の重心が中央よりわずかに右にあるぶん、`-3.3%` は頭のてっぺんの
上に**丸の直径の5%ぶんの余白**を作る位置。証明写真と同じで、頭がぴったり上端に
付くと窮屈に見える。**割合で書いてあるので、吹き出し用(36px)と
ヘッダー用(54px)が同じ規則で揃う。**

### 6.24 ブリーフィング — 明るいのは吹き出しのほう(2026-08-07 / 反転 2026-08-09)

**暗い地に暗い吹き出しを置くと、輪郭が沈んで誰が何を言ったのか読み取れない。**
明るくする対象は2通りある。**地**を明るくするか、**吹き出し**を明るくするか。

> **吹き出しを明るくするほうを採る**(2026-08-09)。一度は地をクリームにして
> 吹き出しを紺のままにしたが、**この画面だけ地が他と違う**ぶん目が慣れず、
> かえって読みづらかった。地はアプリ共通の暗いまま、会話の塊だけを浮かせる。

色は `#scr-chat` の中で閉じた変数で持つ。

| | |
|---|---|
| 地 | **アプリ共通の暗いまま**。この画面だけ地を変えない |
| 吹き出し | `oklch(0.938 0.026 91)` クリーム。**暗い地に明るい塊**が乗る |
| 監督の吹き出し | 金。右寄せ。文字は暗いまま |
| 発言者の名前 | **本文と同じ濃さ**。落とすとクリームの吹き出しに沈んで誰の発言か読めない |
| 見出し・注記・選択肢 | **地の上に直接乗る**ので、周りの画面と同じ明るい字・濃い札 |
| 丸(秘書・監督・選手) | 暗いまま(周りの画面と同じ) |
| 覚醒の合図 | 濃い地の上の緑の光(元のまま) |

> **明るいのは吹き出しの中だけ。** 地・見出し・選択肢は他の画面と同じ暗い側に置く。
> 画面ごと地の色が変わると、行き来したときに目が慣れない。

> **アプリの外枠は暗いまま**。ヘッダー・タブ・引き出しは共通の部品なので触らない。
> 明るいのは「1節の相談をする部屋」だけ、という切り分けにしてある。

#### 見出しは相手クラブ

自クラブ名はアプリのヘッダーに常に出ている。ここで繰り返すより、
**VS + 今節の相手**を置いたほうがこの画面の役に立つ。副題は `第N節` だけ。

#### 出さないもの

- **`SEASON n ・ NODE n` の行**。節は見出しの副題に出ている
- **打ち手3つの説明文**。3つの違いは覚えるもので、毎節読むものではない
- **強化メニューの説明文**。同上(どちらも HELP には残してある)

会話が長いので、**毎節必ず読む場所に読まなくてよい字を置かない**。

#### 発言者にポジションを添える

選手の名前の右に **CF / GK** のような小さなタグを置く。
**誰を育てるかを決める画面**でもあるので、名前だけだと判断材料が足りない
(選手を選ぶ一覧のほうには前からポジションと OVR が出ている)。

#### 打ち手の呼び名

| 旧 | 新 |
|---|---|
| 訓練 | **強化トレーニング** |
| 交流 | **コミュニケーション** |
| 休息 | **休養** |

呼び名は `HANDS` の `label` が正本。**テストや drive.js で文字列を直接書かない**
(`handById("bond").label` を引く)。書き写していたせいで、名前を変えた瞬間に
drive.js が落ちた。

### 6.25 スポンサーの看板(2026-08-07)

**契約中だけ、次戦タイルの下に細い帯を敷く。**

```
────────────────────────────
OFFICIAL PARTNER    ダイナスティ財団
```

- 左に `OFFICIAL PARTNER`(モノスペース・小さく・くすませる)、右に**社名**(金)
- 上に細い罫を1本。試合の情報とは**別の層**に見せる
- 契約が無ければ**帯ごと出ない**。空欄や「—」を置かない

> **ピッチ脇の広告板のつもり。** 押せる要素を増やしたいのではなく、
> 「いま誰がこのクラブを支えているか」が視界の端に入っている状態を作るための飾り。
> だから位置は行き先(`> See Schedule`)の**上**で、タイルの主役にはしない。

### 6.26 発動した札を名前で見せる(2026-08-09)

**何が効いたのかが画面に出ていなかった。** エンジンは札を数値に畳む時点で
**名前を捨てて**いたので、「いま何が起きたのか」を言葉にできなかった。
`skillsOf` が名前を持ったまま畳むようにして、カットインに帯を出す。

```
        マエストロの一差し          ← 見出し(技名に変わる)
    [マエストロ] [決定力]           ← 発動した札。固有は金で光る
      キロス   VS   バチスタ
```

| | |
|---|---|
| どこに | 見出しの下、図の上。**最大2枚**まで |
| 誰の札か | **自分側の選手のもの**だけ(攻めていれば攻撃側、守っていれば守備側) |
| 固有スキル | 金の背景 + 光(→docs/03 §3.41)。普通の札は灰色の丸 |
| 出ない条件 | 倍率が1のまま(持っているだけで効いていない札は光らせない) |

> **54枚すべてが得をする改修**。固有スキルのために作ったが、
> 普通の札も「効いた瞬間」が見えるようになる。

### 6.27 秘書はクラブごと(2026-08-09)

**クラブを移れば秘書も替わる。** 誰になるかは**クラブIDから決まる**ので、
同じクラブに居る限り同じ人が座っている(節をまたいでも、セーブを跨いでも変わらない)。

| | |
|---|---|
| 素材 | `src/assets/art/secretary/*.png`(複数人が並んだ1枚。埋め込まれない) |
| 書き出し | `src/assets/secretary/sec01.webp …`(`tools/slice_secretary.py`) |
| 出る場所 | **HOME のひとこと**・クラブチャット・受信箱の丸。話し手の丸は3者とも同じ形(→§6.23) |

- 切り出しは**アルファの切れ目で人を分ける**。並びや人数が変わっても同じ手順で通る
- **既定では上段だけ**書き出す(`--rows=N` で増やせる)。使わない絵まで書き出すと、
  そのぶん index.html に埋め込まれて重くなるだけ
- 枠は**選手の立ち絵と同じ 420×500**、頭の上端 6% / 足元 97.5% に合わせてある。
  丸の切り出し(図の上から約38%)が選手と共通なので、**枠が違うと顔の位置がずれる**

> **絵を足しても JS は触らない。** 候補は `window.ASSETS.secretary` の並びそのもの。
> 人を増やしたければ素材を足して切り出すだけで、その日から配られる先が増える。

#### HOME のひとこと

顔 + 吹き出しで1行にする。**未読の印は丸の肩に付ける**(通知の印はアイコンに付くもの)。
見出しの「秘書」の真下に丸が来るので、印が見出しに被らないぶんだけ行を下げてある。

### 6.28 クラブカラーはパステル寄りのネオン(2026-08-10)

**暗い盤面の上に暗い丸を置くと、クラブの見分けが付かない。** 明度と彩度を上げて、
どの色も地から浮くようにした。

| | 前 | 後 |
|---|---|---|
| クラブカラー | `oklch(0.58 0.14 h)` | **`oklch(0.80 0.17 h)`** |
| 色相 | CLUBS の並びから黄金角(137.5°)で散らす | 変わらず |

出る場所: 試合のスコア帯の丸 / 足元の影 / カットインの座布団 / DECKの足元 /
任期カレンダーの点 / 交代の一覧。

> **丸の上に字が乗るところは、字を暗い側に 取る。** 明るい丸に白い字だと読めない。
> `clubInk()` が同じ色相の暗い色を返すので、**丸と字が必ず同じ家族**になる。
> 掛かるのは 交代の一覧の枠名・カットインのOVR・足元の★の3つ。

チャットの丸(秘書・監督・選手)も同じ調子に合わせた。こちらは絵が上に乗るので、
色は「誰が話しているか」を形以外で示すためだけに使う。

### 6.29 タイトルはステッカーの壁(2026-08-10)

**Pの丸いマークをやめて、ステッカーを一面に貼った壁にした。** ロゴを一点置くより、
「街の壁に勝手に貼られている」ほうがこのゲームの気分に合う。

素材(`src/assets/art/sticker/*.png`)は**白地の絵**なので、そのままでは白い四角が並ぶ。
`tools/slice_sticker.py` で切り抜く。ここが一番の勘所で、**単純な「灰色を消す」は使えない**
— 元絵は鉛筆画で、灰色こそが絵の本体だからだ。

1. `keyout_white` … **縁から連結した明るい画素だけ**をフラッドフィルで抜く(選手の絵と同じ考え方)
2. `peel_shadow` … 透明になった画素から内側へBFSし、**透明と隣り合う中間の無彩色(196〜245)だけ**剥がす。
   ステッカーの落ち影はここで消える。絵の内側の灰色には手が届かないので無事
3. `drop_specks` … いちばん大きい塊の2%未満のごみを落とす
4. 余白を詰めて**幅220pxのWEBP(q78)**へ。14枚で 277KB(元は 18.3MB)

**書き出し名は素材のファイル名がそのまま**(`scout.png` → `ASSETS.sticker.scout`)。
壁は全部を混ぜて使うが、HOME は絵を名指しで使う(→§6.30)ので、通し番号にはできない。

> **素材そのものを `src/assets/` の直下に置いてはいけない。** `build.py` は直下の画像を
> ぜんぶ base64 で埋め込むので、素材のサイズがそのまま index.html に入る(実際に一度やった)。
> **素材は `art/` の下、書き出しは `sticker/` の下**。
>
> **足すのは素材を置いて `python tools/slice_sticker.py` を流すだけ。**
> 壁は袋から配るので、枚数を意識する場所は無い。
> **名前は中身が分かるものにして、一度決めたら変えない**(HOME が名指しで使う)。

壁の敷き方は `titleWall()`。4列の升目を土台に、**同じ絵が隣り合わないよう袋から順に配る**
(毎回乱数で引くと同じ絵が固まって、壁ではなく壁紙に見える)。位置・角度(±25°)・
濃さ(0.58〜0.92)を散らす。

**種は起動ごとに振るので、壁は毎回ちがう。** 貼り替えられる壁のほうが街らしい。
揃えるのは**大きさだけ**で、セルの 0.95〜1.35 倍に収めてある。ここが広すぎると、
小さい絵は模様に、大きい絵は背景画に見えて、貼り紙らしさが消える。

| 悩んだところ | 落としどころ |
|---|---|
| 白い縁取りが素材に無い | `drop-shadow(0 0 1.5px #fff)` を3枚重ねて型抜きの縁を作る |
| 文字が絵に埋もれる | `.t-plate`(暗い板・−1.4°)に載せ、`.t-name` は柔らかい光ではなく**2pxの硬い縁**を持たせる |
| 版の表記が読めない | `.t-foot` に丸い暗い座布団を敷く |
| 起動直後に壁が途中で切れる | **要素の実測をあてにしない**。ビューポートと突き合わせて大きいほうを採り、2行多めに敷く |

### 6.30 HOME にステッカーを貼る(2026-08-10)

**タイトルの壁(→§6.29)と同じ素材を、HOME の余白に1枚ずつ貼る。**
タイルは文字だけで持たせていたので右側が空いていた。そこに行き先を絵で見せる。

| 場所 | 絵 | 選び方 |
|---|---|---|
| スカウトのタイル | `scout`(手帳を持つスカウトマン) | **固定** |
| チーム編成のタイル | `board`(戦術ボード) | **固定** |
| 次戦のタイル | `stadium` / `coach` / `fans` | **試合ごとに1枚** |

> **次戦のタイルの右上にあった光(`.nx::after` の橙の円)は外した**(2026-08-10)。
> 同じ角に飾りが2つ重なると、どちらも主張しきれずに濁る。
> 席をステッカーに明け渡して、絵を 132px → **190px** に大きくしてある。

- 次戦の絵は `hashStr(クラブ+シーズン+節)` で決める。**試合が変われば変わるが、
  描き直しても変わらない**。毎描画で引き直すと、HOMEに戻るたびに絵が飛ぶ
- 素材が無ければ `stickerArt()` は空文字を返す。**絵を消しても画面は崩れない**

#### 貼り方

```css
.tile-st{ right:-16px; bottom:-14px; width:84px; transform:rotate(-7deg) }
.tile-st .stk{ opacity:.42 }      /* 次戦のタイルは .30(文字が大きいので薄く) */
```

- **枠から少しはみ出させて、傾ける。** きれいに収めると枠の中の飾りになってしまい、
  「貼ってある」感じが出ない。`overflow:hidden` で切り落とすところまで含めて絵にする
- **文字を上に置く**(`.tile-t/.tile-s/.tile-i` に `z-index:1`)。絵は下に潜らせる
- 白い縁は素材に無いので、§6.29 と同じく白の `drop-shadow` を重ねて型抜きの縁を作る

> **書き出し名で名指しするので、素材のファイル名を変えてはいけない。**
> 最初は `st01`〜`st14` の通し番号にしていたが、**素材を1枚足すと番号がずれて
> スカウトのタイルにスタジアムが出る**。素材名(`scout.png`)をそのままキーにして、
> 番号に依存しないようにした(→tools/slice_sticker.py)。

### 6.31 任期カレンダーの飾り(2026-08-10)

**96個の枠が同じ顔で並ぶ表なので、「いま」と「狙える大会」だけを立たせる。**

#### 出られない大会はトーンを落とす

カレンダーには**出られない節の開催予定も並べてある**(→docs/03 §3.23)。
先の予定が全部消えると次に何を狙うか決められないからだが、
狙える大会と同じ強さで並ぶと、**いま何ができるのかが埋もれる**。

| | 見た目 |
|---|---|
| エントリーできる | 文字はそのまま ＋ **トロフィーのステッカー** |
| 大会が進行中 / 間隔待ち / 条件を満たさない | 文字を `--text-dim`／`--text-mute` に落とし、**絵は付けない** |

> **理由の但し書きは書かない**(2026-08-10 に外した)。
> 「開催予定（条件を満たせば参加できます）」のような一文を全部の行に添えていたが、
> 出られるかどうかは**文字のトーンで分かる**し、条件そのものは日程タブが持っている。
> 96行ぜんぶに但し書きが付くと、カレンダーが注意書きの列になる。
> 残すのは「他N大会と同日・選べます」だけ — これは**その節にしか無い情報**なので。

判定は `cupCalNote()` の `open`。塞いでいるもの(進行中の大会・`TUNING.cup.rest` の間隔・
参加条件)が**ひとつでもあれば付けない**。理由ごとに書き分けた文はそのまま残す。

#### 済んだ節には飾りを置かない

**読みたいのはスコア**なので、消化した行からは絵を外してある(2026-08-10)。

- カップ戦の記録に貼っていた**トロフィーの絵は出さない**。右端のスコアと重なって読みにくい
- **打ち手の絵文字(💪🤝🛌📣)も出さない**。何をしたかは `title` に残してある

打ち手の絵文字は**ブリーフィングの選択肢からも外した**。選ぶのは3つだけで、
文字を読めば分かる。絵文字は行を賑やかにするが、意味は増やしていなかった。

#### いまの節はロッカーの絵

現在節のタイルにだけ `locker` を貼る。**並んだ枠の中で1枚だけ絵が入る**ので、
数字を読まなくても「ここが今日」だと分かる。

あわせて**見出しを行き先そのものにした**。前は見出しが「この節の準備」で、
押したら何が起きるか(「第N節を開始する」)は右下に小さく置いていた。
タイルの用は1つしかないので、行き先を見出しに上げて、右下の案内は消した。
話しかけたあとの進み具合(「準備完了 ／ 試合へ向かえます」)だけを下に添える。

> **素材の側の限界。** トロフィーの絵は**本体も飛沫も同じ黄緑**なので、
> 行の高さ(50px弱)では形まで読めない。拡大しても、窓を作って寄せても、
> `contrast` を上げても変わらなかった(全部試した)。
> いまは「貼り紙が枠からのぞいている」印として置いてある。
> 形を読ませたいなら、**絵の側に濃淡を入れる**か、行を高くするしかない。

### 6.32 スポンサーの看板(2026-08-10)

**契約中のスポンサー(→docs/03 §3.40)を、ピッチ脇の広告板として出す。**
社名の文字だけだと「設定」に留まるが、看板の絵があると**クラブに金が付いている**感じが出る。

| 場所 | 出し方 |
|---|---|
| HOME の次戦タイル | `OFFICIAL PARTNER` の見出しの右。**社名の代わりに看板が入る** |
| キックオフのカットイン | 両チームのキャプテンの下。帯の幅の72% |

- 絵は**スポンサーの id で引く**(`ASSETS.banner["dynasty"]`)。無ければ**今までどおり社名**
- 23社ぶんを一度に描けるわけがないので、**絵のある会社と無い会社が混ざる前提**で作る。
  見出し(`OFFICIAL PARTNER`)は常に出して、枠だけは揃えておく

#### 絵の作り方

依頼書は [`src/assets/design/sponsor-banner-prompt.md`](../src/assets/design/sponsor-banner-prompt.md)。

1. **1シートに4社ぶんを縦に並べて**描いてもらう(1024×640 / 1段 1024×160)
2. `python tools/slice_banner.py <シート> <id> <id> <id> <id>` で縦4等分 → 幅640のWEBP
3. `python build.py` で埋め込む

> **生成AIはキャンバスサイズを守らない**ので、サイズではなく**割り付け**(縦N等分)を
> 守ってもらい、受け取った画像を等分して切る。選手の立ち絵と同じ考え方(→§6.29)。
>
> **看板は矩形の広告そのもの**なので、ステッカーや立ち絵と違って**背景を抜かない**。
> 切り出しは等分と縮小だけで済む。

#### 依頼で外せない3つ

| | なぜ |
|---|---|
| **社名の文字は板の高さの45〜60%** | 実際に出るのは横350px。ふつうの広告の比率だと読めない |
| **ラテン文字だけ** | 日本語は崩れる。実際のピッチ脇の看板もラテン文字が多い |
| **真っ黒と山吹色を大面積で使わない** | 暗い画面に沈む／主役の金色と喧嘩する |

### 6.33 タイトルを明るくする(2026-08-10)

ステッカーの壁(→§6.29)を敷いたあと、**題字も打ち手も暗いままだった**ので、
壁だけが賑やかで中央が沈んで見えていた。**中央を明るい札に寄せる**ことで直した。

| | 前 | 後 |
|---|---|---|
| 題字の札 | 暗い板(`oklch(0.13 …)`) ＋ 金の細い枠 | **クリームの札** ＋ **白フチ7px** |
| 題字の色 | 白 ＋ 影と滲み | **濃紺の字**(明るい地なので縁は不要) |
| `Ball` | `--accent`(山吹) | **濃いオレンジ**(クリームの上で沈まない色に) |
| 打ち手 | 金の細い線 ＋ 薄い字 | **塗りつぶした札** ＋ 白フチ |
| 覆い(`.t-scrim`) | 中央 97% | **中央 74%**。札が読ませる役を持ったので薄くできる |

- **暗い札は壁に穴を開ける。** 貼り紙の壁の真ん中に暗い矩形を置くと、
  そこだけ絵が抜けたように見えて画面がしぼむ。壁と同じ**白フチの貼り紙**にすると、
  題字が「いちばん大きいステッカー」として壁の一部になる
- **打ち手の脈動で明るさを落とさない。** 前は `opacity:.55` まで落としていたが、
  これは「点滅」ではなく「暗い」と読まれる。**光の輪だけを呼吸させる**形に変えた
- 明るい地に変えたので、**金色は使えない**(クリームの上で読めない)。
  `Ball` と字の色はそれぞれ濃い側へ寄せてある

### 6.34 固有スキルの帯を派手にする(2026-08-11)

**バッジだけでは「何か出た」が試合の速さに埋もれる。** 金の札(→§6.26)は付いていたが、
カットインは他と同じ見た目だったので、固有スキルが出た瞬間が流れていってしまう。
**帯ごと様子を変える**。

| | 中身 |
|---|---|
| 地と縁 | 暖色の地 ＋ **金の縁** ＋ 内側に金のにじみ |
| 掃引の光 | 白→**金**。速さも 1.1s → **0.7s** |
| 見出し | 金にして、字間を広げ、光を回す(技名がここに出る) |
| **きらめき** | 8点が時間差で瞬く |
| **揺れ** | 帯が出た瞬間に一度だけ揺れる(`.mcut.shake` を流用) |

```
判定 → 固有スキルが出た → 帯に .sig → 金の帯・きらめき・揺れ
```

- **きらめきの位置と間は固定**。毎回散らすと帯がちらついて、肝心の技名が読めない
- **掃引は濃くしすぎない**。`.55` だと通った瞬間に選手の顔が飛ぶので `.38` に留めた
- 揺れは `cutShow` が帯に `.cut.sig` を見つけたときだけ掛ける。
  ゴールの揺れと同じ仕掛けなので、**新しい仕組みは足していない**

> **帯は3種類ある。** マッチアップ(`cutVs`)・パス(`cutPass`)・シュート(`cutShot`)。
> 最初はパスの帯を直し忘れていて、**ベッカムの「精密機械」が出ても見た目が変わらなかった**
> (クロスの札なので、通ればパスの帯になる)。3つとも同じ扱いにすること。
>
> **固有スキルが出たら、抽選で間引かない。** パスの帯は `cutPass` の確率で、
> 枠外は `cutMiss` の確率で間引いている。12人しか持っていない札が出た瞬間まで
> 間引かれると、**出たこと自体に気付けない**。`sigIn()` が立ったら必ず出す。

### 6.35 一覧のページ送りと、戻せない操作(2026-08-12)

#### CARDS のページ送り

所持カードは任期をまたいで増え続けるので、**1ページ12枚**で区切る。

- **1ページに収まるときはページ送りを出さない**。要らない操作を置かない
- **絞り込みを変えたら1ページ目へ戻す**。前のページ番号が残ると空振りする
- 売って減ってページ数が縮んだら、最後のページへ寄せる
- ページを送ったら一覧の頭までスクロールを戻す

#### 戻せない操作は二段にする

売却(→docs/10 §3.46)は**押し直しで確定**にした。

```
[売却する] → [本当に売る]（赤・「この操作は戻せません」を添える）
```

- **同じ見た目のまま二度押させない**。確認の段はボタンの色を変える
- カード詳細を閉じたら確認は解ける(開き直したら最初から)
- 売れないカードは**ボタンを消して理由を置く**。押せるのに何も起きない、を作らない

### 6.36 チャットに実在感を出す(2026-08-12)

**色ではなく「型」で本物らしくする。** 地とクリームの配色(→§6.24)は動かさず、
**普段使っているメッセージアプリと同じ振る舞い**を足した。

| | 中身 |
|---|---|
| **まとまり** | 同じ人が続けて話したら、顔と名前は**最初の1回だけ**。行間も詰める |
| **尻尾** | まとまりの**先頭の吹き出しだけ**に付ける |
| **時刻** | 各発言の足元に。**節から決まる**ので開き直しても同じ |
| **既読** | 監督の最後の発言に付く(相手が読んだ、という形) |
| **日付の区切り** | 会話の頭に「第N節　試合当日」の丸い札 |
| **壁紙** | ごく薄い斜めの綾。ベタ塗りの地は「UI」に見える |

- **いちばん効いたのは"まとまり"。** 秘書が5行続けて話すとき、顔と名前が5回並ぶと
  帳票に見える。1回にするだけで会話になる
- **尻尾を全部に付けない。** 続きの吹き出しにも付けると縁が鋸の歯になる
- **時刻は決定的に作る**(`chatClock`)。実時間で作ると、開き直すたびに
  会話の時刻が動いて嘘になる。9時過ぎから2〜3分おきに話している体
- 壁紙は**柄が読めるほど濃くしない**。読むのは文字であって背景ではない

> **時刻は「発言」ではない。** 秘書は数字を読み上げない決まり(→docs/03 §3.35)があり、
> drive.js が chatLog の文字を見て検査している。時刻を足したらそこに引っかかったので、
> **検査の対象を吹き出しの中(`.ch-b`)に絞った**。画面の飾りと発言は分けて数える。

### 6.37 軸(KP)を盤面で読ませる(2026-08-17)

軸(→[03. §3.44](03-game-design.md))は指名の引き出しの中にしか出ていなかった。
**いま誰を軸にしているのかを見るために、試合を止めて引き出しを開く**必要があり、
指名した実感も無かった。

#### ピッチで光らせる

`.mp.kp` に**クラブカラー(`--kit`)の発光と、足元で呼吸する輪**を付ける。

- **両チームぶん出す。** どちらの軸かは**色で読む**
- 関与中(`.on`)や競り合い(`.vs`)は**一瞬の印**なので足元のリングを使っている。
  軸は**続いている状態**なので、絵そのものの発光と別の輪で分けた
- 指名した瞬間・自動で外れた瞬間の両方で `mKpMark()` を呼ぶ。
  描き直しのときだけ更新すると、**指名しても次のイベントまで光らない**

#### 引き出しは「11人が一度に見えること」が要件

試合を止めて開く画面なので、**送って探すぶんだけ試合が止まる**。
11人が入らないなら、入るまで削るのが正しい。

| 削ったもの | どこへ行ったか |
|---|---|
| 軸の効果の説明(3行) | **DECK のヘルプ**へ。試合画面は止めてはいけないのでヘルプを持てない |
| 相手の軸の行 | **ピッチの光**へ |
| 「ピッチ」の見出し | 控えは並ばないので元から要らなかった |
| 名前の下の固有スキル | **名前の横**へ。縦に積むと1人ぶんの高さが倍になる |

行の詰めは `#kpDrawer` の中だけに効かせる。**`.sb-r` は交代の引き出しと共用**で、
あちらは控えも並ぶぶん行数が違う。

#### 高さはピッチの実寸から取る

引き出しは**ピッチと同じ上端・同じ高さ**にする。盤面の代わりに開く画面なので、
覆う範囲が盤面と一致していると、開いても位置の感覚が途切れない。

**割合(`height:74%`)で決め打ちにしない。** ピッチは `aspect-ratio:3/4` で
幅から高さが決まるので、端末が変われば高さも変わる。`openKp()` が
**開くたびにピッチを実測**して `top` と `height` を入れる。

行の高さはその中の割り当てで決まる。**1行 38px**(11行 + 見出しでピッチの 472px に収まる)。
最初 32px まで詰めたが押しにくく、逆に 9px の余白まで広げると **31px はみ出した**。

> **収まりと押しやすさは両方テストで見る。** 「入るはず」で置いた値は、
> フォントや端末で崩れる。drive.js が
> **①11人目の下端が引き出しからはみ出していないか ②引き出しとピッチの上端・高さが
> 一致しているか ③1行が 30px を下回っていないか**を、実際の描画から測っている。

#### 選んだら閉じる

采配(→§6.22)と同じ作法。**指名は1人だけ**なので、選んだあとに開いたままでも
続きの操作が無い。閉じれば試合がそのまま再開する。

### 6.38 采配を盤面に出し、タブを分ける(2026-08-17)

采配(→[10. §3.50](10-design-log.md))は指示の引き出しの下に間借りしていて、
**開かないと何を敷いているのか分からなかった**。相手が何で来ているのかは
どこにも出ていなかった。

#### 画面外から差し込む帯

ピッチの**対角**に、クラブカラーの半透明の帯を出す。

| 位置 | 誰の |
|---|---|
| **右上** | 相手 |
| **左下** | 自分 |

- **画面外から伸ばす**(`right:-3cqw` / `left:-3cqw`)。`.pitch` は `overflow:hidden` なので
  端で断ち落ちて、**盤面の一部ではなく外から掛かっているもの**に見える
- 対角に置くのは「自分は必ず下」(→§6.17)の延長。**位置でどちらかが読める**
- 敷いていなければ帯ごと消える。**空の枠は出さない**
- 出すのは **`_M` のチームが実際に持っている采配**であって、次の試合の設定ではない

#### TAC タブを分ける

左端は上から **KP → TAC → 指示**。**采配は指示より上位の構え**なので、
上下の並びがそのまま「どちらが土台か」を表す。

**敷けるものだけを並べる。** 試合を止めて開く画面なので、
「覚えていない手」「この陣形では使えない手」を混ぜると選ぶまでが遠くなる。
何を目指せば増えるのかは **`ほかに N 手（熟練度と陣形の条件があります）` の1行**で足りる
(条件つきの一覧を見せるのは、覚える場面 →[10. §3.51](10-design-log.md) の仕事)。

選んだら閉じる。敷いているあいだはタブが光る(軸タブと同じ作法 →§6.37)。

> **試合中に敷き替えられるようにした。** それまで `setTeamTactic` は
> `createMatch` からしか呼ばれず、試合中に選んでも**次の試合まで何も起きなかった**
> (トーストは「次の再開から」と嘘をついていた)。
> 引き出しを分けて盤面に出す以上、押して何も起きないままにはできない。
>
> **掛け直せるようにするのが要点。** 采配は札を `push` し、`k` を掛け算で混ぜるので、
> 素の状態を控えずに2度呼ぶと**前の采配が乗ったまま重なる**。
> `p.sk0` / `p.fit0` に素を控え、毎回そこまで戻してから掛け直す。
> **指示の掛け直しも忘れない**(上げ下げと能力の倍率は采配と合成している)。

### 6.39 試合中の引き出しを揃える(2026-08-17)

軸・采配・指示・交代の4つが、**別々に書かれたせいで別々の作法になっていた**。

#### 左端の3つは同じ見た目にする

`#kpTab` / `#tacTab` / `#ordTab` を**1つの規則にまとめた**。
別々に書いていたら KP だけ縁が明るく(`--accent`)、TAC と ORD が沈んで(`--accent-dim`)
いて、同じ役割のものが違う階層に見えていた。

違うのは**縦の位置と、効いているときの光り方**だけ。上から **KP → TAC → ORD**。

> **ORD だけは光らせない。** 指示は「無指示」も普通の状態なので、
> 光を「何かが効いている」の合図に使えるのは軸と采配だけ。

#### 3つは1本の柱に見せる(2026-08-18)

縦位置を割合(30/45/60%)で置いていたので、**高さ60pxのタブに対して 50〜58px** も
空いて、3つが別々の飾りに見えていた。

- **間隔は px で決める。** `top` は中心なので、
  `calc(50% ± 76px)` で並べれば画面の高さが変わっても隙間が一定になる
- **高さを揃える。** KP は2文字・TAC/ORD は3文字なので、字数まかせだと背が違い、
  中心を等間隔にしても**下だけ 9px 重なった**。`height:70px` で固定して解いた

いまは高さ70px・間隔6px。

> drive.js が**間隔が 16px を超えないこと・重ならないこと・上下で揃っていること**を
> 実際の座標で測っている。

#### 開いた面も揃える — `.hd-in` は右から出る形

引き出しの面は `.hd-in` を共用しているが、これは**右から出る引き出し**(HELP など)の形で、
`border-radius:12px 0 0 12px` / `border-right:none` / 影も左向きに書かれている。

左から出る3つはこれを**左右反転しないといけない**。ところが打ち消しを
`.od-in`(クラス)で書いていたため、**あとから定義されている `.hd-in` に負けていた**。
KP だけ `#kpDrawer .sb-in`(ID付き)で書いてあったので生き残り、
**KP だけ右角が丸く、TAC と ORD は四角い**という食い違いになった。

```css
#kpDrawer .hd-in, #tacDrawer .hd-in, #ordDrawer .hd-in{ ... }
```

**同じものは同じ場所に1回書く。** 打ち消しをクラスで書くと、
共用しているクラスの定義位置しだいで勝ち負けが変わる。

> drive.js が **3つの面の角丸と枠を computed style で突き合わせている**。
> 「ID付きなら勝つ」は書いた本人にしか見えないので、目で見張らない。

タブ名は **ORD**(旧「指示」)。KP / TAC と同じ3文字の略号にそろえた。

#### 説明文を全部落とす

**試合を止めて開く画面に読み物を置かない。** 読んでいるあいだ試合は止まっている。

| 落としたもの |
|---|
| 「いま出している指示: ○○（もう一度押すと解除）」 |
| 指示の効果説明(「攻撃重視。前に出るぶん…」) |
| 「ほかに N 手（熟練度と陣形の条件があります）」 |
| 「スタミナの少ない選手から替えます。一度下がった選手は戻れません。…」 |

十字に並んだ5手は**形そのものが意味**で、選ばれている手は色で分かる。
交代のスタミナは**バーの色**で分かる。落として困るものは何も無かった。

#### 同時に開けるのは1つだけ

4つとも試合を止めて開くので、重なると**どれを閉じれば再開するのか**が分からない。
開くときに他を畳む。

**止めた/戻すの管理を1つにまとめる**のが要点。引き出しごとに
「自分が止めたか」を持たせていたので、**別の引き出しへ移った瞬間に
再生と停止が二重に走っていた**。いまは `_drawerPaused` 1つで、
「何も開いていない状態から開いたとき」だけ記録する。

> drive.js が **KP → TAC → 交代 → ORD と渡り歩いて、常に1つだけが開いていること**、
> **移動中も止まったままであること**、**閉じたら再開すること**を見ている。

### 6.40 発動した札を、その選手の下に置く(2026-08-17)

カットインの札(→§6.26)は**見出しの下に中央寄せで並べていた**。
2人が出ている帯では、**どちらの選手の札なのかが読めなかった**。

札は片方だけのものとは限らない:

| 帯 | 同時に出るもの |
|---|---|
| マッチアップ | **攻めた側と守った側**(`sk` と `dsk`) |
| シュート | 撃った側 |
| パス | 出した側 |

中央に置くと、この3つが全部同じ見た目になる。

#### 直し方 — `cutFig` が札を持つ

札を `cutFig()` の中へ移し、**アバターと名前の下**に置いた。
これで札は必ずどちらかの選手の中にあり、位置がそのまま持ち主を表す。

**両方出すようにした。** それまでは自分側の札しか描いておらず、
相手が対人守備で止めていても画面には出てこなかった
(「相手は何もしていない」ように読めてしまう)。

金の縁(→§6.34)は**持ち主の札にだけ**付く。帯そのものの金枠は
どちらかに固有スキルが出れば光る(出た瞬間を見逃さないための演出なので、
相手の名選手が出したときも光ってよい)。

> drive.js が **選手名から枠を引いて、その枠の中の札が本人のものか**を見ている。
> 「中央に `.cut-sk` が残っていないこと」も併せて見張る。

### 6.41 結果画面の行き先を下に貼り付ける(2026-08-17)

試合結果は **1,678px**(端末の2画面ぶん)ある。採点14人ぶんと試合収益と他会場が
続くので、**次へ進むたびにいちばん下まで送る**必要があった。
読みたいときだけ送ればよいものが、毎回の作業になっていた。

`position:sticky; bottom:0` で下に貼り付ける。

- **`fixed` ではなく `sticky`。** 最後まで送ったときは元の位置(他会場の下)に収まるので、
  **末尾の内容が帯の裏に隠れたままになる、が起きない**
- `.pad` の左右余白ぶん食い出させて全幅にする(下を流れる採点が横から覗かない)
- 上端は**ぼかす**。硬い線で切ると、そこで内容が終わって見える
- この画面は `chrome:"bare"` でタブ帯が無いので、貼り付く先は端末の下端そのもの

CARDS の一括売却の帯(→§6.35)と同じ作法。**送らないと押せない**を作らない。

> drive.js が **いちばん上でも、いちばん下でも、行き先が同じ位置に見えていること**を
> 実際の座標で測っている。あわせて「そもそも送る必要がある画面か」も見ている
> (内容が1画面に収まってしまうと、この検査は何も検査していないことになる)。

### 6.42 スケジュール画面まわりの手当て(2026-08-17)

#### 節目は行き先まで連れていく

全日程を終えたあとの任期カレンダーは
「**全日程を終了。HOMEで今季を終えられます**」と**書いてあるだけ**だった。
読んだ人は自分で HOME タブを押しに行くことになる。

行そのものを押せるようにして HOME へ送る。受信箱の案内(→§3.43)と同じ作法で、
**指示を書いたら、そこへ行く手段も同じ場所に置く**。

見た目も変えた。点線の枠のままだと「まだ何も無い枠」に見えるので、
**押せる行は実線に戻し、右端に行き先(`HOMEへ ›`)を書く**。

#### 右端の柱の名前と見出し

| | 前 | いま |
|---|---|---|
| タブ | 契約 / **日程** | 契約 / **Entry** |
| 見出し | **契約** / **大会と参加条件** | **CONTRACT** / **ENTRY** |

見出しは他の引き出し(KEY PLAYER / TACTICS / ORDER / SUBSTITUTION)と同じ
英字の大文字にそろえた。

#### ENTRY — 説明を消し、戦っている大会を光らせる

頭にあった「条件を満たした大会は…」の説明を落とした。
**並んでいる札そのものが一覧**で、出られるかどうかは各行の状態に書いてある。

かわりに**エントリー中の行を光らせる**(`.comp-card.live`)。
9つ並ぶ中で「いま戦っているのはどれか」が読めないと、次にどこへ行くか決められない。
リーグは常に戦っているので常に光る。

> drive.js が **光る行の数**を数えている(リーグ1つ + 進行中のカップがあれば1つ)。
> 「説明文が残っていないこと」も併せて見張る。

#### CONTRACT にスポンサーの看板を出す

契約の話をしている場所なので、**相手の顔が見えるほうが「どこと組んでいるか」が残る**。
絵(→§6.32)のある会社は看板で、無い会社は社名のまま。
23社ぶんの絵が揃うまでは混ざるので、**絵の有無で行が消えたりしない**ようにしてある。

### 6.43 「1ゴールで2点入る」の正体(2026-08-17)

**エンジンは正しかった。** 得点を増やす場所は1か所しかなく、
7,000試合で `score === goalイベントの数` が一度も崩れなかった。
壊れていたのは**再生ループ**のほう。

#### 何が起きていたか

`mTick()` は1ティックぶんのイベントを配列で受け取り、1件ずつ見せる。
止めると途中で降りるが、**再開すると `stepMatch()` をやり直していた**。

    止める前:  [起点, 連鎖, ゴール, 起点, …]   ← 3件目まで見せて停止
    再開後:    stepMatch() を呼び直す           ← **残りは捨てられる**

捨てた中にゴールがあると、次に出たイベントが持っている `hg/ag` で
**点が一気に2つ増える**。これが「1ゴールで2点」の正体。

もう1つ、`mPause(false)` が**保留中のタイマーを消さずに** `mTick()` を呼んでいた。
止める前の周回が生き返り、開け閉てのたびに**再生ループが1本ずつ増える**。

**引き出し(軸・采配・指示・交代)は開くたびに止めて閉じるたびに再開する**ので、
試合中に一度でも開けば、どちらも踏む。

#### 直し方

- **見せ残しを持つ**(`_mEvs` / `_mIx`)。再開は**続きから**で、
  残りが無いときだけ次のティックを解く
- **周回に札を持たせる**(`_mRun`)。あとから始まった周回が札を進めるので、
  取り残された古い周回は次の一歩で自分から降りる
- 再開の前に**保留中のタイマーを消す**

#### 実測(止めて再開を70回はさみながら1試合)

| | エンジンのゴール | 画面に見せた | 点が2つ以上飛んだ |
|---|---|---|---|
| 直す前 | 7 | **4** | **2回**(2→4, 4→7) |
| 直したあと | 2 | 2 | **0** |

> **不具合の場所を、症状のある層で探さない。** 「点が2つ増える」と聞いて
> まず得点の計算を疑ったが、そこは 7,000試合で無傷だった。
> **不変条件(`score === goalイベントの数`)を先に確かめた**ので、
> 見るべき層が1回で絞れた。

### 6.44 HOME のタイルを4枚にする(2026-08-17)

スカウトとチーム編成の下に**移籍市場**と**実績**を足した。
あわせて**次戦のタイルを小さくした** — 下が4枚に増えたので、
ここが重いと「次に触るもの」が画面の外へ押し出される。

#### タイルは「いま行く理由があるか」だけを返す

中身は開けば分かる。タイルの仕事は**開く価値があるかを1行で言うこと**。

| タイル | 出すもの |
|---|---|
| 移籍市場 | **WC以上が居れば「WC がエントリ中」**、居なければ登録人数 |
| 実績 | **獲った数 / 全部** と、**次に狙うもの** |

実績の「次」は、棚(→[03. §3.36](03-game-design.md))が易しい順に並んでいるので
**まだ獲っていない先頭**をそのまま出せばよい。

#### 市場の絵は、いちばん強い WC の枠で決まる

| 枠 | ステッカー |
|---|---|
| FW | shoot |
| MF | dribble |
| DF | striker |
| GK | gk |

**該当が無ければ空**にする(→§6.30 の「無ければ出さない」)。
絵が出ているかどうかが、そのまま「行く価値があるか」の合図になる。

> **抽選まかせの見た目は、抽選を差し替えて確かめる。** 市場に WC が並ぶ回は
> そう多くないので、drive.js は `marketList` を差し替えて**4つの枠を全部**通す。
> 「一番強い WC の枠で決まること」「居なければ空になること」も同じ場所で見る。

### 6.45 色を鮮やかにする / 背景を選べるようにする(2026-08-17)

#### 色は hex をそのまま置く

インクカラーは**見本で hex を指定してもらった**ので、oklch に置き換えず
**そのまま持つ**。#F8FF26(レモン)のような蛍光に近い色は、
明るさと彩度から作り直すとほぼ必ず鈍る。

    { id:"ink-lemon", hex:"#F8FF26", name:"インクレモン" }

あわせて**サッカーで実際に使われる色**(レッド・クリムゾン・ネイビー・
フォレスト・マルーン・ゴールドなど13色)を足して、全26色。

> **地の明るさで字の色を変える。** レモンや白の上に白字を置くと消える。
> `embLum()`(sRGBの相対輝度)で 0.62 を境に黒字と白字を切り替える。
> 色を増やすときに必ず踏むので、色ではなく**明るさ**で判定する。

#### 背景は端末枠の外側

`body` に着せるので、**盤面(`#app`)の中は一切変わらない**。
どれを選んでも画面の読みやすさは同じ。

| | 中身 |
|---|---|
| **ピッチ** | **既定**。芝の縞とセンターラインを CSS で敷く |
| ブラック | 盤面に集中する |
| ロゴウォール | **会見のバックボード**。白地に斜めの帯で `P-FootBall` を敷き詰める |

既定は `BG_DEFAULT` の1か所だけが持つ。**背景を選んだことが無いセーブもここに落ちる**ので、
既定を変えると古いセーブの見た目も変わる(選んだ人の設定は残る)。

ロゴウォールは**本物の要素**で敷く。

> **データURIの SVG では、ページに埋め込んだフォントが使えない。**
> データURIは別の文書として読まれるので `@font-face` が届かない。
> タイトルと同じ Oswald(`--f-head`)で出したかったので、
> 背景画像をやめて DOM で組み、CSS のフォントをそのまま効かせた。
> **敷き詰めではなく1枚の層**にしたので、継ぎ目も消えた
> (タイル方式では 45度の帯が端で切れて繰り返しが見えていた)。

色はインクカラー13色を**行ごとにずらして**配る。同じ色が縦に並ぶと縞に見えるので、
行番号に素数を掛けて回す。

入口は CLUB の監督欄の右端に置いた歯車。**設定はここに集める**。

### 6.46 監督のカットイン(2026-08-18)

監督は下見(→[10. §3.56](10-design-log.md))にしか出ていなかった。
**試合の中でも顔を出す**と、誰と戦っているのかが盤面に残る。

| いつ | 何が |
|---|---|
| **キックオフの直後** | 敷いている采配の帯。**両軍にあれば2本同時** |
| **采配を敷き替えたとき** | その1本だけ |

**キックオフの帯に監督は載せない。** 一度そうしたら、選手・監督・看板が同じ帯に
積み上がって縦に肥大した。**段を分けて、開始 → 采配、の順に見せる**。

#### 帯は上下に分けて左右から走らせる

| | 位置 | 走る向き | 色 |
|---|---|---|---|
| 自軍 | **上** | 左から | 自クラブのカラー |
| 敵軍 | **下** | 右から | 相手クラブのカラー |

**どちらの手かを位置と色だけで読ませる。** 文字で「自軍」と書く必要が無くなり、
2本同時でも一目で分かる。顔は**バストアップ**で抜く(切り出しはチャットの丸 →§6.23
や契約書と同じなので、枠が違っても顔がずれない)。掛け声(`TACTICS[].line`)も添える。

#### 札は選手の絵に重ねる

発動した札(→§6.40)の置き場は、**3手かかった**。

| 置き方 | 何が起きたか |
|---|---|
| 選手の**下** | 札の数だけ帯が縦に伸びて**カットインが肥大**した |
| 外側の**端**(幅を切る) | 枠に収まらず**札の名前が途中で切れた** |
| 絵の**真ん中**に重ねる | 全文は載るが**選手が完全に隠れた** |
| **外端に整列 + はみ出しは絵の上**| 選手が見えたまま全文が載る ← いま |

- 左の選手は**左端**、右の選手は**右端**に揃える(`left/right:-14%`)
- 収まらないぶんだけ**内側(選手の上)へ伸びる**。地は半透明(74%)なので下の絵は透ける
- 縦は**絵の上のほう**(`top:34%`)。真ん中に置くと選手の名前を覆う

> drive.js が **①省略されていないこと(`scrollWidth` が収まっている)
> ②選手の名前に被っていないこと ③外端に寄っていること**を実際の座標で測っている。
>
> **帯との絶対位置では測れない。** 図は `translateX(-60px)` で滑り込んでくるので、
> 測る瞬間によって位置が変わる。**枠との相対**で見ること(実際に誤検知した)。

> **掛け声は 0.62 秒遅れて出る**(`.cut-word` の animation-delay)。
> 撮るときはそのぶん待つ。待たずに撮って「掛け声が出ない」と誤診した。

> **見た目の検査は、engine の状態ではなく DOM を待つ。** 采配は
> エンジンが掛けた時点ではなく**そのイベントが再生された時点**で帯が出るので、
> `T.tactic` を見て待つと1拍早く、検査が不安定に落ちる。実際に何度も揺れた。

### 6.47 就任先の選び方を分かるようにする(2026-08-18)

新しいキャリアを始めると、いきなりクラブの一覧が並んでいた。
**何が起きていて、次に何をするのか**が書かれていない。

導入の札をひとつ置く。オーナーのタイル(→§6.8)と同じ組み立て。

    ［就任のご案内］
    あなたに 5件 のオファーが届いています。
    無名の監督に声をかけたクラブがあります。
    どこから始めるかで、これからの道のりが変わります。
    カンピオナート　最上位 ゴイアニア・エスメラウジーノ（格★3）
    > 向かうクラブを選んで、契約を結びましょう

**出来事にしてから、次にすることを最後の行で示す。** 一覧そのものは変えていない。

#### 一枚目と二枚目で言うことを変える

| | 見出し | 本文 |
|---|---|---|
| **初就任**(`!S.club`) | 就任のご案内 | 「無名の監督に声をかけたクラブがあります」 |

一枚目は**これから監督人生が始まる**という話、二枚目からは**積み上げた名声の結果**。

#### 裸の数字を置かない

各行の右端に必要名声を出していたが、名声0のうちは **`0` が縦に5つ並ぶ**だけで、
何の数字なのか読めなかった。**要るときだけ数字を出し、要らないときは「いつでも」**と書く。

### 6.53 節の枠は高さをそろえる(2026-08-19)

スケジュール(SEASON / FIXTURES)の節タイルは、中身の行数がまちまちで
**4通りの高さが混ざっていた**。

| 枠 | 中身 | 高さ |
|---|---|---|
| 空枠(`.cal.none`) | 「未定」だけ | 28px |
| 予定(1行) | 大会名だけ | 39px |
| 予定(2行) | 大会名＋補足 | 42px |
| **済んだ節** | 相手＋「S1 第1節 ／ AWAY」 | **60px** |

読みたいものは「何節に何があるか」だけなので、行数の差がそのまま高さの差に
出る必要がない。**いちばん背の高い「済んだ節」を基準**に `.cal` へ
`min-height:60px` を置いてそろえた。

空枠だけは以前 `padding` を削って詰めていた(96〜120枠あるため)。
これも外した。**そこだけ背が低いと、かえって並びが不揃いに見える。**
字は小さいまま、枠の大きさだけ他と同じにしてある。

**代わりに一覧は縦に伸びる。** 空枠が 28 → 60px になるので、任期の後半を
見渡すときのスクロールは増える。並びの均質さを取った判断(→docs/03 §3.29)。

### 6.54 いまの節に、監督と秘書を立たせる(2026-08-19)

いまの節のタイルは**ロッカーの絵**だけで「ここが現在地」を示していた(→§6.31)。
そこへ**監督と秘書**を並べ、ロッカーを背にした一枚にした。
狙いは1つ、**これからブリーフィングに向かう**という手触り。

#### 枠は付けない。切るのは「画角」に見せる

- **枠も丸めも付けない。** 付けた瞬間にアイコンになり、その場に立っている感じが消える
- **膝下はタイルの下端でぴったり切る。** 切り口をタイルの縁に合わせると
  **カメラの画角で切れている**ように見える。中途半端な位置で切ると、
  絵が足りていないように見えてしまう
- 立ち絵は 420×500 の全身で、**膝が高さの 76% あたり**にある。
  枠 54px / 図 72px = 75% で、膝下だけが切れる

#### 切る高さは**枠のほうで持つ**

タイル自身の `overflow` に任せると、相手が決まってタイルが伸びたときに
足まで出てしまい、2人が宙に浮いて見える。`.cur-crew` に高さを持たせて
そこで切る。

#### タイルの高さは他の節と同じまま

節の枠はどれも同じ高さにそろえてある(→§6.53)。ここだけ背を伸ばすと
その努力が消えるので、**伸ばすのではなく2人を小さくして収めた**。

相手が決まるとタイルは2段になる。そのときは `.cal-target` に右の余白を持たせ、
**2人ぶんの列を空ける**。空けないと2人が相手の行の裏に回り、脚だけがのぞく。

#### 立ち絵の透明な余白を見込んで重ねる

420×500 の中で人物が占めるのは横 6 割ほどで、左右に透明の余白がある。
そのまま並べると**間が空いて見える**ので、余白のぶんだけ負のマージンで重ねる。

### 6.55 相手が決まったら、節のタイルを**上書きする**(2026-08-19)

ミーティングで大会を選ぶと相手が決まる。以前はそのとき、いまの節のタイルの
**下に相手の行を足していた**。これをやめ、**タイルの見出しそのものを相手で
上書きする**ようにした。

| | 以前 | いま |
|---|---|---|
| 相手が決まる前 | 「第N節を開始する」 | 同じ |
| 相手が決まった後 | 上に「第N節を開始する」／下に相手の行 | **相手 ＋ 「リーグ 第N節 ／ HOME」** |

理由は2つ。

- **タイルが2段になる。** 節の枠はどれも同じ高さにそろえてある(→§6.53)ので、
  ここだけ伸びると並びが崩れる
- **済んだ節と形が変わってしまう。** 同じ「第N節に誰と戦うか」を指しているのに、
  決まる前・決まった後・戦った後で3通りの並びになっていた。
  **決まった後は済んだ節と同じ並び**にするのが読みやすい

余白も他の節と同じ 9px にした。ここだけ 12px だと、中身が2行になったときに
60px へ収まらず並びから浮く。

#### 済んだ節にもエンブレムを出す

予定のタイルには相手のエンブレムが出ているのに、済んだ節には出ていなかった。
**どこと戦ったのかは、名前を読まなくても分かるほうがいい**(→§3.54)ので、
`logRow` にも同じ 22px のエンブレムを置いた。

カップの相手はクラブIDを持たないので、**枠の名前をたねにする**。
予定のタイルと同じ作りなので、架空の相手にも同じ顔が付く。

### 6.56 SCOUT を「見て、選んで、開ける」場所にする(2026-08-19)

値段と一行の説明が3つ並ぶだけの画面だった。**いちばん嬉しいはずの場所**なのに、
押した瞬間に一覧が書き換わって終わる。3つ足した。

#### ① 見本市 — 引く前に「誰が居るか」を見せる

まだ持っていない実在選手(WC / LEGENDS)を4枚、横に流して並べる。
何が入っているのか分からないままコインを積むのは、補強ではなく賭けになる。

**並びの始まりは節から決まる**(開くたびに総入れ替えだと落ち着かない)が、
そこからは **`TUNING.fair.ms` ごとに1枚ずつ入れ替わる**。止めて眺めるものではなく、
流れている棚にしたい。

**同時に何枚も変えない。** 2枚以上が同時に動くと、どこを見ればいいのか分からなくなる。
入れ替えは**画面を離れたら自分で止まる**(`scr-gacha` が `.on` かを見る)ので、
画面ごとの後始末が要らない。

#### ② パックの行に選手の絵

行の右にはみ出させ、枠で切り落とす(→§6.31 の貼り紙と同じ見せ方)。

**値段のボタンより外に置く。** 最初は文字と値段の間に立たせたが、
それはただの散らかりだった。左を透かして消し、行の右端で切る。
ボタンだけは絵の上に出す — **値段が読めなくなってはいけない**。

#### ③ 開封の演出 — 4拍で出す

    ① 袋が震える → ② 裂ける → ③ カードが裏から翻る → ④ 段の色で光る

カードは**裏から翻して出す**。ただ拡大するだけだと「出てきた」に見えない。
袋は上下に金の縁を入れる。これが無いと、ただの青い長方形で袋にならない。

**いつでも飛ばせる。** 演出は2度目からは邪魔になるので、
**1回目のタップで最後まで送る**。

ただし**流れ切ったら、飛ばす役は降ろす**こと。残していると、演出が終わった後の
1回目のタップがスキップに吸われ、**カードを押しても詳細が開かない**
(2回押さないと開かない)。検証の側も「飛ばしてから押す」順だけを見ていると、
この抜けを素通りする — **待ってから押す経路も別に検査する**。

#### 封の印 — 開ける前に山を作る

袋には**斜めの二重枠で押した印**を置く。小さい字を1行入れるだけだと、
袋が「ラベルの付いた箱」になってしまう。

| 中身 | 印 |
|---|---|
| ふつう | **SCOUT!**(金) |
| **実在選手の WORLD CLASS / LEGENDS** | **TOP SECRET!!!**(赤・脈を打つ) |

**開ける前に分かる**のがこの演出のいちばんの山。裂けるまでの1秒が、
中身を知ってからの1秒より面白い。

#### 出たカードは置きっぱなしにしない

以前は一覧の下に「さっき引いたカード」を並べていた。引いた直後は嬉しいが、
**次に画面へ来たときには、ただの古い結果**が居座っているだけになる。

いまは**カードを押した時点で演出が閉じ、詳細が開く**。
以後は CARDS で見る — 手札を見る場所は1つでいい。

**演出は詳細より手前に立っている**(`.rv` は z-index 90、`#cardModal` は 52)。
演出を残したまま詳細を開くと、**カードが手前に居座って何も起きていないように見える**。
詳細へ渡すときは、渡す側が先に引っ込むのが正しい。

#### 移籍市場への導線は SCOUT から外した

入口は HOME のタイルだけにした。SCOUT は「引く」場所、市場は「選ぶ」場所で、
**引きに来た人を選ぶ場所へ誘導する理由がない**(→docs/10 §3.67)。

### 6.57 同じ色どうしが当たったら、アウェイが着替える(2026-08-19)

クラブの色を**サッカーで実際に使う13色**へ寄せた(→docs/10 §3.54d)結果、
**別のクラブが同じ色を持つことが普通に起きる**ようになった。144クラブを13色で
塗れば当然で、以前の「並び順から色相を振る」やり方では起きなかった問題。

そのままだと**足元の影が同じ色**になり、どちらのチームか見分けが付かない。
実際、ドライバの「両チームの影が同じ色」が落ちて気付いた。

現実のサッカーと同じで、**替えるのはアウェイ側**。

1. アウェイ側の**アウェイカラー**へ替える
2. それもホームと同じなら、ホームの色を暗く落とす

`kitPair(h,a)` が対で返し、試合の中の色は**全部そこから取る**。
片方だけ別の場所から色を引くと、影とカットインで別の色になる。

**144×143 = 20,592 組すべてで色が分かれること**を worldtest が見張っている
(実測では 3,006 組で着替えが起きる)。

### 6.48 画面の見出しは必ず真ん中に(2026-08-21)

> HOME のヘッダをみるとエンブレム、チーム名、HOME、コインと表示が並んでいます。
> 本来 SCOUT などをみると HOME は中央にくるはずなのですが、これが右に押し出されて
> います。原因はクラブ名による圧迫です (監督)

ヘッダーは **左:戻る/クラブ ／ 中央:画面名 ／ 右:コイン** の3列。
`justify-content:space-between` で並べていたので、
**左右の中身の幅の差がそのまま見出しのずれになっていた**。

原因は2つあって、両方直した。

| 原因 | 直し方 |
|---|---|
| 左にクラブの**正式名称**(最大120px)が入る。「ゴイアニア・エスメラウジーノ」のような長い名前だと左が右より 70px 広くなり、見出しが右へ寄る | **3文字の略号**にする(→[10. §3.54e](10-design-log.md))。`GOI` なら左右の幅が揃う。正式名称は `title` 属性へ |
| 幅が揃っても `space-between` では**中身の幅次第で位置が動く** | `.hd-l` / `.hd-r` を `flex:1 1 0` にして左右を同じ幅に伸ばす。見出しは中身に関係なく真ん中に来る |

#### 画面名は「何が並んでいるか」を言う

| 画面 | 前 | 後 | なぜ |
|---|---|---|---|
| 受信箱 | SECRETARY | **ANNOUNCE** | 並んでいるのは**秘書からのお知らせ**。秘書は語りの演出であって、画面の中身の名前ではない |
| 節のチャット | CLUB | **BRIEFING** | CLUB タブと名前がぶつかっていた。ここでやるのは**その節の打ち合わせ** |

### 6.49 フッターは**よく触るものを左に**(2026-08-21)

> フッターメニューのスケジュールとカードの位置を入れ替えてほしい。
> よく触るものが左にあるべきため (監督)

    前  HOME / CARDS / DECK / SCHEDULE / CLUB
    後  HOME / SCHEDULE / DECK / CARDS / CLUB

**SCHEDULE は毎節必ず通る道**(打ち手 → ブリーフィング → 試合)で、
CARDS は増えたときに見に行く場所。往復の回数が2桁違うので、内側へ寄せる。
DECK は真ん中のまま — 節の前に必ず触るが、SCHEDULE ほどではない。

タブの参照は全部 `data-s` の属性選択なので、並べ替えても何も壊れない
(`:nth-child` や添字で拾っている箇所は無い)。`drive.js` に並びそのものを
見張る一文を置いた。

### 6.50 監督とクラブを分ける(2026-08-21)

> CLUB に監督とクラブの両方が混ざっていますね。これを分けたいです (監督)

CLUB 画面には**性質の違う2つ**が同居していた。

    監督のもの … 顔・背景・名声・チケット・メモラビリア・経歴・トロフィー・カード見本
    クラブのもの … エンブレム・施設

**任期をまたいで残るもの**と、**任期のあいだだけ預かるもの**。
この2つが1枚に並んでいると「いま何を見ているのか」が読めない。

#### 入口はヘッダーの右

コインの位置に**監督の顔**を置いて、そこから MANAGER へ入る。
顔の切り出しは `.mgr-face` と同じ値をそのまま使う(→§6.23)ので、枠が変わっても顔がずれない。

コインは**クラブの財布**なので CLUB の現況へ移した。
使う場所(SCOUT と HOME のスカウトタイル)では**その場に残高が出ている**ので、
常時表示を外しても手が止まらない。

#### 何をどちらへ置いたか

| MANAGER（任期をまたぐ） | CLUB（いま預かっている） |
|---|---|
| 顔・背景の設定 | クラブの現況（SEASON の CONTRACT から移した） |
| メモラビリア | クラブロゴ（エンブレム） |
| CAREER（生涯の経歴） | クラブ施設 |
| TROPHIES（通算の棚） | CLUB RECORD（このクラブに来てからの戦績 →[10. §3.9a](10-design-log.md)） |
| カード見本 | |

**SEASON の「契約」の柱は畳んだ。** 中身はクラブの話なので CLUB にある。
SEASON に残るのは大会のエントリーだけになり、柱も1本減った。

#### 分けたことを検査で守る

一度分けても、あとから足すものがどちらに入るかは書いた人次第で崩れる。
`drive.js` で **CLUB の中に監督のものが無いこと**を直接見張る。

```js
for(const id of ['clubHistory','clubTrophies','memList','clubMgrFace'])
  if(scr.querySelector('#'+id))throw new Error('CLUB に監督の '+id+' が残っている');
```

### 6.51 CLUB の段を詰める(2026-08-21)

§6.50 で分けた直後の CLUB は、**同じことを2か所で言っていた**。

    紋章カード … クラブ名 ／ ★の説明文
    CLUB タイル … クラブ ／ いまの舞台 ／ 現在順位 ／ …

紋章の隣には既にクラブ名が出ている。なのに CLUB タイルの1行目もクラブ名だった。

#### 紋章を最上段に置き、その脇に「どこで戦っているか」を集める

| | 前 | 後 |
|---|---|---|
| 紋章の副題 | ワールドクラブチャンピオンカップを獲ると★が付きます（最大3） | ★★　カンピオナート DIV3　**2位** |

**★の説明は要らない。** 獲れば★が出るので、出ていないことがそのまま説明になる。
空いた行に**いまの舞台と現在順位**を置けば、CLUB タイルから2行減らせる。

#### CLUB タイルは「オーナーとの間の数字」だけにする

    クラブの資金 ／ チーム熟練度 ／ オーナーの評価 ／ オーナーの目標

クラブ名・舞台・順位は紋章側にあるので落とす。**4行になった**(前は8行)。

#### スポンサーは別タイル

スポンサーは**別の相手との契約**で、オーナーとの話とは筋が違う。
看板も大きいので、同じタイルに置くと現況が看板に埋もれる。

> **社名が2回出ていた。** 看板の下に金字で社名、その次の行にも「スポンサー ○○（第25節まで）」。
> 看板に添えていたほうを落とした。看板そのものが社名を描いているので、
> 字で重ねる意味がない。

### 6.52 日程は必ず「いまの場所」に戻る(2026-08-21 修正)

> リーグ全日程終了する試合からスケジュールに戻ると「全日程を終了しました」の
> 場所に戻ってこれず、スケジュールのTOPに遷移してしまう (監督)

任期は96節あるので、日程に戻るたび `scrollToCurrent()` が現在節まで送っている。
その的は現在節タイルの `id="calCur"` だった。

**全日程を終えた節には、その行が並ばない。** 代わりに出るのは
「全日程を終了しました」の判定行で、こちらには id が無い。
`scrollToCurrent()` は的を見つけられずそのまま戻り、**先頭に置き去り**になっていた。

#### 的は id ではなく目印(`cal-here`)で持つ

最初は判定行にも `id="calCur"` を付けた。**これは間違いだった** —
`wireCurrentRow()` が `#calCur` にチャットを開くクリックを結び付けているので、
判定行を押すと HOME ではなく**チャットへ飛ぶ**ようになった。

「戻り先の目印」と「押したら何が起きるか」は別の役目なので、分けて持つ。

    現在節タイル … class="cal cur cal-here" id="calCur"   ← 押すとチャット
    判定行       … class="cal judge go cal-here" data-go  ← 押すと HOME

#### 的そのものが無い場面もある

任期が明けたあと(`C.over`)は「いまの節」の行が一切並ばない。
そのときは**最後に消化した節**まで送る。ここで諦めると、やはり先頭に置き去りになる。

```js
let el=box.querySelector(".cal-here");
if(!el){ const done=[...box.children].filter(e=>
  !e.classList.contains("fut")&&!e.classList.contains("none")); el=done[done.length-1]; }
```

### 6.58 HOME を1画面に収める(2026-08-21)

> HOME画面がいっぱいになっており、CLUB NEWS が画面からはみでてしまいます (監督)

HOME は縦に積むものが増え続けていた。試合タイル・4枚のタイル・秘書・CLUB NEWS。
**いちばん下の CLUB NEWS が画面の外**にあり、知らせが増えるほど遠くなっていた。

#### CLUB NEWS は「積む」のをやめて「流す」

    前  HOME の末尾に、全件を積んだタイル(件数ぶん背が伸びる)
    後  試合タイルの直下に**1行**。4.2秒ごとに入れ替わり、押すと全部並ぶ

**高さが知らせの数で変わらない**のが肝。5件でも 36px に収まるので、
いちばん見る場所——試合タイルの真下——に置ける。
溢れた文は省略記号で切り、**絶対に2行にしない**。

止め方は見本市(→§6.56)と同じで、`newsTick` が自分で
「HOME が表示されているか」を見て止まる。画面ごとの後始末を書かなくてよい。

#### 重複していた行を畳む

試合タイルには「AWAY ／ 第2節」という行があった。**節は上の MATCHDAY と同じこと**を
言っている。行ごと消すと HOME/AWAY まで失うので、**上の行に寄せた**。

    前  SEASON 1 · MATCHDAY 02
        （…）
        AWAY ／ 第2節
    後  SEASON 1 · MATCHDAY 02 · AWAY

#### 4枚のタイルを一回り低く

`padding` 14 → 11/12、アイコン 20 → 17px、行間を1〜3px ずつ詰めた。
**絵(ステッカー)の大きさは変えていない**ので、見た目の密度は保っている。

> 結果として **HOME が1画面に収まった**。秘書のひとことまでスクロール無しで届く。

### 6.59 タイトルに端末の淵を出す(2026-08-21)

> トップページのタイトル画面の淵にスマホのディスプレイのようなノッチをつけて、
> デバイス感を演出してみたい (監督)

HOME は「監督のデバイス」という建て付け(→§6.8)なのに、**その板そのものは
一度も見せていなかった**。立ち上げた瞬間＝タイトルだけ、淵を見せる。

    上  ノッチ(142×25)。中はスピーカーのスリットとカメラの丸
    下  指示バー(112×4)。細く薄く

#### 出すのはタイトルだけ

本文の画面に出すと、**上端の情報がノッチの裏に回る**うえ、
毎画面ずっと出ていると演出ではなく邪魔になる。
「アプリを立ち上げた」という一瞬だけの飾りにする。

#### 触りは通す

`pointer-events:none` を必ず付ける。タイトルは**画面のどこを押しても始まる**ので、
ノッチが触りを食うと**上端だけ反応しない**という分かりにくい不具合になる。

> **真っ黒な面だけだと切り抜きに見えない。** 下辺に 1px の明るい線を入れて、
> 「奥にある」ことを示す。中のスピーカーとカメラも、実物と同じ並びにすると板に見える。

#### 淵は1周させる(2026-08-22 追補)

> トップ画面の淵全体にノッチをわずかにつけて、より
> スマートフォンの縁取り風にしてみてください (監督)

ノッチだけだと**「上に何か付いている」で終わる**。
枠は4辺そろって初めて板に見えるので、淵を1周させた。

    1本目  淵そのもの(黒・7〜9px)
    2本目  淵の内側に走る細い光。**面と淵の境**をここで作る
    3本目  画面の縁の落ち込み。中身が淵の下へ潜っていくように見せる

3本の `inset` 影を重ねるだけで、要素は1枚増やすだけで済む。
太さと丸みは変数(`--bz-w` / `--bz-r`)にして、**狭い画面では細くする**
(9px/30px → 7px/24px)。太いままだと壁の見える面積が減る。

ノッチと指示バーも淵の内側へ寄せた。上端ぴったりに置くと**淵から浮いて見える**。

> 実機の画面は角が丸い。`#app` は狭い画面で `border-radius:0` になるが、
> **淵は常に丸める**。ここだけは「実際の枠」ではなく「板の絵」なので、
> 画面の形に合わせる必要がない。

#### 起動の帯が邪魔をしていた

作った直後、画面に出ていない気がして CSS を疑った。実際には描画されていて、
**起動の進捗を出す緑の帯(`#bootStat`)が上端を覆っていた**だけだった。
帯は3秒で自分から消えるが、`drive.js` は 1.2秒で撮っていたので
**タイトルの1枚目には毎回この帯が写り込んでいた**(今回まで気づいていなかった)。
帯が消えるまで待ってから撮るようにした。

### 6.60 画面の色を選べるようにする — セピア(2026-08-21)

> HOME およびメインの画面のカラーデザインをセピア風の明るいカラーも選択できる
> ようにしたい。背景と同じように今度は UI を明るくするバージョンが欲しい (監督)

背景(→§6.45)は端末枠の**外側**だけを着せ替えるものだった。今回は**中身**を替える。

    ナイト  既定。暗い地に金を1色
    セピア  陽に焼けた紙の地。明るい面で読む

#### 色はトークンに集まっている……が、半分だけだった

`:root` の変数を `body.ui-sepia` で差し替えれば全画面が追従する——はずだった。
実際に数えると、**CSS の中に直書きの色が430箇所**あり、
そのうちトークンと同じ値なのは**29箇所だけ**。残りは個別の値だった。

**全部をトークンに寄せる道は採らなかった。** 400箇所の色を決め直す作業で、
ダークの見た目を壊す危険のほうが大きい。代わりに、

1. トークンを差し替える(これで地・パネル・罫線・文字はほぼ追従する)
2. **塗り面として残る暗い島**だけを名指しで直す(ヘッダー・タブバー・
   試合タイル・右端の柱)
3. 明るい地で消える字を直す(白い字が地に溶ける)

#### カードと盤面は替えない

段の色(白/黒/ホロ/虹/黒金)とピッチの緑は**それ自体が意味を持つ意匠**で、
地の色に合わせて動くものではない。セピアにしてもカードはカードのまま並ぶ。
**明るい地に置くと、むしろ段の差がよく見える。**

#### 「読めない字」は機械で探す

明るい地に切り替えると、白い字がそのまま地に溶ける。全画面を目で見比べても
取りこぼすので、`drive.js` で**字と地の明るさの差**を測って落とす。

    主要5画面の全要素について
      字の色と、遡って最初に見つかる不透明な面の色を明るさに直し
      差が 0.16 未満なら「地と見分けが付かない」として落とす

絵の上に載る字(影が付いているもの)は下地が絵なので除く。
この検査で `.bn-name`(控えの名前)・`.mgr-name`(監督名)・`.nx-tag` が見つかった。

#### 状態が付いたときだけ現れる面(2026-08-21 追補)

最初の走査は通ったのに、監督から**9箇所**の報告が来た。

    スカウトのコイン不足 ／ 編成の選択中の枠と陣形 ／ 節の終了タイル ／
    取得済みの実績 ／ 試合中のスコア(白) ／ 実況の背景(暗すぎ) ／
    メモラビリアの勾配 ／ 引き出しの下端 ／ 結果の選手名(白)

**走査が甘かったのではなく、その面が出ていなかった。** 取得済みの実績は
トロフィーを持っていないと現れず、節の終了タイルは全日程を終えないと出ない。
素の状態で全画面を見ても、これらは一度も描かれない。

直し方は2つ。**面を作ってから走査する**のと、**走査の穴を塞ぐ**の両方。

| 穴 | 塞ぎ方 |
|---|---|
| 状態が要る面 | 実績・メモラビリア・コイン0・全日程終了・選択中の枠を**作ってから**走査する |
| 勾配の面 | `backgroundColor` が透明でも `backgroundImage` の最初の色を面として読む |
| 影付きの字 | 除外していた(下地が絵のことが多いため)。**除外をやめ、閾値を下げて**見る |
| 試合と結果 | タブから行けないので、試合を終えた段でその場で走査する |

> **一瞬しか出ないものは、やはり走査に写らない。** トーストは 2.6秒で消えるので、
> 名指しで直した。ここは検査に頼れないと割り切る。

#### 手で潰すのをやめ、機械で一括置き換えにした(2026-08-21 再追補)

追補で9箇所を直したのに、さらに**13箇所**の報告が来た。

    監督の型の札 ／ 固有スキルの金 ／ 売却不能の印 ／ 背景のブラック ／
    エンブレムの編集マーク ／ 市場の WC ／ ENTRY の参戦中 ／
    編成の選択中と設定中 ／ 選択中の陣形 ／ 試合中の柱と引き出し ／
    BRIEFING のヘッダと日付 ／ FIXTURES の敗戦 ／ 施設の建設中

**1つずつ潰す限り必ず漏れる。** 数えると、CSS の中に
**暗い面を持つ宣言が105、明るい字の宣言が37**あり、報告はその一部でしかなかった。

そこで**機械で一括置き換え**に切り替えた。

```
宣言(background / color)を探す
  → 直前の「{」まで戻ってセレクタを引く   ← 入れ子や @media に強い
  → 暗い面なら L を 0.985-L*0.58 に反転、色相を金寄りへ、彩度は 0.085 で頭打ち
  → 明るい字なら L を 1.22-L*1.02 に反転(元の明暗の順序は保つ)
  → body.ui-sepia を前置きして出力(カンマは1つずつ前置きする)
```

面76ルール・字37ルールが出た。**除外は意匠だけ**にする。

    タイトル(壁・覆い・題字・淵) ／ カード ／ ピッチの人 ／ ユニフォームの色 ／
    エンブレム ／ カットイン ／ 設定の見本 ／ 絵の上に載る字(OVR・背番号・スコア)

> **`.mcut` を外し忘れて芝が白茶けた。** カットイン中に盤面を沈める覆いで、
> ここを明るくすると芝の緑が抜ける。**暗いままが正しい覆い**があることに、
> 生成してから気づいた。除外は「意匠かどうか」ではなく
> 「**明るくして意味が通るか**」で決める。

### 6.61 背景を4種にし、施設の段を取り戻す(2026-08-22)

#### 黒と白は、地の明るさから独立させる

> セピアで背景が白くなる問題は2つの背景に分けて選択を自由にできるようにしましょう (監督)

「ブラック」は `body.bg-black` という規則を持たず、**`--bg` トークンをそのまま**
使っていた。だから地の明るさを替えると外周まで一緒に反転し、
**ブラックを選んでいるのに白くなった**。

    前  ピッチ / ブラック(= --bg 任せ) / ロゴウォール
    後  ピッチ / ブラック / ホワイト / ロゴウォール   ← どれも固定色

**地の明るさ(ナイト/セピア)と、外周の色は別の好み**なので、掛け合わせで選べる。
`drive.js` で「地の明るさを替えても黒と白は同じ色のまま」を見張る。

#### 一括置き換えが、派生ルールを潰していた

> ファシリティの成長状況がセピアだと見えなくなっている (監督)

施設の段は5マスあり、建った段だけが金になる。それが**全部空きマスに見えた**。

原因は §6.60 の一括置き換え。

```
.fc-bar i        { background:oklch(0.28 0.02 255) }   ← 空きマス
.fc-bar i.on     { background:var(--accent) }          ← 建った段(あとに書く)
body.ui-sepia .fc-bar i{ background:oklch(0.823 ...) } ← 生成。もっとあとに書かれる
```

`body.ui-sepia .fc-bar i` と `.fc-bar i.on` は**詳細度が同じ**(クラス2+要素1)。
同じなら後が勝つので、**生成した空きマスの色が、建った段の金を上書きしていた**。

同じ危険を数えると **52件**あった(`.trophy.off` / `.skill.on` / `.mfeed .goal` /
`#tabs button.on` / `.sb-bar.low i` …)。

直し方は、**基底を上書きしたセレクタの派生を、元の順序のまま出し直す**。
値は変換せずそのまま写す(`var(--accent)` は触らない)。48ルールを再発行した。

> **一括置き換えは「詳細度を上げる」という副作用を持つ。**
> `body.ui-sepia` を前置きした時点で、元の CSS が積み上げた順序が崩れる。
> 生成でまとめて当てるなら、**派生の再発行までがワンセット**。

### 6.62 CARDS に絞り込みと並べ替えを足す(2026-08-22)

> 検索条件でレアリティ、DECK にはいっているかいないか、CLUBS 所属選手かどうかが
> 欲しい。ソート機能、OVR とレアリティのものが欲しい (監督)

集めるほど探せなくなる画面だった。絞り込みはポジションの1列だけで、
並びは総合力の降順に固定。**「編成に入っていない LE を見たい」が言えなかった。**

#### 軸ごとに1列ずつ置く

    1列目  ALL / GK / DF / MF / FW          … ポジション
    2列目  FULL / ST / RG / SP / WC / LE    … 段
    3列目  全員 / 編成 / 編成外 / 自分 / 貸与  … 居場所

**同じ列に混ぜない。** 混ぜると、どれとどれが排他なのかが読めなくなる。
列を分ければ「1列につき1つ選ぶ」が形で分かり、**軸は重ねて効く**。

段の札は**その段の色で縁取る**。略号だけだと ST と SP、WC と LE の読み分けに
時間がかかる。選ぶとその色で塗りつぶす。

#### 並べ替えは「押して入れ替える」

総合力順と段順の2つしかないので、選択肢を並べずに**ボタンの文言そのものを状態**にする。
段順のときも**同じ段の中は総合力で並べる** — 段だけで並べると、
同じ段のカードの順序が描き直すたびに変わってしまう。

> **絞ったら1ページ目に戻す。** 3ページ目を見ている状態で絞り込むと、
> 該当が3ページ無いときに空の画面が出て「0件」と読めてしまう。

### 6.63 見出しはタイルの内側にそろえる(2026-08-22)

> CLUB と MANAGER の画面に見出し表示でタイルの外に表示があるものと、
> タイルの内側にあるものがあります (監督)

同じ画面で2つの型が混ざっていた。

    タイルの外  MANAGER / MEMORABILIA / CLUB CREST / CLUB / SPONSOR   (`.eyebrow`)
    タイルの内  CAREER / TROPHIES / CLUB FACILITIES / CLUB RECORD     (`.sect-t`)

**内側にそろえる。** 外に置くと見出しと中身が別々の塊に見え、
どこからどこまでが1つのまとまりなのかが読み取りにくい。
内側なら**タイル1枚＝1つの話**が形で分かる。

紋章のタイルだけ手当てが要った。`.crest-card` は `display:flex` で
紋章と名前を横並びにしていたので、**見出しを入れると3つ横に並んでしまう**。
横並びを card そのものではなく**中の1枚**に持たせて解いた。

> **見張りは「無いこと」で書く。** `drive.js` で
> 「両画面に `.eyebrow` が1つも無い」「すべての `.card` が `.sect-t` を持つ」を見る。
> 足したタイルに見出しを付け忘れれば落ちる。

### 6.64 CARDS を4列にする(2026-08-22)

> CARDS のカードを横に4枚×縦に4枚ならべるレイアウトは可能でしょうか？
> スタメンチームを一括で参照できる＆画面のスクロールが減る (監督)

3列12枚から**4列16枚**にした。**16 = スタメン11 + 控え5**なので、
編成そのものが1ページにちょうど収まる。

カードの文字は最初から `cqw`(枠の幅を基準にした単位)で組んであったので、
列を増やすだけで**そのまま比例して縮む**。文字の位置合わせは何も直していない。

#### ただし縁取りだけは比例させてはいけない

文字は選手の絵に重なるので、`text-shadow` を3回重ねて縁取りにしている。
この太さも `cqw` なので、札が 120px → 85px になると**絶対値では細くなる**。
細い縁取りは選手の色に負けて、能力のラベルが読めなくなる。

    --ha:.55cqw   3列(120px)のとき
    --ha:.8cqw    4列(85px)のとき   ← #cardsGrid でだけ上書き

**「比例させる」と「絶対値を保つ」を取り違えると、縮めた瞬間に読めなくなる。**
字の大きさは比例でよく、縁取りは絶対値を保つほうが正しい。

> 1ページの枚数は `CARDS_PER_PAGE` の1箇所だけ。`drive.js` の検査も
> この定数を読むようにしたので、枚数を変えても検査は追従する。

#### 該当なしの枠は全幅に張る(2026-08-22 追補)

> 該当するカードがない場合の空の枠の高さがくずれてしまっています (監督)

「該当するカードがありません」は `#cardsGrid` の**直下**に置いていたので、
格子の**1マス**として扱われていた。3列のときは幅が3分の1で済んでいたが、
4列にしたことで**カード1枚ぶんの幅に潰れ**、段の高さも一緒に崩れた。

```css
.grid > .stub{ grid-column:1 / -1; margin:0 }
```

**列数を変えたら、格子の中に置いた「カード以外」を見直す。**
カードは1マスに収まる前提だが、案内文はそうではない。
`drive.js` で「該当なしのときの枠が格子の全幅と一致すること」を見張るようにした。

### 6.65 ✦粒子が黒く光っていた(2026-08-22 修正)

> カードのキラキラ★が黒く光ります。怖いです (監督)

§6.60 の一括置き換えが、粒子の色まで反転させていた。

```css
.pcard .spark{ color:oklch(0.99 0 0) }        /* 白い光 */
body.ui-sepia .holo-gold .spark{ color:oklch(0.322 …) }   /* ← 生成。黒くなる */
```

粒子は `text-shadow:0 0 7px currentColor` で**自分の色を光らせている**ので、
色を暗くすると「黒い光」という有り得ないものが出る。

**カード・ホロ・段の色と同じで、粒子も意匠そのもの**だった。除外リストに
`.spark` が入っていなかっただけで、§6.60 で決めた基準
(「明るくして意味が通るか」)に照らせば最初から外すべきものだった。

#### 光る側の意匠を機械で洗った

同じ取りこぼしが他に無いか、**`currentColor` で自分を光らせている規則**を
全部拾って突き合わせた。粒子以外に該当は無かった。

検査も足した。`drive.js` が**両方の地で粒子の明るさを測る**。
色は `oklch` のまま返ってくるので、canvas に1px 塗って実際の RGB を読む。

> 直す前の値を入れて**検査が落ちること**も確かめた(sepia 0.20 で失敗)。
> 落ちない検査を足しても意味がない。

### 6.66 HOME にエキシビジョンとミッションを置く(2026-08-22)

> HOME にエキシビジョンのタイルとミッションのタイルを作成します。
> 移籍市場の横にエキシビジョンを配置、下段に実績を移動し、そのとなりにミッションを (監督)

タイルを4枚から**6枚(2枚ずつ3段)**にした。

    スカウト     チーム編成
    移籍市場     エキシビジョン
    実績         ミッション

#### エキシビジョン — **日程に依らない一戦**を集める

いままでメモラビリアは MANAGER の中にあった。だが**あれは試合**で、
監督の記録(経歴・トロフィー・顔の設定)とは性質が違う。
節も日程も使わない一戦、という括りで HOME へ出した。

**いまはメモラビリアだけ**だが、時限イベントや練習試合もここへ足していける。
タイルには開いた数(`1 / 4 戦`)を出すので、まだ開いていない記録があることも分かる。

招待状(→[03. §3.43b](../docs/10-design-log.md))の行き先も
`manager` から `exhibition` へ変えた。

#### 合言葉の枠は一覧の上に置く

    前  見出し → 一覧 → 合言葉
    後  見出し → **合言葉** → 一覧

**開く操作が主で、一覧は「開いた結果」。** 手が先に触れる場所へ置く。
記録が増えるほど、下にあると入力枠を探して送ることになる。

余白も上ではなく下に付け替えた。**1つも開いていないときは一覧が空になる**ので、
`:last-child` のときだけ下の余白を殺している。

#### 実績は MANAGER の棚へ繋ぐ

タイルの行き先が `clubhouse` のままだった。棚は §6.50 で MANAGER へ移したのに、
**タイルだけが取り残されていた**(押すと CLUB が開き、棚が無い)。

行き先を直したうえで、**棚まで送る**。画面を開いただけでは、
顔と経歴とメモラビリアの下に埋もれていて、押した意味が伝わらない。

```js
show("manager",{push:1});
setTimeout(()=>$("clubTrophies").scrollIntoView({block:"start"}),30);
```

#### ミッション — **入口だけ先に通す**

中身はこれからなので、画面は「準備中」の1枚だけ。
それでも**タイルと画面と HELP は先に用意する**。
導線が通っていれば、あとは中身を入れるだけになる。

> **押して何も起きないタイルは置かない。** `drive.js` で
> 「6枚が決まった並びであること」「エキシビジョンとミッションが
> それぞれの画面へ行くこと」を見張る。

#### 閉じタグを1つ落として、試合画面が入れ子になった

メモラビリアの塊を MANAGER から切り出して EXHIBITION へ移したとき、
**カードの `</div>` を1つ取り残した**。その結果 EXHIBITION が閉じきらず、
**以降の全画面がその中に入った**。

症状は「ノッチが178px ずれる」「ピッチの高さが 0」と、原因からいちばん遠い場所に出た。
