## 3. ゲームデザイン

### 3.1 確定していること

- ジャンル: **サッカー**(single play browser football game)。
- プレイ形態: スマートフォン縦持ち・1人プレイ・オフライン。
- 出力形態: 単一HTML(GitHub Pages に置くだけで遊べる)。
- 姉妹作 card-eleven(収集型カードサッカー)の**土台のみ**を継承した別作品であり、
  ゲーム内容は card-eleven の焼き直しにはしない。

### 3.2 コアループ(D1 — 決定 2026-07-31)

**プレイヤーは「監督」であり、ゲームの主軸は監督個人のキャリア。**
クラブ経営を回しながら任期を勤め上げ、実績を積んでより上のクラブへ渡り歩いていく
(WCCF の監督キャリアのような体験を、収集ではなく**キャリアの積み上げ**として本体に据える)。

```
  クラブに就任(任期スタート・クラブの状況と期待値を受け取る)
        ↓
  ┌── 任期中 ──────────────────────────────┐
  │  選手を集める(補強)・クラブを強化する(経営)      │
  │        ↓                                   │
  │      試合 → 結果・評価の変動                  │
  │        ↓                                   │
  │  タイトル獲得 → トロフィー(恒久的な実績)        │
  └────────────────────────────────────────┘
        ↓
  任期満了(達成度で評価が決まる) → 続投 / 解任 / 上位クラブからのオファー
        ↓
  次のクラブへ(名声・トロフィー・采配・**集めた選手カード**は引き継ぐ)
```

- **恒久的に積み上がるもの(プレイヤー/監督のもの)**: **名声**・獲得トロフィーと実績・習得した采配・
  キャリア戦績(渡り歩いた軌跡)・**集めた選手カードのコレクション**(→§3.2.2)。
- **クラブごとにリセットされるもの**: クラブのコインと施設・リーグの順位・**会長の評価**・
  **チーム熟練度**(→§3.7)・**クラブから借りていた選手**(→§3.4 D13)。
  (名声=行ける先を決める恒久資産 / 会長の評価=今のクラブに居られるか。→§3.9)

#### 3.2.1 card-eleven との違い — 体験を監督に統合する

card-eleven は**プレー体験を複数のモードに分散**させていた(ステージ攻略・リーグ戦・ワールドツアー・
デイリー・フレンド対戦・監督キャリア…)。結果として体験にばらつきが出た。

pftb は **WCCF に倣い、最初からキャリアが中心**。前作で散っていた遊びを
**「監督としての体験」1本に統合**する。モードを増やすのではなく、キャリアの中に出来事として置く。

#### 3.2.2 リアルと非リアルの二層(ギャップは受け入れる)

本作には**2つの層**があり、両立させる。この2つは厳密には噛み合わないが、**そのギャップは意図的に許容する**。

| 層 | 誰の物語か | 求めるもの |
|---|---|---|
| **監督体験(リアル寄り)** | 監督というキャラクター | 就任・任期・評価・オファー。ナラティブに進む |
| **コレクション(非リアル)** | **プレイヤー自身** | 選手カードを集め、理想のチームを作る |

- **選手カードはプレイヤーの資産**であり、**クラブを移籍したあとも引き続き使える**。
  現実のサッカーでは監督が選手を連れて回ることはないが、
  **「集めたカードで理想のチームを作る」という目的を成立させるため、この非リアルを受け入れる**。
- 監督体験はナラティブの背骨、コレクションは繰り返し遊ぶ動機。役割が違うので同居して良い。
- **エンドコンテンツとして非同期対戦を想定**(card-eleven と同様)。
  集めたチームを他プレイヤーとぶつける場があることで、コレクションが繰り返しプレーに直結する。
  → 実装は先だが、データ設計の段階から**チーム編成を単体で持ち出せる形**にしておく。

### 3.3 時間の進み方(D2 — 決定 2026-07-31)

**1試合 = 1ターン**。節ごとに「手を1つ打つ → 試合を戦う」を繰り返す。
スマホで1セッション=1節(数分)で切り上げられるリズムを最優先し、試合を主役に保つ。

```
 就任(1シーズン契約で任期スタート)
   ↓
 ┌ シーズン(圧縮リーグ: 12節) ────────────────┐
 │  【手を一つ選ぶ】補強 / 育成 / 経営 / 偵察 …   │
 │        ↓                                    │
 │  【試合】結果 → 勝ち点・順位・評価が動く       │
 └──────────── 次の節へ ───────────────────────┘
   ↓
 シーズン終了: 順位確定・タイトル判定・トロフィー
   ↓
 オフシーズン: 移籍市場をまとめて操作
   ↓
 任期満了 → 続投 / 解任 / 上位クラブからのオファー
```

| 項目 | 暫定値 | 備考 |
|---|---|---|
| 1シーズンの節数 | **12節** | 7クラブのホーム&アウェイ総当たりで確定(→§3.8)。大陸大会が加わり合計15試合前後 |
| 1節にできる操作 | **1手だけ** | 手の種類(補強/育成/経営/偵察)は D3・D4 で確定 |
| 契約(任期)の長さ | **1シーズン(更新可)** | シーズン末に審判: 更新 / 解任 / 上位クラブからのオファー。施設投資(→§3.5)の「来季も自分がここに居るか分からないのに建てるか」という緊張が生まれる |
| オフシーズン | シーズンの切れ目に1回 | 移籍市場だけは「1手」の制限を外し、まとめて操作させる |

> **なぜ1節1手か**: 手数を絞ることで1つ1つの選択に重みが出て、スマホで1画面に収まる。
> 経営SLGの厚み(週単位カレンダー)は操作が重くなり、シーズン一括ダイジェストは試合の手触りが薄れるため見送った。

### 3.4 選手の入手(D3 — 決定 2026-07-31)

**主軸はカードパック。**ただし入手経路は**最初から複数前提の作り**にし、スカウトなどを後から足せるようにする。

```
 【節の手】パックを引く
   コイン △ を消費(またはチケット1枚)
     ↓
   ✦ 開封 ✦
     ↓
   出た選手 → 契約する / 見送る(コインに一部還元)
     ↓
   編成へ(すぐ次の試合で使える)
```

- **card-eleven との違い**: card-eleven のガチャは「コレクションを増やす行為」そのものが目的。
  pftb のパックは**クラブのコインをどう配分するか**という経営判断であり、任期という締め切りの中で
  「今引くか、貯めて上位パックを引くか、経営(D4)に回すか」を迫るための仕組みにする。
- **パックの段階**: **国の格 × クラブの格**(→§3.8)と保有コインに応じて引けるパックが変わる
  (下位国の弱小クラブでは安いパックしか引けない)。種類と確率の数値は `TUNING` に集約する。

#### 入手経路はレジストリで持つ(拡張の要)

入手手段を `SOURCES` レジストリ(1経路=1エントリ)として定義し、パックを最初のエントリとして実装する。
UI(「補強」画面の選択肢)とコストの消費も、レジストリの定義から自動で並べる。

| 経路 | 状態 | 概要 |
|---|---|---|
| `pack` | **v1で実装** | コインを払ってパックを引く。即時に結果が出る |
| `scout` | 将来 | 節の手でスカウトを派遣し、数節後に候補が上がる(遅延型) |
| `market` | 将来 | オフシーズンの移籍市場。他クラブと競合しながら交渉 |
| `youth` | 将来 | 下部組織からの昇格。シーズン境界で発生 |
| `free` | 将来 | 契約満了選手をコイン0で獲得(質は低い) |

> 経路を足すときは `SOURCES` に1エントリ追加すれば済むようにする。
> 「即時か遅延か」「節の手を使うかオフ限定か」を各エントリの属性として持たせ、
> 進行側(節の手の消費)は経路の中身を知らない構造にする。

#### 退任時に選手はどうなるか — **持ち越せる**(2026-07-31 変更)

**集めた選手カードはプレイヤーの資産であり、クラブを移籍しても引き続き使える**(→§3.2.2)。

> **⚠ 方針変更**: 当初は「選手はクラブの資産・退任時に置いていく(記録だけ監督の名鑑に残る)」と
> 暫定で決めていたが、**「集めたカードで理想のチームを作る」というプレイヤー側の目的を優先**して覆した。
> 現実の監督は選手を連れて回らないが、そのギャップは意図的に受け入れる。

- パックで引いた選手が任期の終わりに消えないため、**課金的なコレクションの手応えが成立する**。
- クラブを移るコストは選手ではなく、**コイン・施設・チーム熟練度・会長の評価がリセットされること**で表現する
  (→§3.2 / §3.7)。
- 移籍後も同じチームで戦えることは、エンドコンテンツの**非同期対戦**(→§3.2.2)の前提にもなる。

#### クラブ所属選手は「任期中の貸与」(D13 — 決定 2026-07-31)

就任すると、**そのクラブの所属選手が使える状態で渡される**。自分のカードと**混成して11人を組む**。

```
 国D・弱小FC に就任
 ─────────────────────
 【クラブ所属】任期中だけ借りられる
   GK ハンセン   OVR 68
   DF モラレス   OVR 71
   …(11人分そろうが弱い)

 【手持ちカード】自分の資産
   FW シルヴェイラ OVR 93 ★
   MF オコフォー   OVR 87 ★
     ↓
   混成して編成(★ が自分のカード)
     ↓
 【退任】借りた選手はクラブに残る / ★ は連れて行く
```

| | クラブ所属選手 | 手持ちカード |
|---|---|---|
| 誰のものか | クラブ | **プレイヤー** |
| 質 | **クラブの格で決まる**(弱小は本当に弱い) | 集めた分だけ強くなる |
| 退任時 | クラブに残る | 連れて行く |
| 表示 | 通常 | **★ などで区別**する |

- **これで期待順位と実際の戦力が噛み合う**。弱小クラブは既存戦力が本当に弱いので、
  「残留させれば偉業」(→§3.9)が絵空事にならない。
- **コンビネーション(`combo`)と自然に噛み合う**: 借りた選手は同じクラブ所属なので発動しやすい。
  「借り物中心で結束を取るか、手持ちの強いカードで individual に殴るか」という編成の選択が生まれる。
- **練習場(施設)で育てた選手は持ち出せない**(借り物なので)。施設投資が「クラブに遺すもの」という
  性格を強め、§3.5 の投資判断とも筋が通る。
- 借りた選手を買い取って自分のカードにする仕組みは**今回は入れない**(→バックログの検討候補)。

### 3.5 クラブ経営(D4 — 決定 2026-07-31)

資金は**「コイン」1本**に集約する(給与・スポンサー・維持費といった細かい費目は持たない)。
コインの使い道は **「今を取る(パック=即戦力)」か「先を取る(施設投資)」** の二択で、
任期という締め切りがあるため「**その投資は任期中に回収できるのか**」が毎節の判断になる。

```
 コイン(クラブ予算)
  ├─ 今を取る … パックを引く      → 即座に戦力化
  └─ 先を取る … 施設に投資する    → 数節後に完成、以降ずっと効く
                                     (1シーズン契約なので回収できるとは限らない)

 チケット(報酬券)  … コインを使わずにパックを引ける
  └─ スポンサー依頼の達成・タイトル獲得・実績で配られる
```

- **通貨はコイン1本**。パックも施設もコインを奪い合うため、「今を取るか先を取るか」の判断が成立する。
- **チケットは報酬としてのみ手に入る券**で、コインとは別枠。
  スポンサー依頼(→§3.9)を達成する動機付けになり、コインを温存したまま補強できる救済にもなる。

#### 収入(コインが増える経路)

| 経路 | 説明 |
|---|---|
| 試合結果 | 勝利・引き分けで加算(負けは無し)。上位リーグほど額が大きい |
| 順位・タイトル | シーズン終了時に順位に応じて加算。タイトル獲得で大きく加算 |
| 観客動員 | スタジアム規模 × 成績(勝っているほど客が入る)。節ごとの安定収入 |

#### 施設(4種)

| 施設 | 効果 | 性格 |
|---|---|---|
| 練習場 | 所属選手の成長が速くなる | 長期投資。任期が長いほど効く |
| 医療施設 | 負傷の頻度低下・疲労回復が速い | 連戦を戦い抜くための保険 |
| スタジアム | 観客収入が増える | 投資が投資を生む(早く建てるほど得) |
| スカウト網 | 引けるパックの質が上がる。将来 `scout` 経路(→§3.4)の精度にも効く | パック主軸(D3)との接続点 |

- **完成まで数節かかる**(投資した節には効果が出ない)。この遅延がジレンマの本体。
- **施設はクラブの資産**なので、退任時は置いていく(→§3.2)。
  裏を返せば、**就任するクラブの施設レベルは前任者の遺産**であり、
  「金はあるが施設が無いクラブ」「施設は立派だが選手が老いたクラブ」といった初期状況の差になる。
- レベルの上限・費用・完成節数・効果量はすべて `TUNING` に置く(数値は実装時に決める)。
  就任時の初期施設レベルは国の格(→§3.8)によって水準が変わる。

### 3.6 試合の見せ方(D5 — 決定 2026-07-31)

**2Dピッチ上を選手が動き、実況フィードが流れるフル試合。**陣形がボールに追従し、
戦術・選手の個性が展開に出る(card-eleven と同系統の見せ方)。試合を主役に据える D2 の判断とも一致する。

#### キャリアの長さを潰さないための要件(必須)

キャリアは「12節 × 複数シーズン × 複数クラブ」に及ぶため、フル試合を素直に作ると総プレイ時間が破綻する。
以下を**最初から仕様に含める**(後付けにしない)。

| 要件 | 内容 |
|---|---|
| 倍速 | 等速 / 2倍 / 3倍を試合中に切り替えられる。設定はセーブに保存し、次の試合にも引き継ぐ |
| スキップ | 任意の時点で残りを内部処理に切り替え、結果画面へ飛べる(結果は同じロジックで決まる) |
| 自動消化 | 消化試合・格下との対戦など、監督が見なくてよい試合をまとめて処理できる |
| 1試合の尺 | 等速で 60〜90秒を目標に設計する(card-eleven の 1〜2分より短く詰める) |

#### 実装方針: 3層に分ける(card-eleven から取り込む考え方)

試合まわりは責務を3つに分け、**純粋計算を描画から完全に切り離す**。

| ファイル | 責務 | DOM |
|---|---|---|
| `match-core.js` | 試合の純粋計算とバランス(能力値→勝敗の解決) | **非依存** |
| `match-render.js` | ピッチ・選手・ボールの描画、実況、演出 | 依存 |
| `match-flow.js` | 進行制御(時間を進める・起点から結末までのつなぎ) | 依存 |

**この分離が本作では特に効く理由**:

- 自分の試合だけでなく、**同じ節の他クラブ同士の試合も毎節解決する必要がある**(リーグ表・順位・ライバルの動向)。
  `match-core` が DOM 非依存なら、裏の試合は描画せず一瞬で回せる。**スキップ・自動消化も同じ経路で実装できる**。
- headless Node のテスト(→[04. テストと検証](04-testing.md))でシーズンを何百回も回してバランス検証ができる。

> card-eleven の `src/js/match-core.js` / `match-flow.js` / `match-render.js` が同じ構造の実例。
> 実装時は**考え方と分割の境界を参照するにとどめ、コードは移植しない**(→[CLAUDE.md](../CLAUDE.md))。
> 本作の試合は「監督が采配で関与する」ことが主眼で、card-eleven のカード演出前提の設計とは要件が違う。

### 3.7 試合中の関与(D6 — 決定 2026-07-31)

監督の関与は**2層**。常時いじれる「戦術」と、ここぞで切る「采配」に分ける。

```
 【常時】戦術 — 何度でも変更できる
   🛡守備的 / ⚖バランス / ⚔攻撃的
   攻撃スタイル(中央 / サイド / ロング / ショート …)
        ↓
 【ここぞ】采配 — 1試合 1〜2回だけ
   監督がキャリアで習得した采配から選んで発動
   例) ハイプレス・電撃の交代・堅陣・先育ての契
        ↓
 【交代】残り3回(采配とは別枠)
```

#### 采配スキル = 監督の成長そのもの

- 采配は**選手ではなく監督が持つ**。任期を重ね、実績を積むことで習得していく(→§3.2 の恒久資産)。
- そのため**同じ選手層でも、キャリアを積んだ監督のほうが強い**。
  これが「監督キャリアが主軸」(D1)と試合(D5)を結ぶ中心の仕組みになる。
- 各采配は「発動条件(ビハインド時・後半・特定の相手 など)」「発動率」「効果」を持つ。
- **レジストリで持つ**: 1采配 = 1エントリ(`TACTICS`)。追加が1エントリで済む形にし、
  習得元(実績/任期/クラブ)は別テーブルで紐づける。
- **習得の手段は任期中のイベント**(→下記 D11)。

#### チーム熟練度(EXP) — 選べる戦術はクラブごとに育つ

試合を戦うと **契約中のクラブのチーム熟練度(EXP)** が上がる(結果画面の `+350 EXP`)。
熟練度が上がるほど、**そのクラブで選択できる戦術(フォーメーション・攻撃スタイル)が増える**。

```
 就任直後: 熟練度 0
   選べる戦術 … 4-4-2 / バランスのみ
        ↓ 試合を重ねる(+EXP)
 熟練度 中: 4-3-3・ポゼッション が解禁
        ↓
 熟練度 高: 高度な戦術(可変システム等)が解禁
        ↓
 【退任】次のクラブでは熟練度 0 からやり直し
```

- **熟練度はクラブに紐づき、任期ごとにリセットされる**(→§3.2 のクラブ側資産)。
- そのため**上位クラブに移った直後は、選手は良いのに戦術が不自由**という状態が生まれる。
  「渡り歩くこと」に確かなコストが生まれ、居続けて熟成させる選択にも意味が出る。
- 監督が持ち歩く**采配スキル**(恒久資産)とは別物なので、役割が重ならない。

| | 何に紐づくか | 何を決めるか | 増え方 |
|---|---|---|---|
| **采配スキル** | 監督(恒久) | 試合中に切れる切り札 | 任期中のイベントで習得 |
| **チーム熟練度(EXP)** | クラブ(任期でリセット) | 選べる戦術の幅 | 試合を戦うと自動的に加算 |

#### 采配の習得 = 任期中のイベント(D11 — 決定 2026-07-31)

節の合間に**会長・選手・秘書からのイベント**が発生し、その選択の結果として采配を覚える。
モックの**秘書画面**と**ホームの CLUB NEWS 欄**(→[06. §6.5](06-design-system.md))がそのまま器になる。

```
 第8節の後
 ┌────────────────────┐
 │ SEC 秘書                       │
 │「ベテランのDFが、監督に         │
 │   話があると」                  │
 └────────────────────┘
  ① 話を聞く
  ② 今は試合に集中する
     ↓(①を選ぶ)
  「守り方を知っている。任せてほしい」
     ↓
 ✦ 采配「堅陣」を習得
```

- **イベントもレジストリで持つ**: 1イベント = 1エントリ(`EVENTS`)。
  `{発生条件, 本文, 選択肢[], 結果}` を持ち、追加が1エントリで済む形にする。
- **発生条件は機械判定できる形に限定**する(采配の発動条件・スポンサー依頼と同じ制約)。
  例: 「3連敗中」「無失点が3試合続いた」「ベテランがベンチに座り続けている」「格上に勝った直後」。
- **結果は采配の習得だけではない**。名声の増減・コイン・選手の状態変化・会長の評価も動かせるようにし、
  イベントを「任期の物語を進める汎用の器」として使う。
- 選択には**外れも用意する**(常に得をするなら選択にならない)。ただし理不尽な大損は避け、
  「短期の成績を取るか、長期の信頼を取るか」のような**筋の通ったトレードオフ**にする。
- 采配ごとに習得イベントを紐づけるため、**任期ごとに覚える采配が変わる**。
  同じクラブを渡り歩いても毎回同じ監督像にならない。

#### 発動回数を絞る理由

**1試合あたり1〜2回を上限**とする。card-eleven では采配の複数回発動が
「多くの采配を持つ監督が一方的に強い」格差を生み、後から1試合1回に制限した経緯がある
(同リポジトリのコミット「監督采配を1試合1回までに制限」)。本作は最初から上限付きで設計する。

#### 倍速・自動消化との整合(→§3.6)

- 采配は任意タイミング発動なので、倍速中でもそのまま成立する。
- **自動消化・スキップ時**は采配を「CPUが条件に従って自動発動」する。
  自動と手動で結果の期待値が大きくズレないよう、発動条件は最初から機械的に判定できる形で定義する
  (「ビハインドかつ後半」のように、人間の勘に依存しない条件にする)。

### 3.8 キャリアの舞台(D7 — 決定 2026-07-31)

**4カ国のリーグ + 大陸大会。**昇降格ではなく、**国の格 × クラブの格**でキャリアの上下を表現する。
下位国の中位クラブから始め、実績を上げて上位国の名門へ渡り歩くのが基本の道筋。

```
  国A(最高格) ★★★★    国B ★★★
   7クラブ                7クラブ
  国C ★★                国D ★     ← ここから始まる
   7クラブ                7クラブ
        ↘     ↓     ↙
     【大陸大会】各国の上位が集まる
      下位国のクラブでも上位国の強豪を倒せる
```

| 項目 | 値 | 根拠・備考 |
|---|---|---|
| 国(リーグ)の数 | 4 | 各国に格(★1〜4)を付け、キャリアの階段にする |
| 1リーグのクラブ数 | **7クラブ**(自クラブ含む) | ホーム&アウェイの総当たりで **ちょうど12節**(→§3.3 の暫定値を確定) |
| 総クラブ数 | 28 | 手で個性を書ける現実的な量。名前・エンブレム・色・特徴を持たせる |
| 大陸大会 | シーズンに並走 | 各国の上位が出場。ノックアウト方式で数試合。シーズン合計は15試合前後 |
| 昇降格 | **持たない** | 各国1リーグのみ。キャリアの上下は「オファー」で表現する(→D8) |

#### 国ごとの色

リーグに性格を持たせ、渡り歩く先によって戦い方と経営の勝手が変わるようにする
(具体的な傾向と数値は実装時に決め、`TUNING` と国データに置く)。

| 観点 | 差の付け方の例 |
|---|---|
| 戦術傾向 | 守備的で堅いリーグ / 打ち合いになるリーグ |
| 資金規模 | コイン収入・移籍額の水準(上位国ほど大きい) |
| 選手の質 | 引けるパックの質(→§3.4)、若手の豊富さ |
| 施設水準 | 就任時にクラブが持っている施設レベル(→§3.5)の平均 |

> **キャリアの手触り**: 「国D の弱小で結果を出す → 国C の中位からオファー → 大陸大会に出る →
> 国A の名門に呼ばれる」という筋道が、そのまま監督の物語になる。

### 3.9 評価・名声・オファー(D8 — 決定 2026-07-31)

監督を測る軸は**2本**あり、役割をはっきり分ける。

| 軸 | 決めるもの | 範囲 | 動く要因 |
|---|---|---|---|
| **会長の評価** | **今のクラブに居られるか**(続投・解任) | クラブ限定。移籍するとリセット | 期待順位との差 |
| **名声** | **次にどのクラブへ行けるか** | 監督の恒久資産。キャリア全体で積み上がる | スポンサー依頼の達成 / クラブ目標の達成 / タイトル |

#### 会長の評価 — 期待値との差

就任時にクラブが「今季の期待順位」を提示する。実績がそれを**上回れば評価が上がり、下回れば下がる**。

```
 就任: 国D・弱小FC(1シーズン契約)
  会長「今季は 5位 でいい」
     ↓
 第6節: 現在 3位  → 会長の評価 ███████░ 良好 ↑
     ↓
 シーズン終了: 2位(期待 +3) → 評価 大幅上昇
     ↓
 評価が閾値を下回り続けると、任期途中でも解任
```

- **弱小クラブでの残留も偉業になる**ため、タイトルに手が届かないキャリア序盤が成立する。
- 強豪に就任すれば「優勝以外は失敗」になる。

#### 期待順位は「持ち込んだ編成」も見る(重要)

期待順位を**クラブの格だけ**から決めてはいけない。選手カードはプレイヤーの資産で
クラブを移っても持ち越せる(→§3.2.2)ため、キャリアが進むほどコレクションが強くなり、
**弱小クラブに最強の11人を持ち込んで期待順位を楽々と上回る**——という抜け道ができてしまう。

そこで期待順位は次の合成で決める:

```
 期待順位 = f( クラブの格・国の格・前年成績 ,  就任時点の編成の強さ )
                └── クラブ側の事情 ──┘     └─ 持ち込んだ戦力 ─┘
```

- **強いチームを持ち込めば、会長の期待もそれだけ上がる**。
  「あなたほどの陣容なら優勝して当然だ」という圧がかかり、評価軸(D8)が終盤まで機能し続ける。
- 逆に、あえて手持ちを使わず借り物中心(→§3.4 D13)で戦えば期待は低く抑えられる。
  **難度を自分で選べる**構造になり、腕試しの余地が生まれる。
- 合成の重みは `TUNING` に置き、実装時に調整する。

#### 名声 — スポンサー依頼とクラブ目標で増減する

名声は**クラブを移っても失われない監督個人の資産**で、**移籍可能な先の範囲**を決める。

| 増減の要因 | 説明 |
|---|---|
| **スポンサー依頼** | 任期中に提示される達成課題。達成で名声↑ + コイン/チケット↑、失敗で名声↓(例:「若手を3人以上先発させる」「ダービーに勝つ」「大陸大会に出場する」) |
| **クラブ目標の達成** | シーズン開始時にクラブが掲げる目標(順位・カップ進出など)。達成で名声↑ |
| **タイトル獲得** | リーグ/カップ/大陸大会。格に応じて大きく名声↑。トロフィーとして恒久記録 |
| **解任** | 名声↓ |

- **各クラブに「必要名声」**を設定する(国の格 × クラブの格で決まる)。
  名声が届いたクラブからオファーが来るため、名声がそのままキャリアの階段になる。
- スポンサー依頼は**弱小クラブでも名声を稼げる道**として機能する
  (順位では勝てなくても、依頼を達成すれば次のクラブへの道が開く)。
- **依頼はレジストリで持つ**: 1依頼 = 1エントリ。達成条件は采配(→§3.7)と同じく
  **機械的に判定できる形**に限定する(自動消化した試合でも同じ判定になるように)。

#### トロフィーと実績 — 集めると報酬になる

**監督の実績は、そのままプレイヤーの実績**である(→§3.2.2 の二層)。
獲得したタイトルは**キャビネットに恒久記録**として残り(クラブを移っても消えない)、
キャリアの軌跡(いつ・どのクラブで・何を獲ったか)がそのまま監督の履歴になる。

- **トロフィーが集まること自体が報酬に繋がる**。所持数・種類・格に応じて**ゲーム内報酬**を配る
  (チケット・限定パック・コイン・采配の解禁 など)。
- これにより、**目先の順位では測れない長期の遊び**が生まれる
  (「まだ獲っていない国のタイトルを獲りに行く」という動機がキャリアの選択に効く)。
- トロフィーは**キャリアを跨いで累積**するため、コレクション(→§3.2.2)と同じく
  **繰り返し遊ぶ側の資産**として働く。
- 報酬のしきい値と中身は実装時に決め、`TUNING` に置く。トロフィーの定義もレジストリで持つ。

### 3.10 ビジュアル方向性(D9 — 決定 2026-07-31)

**ピクセル選手が活躍するカードゲーム(card-eleven の系譜)を、モダンでスタイリッシュな画面に載せる。**

- **選手の描画はピクセル**(ドット絵)。試合ピッチ上の選手・カードの選手像はドットで表現する。
- **UI はモダン**。レトロUI(RPGウィンドウ枠・CRTスキャンライン)は使わず、
  暗色ベース + ゴールドのアクセント + 細いタイポグラフィで構成する。
- **画面デザインの正本は [`src/assets/design/P-footBall.html`](../src/assets/design/P-footBall.html)**
  (Claude Design で作成したモックアップ)。色・タイポ・レイアウト・画面構成はこれに従う。
  → トークンと画面インベントリは **[06. デザインシステム](06-design-system.md)** に整理した。

> モックアップ内の作品名は「P-footBall / CLUB CARD FOOTBALL」。リポジトリ名(pftb)は
> **P-footBall** の略として整合する。
