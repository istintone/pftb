## 3. ゲームデザイン

### 3.1 確定していること

- ジャンル: **サッカー**(single play browser football game)。
- プレイ形態: スマートフォン縦持ち・1人プレイ・オフライン。
- 出力形態: 単一HTML(GitHub Pages に置くだけで遊べる)。
- 姉妹作 card-eleven(収集型カードサッカー)の**土台のみ**を継承した別作品であり、
  ゲーム内容は card-eleven の焼き直しにはしない。

### 3.2 コアループ(D1 — 決定 2026-07-31)

**プレイヤーは「監督」であり、ゲームの主軸は監督個人のキャリア。**
クラブ経営を回しながら任期を勤め上げ、実績を積んでより上のクラブへ渡り歩いていく
(WCCF の監督キャリアのような体験を、収集ではなく**キャリアの積み上げ**として本体に据える)。

```
  クラブに就任(任期スタート・クラブの状況と期待値を受け取る)
        ↓
  ┌── 任期中 ──────────────────────────────┐
  │  選手を集める(補強)・クラブを強化する(経営)      │
  │        ↓                                   │
  │      試合 → 結果・評価の変動                  │
  │        ↓                                   │
  │  タイトル獲得 → トロフィー(恒久的な実績)        │
  └────────────────────────────────────────┘
        ↓
  任期満了(達成度で評価が決まる) → 続投 / 解任 / 上位クラブからのオファー
        ↓
  次のクラブへ(名声・トロフィー・采配・**集めた選手カード**は引き継ぐ)
```

- **恒久的に積み上がるもの(プレイヤー/監督のもの)**: **名声**・獲得トロフィーと実績・習得した采配・
  キャリア戦績(渡り歩いた軌跡)・**集めた選手カードのコレクション**(→§3.2.2)。
- **クラブごとにリセットされるもの**: クラブのコインと施設・リーグの順位・**会長の評価**・
  **チーム熟練度**(→§3.7)・**クラブから借りていた選手**(→§3.4 D13)。
  (名声=行ける先を決める恒久資産 / 会長の評価=今のクラブに居られるか。→§3.9)

#### 3.2.1 card-eleven との違い — 体験を監督に統合する

card-eleven は**プレー体験を複数のモードに分散**させていた(ステージ攻略・リーグ戦・ワールドツアー・
デイリー・フレンド対戦・監督キャリア…)。結果として体験にばらつきが出た。

pftb は **WCCF に倣い、最初からキャリアが中心**。前作で散っていた遊びを
**「監督としての体験」1本に統合**する。モードを増やすのではなく、キャリアの中に出来事として置く。

#### 3.2.2 リアルと非リアルの二層(ギャップは受け入れる)

本作には**2つの層**があり、両立させる。この2つは厳密には噛み合わないが、**そのギャップは意図的に許容する**。

| 層 | 誰の物語か | 求めるもの |
|---|---|---|
| **監督体験(リアル寄り)** | 監督というキャラクター | 就任・任期・評価・オファー。ナラティブに進む |
| **コレクション(非リアル)** | **プレイヤー自身** | 選手カードを集め、理想のチームを作る |

- **選手カードはプレイヤーの資産**であり、**クラブを移籍したあとも引き続き使える**。
  現実のサッカーでは監督が選手を連れて回ることはないが、
  **「集めたカードで理想のチームを作る」という目的を成立させるため、この非リアルを受け入れる**。
- 監督体験はナラティブの背骨、コレクションは繰り返し遊ぶ動機。役割が違うので同居して良い。
- **エンドコンテンツとして非同期対戦を想定**(card-eleven と同様)。
  集めたチームを他プレイヤーとぶつける場があることで、コレクションが繰り返しプレーに直結する。
  → 実装は先だが、データ設計の段階から**チーム編成を単体で持ち出せる形**にしておく。

### 3.2.3 任期 = キャリア1周(D14・D15 — 決定 2026-07-31)

**1周のキャリアは「任期96節」**。好成績なら **+24節の延命**があり、**最大120節**。
card-eleven の「限られた任期(48週)」と同じ位置づけで、**任期の満了がキャリア1周の終わり**になる。

```
 【1節】= 打ち手 ひとつ  →  試合 ひとつ(リーグ or カップ)
                     ↓ ×96
 任期96節 …… 到達しても進行中の大会は最後まで戦う
   ├ 96節以降は【新規の大会へエントリーしない】
   └ 進行中のリーグ/カップが終わった時点で
        好成績 → 延命 +24節(最大120節)
        そうでなければ → 任期終了(キャリア1周が終わる)
```

#### シーズンと任期は切り離す

大会(リーグ・カップ)への参戦が混ざる以上、節数はシーズンで割り切れない。
そこで**任期は節で通算し、シーズンは独立に回す**。

- 96節ちょうどでリーグやカップの途中でも、**中途半端に打ち切らない**。
- 96節に達したら新規エントリーを止め、**今戦っている大会の決着まで**進める。
- 決着した時点で「延命 +24節」か「任期終了」が報告される。

> **なぜ割り切らないか**: 12節×8シーズンのように割り切れる構成も検討したが、
> カップの参戦数はシーズンごとに変わる(勝ち進めば増える)ため、結局は固定できない。
> 「区切りのよい節で終わる」より「**大会の決着で終わる**」ほうが物語として自然に着地する。

#### 打ち手(各節に1つ選ぶ)

WCCF を踏襲した3種。**効果の詳細は今後詰める**(→§3.13 の D16)。

| 打ち手 | 効果 | 上限 |
|---|---|---|
| **訓練** | 選手の **★**(任期中だけ高まる能力)が上がる | ★5 |
| **交流** | 選手同士の**連携**が上がる(card-eleven の連携線にあたる) | 3段階 |
| **休息** | 全選手のメンタルが回復。**負傷者がいれば「治療」に変化**し、復帰の機会になる | — |

- ★も連携も**任期中だけのもの**で、クラブを移ると失われる(→§3.2 のクラブ側資産と同じ扱い)。

#### 1節の決め方: 打ち手 → 出場する大会

```
 【1節】 ① 打ち手を選ぶ（訓練 / 交流 / 休息）
          ↓
        ② 出場する大会を選ぶ（リーグ戦 / カップ戦）
          ↓
        ③ 試合
```

- **リーグの日程は節に固定しない**。カップ戦が割り込むため、
  「第3節=リーグ第3節」と決め打ちにはできない。**リーグを選んだ節に、次の1試合を消化する**。
- そのため任期カレンダーの未来は**空枠(未定)**として並ぶ。埋まっているのは
  「先に決まっている予定」だけ。
- **カップの連戦のように、先に予定が埋まる場合がある**。その節は大会を選べず、確定した予定が入る
  (実装上は `career.plan[節] = {comp, label}`)。
- 選べる大会が1つしかない節は、その大会に自動で寄せる(選ばせる意味がないため)。

### 3.3 時間の進み方(D2 — 決定 2026-07-31)

**1試合 = 1ターン**。節ごとに「手を1つ打つ → 試合を戦う」を繰り返す。
スマホで1セッション=1節(数分)で切り上げられるリズムを最優先し、試合を主役に保つ。

```
 就任(1シーズン契約で任期スタート)
   ↓
 ┌ シーズン(圧縮リーグ: 14節) ────────────────┐
 │  【手を一つ選ぶ】補強 / 育成 / 経営 / 偵察 …   │
 │        ↓                                    │
 │  【試合】結果 → 勝ち点・順位・評価が動く       │
 └──────────── 次の節へ ───────────────────────┘
   ↓
 シーズン終了: 順位確定・タイトル判定・トロフィー
   ↓
 オフシーズン: 移籍市場をまとめて操作
   ↓
 任期満了 → 続投 / 解任 / 上位クラブからのオファー
```

| 項目 | 暫定値 | 備考 |
|---|---|---|
| 1シーズンの節数 | **14節** | 8クラブのホーム&アウェイ総当たり・休みなし(→§3.8)。D2 当初の要件「10〜14節」の範囲内 |
| 1節にできる操作 | **1手だけ** | 手の種類(補強/育成/経営/偵察)は D3・D4 で確定 |
| クラブとの契約 | **1シーズン(更新可)** | シーズン末に審判: 更新 / 解任 / 上位クラブからのオファー。施設投資(→§3.5)の「来季も自分がここに居るか分からないのに建てるか」という緊張が生まれる |
| **キャリア1周(任期)** | **96節**(延命で最大120節) | クラブとの契約とは別軸。任期はシーズンをまたいで通算する(→§3.2.3) |
| オフシーズン | シーズンの切れ目に1回 | 移籍市場だけは「1手」の制限を外し、まとめて操作させる |

> **なぜ1節1手か**: 手数を絞ることで1つ1つの選択に重みが出て、スマホで1画面に収まる。
> 経営SLGの厚み(週単位カレンダー)は操作が重くなり、シーズン一括ダイジェストは試合の手触りが薄れるため見送った。

### 3.4 選手の入手(D3 — 決定 2026-07-31)

**主軸はカードパック。**ただし入手経路は**最初から複数前提の作り**にし、スカウトなどを後から足せるようにする。

```
 【節の手】パックを引く
   コイン △ を消費(またはチケット1枚)
     ↓
   ✦ 開封 ✦
     ↓
   出た選手 → 契約する / 見送る(コインに一部還元)
     ↓
   編成へ(すぐ次の試合で使える)
```

- **card-eleven との違い**: card-eleven のガチャは「コレクションを増やす行為」そのものが目的。
  pftb のパックは**クラブのコインをどう配分するか**という経営判断であり、任期という締め切りの中で
  「今引くか、貯めて上位パックを引くか、経営(D4)に回すか」を迫るための仕組みにする。
- **パックの段階**: **国の格 × クラブの格**(→§3.8)と保有コインに応じて引けるパックが変わる
  (下位国の弱小クラブでは安いパックしか引けない)。種類と確率の数値は `TUNING` に集約する。

#### 入手経路はレジストリで持つ(拡張の要)

入手手段を `SOURCES` レジストリ(1経路=1エントリ)として定義し、パックを最初のエントリとして実装する。
UI(「補強」画面の選択肢)とコストの消費も、レジストリの定義から自動で並べる。

| 経路 | 状態 | 概要 |
|---|---|---|
| `pack` | **v1で実装** | コインを払ってパックを引く。即時に結果が出る |
| `scout` | 将来 | 節の手でスカウトを派遣し、数節後に候補が上がる(遅延型) |
| `market` | 将来 | オフシーズンの移籍市場。他クラブと競合しながら交渉 |
| `youth` | 将来 | 下部組織からの昇格。シーズン境界で発生 |
| `free` | 将来 | 契約満了選手をコイン0で獲得(質は低い) |

> 経路を足すときは `SOURCES` に1エントリ追加すれば済むようにする。
> 「即時か遅延か」「節の手を使うかオフ限定か」を各エントリの属性として持たせ、
> 進行側(節の手の消費)は経路の中身を知らない構造にする。

#### 退任時に選手はどうなるか — **持ち越せる**(2026-07-31 変更)

**集めた選手カードはプレイヤーの資産であり、クラブを移籍しても引き続き使える**(→§3.2.2)。

> **⚠ 方針変更**: 当初は「選手はクラブの資産・退任時に置いていく(記録だけ監督の名鑑に残る)」と
> 暫定で決めていたが、**「集めたカードで理想のチームを作る」というプレイヤー側の目的を優先**して覆した。
> 現実の監督は選手を連れて回らないが、そのギャップは意図的に受け入れる。

- パックで引いた選手が任期の終わりに消えないため、**課金的なコレクションの手応えが成立する**。
- クラブを移るコストは選手ではなく、**コイン・施設・チーム熟練度・会長の評価がリセットされること**で表現する
  (→§3.2 / §3.7)。
- 移籍後も同じチームで戦えることは、エンドコンテンツの**非同期対戦**(→§3.2.2)の前提にもなる。

#### クラブ所属選手は「任期中の貸与」(D13 — 決定 2026-07-31)

就任すると、**そのクラブの所属選手が使える状態で渡される**。自分のカードと**混成して11人を組む**。

```
 国D・弱小FC に就任
 ─────────────────────
 【クラブ所属】任期中だけ借りられる
   GK ハンセン   OVR 68
   DF モラレス   OVR 71
   …(11人分そろうが弱い)

 【手持ちカード】自分の資産
   FW シルヴェイラ OVR 93 ★
   MF オコフォー   OVR 87 ★
     ↓
   混成して編成(★ が自分のカード)
     ↓
 【退任】借りた選手はクラブに残る / ★ は連れて行く
```

| | クラブ所属選手 | 手持ちカード |
|---|---|---|
| 誰のものか | クラブ | **プレイヤー** |
| 質 | **クラブの格で決まる**(弱小は本当に弱い) | 集めた分だけ強くなる |
| 退任時 | クラブに残る | 連れて行く |
| 表示 | 通常 | **★ などで区別**する |

- **これで期待順位と実際の戦力が噛み合う**。弱小クラブは既存戦力が本当に弱いので、
  「残留させれば偉業」(→§3.9)が絵空事にならない。
- **コンビネーション(`combo`)と自然に噛み合う**: 借りた選手は同じクラブ所属なので発動しやすい。
  「借り物中心で結束を取るか、手持ちの強いカードで individual に殴るか」という編成の選択が生まれる。
- **練習場(施設)で育てた選手は持ち出せない**(借り物なので)。施設投資が「クラブに遺すもの」という
  性格を強め、§3.5 の投資判断とも筋が通る。
- 借りた選手を買い取って自分のカードにする仕組みは**今回は入れない**(→バックログの検討候補)。

### 3.5 クラブ経営(D4 — 決定 2026-07-31)

資金は**「コイン」1本**に集約する(給与・スポンサー・維持費といった細かい費目は持たない)。
コインの使い道は **「今を取る(パック=即戦力)」か「先を取る(施設投資)」** の二択で、
任期という締め切りがあるため「**その投資は任期中に回収できるのか**」が毎節の判断になる。

```
 コイン(クラブ予算)
  ├─ 今を取る … パックを引く      → 即座に戦力化
  └─ 先を取る … 施設に投資する    → 数節後に完成、以降ずっと効く
                                     (1シーズン契約なので回収できるとは限らない)

 チケット(報酬券)  … コインを使わずにパックを引ける
  └─ スポンサー依頼の達成・タイトル獲得・実績で配られる
```

- **通貨はコイン1本**。パックも施設もコインを奪い合うため、「今を取るか先を取るか」の判断が成立する。
- **チケットは報酬としてのみ手に入る券**で、コインとは別枠。
  スポンサー依頼(→§3.9)を達成する動機付けになり、コインを温存したまま補強できる救済にもなる。

#### 収入(コインが増える経路)

| 経路 | 説明 |
|---|---|
| 試合結果 | 勝利・引き分けで加算(負けは無し)。上位リーグほど額が大きい |
| 順位・タイトル | シーズン終了時に順位に応じて加算。タイトル獲得で大きく加算 |
| 観客動員 | スタジアム規模 × 成績(勝っているほど客が入る)。節ごとの安定収入 |

#### 施設(4種)

| 施設 | 効果 | 性格 |
|---|---|---|
| 練習場 | 所属選手の成長が速くなる | 長期投資。任期が長いほど効く |
| 医療施設 | 負傷の頻度低下・疲労回復が速い | 連戦を戦い抜くための保険 |
| スタジアム | 観客収入が増える | 投資が投資を生む(早く建てるほど得) |
| スカウト網 | 引けるパックの質が上がる。将来 `scout` 経路(→§3.4)の精度にも効く | パック主軸(D3)との接続点 |

- **完成まで数節かかる**(投資した節には効果が出ない)。この遅延がジレンマの本体。
- **施設はクラブの資産**なので、退任時は置いていく(→§3.2)。
  裏を返せば、**就任するクラブの施設レベルは前任者の遺産**であり、
  「金はあるが施設が無いクラブ」「施設は立派だが選手が老いたクラブ」といった初期状況の差になる。
- レベルの上限・費用・完成節数・効果量はすべて `TUNING` に置く(数値は実装時に決める)。
  就任時の初期施設レベルは国の格(→§3.8)によって水準が変わる。

### 3.6 試合の見せ方(D5 — 決定 2026-07-31)

**2Dピッチ上を選手が動き、実況フィードが流れるフル試合。**陣形がボールに追従し、
戦術・選手の個性が展開に出る(card-eleven と同系統の見せ方)。試合を主役に据える D2 の判断とも一致する。

#### キャリアの長さを潰さないための要件(必須)

キャリアは「14節 × 複数シーズン × 複数クラブ」に及ぶため、フル試合を素直に作ると総プレイ時間が破綻する。
以下を**最初から仕様に含める**(後付けにしない)。

| 要件 | 内容 |
|---|---|
| 倍速 | 等速 / 2倍 / 3倍を試合中に切り替えられる。設定はセーブに保存し、次の試合にも引き継ぐ |
| スキップ | 任意の時点で残りを内部処理に切り替え、結果画面へ飛べる(結果は同じロジックで決まる) |
| 自動消化 | 消化試合・格下との対戦など、監督が見なくてよい試合をまとめて処理できる |
| 1試合の尺 | 等速で 60〜90秒を目標に設計する(card-eleven の 1〜2分より短く詰める) |

#### 実装方針: 3層に分ける(card-eleven から取り込む考え方)

試合まわりは責務を3つに分け、**純粋計算を描画から完全に切り離す**。

| ファイル | 責務 | DOM |
|---|---|---|
| `match-core.js` | 試合の純粋計算とバランス(能力値→勝敗の解決) | **非依存** |
| `match-render.js` | ピッチ・選手・ボールの描画、実況、演出 | 依存 |
| `match-flow.js` | 進行制御(時間を進める・起点から結末までのつなぎ) | 依存 |

**この分離が本作では特に効く理由**:

- 自分の試合だけでなく、**同じ節の他クラブ同士の試合も毎節解決する必要がある**(リーグ表・順位・ライバルの動向)。
  `match-core` が DOM 非依存なら、裏の試合は描画せず一瞬で回せる。**スキップ・自動消化も同じ経路で実装できる**。
- headless Node のテスト(→[04. テストと検証](04-testing.md))でシーズンを何百回も回してバランス検証ができる。

> card-eleven の `src/js/match-core.js` / `match-flow.js` / `match-render.js` が同じ構造の実例。
> 実装時は**考え方と分割の境界を参照するにとどめ、コードは移植しない**(→[CLAUDE.md](../CLAUDE.md))。
> 本作の試合は「監督が采配で関与する」ことが主眼で、card-eleven のカード演出前提の設計とは要件が違う。

### 3.7 試合中の関与(D6 — 決定 2026-07-31)

監督の関与は**2層**。常時いじれる「戦術」と、ここぞで切る「采配」に分ける。

```
 【常時】戦術 — 何度でも変更できる
   🛡守備的 / ⚖バランス / ⚔攻撃的
   攻撃スタイル(中央 / サイド / ロング / ショート …)
        ↓
 【ここぞ】采配 — 1試合 1〜2回だけ
   監督がキャリアで習得した采配から選んで発動
   例) ハイプレス・電撃の交代・堅陣・先育ての契
        ↓
 【交代】残り3回(采配とは別枠)
```

#### 采配スキル = 監督の成長そのもの

- 采配は**選手ではなく監督が持つ**。任期を重ね、実績を積むことで習得していく(→§3.2 の恒久資産)。
- そのため**同じ選手層でも、キャリアを積んだ監督のほうが強い**。
  これが「監督キャリアが主軸」(D1)と試合(D5)を結ぶ中心の仕組みになる。
- 各采配は「発動条件(ビハインド時・後半・特定の相手 など)」「発動率」「効果」を持つ。
- **レジストリで持つ**: 1采配 = 1エントリ(`TACTICS`)。追加が1エントリで済む形にし、
  習得元(実績/任期/クラブ)は別テーブルで紐づける。
- **習得の手段は任期中のイベント**(→下記 D11)。

#### チーム熟練度(EXP) — 選べる戦術はクラブごとに育つ

試合を戦うと **契約中のクラブのチーム熟練度(EXP)** が上がる(結果画面の `+350 EXP`)。
熟練度が上がるほど、**そのクラブで選択できる戦術(フォーメーション・攻撃スタイル)が増える**。

```
 就任直後: 熟練度 0
   選べる戦術 … 4-4-2 / バランスのみ
        ↓ 試合を重ねる(+EXP)
 熟練度 中: 4-3-3・ポゼッション が解禁
        ↓
 熟練度 高: 高度な戦術(可変システム等)が解禁
        ↓
 【退任】次のクラブでは熟練度 0 からやり直し
```

- **熟練度はクラブに紐づき、任期ごとにリセットされる**(→§3.2 のクラブ側資産)。
- そのため**上位クラブに移った直後は、選手は良いのに戦術が不自由**という状態が生まれる。
  「渡り歩くこと」に確かなコストが生まれ、居続けて熟成させる選択にも意味が出る。
- 監督が持ち歩く**采配スキル**(恒久資産)とは別物なので、役割が重ならない。

| | 何に紐づくか | 何を決めるか | 増え方 |
|---|---|---|---|
| **采配スキル** | 監督(恒久) | 試合中に切れる切り札 | 任期中のイベントで習得 |
| **チーム熟練度(EXP)** | クラブ(任期でリセット) | 選べる戦術の幅 | 試合を戦うと自動的に加算 |

#### 采配の習得 = 任期中のイベント(D11 — 決定 2026-07-31)

節の合間に**会長・選手・秘書からのイベント**が発生し、その選択の結果として采配を覚える。
モックの**秘書画面**と**ホームの CLUB NEWS 欄**(→[06. §6.5](06-design-system.md))がそのまま器になる。

```
 第8節の後
 ┌────────────────────┐
 │ SEC 秘書                       │
 │「ベテランのDFが、監督に         │
 │   話があると」                  │
 └────────────────────┘
  ① 話を聞く
  ② 今は試合に集中する
     ↓(①を選ぶ)
  「守り方を知っている。任せてほしい」
     ↓
 ✦ 采配「堅陣」を習得
```

- **イベントもレジストリで持つ**: 1イベント = 1エントリ(`EVENTS`)。
  `{発生条件, 本文, 選択肢[], 結果}` を持ち、追加が1エントリで済む形にする。
- **発生条件は機械判定できる形に限定**する(采配の発動条件・スポンサー依頼と同じ制約)。
  例: 「3連敗中」「無失点が3試合続いた」「ベテランがベンチに座り続けている」「格上に勝った直後」。
- **結果は采配の習得だけではない**。名声の増減・コイン・選手の状態変化・会長の評価も動かせるようにし、
  イベントを「任期の物語を進める汎用の器」として使う。
- 選択には**外れも用意する**(常に得をするなら選択にならない)。ただし理不尽な大損は避け、
  「短期の成績を取るか、長期の信頼を取るか」のような**筋の通ったトレードオフ**にする。
- 采配ごとに習得イベントを紐づけるため、**任期ごとに覚える采配が変わる**。
  同じクラブを渡り歩いても毎回同じ監督像にならない。

#### 発動回数を絞る理由

**1試合あたり1〜2回を上限**とする。card-eleven では采配の複数回発動が
「多くの采配を持つ監督が一方的に強い」格差を生み、後から1試合1回に制限した経緯がある
(同リポジトリのコミット「監督采配を1試合1回までに制限」)。本作は最初から上限付きで設計する。

#### 倍速・自動消化との整合(→§3.6)

- 采配は任意タイミング発動なので、倍速中でもそのまま成立する。
- **自動消化・スキップ時**は采配を「CPUが条件に従って自動発動」する。
  自動と手動で結果の期待値が大きくズレないよう、発動条件は最初から機械的に判定できる形で定義する
  (「ビハインドかつ後半」のように、人間の勘に依存しない条件にする)。

### 3.8 キャリアの舞台(D7 — 決定 2026-07-31 / D21 で実在リーグへ 2026-08-02)

**6リーグ + 大陸大会。**昇降格ではなく、**リーグの格 × クラブの格**でキャリアの上下を表現する。
下位リーグの中位クラブから始め、実績を上げて上位リーグの名門へ渡り歩くのが基本の道筋。

```
  プレミア ★6          ラ・リーガ ★5
  セリエ ★4            ブンデス ★3
  リーグアン ★2        カンピオナート ★1  ← ここから始まる
        ↘     ↓     ↙
     【大陸大会】各リーグの上位が集まる
      下位リーグのクラブでも上位リーグの強豪を倒せる
```

| リーグ | 国 | 格 | 性格 | 予算 | 自国籍の比率 |
|---|---|---|---|---|---|
| **プレミア** | イングランド | ★6 | 強度 | 1.00 | 低い(30) — 世界中から集まる |
| **ラ・リーガ** | スペイン | ★5 | 技巧 | 0.92 | 45 |
| **セリエ** | イタリア | ★4 | 堅守 | 0.82 | 42 |
| **ブンデス** | ドイツ | ★3 | 組織 | 0.76 | 55 |
| **リーグアン** | フランス | ★2 | 個 | 0.66 | 45 |
| **カンピオナート** | 南米 | ★1 | 創造 | 0.50 | **高い(75)** — 地元中心 |

| 項目 | 値 | 根拠・備考 |
|---|---|---|
| リーグの数 | **6** | 実在リーグを想定。格(★1〜6)がそのままキャリアの階段になる |
| 1リーグのクラブ数 | **8クラブ**(自クラブ含む) | ホーム&アウェイの総当たりで **14節**・休みなし(→§3.3)。※当初「7クラブ=12節」としていたが、7は奇数で毎節1クラブが休みになり実際は14節。12は**試合数**であって節数ではなかった |
| 総クラブ数 | **48** | 手で個性を書ける現実的な量。名前・エンブレム・色・特徴を持たせる |
| 大陸大会 | シーズンに並走 | 各リーグの上位が出場。ノックアウト方式で数試合。**未実装**(第3段以降) |
| 昇降格 | **持たない** | 各リーグ1部のみ。キャリアの上下は「オファー」で表現する(→D8) |

#### クラブ名は元ネタが分かる程度に改変する

実在クラブの商標は持ち込まないが、**どのクラブがモデルか分かる名前**にする
(→§3.13 の実在選手と同じ方針)。地名 + 愛称・色・伝統的な呼び名の組み合わせで作る。

| リーグ | 例 |
|---|---|
| プレミア | マンチェスター・レッズ / ロンドン・ガナーズ / リヴァプール・コップ |
| ラ・リーガ | マドリード・ブランコス / カタルーニャ・ブラウグラナ |
| セリエ | トリノ・ビアンコネーリ / ミラノ・ネラッズーリ |
| ブンデス | ミュンヘン・ローテン / ドルトムント・シュヴァルツゲルプ |
| リーグアン | パリ・キャピタル / マルセイユ・オリンピアン |
| カンピオナート | リオ・ルブロネグロ / ブエノスアイレス・ボンボネーラ |

#### リーグごとの色

リーグに性格を持たせ、渡り歩く先によって戦い方と経営の勝手が変わるようにする
(具体的な傾向と数値は実装時に決め、`TUNING` とリーグデータに置く)。

| 観点 | 差の付け方の例 |
|---|---|
| 戦術傾向 | 守備的で堅いリーグ / 打ち合いになるリーグ |
| 資金規模 | コイン収入・移籍額の水準(上位リーグほど大きい) |
| 選手の質 | 引けるパックの質(→§3.4)、若手の豊富さ |
| 施設水準 | 就任時にクラブが持っている施設レベル(→§3.5)の平均 |
| **国籍構成** | **実装済み**。自国比率が `homeW` で決まり、プレミアは国際的・カンピオナートは地元中心 |

> **キャリアの手触り**: 「カンピオナートの弱小で結果を出す → リーグアンの中位からオファー →
> 大陸大会に出る → プレミアの名門に呼ばれる」という筋道が、そのまま監督の物語になる。

### 3.9 評価・名声・オファー(D8 — 決定 2026-07-31)

監督を測る軸は**2本**あり、役割をはっきり分ける。

| 軸 | 決めるもの | 範囲 | 動く要因 |
|---|---|---|---|
| **会長の評価** | **今のクラブに居られるか**(続投・解任) | クラブ限定。移籍するとリセット | 期待順位との差 |
| **名声** | **次にどのクラブへ行けるか** | 監督の恒久資産。キャリア全体で積み上がる | スポンサー依頼の達成 / クラブ目標の達成 / タイトル |

#### 会長の評価 — 期待値との差(**累積しない**)

評価は「今の順位が期待に対してどうか」から**毎回導出**する。差分を足し込む累積式にしてはいけない。

> 累積式にすると、**期待1位のクラブは `期待 − 順位` が常に0以下にしかならず評価が減る一方**になり、
> 逆に**期待最下位のクラブは常に0以上で決してクビにならない**、という非対称が生まれる
> (実装時に検証テストで発覚した)。導出式なら「期待どおり = 基準値」「上回れば上・下回れば下」が
> 順位に関わらず対称に効く。
>
> `評価 = 基準値 + (期待順位 − 現在順位) × 係数`（0〜100でクランプ）


就任時にクラブが「今季の期待順位」を提示する。実績がそれを**上回れば評価が上がり、下回れば下がる**。

```
 就任: 国D・弱小FC(1シーズン契約)
  会長「今季は 5位 でいい」
     ↓
 第6節: 現在 3位  → 会長の評価 ███████░ 良好 ↑
     ↓
 シーズン終了: 2位(期待 +3) → 評価 大幅上昇
     ↓
 評価が閾値を下回り続けると、任期途中でも解任
```

- **弱小クラブでの残留も偉業になる**ため、タイトルに手が届かないキャリア序盤が成立する。
- 強豪に就任すれば「優勝以外は失敗」になる。

#### 期待順位は「持ち込んだ編成」も見る(重要)

期待順位を**クラブの格だけ**から決めてはいけない。選手カードはプレイヤーの資産で
クラブを移っても持ち越せる(→§3.2.2)ため、キャリアが進むほどコレクションが強くなり、
**弱小クラブに最強の11人を持ち込んで期待順位を楽々と上回る**——という抜け道ができてしまう。

そこで期待順位は次の合成で決める:

```
 期待順位 = f( クラブの格・国の格・前年成績 ,  就任時点の編成の強さ )
                └── クラブ側の事情 ──┘     └─ 持ち込んだ戦力 ─┘
```

- **強いチームを持ち込めば、会長の期待もそれだけ上がる**。
  「あなたほどの陣容なら優勝して当然だ」という圧がかかり、評価軸(D8)が終盤まで機能し続ける。
- 逆に、あえて手持ちを使わず借り物中心(→§3.4 D13)で戦えば期待は低く抑えられる。
  **難度を自分で選べる**構造になり、腕試しの余地が生まれる。
- 合成の重みは `TUNING` に置き、実装時に調整する。

#### 名声 — スポンサー依頼とクラブ目標で増減する

名声は**クラブを移っても失われない監督個人の資産**で、**移籍可能な先の範囲**を決める。

| 増減の要因 | 説明 |
|---|---|
| **スポンサー依頼** | 任期中に提示される達成課題。達成で名声↑ + コイン/チケット↑、失敗で名声↓(例:「若手を3人以上先発させる」「ダービーに勝つ」「大陸大会に出場する」) |
| **クラブ目標の達成** | シーズン開始時にクラブが掲げる目標(順位・カップ進出など)。達成で名声↑ |
| **タイトル獲得** | リーグ/カップ/大陸大会。格に応じて大きく名声↑。トロフィーとして恒久記録 |
| **解任** | 名声↓ |

- **各クラブに「必要名声」**を設定する(国の格 × クラブの格で決まる)。
  名声が届いたクラブからオファーが来るため、名声がそのままキャリアの階段になる。
- スポンサー依頼は**弱小クラブでも名声を稼げる道**として機能する
  (順位では勝てなくても、依頼を達成すれば次のクラブへの道が開く)。
- **依頼はレジストリで持つ**: 1依頼 = 1エントリ。達成条件は采配(→§3.7)と同じく
  **機械的に判定できる形**に限定する(自動消化した試合でも同じ判定になるように)。

#### トロフィーと実績 — 集めると報酬になる

**監督の実績は、そのままプレイヤーの実績**である(→§3.2.2 の二層)。
獲得したタイトルは**キャビネットに恒久記録**として残り(クラブを移っても消えない)、
キャリアの軌跡(いつ・どのクラブで・何を獲ったか)がそのまま監督の履歴になる。

- **トロフィーが集まること自体が報酬に繋がる**。所持数・種類・格に応じて**ゲーム内報酬**を配る
  (チケット・限定パック・コイン・采配の解禁 など)。
- これにより、**目先の順位では測れない長期の遊び**が生まれる
  (「まだ獲っていない国のタイトルを獲りに行く」という動機がキャリアの選択に効く)。
- トロフィーは**キャリアを跨いで累積**するため、コレクション(→§3.2.2)と同じく
  **繰り返し遊ぶ側の資産**として働く。
- 報酬のしきい値と中身は実装時に決め、`TUNING` に置く。トロフィーの定義もレジストリで持つ。

### 3.12 選手パラメータ(D17 — 決定 2026-08-01)

card-eleven と同じ6軸にしたうえで、**上限を WCCF 由来の20**にする。
試合ロジックを card-eleven の考え方の上に置きつつ、数値の意味を別物にするための土台。

#### 能力は6つ・各20が上限・OVR は合計

| 能力 | 意味 |
|---|---|
| **ATK** | 攻撃(GKはフィード) |
| **DEF** | 守備(GKはセービング) |
| **POW** | 強さ・競り合い |
| **TEC** | 技術 |
| **SPD** | 速さ |
| **STA** | スタミナ |

- 各能力は **1〜20**。**OVR = 6能力の合計**なので**上限は120**。
- 生成は「OVR ÷ 6 × ポジション別の重み」で配る。重みの合計を 6.0 に揃えてあるので
  平均が動かず、端数と上限クランプでずれた分は最後に配り直して
  **OVR = 合計** を必ず成立させる(検証テストあり)。
- レア度ごとの OVR の目安: STANDARD 54〜72 / RARE 68〜86 / SUPER 82〜98 / ULTRA 94〜112。

#### ポジションはメイン + サブ(複数)

```
 pos : "MF"            ← メイン(大分類 GK/DF/MF/FW)
 subs: ["OMF", "CB"]   ← サブ。subs[0] がプライマリ
```

| メイン | サブ |
|---|---|
| GK | GK |
| DF | CB / LSB / RSB |
| MF | DMF / CMF / OMF / LMF / RMF |
| FW | CF / ST / LWG / RWG |

- **プライマリ(subs[0])は必ずメインの側から選ぶ**ので、所属する大分類が揺らぐことはない。
- 例外として**隣接するサブ**を持てる(FW→OMF / MF→CB・ST・CF / DF→DMF)。
  「FW で ST だが OMF もこなす」はこの形で表す。メインは FW のまま。
- レアなほど複数のサブを持ちやすい。

#### 枠適性(編成の良し悪し)

| 状態 | 係数 |
|---|---|
| プライマリが一致 | **1.00** |
| 他のサブが一致 | **0.95** |
| 大分類だけ同じ | 0.85 |
| それ以外 | 0.60 |

複数ポジションをこなす選手に価値が出るよう、サブ一致を大分類一致より高くしてある。

### 3.13 レアリティ(D18 — 決定 2026-08-01)

段は**監督から見たその選手の役割**で分ける。WCCF/card-eleven と同じく、
**カードの背景レイアウトがレアリティを示す主役**になる(→[06. §6.13](06-design-system.md))。
地の色は WCCF と同じ階段で上がる: **白 → 黒 → 黒のホロ → 虹のホロ → 黒金**。

| 段 | 略称 | 意味 | 見た目 | OVR目安 | スキル | 排出 |
|---|---|---|---|---|---|---|
| **STANDARD** | `ST` | 控え。クラブにはいるがレギュラーではない | **白** | 54〜72 | 1 | 62% |
| **REGULAR** | `RG` | スタメン。クラブのメイン選手 | **黒**(銀の縁) | 68〜86 | 2 | 30% |
| **SPECIALS** | `SP` | 切り札。試合を支配するヒーロー | **黒のホロ** | 82〜98 | 3 | 8% |
| **WORLD CLASS** | `WC` | **実在の現役選手** | **虹のホロ**(華やかさで頂点) | 96〜110 | 3 | — |
| **LEGENDS** | `LE` | **実在の過去の名選手** | **黒金**(静かな重厚さ・最上位) | 100〜116 | 4 | — |

- レアリティが決めるのは **OVR帯 / スキル数 / サブポジションの数**(D18-2)。
- **WORLD CLASS と LEGENDS はパックから出ない**。自動生成もしない。
  実在選手をモチーフにするため**手で定義するデータ**で、トロフィー・実績など別経路で配る
  (card-eleven のシグネチャー/エモーショナルと同じ扱い)。
- 実装では `RARITY[段].w = 0` がその印。`RAR_DROPS` がパック対象の段だけを持つ。
- **カード左上のクレストには2文字略称**(`ST`/`RG`/`SP`/`WC`/`LE`)を入れる。正式名称は盾に入らない。
- 見る手段が無い段は **CLUB のカード見本**で確認できる(→[06. §6.14](06-design-system.md))。

#### WORLD CLASS はテーマレアへ派生させる

WCCF に倣い、**BANDIERA / MVP / BEST ELEVEN** のようなテーマ別のレアを今後足す。
派生しても**版面(区画の位置)は5種と同じ**に保つので、増えるのは背景1枚だけで済む。

#### 実在選手の扱い(2026-08-01 決定)

WORLD CLASS / LEGENDS は実在の人物をモチーフにする。本作は GitHub Pages で公開しているため、
**第三者の商標は持ち込まない**方針を取る。

| 対象 | 対応 |
|---|---|
| **スポンサー名** | **架空の造語に置き換える**(AETHERNET / KINETICA など) |
| **クラブエンブレム** | **架空の意匠に置き換える**。右胸・左胸・パンツの裾の**3か所すべて** |
| **メーカーロゴ** | 描かない |
| **クラブ名** | **実在の元ネタが分かる程度に改変**した名前を使う |
| 代替案 | 代表ユニフォームで対応してもよい |

> **取りこぼしやすい点**: 生成AIは**スポンサーだけ架空にしてエンブレムを実在のまま残す**。
> 実際に一度起きた。受け取ったら `python tools/zoom_kit.py <シート>` で胸元を拡大し、
> **エンブレムまで架空になっているか**を毎回確認する。
>
> なお、これで外せるのは商標の問題であって、**人物の肖像そのものは変わらない**。
> 公開範囲を広げるときは改めて判断すること。

#### どこに置くか

実在選手カードは自動生成の経路に混ぜず、**`src/js/signatures.js` の `SIGNATURES` に手で書く**。
6能力を直接指定し、OVR は `calcOvr()` で合計として取り直すので、
手書きの値と表示がずれない(→§3.12)。

| もの | 置き場所 |
|---|---|
| カードの定義 | `src/js/signatures.js` の `SIGNATURES`(`art` がイラストのキー) |
| イラスト | `src/assets/players/<art>_stand|play|goal.webp` |
| 取り出し | `signatureCards()` → 通常のカードと同じ形。ID は 8,000,000 番台 |

イラストは **3枚セットのシートを `python tools/slice_player.py <シート> <art>` で切り出す**
(3等分 → 白背景を透過 → 420×500 に統一)。カード面に出るのは **②プレイ絵**
(`playerArt()` → `.pc-img`)。ピクセルアートなので `image-rendering:pixelated` を必ず当てる。
**イラストが無くても `PLAYER` のプレースホルダで成立する**ので、
自動生成の選手(STD/REG/SPE)は絵を持たないまま動く(→ D19 で決める)。

初出: **C. ロナウド**(WC / OVR 97 / マンチェスター・レッズ)。

### 3.14 枠適性(D20 — 決定 2026-08-02)

**誰をどこに置くか**が編成の勝負どころになるように、枠に合わない選手は本来の力を出せない。
card-eleven の考え方を踏襲し、**3段**にする(細かく刻んでも読み取れないため)。

| 状態 | 係数 | 意味 |
|---|---|---|
| **サブポジションが一致** | **1.00** | 本来の力を発揮できる |
| サブは不一致・**メイン(大分類)が一致** | **0.75** | とりあえず使えるが、本来の力は出ない |
| **サブもメインも不一致** | **0.50** | ほぼ機能しない |

- **プライマリと他のサブは区別しない**。どのサブでも 1.00。
  複数のサブを持つこと自体が、その選手の価値になる(→§3.12 のサブポジション複数持ち)。
- 係数は `TUNING.fit` に置く。ロジックへ直書きしない。
- 例外のサブ(FWのSTがOMFもこなす等)も**サブに入っていれば 1.00**。
  大分類をまたぐサブを持つ選手は、それだけで置ける枠が広い。

#### 係数を決めた経緯(2026-08-02)

**どちらも当初値から下げた。上げ幅ではなく「OVRで覆せてしまうか」で決めている。**

不一致の選手が完全一致の選手を上回るのは `OVR比 > 1 / 係数` のとき。
OVR の幅は 54〜116(**2.1倍**)しかないので、係数が高いと**OVRがポジションを完全に食う**。

##### 不一致: 0.70 → 0.50

当初 0.70 で入れたところ、**OVR がポジションを完全に食ってしまった**。

当初 0.70 で入れたところ、**フィールドプレイヤーがゴールを守った**。

| 係数 | 覆すのに要るOVR比 | 自動編成でGK枠にGK以外 | 枠に合わない配置 |
|---|---|---|---|
| 0.70 | 1.43倍 | **4 / 32 クラブ** | 33.8%（不一致を含む） |
| **0.50** | **2.00倍** | **0 / 32 クラブ** | 32.1%（すべてメインのみ） |

2.1倍しかないOVR幅で2倍の差を作るのは難しく、**不一致の配置が自動編成から消えた**。

##### メインのみ: 0.85 → 0.75

**上限は 83.2%**。16人の名簿では全11枠ぶんのサブが揃わないので、
完全一致にできる枠は 293/352 が限界であり、100% は最初から不可能。

| 係数 | 覆すのに要るOVR比 | 完全一致 | メインのみ | 不一致 |
|---|---|---|---|---|
| 0.85 | 1.18倍 | 67.9%（上限の82%） | 32.1% | 0件 |
| 0.80 | 1.25倍 | 73.3%（上限の88%） | 26.4% | 1件 |
| **0.75** | **1.33倍** | **77.8%（上限の94%）** | **21.6%** | **2件** |
| 0.70 | 1.43倍 | 79.5%（上限の96%） | 17.9% | **9件** |

**0.75 で止める。** これ以上下げても完全一致はほとんど増えないのに、
**`main` が `none` に近づくぶん、高OVRの不一致が「メインのみ」を押しのけて増える**
(0.70 で 2件 → 9件)。`main` と `none` の間隔は 1.5倍(0.75/0.50)を保つ。

> **どちらの変更でも試合バランスは動かない**(平均2.46点 / 引き分け26.8%)。
> CPU も同じ適性で編成するため、両者が同じだけ影響を受けて相殺される。
>
> `worldtest.js` が32クラブぶんの自動編成を回して
> 「GKがいる名簿でGK枠にGK以外を置かない」「不一致の配置は2%未満」を検査する。

#### どこに効くか

| | 適性を掛けるか |
|---|---|
| **試合の強さ**(`match-core`) | **掛ける**。実際に戦うのは配置込みの力 |
| **DECK の総合力表示**(`squadPowerAt`) | **掛ける**。この画面で決めるのは「誰をどこに置くか」だから |
| 期待順位(`expectedRank` → `squadPower`) | **掛けない**(OVRの平均) |
| 自動編成(`autoSquad`) | 掛ける。`slotFit × OVR` が最大になる並びを採る |

> **期待順位に適性を掛けないのは意図的**。会長は「持っている戦力」を見て期待を決める。
> **並べ方を誤ったのは監督の責任**であって、期待が下がる理由にはならない。
> だから雑な配置は「期待は据え置きのまま実力だけ落ちる」形で罰せられる。

見せ方(ピッチ上のポジション名の濃さ)は [06. §6.15](06-design-system.md)。

### 3.15 選手の国籍(D21 — 決定 2026-08-02)

**選手の国籍は実在の16か国**。クラブの所属リーグ(→§3.8)とは**別物**で、
どのリーグのクラブにも他国から選手が集まる。

| 地域 | 国籍 |
|---|---|
| ヨーロッパ(11) | イングランド / スペイン / イタリア / フランス / ドイツ / ポルトガル / オランダ / ベルギー / クロアチア / デンマーク / ポーランド |
| 南米(3) | ブラジル / アルゼンチン / ウルグアイ |
| アフリカ(2) | セネガル / ナイジェリア |
| アジア(1) | **日本** |

#### なぜ実在の国籍にするか

**実在選手カード(WORLD CLASS / LEGENDS)との国籍シナジーを載せるため**(→§3.13)。
架空の国のままだと「同じ国の選手同士」という関係が作れず、
実在選手をモチーフにする段と噛み合わない。国籍は今後の連携・コンビネーションの軸になる。

#### リーグごとの国籍構成

`nationBox(league)` が抽選箱を作る。**自国 `homeW` / 近い国 各10 / それ以外 各3** の重み。

- どのリーグにも**16か国すべてから選手が来うる**(重み3でも0ではない)
- **プレミアは自国比率が最も低く(30)、カンピオナートが最も高い(75)**。
  実際のリーグの国際色をそのまま反映している
- 「近い国」はリーグごとに定義する(セリエなら南米とフランス・クロアチア、など)

#### 名前

姓は**国籍ごとに20個**(計340個)。1クラブ16人は複数の国籍から集まるので、
`makeRoster` は**ロスター全体で姓が重ならないように**配る
(国籍ごとではなく全体で見る。同じクラブに同姓が並ぶと編成画面で見分けが付かない)。

**名の形式と姓名の並び順は国籍が持つ。**

| | 名 | 並び | 例 |
|---|---|---|---|
| 既定(`west`) | イニシャル1文字 (`GIVEN`) | 名 → 姓 | `A. スミス` |
| **日本**(`order:"east"`) | 漢字の名 (`GIVEN_BY_NATION.jpn`) | **姓 → 名** | `秋山 拓海` |

> **姓はカードの `sur` に別途持たせている。** 並び順が国籍で変わる以上、
> 表示名を分割して末尾を取る方法では姓が取れない(日本は先頭が姓)。
> 一覧やピッチに出す短い名前(`shortName`)は `sur` を見る。
>
> 別の並び順を持つ国籍(ハンガリーなど)を足すときも、`order` を付けるだけで済む。

日本は欧州のクラブに散らばる形で入り、**ブンデスの「近い国」に含めてある**
(実際のリーグの傾向に合わせた)。48クラブ768人のうち日本人は18人前後、
うちブンデスが最多になる。

### 3.16 フォーメーション(D22 — 決定 2026-08-02)

**card-eleven の16種を踏襲する。**枠の配置は同じ考え方(細分ポジション + ピッチ上の%座標)で、
数を揃えるほど「手持ちに噛み合う形を探す」遊びが成立する。

```
 標準       4-4-2 / 4-3-3 / 3-5-2 / 5-3-2 / 4-3-1-2 / 4-2-3-1
 守備寄り   5-4-1 / 4-1-4-1
 攻撃寄り   3-4-3 / 4-3-2-1 / 4-2-4
 特徴的     4-4-2ダイヤ / 4-2-2-2 / ゼロトップ / 4-3-3アシメ / 9.5番
```

#### 座標はそのまま持ってこられない

card-eleven とは**ピッチの縦横比が違う**(こちらは 3:4 → [06. §6.15](06-design-system.md))。
そのまま使うと GK の名前帯がゴールラインの外へ出る。

- **y を 13〜87 に線形で詰める**(あちらは 13〜90)。x はそのまま
- そのうえで**最終ライン(y 70〜80)を2%上げる**。詰めた結果 GK との間隔が12%になり、
  名前が長いと**名前帯どうしが触れた**(実測で 3×6px の重なりを検出)。
  1枠の高さは「ポジション名 + 丸 + 名前帯」で約13%なので、**間隔は13.5%以上**要る
- 16種すべてを実際に描いて**枠の矩形が重なっていないかを実測**する
  (`drive.js` が毎回チェックする。名前の長さで変わるので、計算では詰め切れない)

#### 陣形は「選ぶ前に結果が見える」ようにする

16種を巡回ボタンで回すのは現実的でないのでピッカーにした。
**陣形は好みではなく「手持ちがどの形に噛み合うか」で選ぶもの**なので、
各行に**いまの11人をその形へ並べ直したときの総合力**を出す。

| 行の中身 | |
|---|---|
| 数字 | その形に並べ直したときの総合力(`squadPowerAt`) |
| 枠の内訳 | `DF 4 / MF 4 / FW 2` |
| 枠に合わない人数 | 完全一致でない枠の数 |
| **最適** | 最も総合力が高い形の印 |

> **数字に色は付けない。** 黄と赤は「枠適性で目減りしている」印として使っているので、
> ここで「一番ではない」の意味に流用すると読み違える(実際に一度やって全部黄色になった)。

- 陣形を変えても**選手は入れ替えない**。同じ11人を新しい枠へ並べ直すだけ(`refitSquad`)。
  `autoSquad` で組み直すと手で作った編成が丸ごと捨てられる。

#### まだ入れていないもの — キーポジション

card-eleven には **`KEYPOS`**(陣形ごとに「その形の特徴を担う枠」を決め、
該当枠の選手の特定ステータスに係数を掛ける)がある。
例: 4-4-2 は2トップの得点力、4-3-3 は両ウイングの速さ、5-3-2 は両WBのスタミナ。

**これは踏襲する価値があるが、試合エンジンと一緒に決める。**
係数がどこに効くかはエンジンの計算式に依存するため、先に入れても検証できない。
→ [05. 実装バックログ](05-decisions-backlog.md) 第3段の論点として持つ。

### 3.17 編成は16人(D23 — 決定 2026-08-02)

**先発11 + 控え5 = 16人**を1チームの単位にする。敵味方とも同じ構成。
交代を扱うために、控えを**常設の枠**として持つ。

| | |
|---|---|
| 先発 | 11。陣形の枠に紐づき、**枠適性が掛かる**(→§3.14) |
| 控え | 5。**枠のポジションを持たない**ので適性は掛からない。素のOVRで並ぶ |
| 実装 | `S.squad` は16要素。0〜10が先発、11〜15が控え |
| クラブの名簿 | `makeRoster` が元から16人を作る(`plan` が16)。CPUも同じ |

- **控えに適性を掛けないのは、誰の代役にもなりうるから。**
  どの枠に入るかは交代のときに決まるので、ベンチにいる間は素の力で比べる。
- 控えも先発と同じ**枠**として扱う。タップして差し替えられ、
  先発の選手を選べばその枠と入れ替わる(昇格・降格が同じ操作で済む)。
- 自動編成は「先発を枠ごとに 適性×OVR で埋める → 控えは**ポジションを揃えてから**OVR順」。
  素のOVR順だけだとGKもDFも居ない控えになり、投入時に枠適性0.50で**交代が損になる**。
- 陣形を変えても**控えは持ち越す**。並べ直すのは先発の11枠だけ。

> 交代そのもの(いつ・誰を・何人)は試合エンジンと一緒に決める。
> ここで用意したのは**交代要員を選んでおける器**まで。

### 3.18 現状の実装(実装バックログ第2段まで)

**キャリアが1周できる**。就任 → 14節を戦う → 順位確定 → 審判(続投/解任) → 次のクラブへ、が通る。

| | 実装済み |
|---|---|
| 世界 | 4カ国 × 8クラブ = 32クラブ。選手はセーブに持たず**シードから決定的に再生成**する |
| 就任 | 名声で届くクラブからオファー → 契約書に署名 → 貸与選手を受け取る(D13) |
| シーズン | 14節のホーム&アウェイ総当たり。**自クラブの試合も他クラブ同士の試合も** `match-core` が解決 |
| 評価 | 期待順位(クラブの格 × 持ち込んだ編成)との差から**導出**。上回れば上、下回れば下 |
| 審判 | シーズン末に名声が増減し、続投/解任が決まる。キャリア履歴が残る |
| 画面 | HOME(秘書・CLUB NEWS)/ CARDS / DECK(ピッチ配置)/ SEASON / SCHEDULE / STANDINGS / CLUB / 結果 / オファー |

**まだ無いもの**: 試合の描画(結果だけ出る)・パック・施設投資・采配・イベント・トロフィー・大陸大会。
節の「1手」もまだ選べない(試合を進めるだけ)。次は第3段(試合)
→ [05. §5.2 実装バックログ](05-decisions-backlog.md)。
